For ranking, all confirmed sites have the same immediate consequence: **process termination**. I distinguish their input scope rather than claim measured workload frequency:

- **I1:** already-supported value or RAM access is terminated.
- **I2:** an unimplemented device operation or CPU feature terminates execution.
- **I3:** rejection, invalid-state, or fault-recovery handling terminates execution.

Effort is independent:

- **E1:** an identified predicate has a one-to-five-line product change and an existing test carrier.
- **E2:** localized work, but validation, diagnostics, or an adequate assertion prevents certifying E1.
- **E3:** feature, state-machine, or shared execution-flow work.

**`mapledmaaddr` — severity `high`.**

**`mk48nvram` — severity `high`.**  
**Title:** `DEVICE_ACCESS(mk48txx) misclassifies MK48T08 NVRAM bytes as unsupported registers and terminates ordinary RAM accesses.

The grep anchor is [`DEVICE_ACCESS(mk48txx)`](C:/DocumentNoSnc/CC/GXEMUL/GXEMUL-SEC/src/devices/dev_mk48txx.c:76); the exit is at **118**. The actual [MVME187 constructor](C:/DocumentNoSnc/CC/GXEMUL/GXEMUL-SEC/src/machines/machine_mvme88k.c:114) explicitly attaches an **MK48T08**.

The range bypass leaves bank-relative positions **0,1,2,3,4,5,6,7,8** entering the switch. Its sole case handles **8**, `MK48TXX_ICSR`. Thus the eight positions **0,1,2,3,4,5,6,7** reach default. M88K can receive a device access exception, but reporting one for these RAM bytes would choose the wrong behavior.
