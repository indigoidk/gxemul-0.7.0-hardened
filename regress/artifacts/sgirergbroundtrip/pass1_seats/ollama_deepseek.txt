**Q1 — Which arm is wrong?**  
READ from the quoted code:  
- PUT RGB writes `buf[0]=R, buf[1]=G, buf[2]=B, buf[3]=0`.  
- GET RGB reads `buf[1]<<24 + buf[2]<<16 + buf[3]<<8`, ignoring `buf[0]`.  

REASONED: These are not inverses. The PUT order matches RGBA’s `R,G,B,A` layout with `A` replaced by a zero pad at `buf[3]`. The GET order matches neither RGBA nor ABGR; it is a third layout `pad,R,G,B`. Internal consistency therefore favors GET being wrong.  
The other side: if the hardware expects RGB pixels as `0x00RRGGBB` in big-endian memory order, then GET is correct and PUT should write `buf[0]=0, buf[1]=R, buf[2]=G, buf[3]=B`. That cannot be ruled out from the packet alone.
