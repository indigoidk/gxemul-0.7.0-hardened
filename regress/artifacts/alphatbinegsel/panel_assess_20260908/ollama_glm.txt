## Q2 — ship the coarse repair: yes

REASONED: every deviation of `a0 >= 1 && a0 <= 3` is **over**-invalidation — a0=0 and a0≥4 go to ALL (hardware treats those as no-op / low-bit-selected; over-flush is architecturally permitted), TBIAP goes to ALL instead of ASM=0-selective (flushing more than asked can never leave stale state, which is the failure mode this row is about). The finer semantics need per-entry ASM tagging plus a new invalidate mode — a separate feature row. The disclosure should state **both** the ASM=0 gap and the performance cost: ALL-flush on every TBIAP/TBIA nukes all cached translations including code, so a switch-heavy guest re-walks heavily. (A signed-cast repair, `(int64_t)a0 >= 1`, is equivalent for the wrapper set; the bounded form is more defensive. Either is shippable.)

## Q3 — smallest correct-looking reinstatement

REASONED, primary edit: replace the test with the operator's low-bit stream decode — `if (a0 & 3)` → VADDR, else ALL, ideally dressed as `switch (a0 & 3) { case 1: /* I */ case 2: /* D */ case 3: /* I+D */ …VADDR…; default: ALL }` with a comment citing the architectural encoding. It *looks like an upgrade* — it implements stream selectivity and handles 1/2/3 exactly right — but `0xff…fe & 3 = 2` and `0xff…ff & 3 = 3`, so TBIA and TBIAP both land in VADDR(a1=0): the identical defect, wearing a spec citation. Secondary: `if (a0 >= 1 && a0 != (uint64_t)-1)` — "explicitly special-case TBIAP" — fixes TBIAP, leaves TBIA broken, and defeats any witness that exercises only TBIAP.

## Q4 — channels the witness would miss: yes, three

1. **Content coincidence** (the direct answer to "value happens to match"): if old and new backing hold the same bytes at the observed offset — the classic case being two zero pages — both builds read identically and the row is vacuous. The witness must write a distinct sentinel into the old backing and assert a **difference between builds** (defective reads A, fixed reads B), not merely an expected value.
2. **Re-walk anyway on the defective build**: target page = 0 (TBIA genuinely flushes it), or the stale entry evicted by intervening translation-cache pressure before the observing load. Keep the target off page 0 and the sequence short inside the one `step N`.
3. **Something else does TBIA's job**: if any store into the page-table page triggers translation invalidation, both builds re-walk and the row is green. Not checkable from the packet; settling fact: whether stores to PTE pages invalidate translations on this arch. (Separately, a coverage gap rather than vacuity: the witness observes only reads; stale-`host_store` corruption of a reallocated frame goes unobserved.)
