**Premise audit**

The THEREFORE and §2's settled witness (stale OLD value observed on a non-page-0 VA) are only consistent with the opposite reading: **match ⟹ invalidate**. So the packet is internally inconsistent exactly once, at this sentence, and §2's witness result independently corroborates that the sentence is the misstatement. **Q2 — ship the coarse repair (REASONED).** The error direction is safe: over-invalidation costs re-walks, never stale data — the exact opposite of the defect. **Q3 — smallest plausible re-break (REASONED):** replace the guard with a shifted window on unsigned arithmetic:

    if (a0 + 2 <= 3 + 2)   /* selectors are 1..3 */

By mod-2⁶⁴ wrap, the admitted set is exactly {−2, −1, 0, 1, 2, 3}. Every one of the five documented wrappers (`-2, -1, 1, 2, 3`) takes the *identical* branch it took on the original broken build, so any regression test authored against the defective behavior stays green, and the diff reads as an idiomatic range check. Its honest look-alike — `(a0 - 1) <= 2` — is correct (lo=1, hi=3, negatives wrap *out*), which is precisely why the `+2` form survives review. Backup variant: `if (abs((int)a0) >= 1 && abs((int)a0) <= 3)` ("normalize the ±selector"), same effect. Reviewer invariant to enforce: the true-branch preimage over all 2⁶⁴ inputs must be exactly {1,2,3}; any test expressed as addition/subtraction on the unsigned `a0` is a red flag.

**Q4 — missed channels (REASONED):**
* **Stale stores are invisible to this witness.** Sequence: remap VA→PA2, TBIA (survives), *store* Z through VA → lands in PA1 via the stale entry; then *load* VA → same stale entry returns Z. Defective and correct builds both "return what was written": green on the broken build, while PA1 — which the guest believes unmapped — is silently corrupted. The witness is safe only because it *ends in a load* and never self-checks via store→load through one VA. Any "hardening" that adds a store-verify through the same VA would collapse the row to vacuous. Corruption confirmation requires a second path: an alias VA or device read of PA1.
* **Permission-only remaps are invisible.** If the PTE change tightens rights without moving the page, values match by construction; the defect shows as a *write that should fault but doesn't* (stale `host_store`). And §2 settles that member-5 FAULT is unavailable on Alpha — so this channel has no witness primitive at all. Record as known-missed, not vacuous.
* **Instruction fetch:** if fetch consumes `host_load`, stale code executes after a code-page remap; a data-value witness never sees it. Not stated in the packet whether fetch uses those pointers — not checkable from here.
* Also note the trivial vacuities already avoided by design: equal page contents (use distinct markers) and page-0 VAs (the defective flush *does* handle page 0).
