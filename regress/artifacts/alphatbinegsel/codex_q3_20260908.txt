Consequently, the earlier comment claiming VADDR clears only the quick array is stale for this implementation.

Alpha uses **8 KiB pages**, and normal CPU construction gives it an **all-ones `vaddr_mask`**. Thus `ALPHA_TBIA()` currently invalidates only cached virtual page zero—nothing if that page is absent. Every other cached mapping survives. [Page size](/C:/DocumentNoSnc/CC/GXEMUL/GXEMUL-SEC/src/cpus/cpu_alpha.c:50), [mask initialization](/C:/DocumentNoSnc/CC/GXEMUL/GXEMUL-SEC/src/cpus/cpu.c:140).

**The guest-visible consequence is stale translations surviving a flush the OS believes succeeded.** A previously cached, subsequently remapped nonzero virtual page can still access its old physical backing: Alpha’s [load/store fast path](/C:/DocumentNoSnc/CC/GXEMUL/GXEMUL-SEC/src/cpus/cpu_alpha_instr_loadstore.c:151) consumes those surviving host pointers.

An empty cache can make the two calls coincide; that does not make their semantics equivalent. “ALL” here clears address-translation mappings, rather than discarding all separately cached compiled instructions.
