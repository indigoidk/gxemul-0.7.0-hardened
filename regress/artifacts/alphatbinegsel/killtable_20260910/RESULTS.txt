THE AXIS SET, AND WHY IT IS CLOSED IN ONE DIFF RATHER THAN ONE PER PASS.
Three consecutive passes each bought exactly one axis of this same guard: the
two-sided window's four sides, then the body's other lvalue, then operand
magnitude.  That converges linearly and does not terminate.  Table 3 enumerates
the axes and closes them together:
  lower bound accept  a0=1                   bnd lo     M_A
  lower bound reject  a0=0                   bnd zero   M_D
  upper bound accept  a0=3                   bnd hi     M_B
  upper bound reject  a0=4                   bnd out    M_C, HEAD
  interior            a0=2                   bnd mid    M_F
  negative selectors  a0=-1,-2               tbia/tbiap obs   HEAD
  a1 zero vs non-zero a0=2, a1=0             bnd a1z    M_E, M_F
  a1 magnitude        a0=2, a1=0x8000        bnd a1hi   M_I, M_F
  a0 magnitude        a0=0x0000000100000001  bnd wide   M_G, M_H, HEAD
Disclosed and deliberately NOT rowed: the -1 vs -2 distinction (unrepresentable
in this model -- no ASM/ASN metadata); selector values above 4 individually (same
guard cell as a0=4); a1 thresholds other than 0 and 0x8000; multi-axis joints;
and the case-0x33 dispatch label, which is clause (e) because the palcode selector
flows into no lvalue the guarded body reads and the body never re-tests it.

WHY THE MAGNITUDE AXIS WAS INVISIBLE, verified by enumeration before it was built:
for any small value (int32_t)a0 == (int64_t)a0, so narrowing the cast disagrees
with the fix at NONE of the seven selector values the other rows drive.  The
smallest discriminating input is a0 = 0x0000000100000001 -- the fix sees
4294967297, fails <= 3 and invalidates everything; a narrowed cast truncates to 1
and flushes one page.  load_const builds only sign-extended 32-bit constants, so
that row loads a0 from the pointer vector with LDQ.  NO NEW INSTRUCTION ENCODING
was introduced anywhere in this file, which is the standing caution here.

KNOWN REDUNDANCY, recorded rather than glossed: M_F reddens three rows, because
bnd mid, bnd a1z and bnd a1hi all drive a0 = 2.  This is unavoidable by
construction -- an a1-axis row must use SOME selector inside [1,3], and each of
those already has a cell row.  It leaves no hole: each of the three independently
kills M_F, bnd a1z is the only row that kills M_E, and bnd a1hi the only one that
kills M_I.
