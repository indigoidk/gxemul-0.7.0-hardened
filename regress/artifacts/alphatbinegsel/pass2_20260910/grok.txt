### 1. Premises

**S2, enumerated, not reasoned.** `a0` is `uint64_t` at `uint64_t a0 = cpu->cd.alpha.r[ALPHA_A0]`. Old test `a0 >= 1`:

| bit pattern | as signed | `>= 1` unsigned | old arm | new `(int64_t)a0` in `[1,3]` |
|---|---|---|---|---|
| `0` | 0 | F | ALL | ALL |
| `1` | 1 | T | VADDR | VADDR |
| `2` | 2 | T | VADDR | VADDR |
| `3` | 3 | T | VADDR | VADDR |
| `4` | 4 | T | **VADDR** | ALL |
| `2^64-1` (`LDA -1`) | −1 | T | **VADDR** | ALL |
| `2^64-2` (`LDA -2`) | −2 | T | **VADDR** | ALL |

Both PAL “invalidate everything” encodings took VADDR with `a1`. `t2/probe_HEAD.raw` still shows that: `tbia obs` and `tbiap obs` stay on the pre-remap value.

**The arm header is a copy, not the authority.** The independent source in this tree is the NetBSD import, labelled `[OSF/1 PALcode Specific]`:

```
ALPHA_TBIA()  alpha_pal_tbi(-2, 0)   /* all TB entries */
ALPHA_TBIAP() alpha_pal_tbi(-1, 0)   /* all per-process */
ALPHA_TBISI   1   /* ITB entry for va */
ALPHA_TBISD   2   /* DTB entry for va */
ALPHA_TBIS    3   /* all for va */
```

That matches the header table. It is **OSF/1 PAL**, not the Alpha ARM. `21066_66a_hrm.txt` has `ITBASM`/`DTBASM`/`IOC_TBIA` and **zero** `TBIAP`/`PAL_OSF1_tbi` selector encodings — the same over-read the 2026-09-09 adjudication already caught.

**S5 is right in the model, and the product comment does not overclaim I-vs-D.** One `if`, same `INVALIDATE_VADDR`/`a1` for 1, 2 and 3. An edit that made `a0==1` ITB-only (a no-op on data) would redden `bnd lo` on `obs X`, not on Y.

**S6 is right on the default, slightly wrong on the failure mode.** `cpu_alpha.c` never assigns `vaddr_mask`; `is_32bit = 0`; `cpu.c` then does `cpu->vaddr_mask = (int64_t)-1`. If a later Alpha `cpu_new` installed a collapsing mask, the survive-side rows (`bnd lo`/`mid`/`hi`/`a1z`) would **false-fail on BASE**, not go vacuous. **Premise this brief did not give me:** `(int64_t)a0` when `a0 > INT64_MAX` is C99 6.3.1.3 implementation-defined. That set **includes both PAL negatives**. ### 2. Smallest edit that breaks the fix and still passes 13/13

**The unrowed axis of the cast is WIDTH, not signedness.**

```c
if ((int32_t)a0 >= 1 && (int32_t)a0 <= 3)
```

(or `(int8_t)`). Every driven selector is in `[-2, 4]` and survives 8-bit truncation, so **all 13 stay green**, including `tbia obs` and `bnd out`. `a0 = 0x101` would then compare as `1` and take VADDR: under-invalidation, the dangerous direction, on an undefined encoding. That is clause (e), not a floor breach: the body’s partition of `a0` is the signed window `{<1, 1, 2, 3, >3}`; truncation is a new decode, and the contract already discloses individual values above 4. Still the one-token answer to “what did I not row.”

### 3. Option set

Silent ALL for undefined selectors is the right member (conservative ACCEPT). Two members the ruling did not name, both found by grepping this file rather than arguing:

**HALT — the sibling idiom, one case down.** `PAL_OSF1_wrent` on `a1 >= N_ALPHA_KENTRY` does `fatal(...)` then `cpu->running = 0`. The `default:` arm of `alpha_palcode()` is the same. That is this file’s handling of an out-of-range PAL selector. It should be named so it can be rejected: a bad `tbi` op from a guest OS would stop the emulator. Over-invalidation is strictly cheaper.

**Silent no-op (DECLINE).** Under-invalidation; worse than the defect. No PAL precedent for it here.

FAULT is not available: S4 is a *device* path, and `tbi` never goes through `memory_rw`. Latched announce is the device-house idiom (`(once)`), not the PAL-house idiom (unlatched `fatal` + halt). IMPLEMENT of ASM-selective TBIAP is blocked by the cache entry: `arch_vpg_tlb_entry` is `valid`, `writeflag`, `vaddr_page`, `paddr_page`, `host_page`. `ALPHA_PTE_ASM` is the `#define` at `alpha_cpu.h` only; `apcb_asn` is PCB save/restore in `swpctx`, not a cache tag. The comment’s “no ASM/ASN metadata to spare anything BY” is right as a *struct* claim.
