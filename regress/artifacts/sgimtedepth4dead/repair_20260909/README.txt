ONE RESIDUAL, FOUND WHILE VERIFYING A CONTRACT SENTENCE.  A READING, NOT A MEASUREMENT.
------------------------------------------------------------------------------------------
The contract says the `dst_tlb' default arm "diagnoses and continues".  Checking that rather
than asserting it, the arm is:

    default:
            fatal("[ sgi_mte: TODO! unimplemented dst_tlb 0x%x ]", dst_tlb);
    }

*** IT IS GUEST-DRIVABLE AND UNLATCHED. ***  `dst_tlb' is `(mode & 0x1c) >> 2' from a guest
MTE_MODE write, so values 3 (MTE_TLB_TEX), 6 (MTE_TLB_CLIP) and 7 reach this arm, and
`do_mte_transfer' runs once per START write -- one unbounded `fatal()' per transfer.  This
file already carries the house remedy: a ten-bit `SGIRE_W_*' latch enum whose comments
record, from `#498' and `#513', that a new site gets ITS OWN BIT rather than sharing one
(sharing was measured at 23/25).  So the fix shape is settled and cheap; what is missing is
the row.  `grep -n 'unimplemented dst_tlb' OUTSTANDING_BUGS.md' returns nothing -- it is not
filed.

I did NOT drive it, so this is a READING and is ranked as one.  The measurement is one
session: `fill_at(A, RE_TLB_A, 3 << 2)' in this probe's own helper puts dst_tlb = 3 and
reaches the arm; repeat the START write and count the diagnostics.  It is deliberately NOT
added to the instrument here -- a flood row is a different round, and adding it would change
the instrument this table measured.
