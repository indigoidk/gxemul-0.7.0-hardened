## 1. Central claim, enumerated

`depth = 8 << ((mode & 0x300) >> 8)`. The mask 0x300 covers exactly bits 8–9 of `mode`. Right-shifting by 8 yields the two-bit field value in `{0,1,2,3}`. So:

| field | depth  | bufdepth = 1<<field | depth == 4? |
|------:|------:|--------------------:|:-----------:|
| 0     | 8     | 1                   | no          |
| 1     | 16    | 2                   | no          |
| 2     | 32    | 4                   | no          |
| 3     | 64    | 8                   | no          |

Four values walked, none equals 4. **Branch is unreachable.** (REASONED from the inline arithmetic.)

`bufdepth == depth/8` for all four values, so `depth == 32` and `bufdepth == 4` are exactly the same condition. (REASONED.)

## 5. F1–F5 option set

The closest cousin I can name without file access is "initialise the uninitialised portion of buf in the CI arm" (a hybrid of F4 and F5), which would close depth=16 and depth=32 in one go but is the same defect class as F4 and doesn't address the byte-order question. ## 6. Q4 — three cells, one fix
