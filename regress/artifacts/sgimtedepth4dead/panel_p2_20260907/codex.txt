Six seats answered pass 1 (`_scratchpad/panel_20260907_170713`; durable copy at
`regress/artifacts/sgimtedepth4dead/panel_p1_20260907`).  All six confirmed these by
enumeration, several from the packet alone:

* **`depth = 8 << ((mode & 0x300) >> 8)`, a two-bit field, so `depth ∈ {8,16,32,64}`.**
  `depth == 4` is unreachable; the byte count is 4 and the author used `/ (depth / 8)`
  correctly two lines above.
* **`depth == 32` ⟺ `bufdepth == 4`** — both are bijections of the same field value.
* **With the branch dead, both constructed modes carry no type bits, so `DE_MODE_TYPE_CI`
  (== 0) is always selected.**
* **At 32bpp the CI arm assigns `buf[0]` only, and `memory_rw` copies `bufdepth` = 4 bytes
  from a `uint8_t buf[8]` with no initialiser** — three bytes of host stack reach guest RAM.
* **The header defines `MTE_DEPTH_8/16/32` and no `MTE_DEPTH_64`**; field value 3 computes
  64 and is undefined by the header.
* **Corrected in pass 1, by two seats independently:** at field value 3, CI leaves **seven**
  bytes uninitialised and an RGBA substitution would leave **four** — a reduction, not a
  neutral swap.  My brief had said "four into four".
* **There is NO SGI/CRIME hardware documentation in this project** — derived by
  `ls _scratchpad/*.pdf`, sixteen manuals, none for this device.  So the warrant for RGBA
  over RGB is the dead branch's own choice plus the comment ("copy 32 bits", which RGB's

    5: #      :1311  int depth = 8 << ((mode & MTE_MODE_DEPTH_MASK) >> MTE_DEPTH_SHIFT);   /* BITS */
    6: #      :1359  src_x1 /= (depth / 8);                     <- the author converting bits -> bytes
    7: #      :1369  // ... this makes sure that we copy 32 bits when doing 32-bit transfers.
    8: #      :1371  if (depth == 4) { src_mode |= DE_MODE_TYPE_RGBA; dst_mode |= ...; }
    9: #
   10: #  The field is two bits, so `depth' is 8/16/32/64 -- never 4.  The branch is dead, the constructed
   11: #  modes carry no type bits, `color_mode' stays CI, and CI's PUT assigns buf[0] only while the
   12: #  transfer moves `bufdepth' bytes.
   13: #
   14: #  *** THIS IS A WITNESS, NOT A DETECTOR.  Its rows assert the CORRECT behaviour and are expected to
   15: #  FAIL here; it must not be gated. ***
   16: #
   17: #  ---------------------------------------------------------------------------------------------
   18: #  THE ORACLE IS `dest[0]' OF A TILED **FILL**, AND EVERY OTHER CHANNEL I PROPOSED WAS REFUSED.
   19: #  From the grok design review, each point measured against the source rather than argued:
   20: #
   21: #  * A PRE-PAINTED TAIL CANNOT WORK.  CI PUT does not replicate buf[0] across the span and does not
   22: #    leave a tail: it writes buf[0] at the lowest address and buf[1..bufdepth-1] as uninitialised
   23: #    stack, and memory_rw memcpys `bufdepth' bytes.  So the paint is OVERWRITTEN WITH GARBAGE.  A row
   24: #    asserting "tail still painted" reds on HEAD because the path RAN -- which reads as "the witness
   25: #    never reached MTE".  A row asserting "tail != paint" is true on HEAD *and* after the fix.
   26: #
   27: #  * COPY CANNOT WITNESS THIS AT ALL.  Source `aa bb cc dd': CI GET takes buf[0] == 0xaa and CI PUT
   28: #    writes 0xaa at dest[0]; RGBA GET reconstructs 0xaabbccdd and RGBA PUT also writes 0xaa there.
   29: #    The first byte of a copy is the one byte CI already gets right, and the broken bytes are exactly
   30: #    the uninitialised ones that must not be read.  "If the witness is a blit, refuse it."
   31: #
   32: #  * FILL IS DETERMINISTIC BECAUSE IT NEVER GETs.  With bg = 0x11223344:
   33: #        CI   PUT -> buf[0] = (uint8_t)bg          -> dest[0] = 0x44   (the LOW byte)
   34: #        RGBA PUT -> [bg>>24, bg>>16, bg>>8, bg]   -> dest[0] = 0x11   (the HIGH byte)
   35: #    dest[1..3] are uninitialised on HEAD.  **DO NOT ASSERT THEM THERE.**
   36: #
   37: #  *** THAT SENTENCE USED TO END "only the top byte of the big-endian word is READ", WHICH IS
   38: #  FALSE AND WAS CAUGHT BY THE PASS-1 CODEX SEAT.  The probe executes `lw' and masks afterwards:
   39: #  it READS four bytes and ASSERTS one.  Corrected 2026-09-07 -- the distinction matters because
   40: #  the tail IS assertable once the fix lands (RGBA writes all four), which is what `fill bot'
   41: #  below now does. ***
   42: #
   43: #  * TLB_A WITHOUT BIT 15 RETURNS SILENTLY and leaves the destination painted, which looks like "MTE
   44: #    did nothing".  sgi_re_rgb_probe.py paid for that trap twice; TLBA_TILE = 0x8002 is why.
   45: #
   46: #  * MTE LIN_A/B at depth 32 would `exit(1)' in the LINEAR arm -- host death, not a red row.

   92: #  `if (startFlag) do_mte_transfer(cpu, d);' sits at the END of DEVICE_ACCESS(sgi_mte), so any MTE
   93: #  write with bit 0x800 in its ADDRESS fires the transfer.  DST1 is written last, with START.

   95: #  dst_tlb = (mode & MTE_MODE_DST_BUF_MASK 0x1c) >> 2  -> MTE_TLB_A = 0

   97: #  MTE_MODE_COPY 0x800 CLEAR = fill.  (0x800 here is a MODE bit; the 0x800 in the address is START.)

  100: CI_TOP          = 0x44            # what the DEFECT writes at dest[0]

  102: PAINT           = 0x99999999      # neither -- liveness only, NOT a tail oracle
  103: PAINT_TOP       = 0x99

  105: #  DEPTH IS AN AXIS, NOT A CONSTANT.  Two seats independently showed the six-row witness blind to
  106: #  an OVER-REACH mutant: `depth >= 16' fires at 32 (so `fill top' stays green) and is cold at 8
  107: #  (so `depth8 top' stays green).  The adjacent DOCUMENTED cell -- 16 -- is what catches it.
  108: MODE_D8    = 0x000                # MTE_DEPTH_8  << MTE_DEPTH_SHIFT
  109: MODE_D16   = 0x100                # MTE_DEPTH_16 << MTE_DEPTH_SHIFT
  110: MODE_D32   = 0x200                # MTE_DEPTH_32 << MTE_DEPTH_SHIFT
  111: MODE_COPY  = 0x800                # MTE_MODE_COPY (a MODE bit; the 0x800 in an ADDRESS is START)
  112: MTE_SRC0   = 0xb5003020           # CRIME_MTE_SRC0 0x3020 -- no 0x800, so it does not fire START
  113: 
  114: #  *** THE FIRST SOURCE BYTE IS DELIBERATELY BELOW 0x80. ***  Every GET arm computes
  115: #  `buf[0] << 24' on a uint8_t, which promotes to signed int -- so a first byte >= 0x80 shifts
  116: #  past INT_MAX and is undefined behaviour.  That is a SEPARATE filed defect ([[sgirebufshiftub]],
  117: #  re-derived independently by the pass-1 codex seat); this probe must not stand on it, so the
  118: #  copy rows use 0x1a as byte 0.  Four distinct bytes, so each names its own position.

  123: SRC_PIX_X  = 4                    # src0's x field; /(depth/8) = 1 -> source byte offset 4
  124:

  131: #  `for (y = y1; y != y2+dy; y += dy)' with dy = 1 runs once.

  133: DST1 = 0x00000000

  135: def session(cmds, settle=1.5, spin=1.8):
  136:     pid, fd = pty.fork()
  137:     if pid == 0:
  138:         os.execv(BIN, [BIN, "-V", "-x", "-E", "sgi", "-e", "ip32", "-M", "64",
  139:                        "0x%x:" % CODE + DUMMY])
  140:         os._exit(127)
  141:     buf = ""
  142:     def rd(t):
  143:         nonlocal buf
  144:         end = time.time() + t
  145:         while time.time() < end:
  146:             r, _, _ = select.select([fd], [], [], 0.1)
  147:             if not r:
  148:                 continue
  149:             try:
  150:                 d = os.read(fd, 65536)
  151:                 if not d:
  152:                     return False
  153:                 buf += d.decode("latin-1", "replace")
  154:             except OSError:
  155:                 return False
  156:         return True
  157:     alive = rd(settle)
  158:     for i, c in enumerate(cmds):
  159:         try:
  160:             os.write(fd, (c + "\n").encode("latin-1"))
  161:         except OSError:
  162:             alive = False; break
  163:         if not rd(spin if i == len(cmds) - 1 else 0.22):
  164:             alive = False; break
  165:     try:
  166:         os.write(fd, b"quit\n"); rd(0.4)
  167:     except OSError:
  168:         pass
  169:     try:
  170:         os.close(fd)
  171:     except OSError:
  172:         pass
  173:     return buf.replace("\r", ""), alive

  179: class Addr(object):
  180:     def __init__(self, base): self.a = base
  181:     def take(self, n):
  182:         got = self.a; self.a += 4 * (n + 2) + 0x20; return got
  183: 
  184: def run_ops(ops, at):
  185:     put = ["put w 0x%x, 0x%08x" % (at + 4 * i, op) for i, op in enumerate(ops)]
  186:     put += ["put w 0x%x, 0x%08x" % (at + 4 * len(ops), OP_B_SELF),
  187:             "put w 0x%x, 0x%08x" % (at + 4 * len(ops) + 4, OP_NOP)]
  188:     return put + ["pc=0x%x" % at, "step %d" % len(ops)]

  190: def store(A, addr, val, op=OP_SW_T0_A3):
  191:     return ["a3=0x%x" % addr, "t0=0x%x" % val] + run_ops([op], A.take(1))

  193: def load(A, addr):
  194:     return ["at=0x%x" % addr, "v0=0x%x" % SENTINEL] + run_ops([OP_LW_V0_AT], A.take(1))

  203:     if not s.startswith("0x"):

  207: def fill(A, depth=MODE_D32):
  208:     """Program a tiled FILL at `depth' and fire it.  Every store is a REAL GUEST INSTRUCTION."""
  209:     #  re_tlb_a[0] = 0x8002.  The RE TLB write walks `len' in halfwords from tlbi 0, so an `sd'
  210:     #  carrying the tile in its TOP halfword lands it at index 0 -- the packing sgi_re_rgb_probe.py
  211:     #  established, and getting it wrong leaves the valid bit clear and the transfer silent.
  212:     c  = store(A, RE_TLB_A, TLBA_TILE << 48, op=OP_SD_T0_A3)
  213:     c += store(A, DEST, PAINT)                     # pre-paint: liveness, NOT a tail oracle
  214:     c += store(A, MTE_MODE, depth)
  215:     c += store(A, MTE_BG,   BG_VAL)
  216:     c += store(A, MTE_DST0, DST0)
  217:     c += store(A, MTE_DST1_START, DST1)            # START fires do_mte_transfer()
  218:     return c

  220: def copy(A):
  221:     """Tiled 32-bit COPY of ONE pixel: source (1,0) -> dest (0,0), both in TLB_A's tile.
  222: 
  223:     These rows exist because a FILL never reads `src_mode': deleting only
  224:     `src_mode |= DE_MODE_TYPE_RGBA' is invisible to every fill row.  Three seats confirmed both
  225:     the prediction and the byte walk.  dest[0] is 0x1a under BOTH correct shapes -- so `copy top'
  226:     distinguishes neither HEAD nor the fix, and that IS its job: it reds only under a ONE-SIDED
  227:     edit (source-only -> 0x4d, dest-only -> 0x00).
  228: 
  229:     A note the kimi seat asked for, so a future reader does not "correct" the want: the
  230:     dest-only cell gives 0x00 because the CI GET *assigns* `*color = buf[0]', zero-extending it.
  231:     Had the GET left `bg' untouched, an RGBA PUT would have emitted bg>>24 instead.  The row is
  232:     right; the reason is the assignment, not "the high byte of a low-byte colour" in general.
  233: 
  234:     The destination is PRE-PAINTED so that a transfer which silently does nothing (an invalid
  235:     TLB entry, say) reports 0x99 rather than looking like a plausible byte."""
  236:     c  = store(A, RE_TLB_A, TLBA_TILE << 48, op=OP_SD_T0_A3)
  237:     c += store(A, DEST + 4, SRC_WORD)              # the source pixel, four distinct bytes
  238:     c += store(A, DEST,     PAINT)                 # the destination, so a no-op is visible
  239:     c += store(A, MTE_MODE, MODE_D32 | MODE_COPY)
  240:     c += store(A, MTE_SRC0, SRC_PIX_X << 16)       # src x=4 -> pixel 1 at depth 32, y=0
  241:     c += store(A, MTE_DST0, DST0)
  242:     c += store(A, MTE_DST1_START, DST1)            # START fires do_mte_transfer()
  243:     return c
