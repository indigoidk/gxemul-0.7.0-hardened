DISPOSITION -- DONE, AND MEASURED.  The row `occupancy above 12 does not
dispatch` was added and `M7_ge12` now DIES ON IT ALONE (see the verdict table
above).  It reaches occupancy 14 by preloading THIRTEEN bytes and writing one,
so the ring never passes through 12 -- a fixture writing two bytes at a time
would dispatch at 12 and never reach the overshoot.  The oracle is the dispatch
count, so it reds on an ORDINARY build and needs no sanitiser.  The overshoot objection that
motivated the wrong classification is real but is answered AT THE RIGHT LAYER:
by flushing the ring (filed as `wdcringnoflush`), never by widening a bound
that guards a `malloc(12)`.  The shipped `== 12` is safe -- the bound holds --
but it is IMPLICIT and REMOTE, so the allocation now carries a comment naming
what bounds it.

`inbuf_len == 12` sits on the diff's own edited line, so it was inside clause

enumeration was run; the consequence of weakening it was assessed by reading

*** THE OTHER ESCAPE ***

M2_curcmd  --  a `d->cur_command == ATAPI_PKT_CMD` conjunct added to the guard.
    On the shipped table it scored KILLED -- but by `row_arm_overrun`'s two
    rows, because NO fixture set cur_command at all.  The real device assigns
    cur_command, the flag and the phase together (`cur_command = idata`, then
    the ATAPI_PKT_CMD arm), so every fixture was building a state the device
    never produces, and the mutant died because LEGAL DISPATCH vanished rather
    than because of the defect.  Found by the codex seat.

    With cur_command set in all four active-packet fixtures it ESCAPES.  The
    obvious reading is "redundant conjunct, provably equivalent" -- and that
    reading is WRONG.  The discriminating state is reachable: the ALT-CTRL arm
    sets cur_command = COMMAND_RESET and does NOT clear atapi_cmd_in_progress
    (the only clear is inside wdc_command).  So a guest can write A0h, touch
    ALT-CTRL, and arrive at `flag == 1 && cur_command == COMMAND_RESET` with
    the phase still CMDOUT.  A REAL behavioural difference on a REACHABLE
    path, so this is coverage debt and is FILED as such.

    Two live defects fell out of that check, both FILED:

      wdcaltctrlbit    the arm tests WDCTL_4BIT (0x08, "use four head bits
                       (wd1003)") where the reset bit is WDCTL_RST (0x04).
      wdcsrstnoabort   the same arm leaves atapi_cmd_in_progress set, so an
                       in-flight packet command survives what the device
                       itself calls a reset.  *** UPGRADED from READ to
                       MEASURED by the Opus seat: it also confirmed neither
                       ATAPI_SOFT_RESET nor the ALT-CTRL reset flushes the
                       ring. ***

**Both escapes were chased rather than classified, and both times the chase
overturned the comfortable reading.**  M2 looked like an equivalence and was
