## Q2 — Refusal is the right member; disclose two things, do not announce

**(a) Silence, not `(once)`.** Type-1 cycles are how a guest scans behind a host bridge. A latched announce on bus-field-0 would fire on the first such probe and then lie in the log forever. Empty-slot **reads** in `bus_pci` are already silent. Match that. Hardware does not print a host diagnostic.

**(b) The write-half mismatch is real and the comment overclaims.** Empty-slot **writes** print; the refusal discards. That is sibling-parity with `bus_pci`'s `dev == NULL` write arm, not with `dev >= 21` (PRETABLE compared the wrong sibling for Q2(b) — that one is also silent, so of course it “matches”). Defensible: the `bus_pci` write `fatal()` is itself an emulator-ism, unlatched, guest-drivable. Do not add a second one. **Do** stop saying the refusal matches the empty-slot contract *wholesale*; it matches the read half only.

**(c) Yes, disclose.** FAULT is not available on Alpha (`memory_rw` bus-error delivery is MIPS/M88K). HRM §6.2.18 is not “return all-ones”. It is arbitrary data + instruction exception + internal interrupt + STAT0 CODE=1. All-ones is `bus_pci`'s empty-slot convention, already used by the type-0 path this machine actually boots through. Shipping the refuse arm on that convention is right; calling it the hardware contract is not. One CHANGELOG/header sentence.

Member 7 for the old `else { fatal; exit(1); }` is correct: no decode, no value being refused. Member 4 does not apply. UniNorth/SH4 `PCIPAR` forward type-1 including bus 0 into the same lookup — that is the emulator's logical PCI model, and it is exactly the misrouting this comment is preventing. Do not copy them.
