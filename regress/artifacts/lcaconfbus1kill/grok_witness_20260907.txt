### 2. `LCA_PCI_CONF+0` is a clean offset. It does **not** have HAE’s property.

HAE is `case LCA_IOC_BASE:` in **`lca_ioc`**: an exact-address `break` with no store and no kill. `lca_pci_conf` has no per-offset special case. Offset 0 is `relative_addr==0` → `tag==0`, `reg==0`.

On the **armed** session that never matters: `bus==1` exits before `tag`/`dev` are used, so every offset in the `0x20000000` window is equivalent.

On the **surviving control** (`ioc_conf==0`): tag 0 matches no IDSEL bit, the `dev>=21` body is already the commented-out kill with `dev=0;`, then `bus_pci_setaddr(..., bus=0, dev=0, func=0, reg=0)` and `bus_pci_data_access` of an empty slot. A **read** of `cur_reg==0` with no device sets `*data = (uint64_t)-1` and returns; it does not `exit`. That is a live PCI ID probe of a missing function, not a silent `break`.

Offset 0 is also 8-byte aligned, so `ldq` does not take the unaligned `LS_GENERIC_N` path for alignment reasons (it still goes there because I/O pages have `host_load==NULL`, which is what you want).

`0x18` is the NetBSD encoding (`| 0x3 << 3`) and yields the same `tag`/`reg` (`24>>5==0`). Same PCI transaction. No reason to move.

Do **not** pick `relative_addr = 0x800000` unless you intend to talk to the registered `i82378zb` at device 7. Offset 0 is the quieter control.

### 3. The matched surviving control is sufficient to attribute the kill to the value.

S1’s write arm (`lca_ioc`, `case LCA_IOC_CONF`) does one thing on `0x1`: `d->ioc_conf = idata;` then `idata & ~1` is 0, so no `fatal`/`exit`. An 8-byte store at `+0x020` does not overlap `STAT0` at `+0x040`. Tree-wide, `ioc_conf` is written only there and read only there (readback) and at `lca_pci_conf`’s `bus = d->ioc_conf & 1`. Nothing else can be armed by S1.

So the two sessions differ by one field, and only one later arm consumes that field as a kill.

What the pair rules out:

| Alternative | Why it dies |
|---|---|
| Address / width / “touched the window” | Same `ldq`, same address, same width on the control |
| Unmapped / missed the device | Unmapped Alpha read is zero-fill and survive (`memory_rw.c`); it cannot print `TODO. Non-zero bus.` |
| Unconditional kill in `lca_pci_conf` or `bus_pci_*` | Control would die too. Empty-slot **read** does not exit. `bus_pci_setaddr` exits only on NULL `cpu`/`pci_data`, which `DEVINIT` does not leave NULL |
| `lca_interrupt_assert` / `_deassert` | Different `fatal` text; also `cpu_dyntrans.c` skips interrupt delivery while `single_step` |

`fatal()` itself does not terminate (`debugmsg.c`: `va_debug` only). The `exit(1)` does. The literal is unique in `src/` (one site, `dev_lca.c`). That is a real device signature. RAM and unmapped cannot emit it.

Residual, not a hole: separate `session()` processes could in principle differ by something that ran before the debugger prompt. `-V` sets `single_step` from startup, and `DEVINIT` `memset`s `ioc_conf` to 0. A tighter variant is one process: control `ldq` (survive), then S1, then armed `ldq` (die) — only `ioc_conf` changes between the two loads. Separate sessions are still adequate.

**Liveness is mislabeled.** `ioc rt` proves the **writer** (`lca_ioc` CONF) round-trips `0x1`. It does not prove S2’s window. PCI_CONF liveness is the armed session’s unique message (handler ran) plus the control surviving (same access is not an unconditional kill). If you want a positive signature on the control, the empty-slot read returns `0xffffffffffffffff` via `memory_writemax64`; unmapped returns 0. Not required for attribution.

### 4. A read is the right S2. The write path reaches the same line.

The only `writeflag` use before `bus =` is filling `idata`. A store also reaches the kill.

Use a read anyway:

- Empty-slot **write** in `bus_pci_data_access` prints `[ bus_pci_data_access(): write to non-existant device ... ]` and still does **not** `exit`. The control would survive but stderr would carry a second `fatal()`.
- Empty-slot **read** of reg 0 is the architectural ID probe and is silent.
- A write that accidentally selected device 7 would enter `i82378zb` config-write, which is a worse control.

Guest `ldq` is required (the file’s trap 2): `dump` uses `NO_EXCEPTIONS` against `DM_DEFAULT`, skips the handler, and returns the `#95` pre-zero. That would make both sessions look like unmapped.
