**Q1.** Write **`0x0a` to PIC1’s command port, `0x20`**, then byte-load that same port. The model implements these specific OCW3 values. Its write handler tests `if (idata == 0x0a)` and assigns `d->current_command = 0x0a;`. Readback dispatch is literally:

```c
case 0x0a:
	odata = d->irr;
	break;
case 0x0b:
	odata = d->isr;
	break;
```

Thus IRR readback is **unmasked**: there is no `& ~d->ier` in that read arm. Selecting IRR and reading it neither acknowledges an interrupt nor clears pending bits. [dev_8259.c](/C:/DocumentNoSnc/CC/GXEMUL/GXEMUL-SEC/src/devices/dev_8259.c:96)

With `current_command == 0x0c`, or its reset/default value, command-port reads instead return zero when nothing is pending, otherwise `0x80 | i` for the lowest pending bit. The source calls this “Buffered mode,” but the returned value is poll-style. **Both `irr == 0x02` and `irr == 0x12` therefore return `0x81`** through that path: omitting the selector would destroy this row’s discrimination.

Outside initialization, reading `0x21` returns `d->ier`, the **IMR**, initially zero. That exposes masks, not the pending set.
