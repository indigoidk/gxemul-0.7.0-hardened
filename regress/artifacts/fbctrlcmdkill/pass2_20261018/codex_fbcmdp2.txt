1. **Premise audit.**

   For `sb`, `sh`, `sw`, and `sd`, the producer widths are respectively 1, 2, 4, and 8 bytes. The unsigned accumulator starts at zero; both byte-order branches preserve those complete scalar values. At each width, the accepted values are exactly `{0,1,2}`.

   However, ordinary `testppc` installs this same device, and its implemented `stvx`/`stvxl` path supplies 16 bytes. DATA offset `0x10` plus 16 bytes exactly fits the device’s `0x20` extent, so the dispatcher does not shorten the transfer. See [testppc setup](/C:/DocumentNoSnc/cc/GXEMUL/GXEMUL-SEC/src/machines/machine_test.c:440) and [device-length handling](/C:/DocumentNoSnc/cc/GXEMUL/GXEMUL-SEC/src/cpus/memory_rw.c:495).

   Enumerating representative actual vector payloads through the decoder:

   | Upper 64 bits | Lower 64 bits | `idata` | Result |
   |---:|---:|---:|---|
   | 1 | 0 | 0 | Executes NOP |
   | 1 | 1 | 1 | Executes SET |
   | 1 | 2 | 2 | Executes GET |
   | 1 | 3 | 3 | Refuses |

   Thus `0x10000000000000002` executes GET despite being unsupported as a complete transfer. Handle oversized COMMAND writes before conversion and add a vector-store regression. This is a source-derived counterexample, not a new emulator measurement.

   The other three premises hold. COMMAND starts at zero; the guarded dynamic store is its only subsequent writer; GET writes X1/Y1. Even the vector counterexample stores only 0–2, so the command-default exit remains unreachable. Reads and refused-write preservation are unchanged. See [the frozen device](/C:/DocumentNoSnc/cc/GXEMUL/GXEMUL-SEC/regress/artifacts/fbctrlcmdkill/pass2_20261018/frozen/dev_fbctrl.c.txt:113).
