1. **Choose member 3.** Preserve a bounded diagnostic without allowing unsupported commands to terminate the emulator. One message, such as “unsupported command 0x…; ignored; COMMAND unchanged (once),” truthfully covers both unimplemented named commands and unknown values. One per-device `warned_cmd` suffices; separate messages and latches are unnecessary. Keep it independent of `warned_port`.

   The omitted member is **6 BACKED ACCEPT**, explicitly defined at [tools/CLAUDE.md:2042](C:/DocumentNoSnc/cc/GXEMUL/GXEMUL-SEC/tools/CLAUDE.md:2042). There is no warrant here to invent command semantics or additional storage. FAULT is mechanically possible, but no identified controller specification requires unsupported command values to cause a bus error.

2. **Validate full `uint64_t idata` before assigning COMMAND.** Accept exactly 0, 1 and 2; decline everything else. Currently, narrowing happens at [src/devices/dev_fbctrl.c:150](C:/DocumentNoSnc/cc/GXEMUL/GXEMUL-SEC/src/devices/dev_fbctrl.c:150), before dispatch.

   On refusal, preserve the previous COMMAND, selector, argument/color cells and framebuffer; only the announcement latch changes. Selecting port 0 and reading **DATA** therefore returns the previous accepted command, initially 0. Reading **PORT** returns the selector. This preservation policy is a new explicit contract, not something already specified by the header.

   Place the refusal before the COMMAND store, preserve ordinary non-COMMAND DATA handling, and retain the common tail and handled return value of 1.
