## 2. Architectural requirement

Read directly from the manuals:

- A Thumb exception preserves the old T bit in the SPSR and, for classic ARM, switches to ARM state before starting the handler ([ddi0100i.txt:20337-20343](C:/DocumentNoSnc/CC/GXEMUL/_scratchpad/ddi0100i.txt:20337)).
- From Thumb, Prefetch Abort sets `LR_abt` to aborted-fetch address +4; Data Abort uses faulting-instruction address +8 ([ddi0100i.txt:20347-20353](C:/DocumentNoSnc/CC/GXEMUL/_scratchpad/ddi0100i.txt:20347)).
- Prefetch Abort enters ABT mode, saves CPSR, clears T, and loads 0x0c/high-vector equivalent ([ddi0100i.txt:2194-2218](C:/DocumentNoSnc/CC/GXEMUL/_scratchpad/ddi0100i.txt:2194)). After fixing the fault, `SUBS PC,R14,#4` restores CPSR and retries ([2223-2228](C:/DocumentNoSnc/CC/GXEMUL/_scratchpad/ddi0100i.txt:2223)).
- Data Abort does the equivalent with vector 0x10 and `LR_abt = instruction + 8` ([ddi0100i.txt:2230-2258](C:/DocumentNoSnc/CC/GXEMUL/_scratchpad/ddi0100i.txt:2230)); the handler can retry or skip using the documented returns at lines 2260-2269.
- DDI0406 states the decisive final entry step: after loading the exception vector, execution continues from the PC ([ddi0406.txt:56489-56501](C:/DocumentNoSnc/CC/GXEMUL/_scratchpad/ddi0406.txt:56489)).

Therefore the architecture requires execution of the guest handler. It does not permit the emulator to stop after completing exception entry.

ARMv7 qualification: handler state is controlled by `SCTLR.TE`; TE=0 selects ARM and TE=1 Thumb ([ddi0406.txt:57197-57219](C:/DocumentNoSnc/CC/GXEMUL/_scratchpad/ddi0406.txt:57197)). Unconditional T clearing is correct for the classic machines here and ARMv7 TE=0, but is not a universal ARMv7 rule.

## 4. Smallest practical witness

This is source-derived and not executed.

`-E cats` is cheaper than constructing a testarm page table. CATS starts MMU-on with TTB `0x006f8000` ([machine_cats.c:131](C:/DocumentNoSnc/CC/GXEMUL/GXEMUL-SEC/src/machines/machine_cats.c:131)); setup initially fills all 4096 section descriptors ([cpu_arm.c:231-255](C:/DocumentNoSnc/CC/GXEMUL/GXEMUL-SEC/src/cpus/cpu_arm.c:231)). The table is nevertheless writable guest RAM.

For hole VA `0x00100000`, its L1 descriptor is `0x006f8000 + 4 = 0x006f8004`. Preload registers and plant an ARM abort handler at vector 0x10, then execute:

```asm
str r0,[r2]                ; r0=0, r2=0x006f8004: clear section-1 descriptor
mcr p15,0,r0,c8,c7,0      ; 0xee080f17: invalidate translation caches
bx  r6                     ; r6 = thumb_code | 1
.thumb
ldr r0,[r1,#0]             ; 0x6808, r1=0x00100000
```

The last instruction reaches site 1600. `memory_arm.c:131-159` reloads the descriptor and type zero selects a section translation fault; `memory_arm.c:257-276` sets FAR/FSR and delivers DATA_ABT. The CP15 c8 path invalidates caches at [cpu_arm_coproc.c:230-243](C:/DocumentNoSnc/CC/GXEMUL/GXEMUL-SEC/src/cpus/cpu_arm_coproc.c:230).

On HEAD, exception entry selects PC=0x10 and clears T, then site 1600 clears `running`; the handler marker remains unchanged. With only the halt deleted, the next dispatch executes the ARM handler and changes the marker.

Necessary controls:

- MRC CP15 c1 and publish a result requiring M=1.
- Confirm descriptor `0x006f8004` is zero, while the handler/code/marker remain in mapped section 0.
- In a fresh process, run the same Thumb `0x6808` against mapped data and require the correct loaded value.
- Require the exact planted halfword/disassembly and the exact line-1599 diagnostic once.
- In a fresh process, execute an ARM `LDR` against the same hole and require the handler marker; this proves the MMU fault and vector independently of Thumb.
- Have the handler publish a unique marker, ABT32/T=0, FAR=`0x00100000`, and section-translation FSR=`0x05`. Survival alone is not an oracle.
- Plant everything before clearing the descriptor; use fresh processes for aborting cases.

Closest existing coverage is composite:

- [arm_flags_probe.py:948](C:/DocumentNoSnc/CC/GXEMUL/GXEMUL-SEC/regress/arm_flags_probe.py:948) has the handler-marker pattern and lines 1245-1265 the ARM-to-Thumb BX pattern.
- [arm_bdt_probe.py:615](C:/DocumentNoSnc/CC/GXEMUL/GXEMUL-SEC/regress/arm_bdt_probe.py:615) is the closest existing Thumb-memory executor.
- [footbridge_sites_probe.py:13](C:/DocumentNoSnc/CC/GXEMUL/GXEMUL-SEC/regress/footbridge_sites_probe.py:13) is closest overall: cold CATS, MMU-on controls, CP15 encodings, planting, and stepping.
- [gate_arm.sh:1052](C:/DocumentNoSnc/CC/GXEMUL/GXEMUL-SEC/regress/gate_arm.sh:1052) gates the CATS real-memory path; its MMU-on assertions are at lines 1137-1140. `arm_bdt` is wired at lines 665-700 and `arm_flags` at lines 84-97.

No existing probe combines those pieces into an `armthumbabortkill` witness.
