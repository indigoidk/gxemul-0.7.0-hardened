2. Architecture and device documentation

I enumerated all 428 root-level `_scratchpad/*.txt` files. Only `vmesbcp2.txt` covers PCCchip2/C040; `mc88100.txt` supplies the instruction semantics.

Read from the MC88100 manual:

- `C:\DocumentNoSnc\cc\GXEMUL\_scratchpad\mc88100.txt:5887-5893,5913-5917,5927-5933`: `st.b` stores the specified register’s low byte to the base-plus-index address.

Read from the MVME187 manual:

- `vmesbcp2.txt:4653-4657`: PCCchip2 CSRs begin at `$FFF42000`; byte access is supported.
- `:4857-4864`: GENCTL is the 8-bit register at `$FFF42002`.
- `:4866-4872`: C040 is explicitly R/W; bits 6–3 are read-only.
- `:4895-4906`: MIEN gates both EIPL and INT outputs.
- `:4908-4915`: C040 should be set for an M68000-family MPU and clear for an MC88100; setting it changes EIPL pins to outputs.
- `:4544-4556`: with C040 set, PCCchip2 drives its highest internal request level on EIPL.
- `:4558-4581`: with C040 clear, levels are combined, compared with MASK, and delivered through INT.
- `:6441-6447`: C040 changes pin routing, not whether the internal IPL is calculated.

Inference: writing C040 on an MVME187 is a legal but inappropriate configuration. Hardware changes interrupt routing; it does not terminate the host or fault the write. The evidence supports HEAD’s conservative approximation: retain/read back C040, continue calculating IPL/vector state, announce the missing EIPL implementation once, and suppress delivery to the modeled MC88100 INT pin. Fully modeling EIPL would be more faithful but is a larger feature.

Thus the evidence supports the committed hybrid: accept/back C040, recalculate state, then decline only the unavailable output with a per-instance latched announcement (`HEAD:src/devices/dev_pcc2.c:301-397`). MIEN’s existing output-gating pattern at `:359-361` is the closest structural precedent.

- Verbatim acceptance is contradicted by `vmesbcp2.txt:4866-4872`.
- Declining or faulting the whole byte is also wrong because bits `0x87`—DR0, C040, MIEN and FAST—are writable.
- The supported option is to preserve old bits `0x78` and update only writable bits `0x87`. Same-tree precedents are VECBASE masking/announcement at `dev_pcc2.c:523-527` and explicit “read-only bits come from old register” RMW logic at `HEAD:src/devices/dev_sii.c:343-347,380-384`.
