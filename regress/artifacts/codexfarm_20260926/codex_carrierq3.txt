2. **Conflicts with the surrounding clauses**

- **The 2026-09-09 label clause:** Its existing fallback says a label that “touches nothing the body reads is clause (e).” The new suppression case deliberately qualifies without that selector-to-body connection. Appending it leaves two applicable sentences pointing in opposite directions. Make suppression an explicit third alternative; the exclusion applies when none of the alternatives qualifies.

- **The body-tested-partition bound:** The existing rule enumerates cells “EXACTLY WHEN THE GUARDED BODY’S OWN CODE DISTINGUISHES THEM,” using partitions induced by its tests. The suppression amendment deliberately obtains the missing label axis from the skipped dispatch. That exception is authorized, but its extent should be explicit: it changes the source of the **label axis**, without importing every predicate, value or state encountered inside skipped arms. Otherwise “guard’s own partition” leaves the old bound’s application uncertain. [Partition rule](C:/DocumentNoSnc/CC/GXEMUL/CLAUDE.md:1397)

- **The pass-11 floor:** The floor includes the guard’s dominating predicates and device-state lvalues “the fix’s own repair path reads” that are “JOINTLY REACHABLE.” Calling the whole decline empty conflicts with that definition; limiting its partition to the guard expression can under-enumerate it. Conversely, crossing labels with arbitrary skipped-body state would over-enumerate it. The source confirms that the repair path tests the latch at line 314 and sets it at 315, before the jump at 319. [Pass-11 definition](C:/DocumentNoSnc/CC/GXEMUL/CLAUDE.md:1450), [repair path](C:/DocumentNoSnc/CC/GXEMUL/GXEMUL-SEC/src/devices/dev_sgi_ip32.c:314)

3. **Reuse on another device**

Not fully without guessing. The label source, observability filter and measurement requirement transfer reasonably clearly. The state factor does not.

The one unresolved question is: **On another device, which predicates and device-state partitions constitute the “guard’s own partition” that must be crossed with the skipped labels?**

“Check it on first reuse” acknowledges uncertainty but does not answer that question. The replacement should connect the new label axis explicitly to the existing partition and pass-11 definitions.
