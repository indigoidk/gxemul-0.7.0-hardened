The MIPS documentation establishes only access and exception mechanics:

- KSEG1 is uncached and accesses physical memory or MMIO directly: [`mips_r4000.txt:685`](C:/DocumentNoSnc/cc/GXEMUL/_scratchpad/mips_r4000.txt:685).
- DBE is the data load/store bus-error exception: [`mips_r4000.txt:1009`](C:/DocumentNoSnc/cc/GXEMUL/_scratchpad/mips_r4000.txt:1009).
- Board circuitry may raise it for invalid physical addresses or access types: [`mips_r4000.txt:1132`](C:/DocumentNoSnc/cc/GXEMUL/_scratchpad/mips_r4000.txt:1132).
- The relationship between load/store instructions and external bus errors is implementation-dependent: [`mips-iv.txt:86`](C:/DocumentNoSnc/cc/GXEMUL/_scratchpad/mips-iv.txt:86).

The closest device description is the committed NetBSD-derived O2 CRM register header. It names:

- TLB A/B/C, TEX, LIN_A/B, and CLIP selectors;
- depth 8, 16, and 32;
- STIPPLE;
- COPY, explicitly “1-copy, 0-clear dst”;
- the BYTEMASK register.

See [`crmfbreg.h:239–273`](C:/DocumentNoSnc/cc/GXEMUL/GXEMUL-SEC/src/include/thirdparty/crmfbreg.h:239).

Therefore:

- The named fields are evidence that these are real command encodings, not grounds for terminating the emulator.
- No supplied document defines stipple layout, partial-byte lane semantics, or all valid source/destination combinations well enough to implement them faithfully.
- MIPS permits a modeled DBE, but nothing says these mapped, named MTE commands should fault. A command-level decline is better supported until an actual CRM specification is obtained.

Per site:

- **STIPPLE:** implement with a hardware contract; otherwise latched whole-command decline. Clearing STIPPLE would execute an unstippled transfer.
- **Source selector:** split the predicate. A fill must ignore source bits because source is consumed only under COPY ([`dev_sgi_re.c:1564–1568`](C:/DocumentNoSnc/cc/GXEMUL/GXEMUL-SEC/src/devices/dev_sgi_re.c:1564)). Unsupported copy sources should decline the entire command before any destination PUT.
- **LINEAR COPY:** implement true copy or decline. Deleting/clearing COPY converts a copy into a background fill.
- **LINEAR depth:** implement documented 16/32-bit behavior; decline until then. Forcing depth 8 changes byte counts and values. Field value 3 produces 64 internally but is not named by the header.
- **BYTEMASK:** implement selective lanes when semantics are known; otherwise decline. Setting it to all ones writes bytes the guest disabled.
- **Dead width arm:** remove or document only as dead-code cleanup under `sgimtewidth`; never reorder it into a live exit. The real width fix should explicitly accept supported sizes and gracefully decline others.

Any latched implementation needs distinct bits per message site. The shared-struct collision rule and next free bit `1 << 13` are at [`dev_sgi_re.c:58–66,157–169`](C:/DocumentNoSnc/cc/GXEMUL/GXEMUL-SEC/src/devices/dev_sgi_re.c:58).
