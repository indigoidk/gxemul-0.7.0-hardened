2. **What it reads, compares, and reports**

Use existing ledger fields as follows:

| Fields | Purpose |
|---|---|
| `rows[].id`, entry index, `phase`, `seat`, `date` | Identify every affected credit; date alone is not a unique key. |
| `entries[].ev` | Locate the claimed answer artifact. |
| `entries[].note`, through `stage_tokens` | Distinguish an answer from an annotation, hold, or `[NOT A SEAT ANSWER]` record. |
| `grade`, `outcome`, `grader`, `d`, `b` | Audit what credit/display was awarded; these are not identity evidence. |
| `seats[].id` and declared `model` | Identify the claimed seat, while preserving historical model-version changes. |

**The missing piece is a deterministic entry-to-transcript join.** Current entries have no structured session, agent, or answer-message identifiers. Free-text `ev`, timestamps, and descriptions can support reconstruction, but cannot reliably establish that join.

Preserve the relevant transcript evidence durably. These are proposed fields, not fields I found.

4. **Negative controls**

The suite should include both cases that must be rejected and cases that must retain credit:

- **Historical clean models:** uninterrupted `claude-fable-5`, Fable 5.1, Opus 5, and Opus 5.5 invocations. I inspected clean August Fable-5 transcripts and the `n6` Fable transcript with 12/12 Fable-5.1 assistant records. Comparing all history against today’s fixed ID would falsely reject them.
- **Operational failure without fallback:** `n6`’s Opus agent has 57 Opus-5 records followed by a synthetic limit error. Report seat failure, not model substitution.
- **Metadata versus prose:** quoted “refusal,” copied identity lines, and `thinking_drop` with `prefix_mismatch` but no assistant-model change must not establish fallback. A refusal followed by a completed same-model response is also distinct from fallback.
- **Answer boundaries:** the rejected and valid `fable5_rulings*.md` pair; an earlier valid answer followed by a later unrelated failure; and a fallback-written file followed only by a clean-model acknowledgment. Only the specifically established answer earns credit.
- **Missing linkage:** absent metadata/transcript, malformed JSONL, wrong agent or message UUID, changed artifact digest, and no discovered transcripts despite claimed Agent credits must produce `UNVERIFIABLE` or a hard failure.
- **Classification and wiring:** an entry-scoped exclusion must not silence sibling entries. Test the actual hook on a clean tree as well as a changed ledger, and require the expected diagnostic and exit status—not merely “some nonzero exit.”

These are recommended controls; I did not create or run a new control suite.

5. **What it cannot see**

This establishes **logged provenance**, not cryptographic proof of the backend model. A substitution that retains the same reported model ID is invisible. With alias-only metadata such as `"model": "opus"`, an initially wrong model within that family also needs independently captured dispatch information to be recognized reliably.

It cannot reconstruct absent transcripts, infer arbitrary shell-file authorship, or authenticate later manual copying without a verifiable artifact link. Those cases must remain unverified.

It cannot establish correctness, independent reasoning, or independent measurement merely because the final verdict came from the requested model. Nor do the transcript fields prove which internal classifier caused a refusal.

Finally, this gate can prevent unsupported **recorded credit**. It cannot prevent the Agent tool itself from switching models.
