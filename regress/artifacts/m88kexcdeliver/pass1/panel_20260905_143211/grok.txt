## 1. Premise audit

**Two switches.** D1 delivers; D2 halts. Re-derived from the inlined function, not from the brief’s conclusion.

- Fallback (`vector < M88K_EXCEPTION_USER_TRAPS_START && !implemented`, `USER_TRAPS_START` = 128): only RESET / INTERRUPT / INSTRUCTION_ACCESS / DATA_ACCESS set `implemented`. The five leave it false, so every guest CPU is stopped and the function **returns before** shadows, PSR, or `pc = VBR + 8*vector`. That matches `probe_head.out`: `unimplemented vector=0x008/0x009/0x004`, `pc=0x00010004`, `emul: All machines stopped.` (`emul.c` prints that line). Graceful stop, not `exit`.
- D1: `implemented = true` passes the fallback, common path runs (SXIP/SNIP/PSR/pc). Then the tail `switch` has only RESET/INTERRUPT/INSTRUCTION_ACCESS/DATA_ACCESS; the five hit `default:` → `"internal error"` + **this** CPU `running = false`. On uniprocessor `testm88k` that is still a halt, with `pc` already at `8*vector`. The retrospective “just set `implemented`” sketch is exactly D2.
- Tail `break` is load-bearing: it falls through to `m88k_pc_to_pointers`. A tail `return` skips that (same shape as the sketch rule’s early-return). That mutant belongs in the table as **M_TAILRETURN**.

**rte resumes at SNIP, for all five. Do not back up.** The `#if 0` doubt is resolved by the manual, not by taste:

- 6.4.3 / `:8983-8985`: rte executes SNIP; hardware does not use SXIP on return.
- 6.8.3 Integer-divide (`:10300-10305`): SXIP = the `div`/`divu`; **destination unchanged**.
- 6.6 Integer overflow (`:9303-9308`, the section the packet left as a question): SXIP = the add/sub; **destination and carry unchanged**.
- 6.5.2–6.5.4: same precise-exception shape for misaligned / unimplemented / privilege.

Common path already does SXIP = `pc | V`, SNIP = `pc+4 | V`. Retry (`SNIP = pc`) would re-execute a faulting `divu` forever. `X(rte)` really does “First try the NIP, if it is Valid”.

**Table 6-1 stagger (extracted text, not the brief’s numbers).** `mc88100.txt:8526-8538` prints Exception Number one row behind the definition (Reset’s `0` sits on the address line). Naive pairing would call misaligned vector 3. The header (`MISALIGNED=4` … `OVERFLOW=9`) and `8*vector` match the **address** column + definitions. The brief’s offsets are right; the extracted number column is not.

**Raise-site census (named constants in `cpu_m88k*.c`).** Counts match: SFU1_PRECISE 58, PRIVILEGE 10, DIVIDE 4, OVERFLOW 3, MISALIGNED 1, UNIMPLEMENTED 1; BOUNDS/ERROR/SFU1_IMPRECISE zero named raises. Two qualifications:

- The **list** of 10 privilege sites is `ldcr` / `fldcr` / `stcr` / `fstcr` / `xcr` / `rte` / `LS_USR` (one template) / `tb0` / `tb1` / `tcnd`. The brief named nine and omitted `fldcr`/`fstcr`.
- Domain is incomplete: supervisor `tb0`/`tb1`/`tcnd` call `m88k_exception(cpu, ic->arg[2], 1)` with a **guest vector**. A supervisor trap with vector 4–9 is another way to reach these numbers (and today it still hits the fallback). User-mode low vectors become PRIVILEGE (`is_trap=0`), correctly.

**SFD1 at reset is clear.** `cr[M88K_CR_PSR] = M88K_PSR_MODE | M88K_PSR_IND` (`0x80000002`). `M88K_PSR_SFD1` is `0x00000008`, not set. `testm88k` does not poke PSR later (`default_test` only). So `divu` by zero is ILLEGAL_INTEGER_DIVIDE, not SFU1. (Witness CPU **name** is 88110; `cpu_m88k.c` says `M88110: Not yet.` — delivery is the 88100 model. luna88k’s default CPU is 88100.)

**`stcr` / `ldcr` (asked).** `case 0x20`:

- `ldcr`: `(iword & 0x001ff81f) == 0x00004000`, `cr6 = (iword>>5)&0x3f`  
  `ldcr r2, cr1` (PSR) = `0x80404020`
- `stcr`: `(iword & 0x03e0f800) == 0x00008000` and `s1==s2`

Simpler user-mode entry: debugger `PSR=0x2`. Init registers every CR by name (`CPU_SETTINGS_ADD_REGISTER32`). That write **does not** go through `m88k_stcr`, so it does not flush translations — and does not need to: `X(ldcr)` reads PSR at execution time.

**Mode vs translation cache.** Caches are **not** mode-tagged. `m88k_stcr` on PSR, if `(old ^ value) & MODE`, calls `invalidate_translation_caches(..., INVALIDATE_ALL)`. Hardware says MODE should only be cleared by rte; the fork warns at `VERBOSITY_WARNING` and continues. Either `PSR=0x2` or a supervisor `stcr` then `ldcr` is a valid privilege row.

`tb1 0,r0,0x10` = `0xf000d810` (`op26=0x3c`, `op10=0x36`). User-mode vector `< 128` raises PRIVILEGE **before** the bit test, so r0=0 is fine. `prom_call` in user mode is `0xf400fc92` (`M88K_PROM_INSTR`).

**Witness.** Rung 3 on committed `testm88k` is real: three HALT, two DONE, `r2` live=6 / attrib=1 / faults still `deadbeef`. The repeated `unimplemented` lines are the fallback calling `m88k_pc_to_pointers` **without moving `pc`**, so the quantum re-executes the same insn until the outer loop sees `running=false`. ## 3. Option set

**D1 is the right member.** D2 is the (d) mutant. D3 (decline / latched announce) does **not** apply: these are architected CPU exceptions with guest handlers; suppressing them lies to the guest.

Unnamed member worth rejecting in the record: **retry** (SNIP = pc), which is the `#if 0` author’s question. Manual says skip, not retry.

**House idiom — deliver, do not stop.**

- SH: `#217` reserved insn, `#315` slot variants, `#457` TLB multi-hit — recognized classes that used to `exit(1)` now take the general vector.
- MIPS: `mips_cpu_exception` **always** delivers (RI included, WARNING not halt).
- ARM: UND/SWI/aborts deliver; only RESET stops.
- PPC: `ppc_exception` always vectors.

That decides Q-D1b/c:

- **Q-D1a INFO:** yes, match the four implemented classes. No hygiene row owed. Disclose M_LEVEL.
- **Q-D1b BOUNDS:** leave unimplemented. `tbnd` is disassembler-only. Delivering a class with no raise site is an untestable claim (addition licence). When `tbnd` is implemented, that round delivers vector 7.
- **Q-D1c ERROR:** **file**, not this round. The re-route already exists for the four implemented classes (DATA_ACCESS with SFRZ set rewrites the vector to ERROR, then the **tail** default stops with `"internal error"` — it never hits the unimplemented fallback). D1 makes that nested path reachable from the five as well. Different contract (shadows frozen). OpenBSD’s error handler panics; still the guest’s panic, not ours — but it needs its own witness.
- **Q-D1d MISALIGNED / DMT:** DMT zeroed is correct (precise, before data-unit dispatch, `:9236-9237`). Scoreboard is unmodelled (`SSBR = 0` on every exception). File. MXM is a separate halt (`stcr: TODO: MXM support`).
- **Q-D1e fcr2/fcr4/fcr5:** file with `m88kexcsfu1`. Not on disk; do not guess OpenBSD’s SIGFPE path.

**Delay-slot row:** not floor (the diff does not edit that arm). One `br.n` + faulting delay insn would pin the “perhaps” SNIP/SFIP split. Disclose if skipped.
