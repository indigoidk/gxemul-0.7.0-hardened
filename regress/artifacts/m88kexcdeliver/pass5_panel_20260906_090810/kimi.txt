## Build commands

Produces `./gxemul` — a dynamically-linked **Linux x86-64 ELF** (run it inside

> **Parallel builds:** a stock `make -j` used to fail *intermittently* while
> generating `src/devices/autodev.c` — the recursive-make chain
> (`all`→`objs`→`autodev.o`) could run the non-atomic generator concurrently,
> corrupting a random `device_register`/`pci_register` line (`expected ';' before
> ')'` at a moving line number). Correction #61 makes `makeautodev.sh` write a
> PID-unique temp file and atomically `mv` it into place, so `-j` is now reliable.

## The one required fix: `-fgnu89-inline`
A stock `./configure && make` compiles all 265 objects but **fails at link** with:
```
multiple definition of `__cmsg_nxthdr' / `recv' / `recvfrom' / `inet_ntop' / `inet_pton'
```
Root cause: this is 2021 code written for the GNU89 `extern inline` semantics.
Modern glibc + GCC 10+ (and Gentoo enabling `_FORTIFY_SOURCE` by default) turn
glibc's `extern __inline` socket wrappers into an external definition in *every*
translation unit that includes `<sys/socket.h>`/`<arpa/inet.h>` (pulled in widely
via the common headers), so the linker sees dozens of duplicate definitions.

`-fgnu89-inline` restores the original inline semantics (an `extern inline`
function emits no external symbol), eliminating all the duplicates. It is the
standard, low-risk fix for this exact symbol set and changes no behavior.
Key facts: the build toolchain is WSL Gentoo (`wsl -d Gentoo`), gcc 15.2.1. The build/ tree is a full source copy + Makefile with a built `gxemul` Linux ELF. Builds run under WSL.
