**1. The delay-slot else-arm is one pipeline stage early; the diff makes it reachable, certifies it, and the `dslot` row pins it (L4 in-round + FILE `m88kdslotshadow`).**
- Manual, pointer definitions `mc88100.txt:2097-2104`: "For sequential execution ... (FIP = NIP+4). ... Unconditional branch addresses are computed from the XIP plus the signed 26-bit word displacement (FIP = XIP + d26). Conditional branch addresses for the branch taken case are calculated as FIP=XIP+d16." Same from the instruction side, `:4207-4208` (bsr): "Operation: FIP <- XIP+D26x2; r1 <- NIP (+4 if .n option)". So while the branch is in XIP: NIP = branch+4 (the slot), FIP = target. One stage later, while the SLOT executes: NIP = target, FIP = target+4. A precise fault in the slot therefore leaves SXIP = slot, **SNIP = target|V, SFIP = target+4|V**.
- Corroboration: `:8940-8947` lists the only three reasons SNIP.V is clear — the branch-related one is "the instruction pointed to by the SNIP followed a branch ... invalid if the .n option was not specified and the branch is taken" (NIP = branch+4 while XIP = branch); nothing annuls the instruction two after a taken `.n` branch, which the fork's model would require. `:8898-8902`: SFIP is "the instruction following the next instruction OR the target of a jump or branch" — the latter is the state while the BRANCH is in XIP (what an interrupt after a branch sees), not while the slot is. rte flow `:9023-9033`, `:9040-9050`: NIP <- SNIP, FIP <- SFIP; the SNIP instruction executes, then the SFIP one.
