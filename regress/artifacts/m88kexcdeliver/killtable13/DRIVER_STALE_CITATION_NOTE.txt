APPARATUS DEFECT IN THIS TABLE'S DRIVER -- found immediately after the run, recorded because the numbers it
PRINTED were real numbers of the WRONG ARTIFACT, which is the hardest kind of wrong number to notice.

WHAT HAPPENED.  The driver was derived from table 12's by substitution.  Its closing section WRITES the HEAD and
final runs to probe_v16_head.out / probe_v16_fix_final.out -- and then GREPS probe_v11_head.out /
probe_v11_fix_final.out, filenames the substitution did not reach.  Those two files exist, from table 11 at
12:32 today, so the grep succeeded and printed:

    M88KEXC_RESULT=7/46      <- probe_v11_head.out, mtime 12:32:02
    M88KEXC_RESULT=46/46     <- probe_v11_fix_final.out, mtime 12:32:49

The runs the driver had just made say something different, and they are the ones that count:

    M88KEXC_RESULT=7/54      probe_v16_head.out       HEAD 83df95c with the 54-row instrument
    M88KEXC_RESULT=54/54     probe_v16_fix_final.out  the rebuilt build/ with the same instrument

HOW IT WAS CAUGHT, and it was not by a check: the DENOMINATOR was wrong.  The probe is v16 with 54 rows and the
driver log said 46, which is arithmetically impossible for a run of that file.  A reader comparing only the
NUMERATORS -- 7 both times -- would have seen agreement and moved on.

WHY IT MATTERS MORE THAN A COSMETIC SLIP.  This is the citation-decay class the project already records: a record
that names a log is only as good as the log still being the one the run produced.  Here the two numbers would have
gone into the round block as the v16 HEAD narration and the v16 final score, both wrong, both citing files that
really do contain them.  Nothing downstream would have contradicted it.

THE GENERAL SHAPE, worth more than this instance: A DRIVER DERIVED BY SUBSTITUTION FROM ANOTHER DRIVER CAN END UP
WRITING ONE FILE AND READING ANOTHER, and the read will SUCCEED whenever the previous round's artifact is still on
disk -- which it always is, because this project preserves them on purpose.  The two safe forms are to write the
output path into a variable used by both the redirect and the grep, or to have the driver name the file it is about
to read and fail if the path it reads differs from the path it wrote.

NOT FIXED IN THIS DRIVER: it has already run and its frozen copy is the record of what ran.  The correction belongs
to the next table's driver, and the numbers above are the ones any record must cite.
