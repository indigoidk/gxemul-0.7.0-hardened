IS ONE SHARED HELPER THE MINIMAL FIX?
-------------------------------------
  For the LIVE member, no: gate 3's minimal fix is its own two-line guard (fix/selftest_mutation.diff), and it
  needs no new file.  For the CLASS, yes -- with a condition.  19 of the 20 are one-off drivers, each written
  from scratch per round, and the class recurred after it was filed: 08-27 (nine), 08-29, 08-30 (five, the
  same day killswap.sh was fixed), 09-03, 10-09, 10-16.  Patching frozen records fixes nothing that will run
  again; a shared ks_score stops the NEXT driver -- but only if something makes the next driver use it.  That
  is this project's structure-first rule: a helper nobody is pointed at is prose with a file extension.
  The trigger is an OWNER decision, not made here: a BRIEF_TEMPLATE / PRETABLE line ("the driver scores through
  regress/killscore.sh, or runs under mutmeasure.py"), or a precommit check that a new killtable dir's
  driver calls ks_score or prints NOLOG.  mutmeasure.py already implements the same rule for whole tables
  (controls/mm_parse_control.out), so the helper is for ad-hoc shell drivers only.
