The real time-register RAM path is intentional in this model, but its semantics need precise qualification. [The updater](C:/DocumentNoSnc/CC/GXEMUL/GXEMUL-SEC/src/devices/dev_mk48txx.c:58) writes only `ISEC..IYEAR`; its only callers in the tree are initialization and the [control case](C:/DocumentNoSnc/CC/GXEMUL/GXEMUL-SEC/src/devices/dev_mk48txx.c:98).

| Event | Current behavior, preserved by the correction |
|---|---|
| Initialization | Populate all seven time bytes from host UTC. |
| Guest time-register write | Store the byte immediately, without consulting `CSR_WRITE`. |
| Subsequent time-register read | Return that stored byte; no refresh occurs. |
| READ bit `0 → 1` | Overwrite all seven time bytes from host UTC, then store control. |
| READ bit `1 → 1` | No refresh. |
| READ bit `1 → 0` | Store control; no refresh. |

Thus clock writes are **honored, readable, and subsequently overwritten on the next qualifying edge**. They are not silently discarded or persistently applied to an emulated clock.

The seven time slots are shared storage for guest writes and host snapshots. The eight newly admitted NVRAM slots are separate array elements: the updater neither reads nor writes them. Accepting those eight writes therefore does not contaminate a later clock value.

There are separate fidelity gaps: unlatched reads do not advance with time, and the WRITE-bit commit protocol is absent. Actual hardware resumes register updates after READ clears and transfers staged time into its counters when WRITE clears. [ST datasheet, page 14](https://www.st.com/resource/en/datasheet/m48t08.pdf) Those gaps do not require moving the seven time bytes into this switch to correct the NVRAM boundary.

The built-in [MVME PROM emulation](C:/DocumentNoSnc/CC/GXEMUL/GXEMUL-SEC/src/promemul/mvmeprom.c:99) handles console output, exit, and board identification; it contains no clock/NVRAM access. The [MVME documentation](C:/DocumentNoSnc/CC/GXEMUL/GXEMUL-SEC/doc/machine_mvme88k.html:62) directs users to download OpenBSD externally and includes an old boot transcript identifying MK48T08. That is not proof about every external guest or opaque PROM image, nor a current compatibility test. Existing accepted accesses retain their behavior under this edit.

For the detector, there is an unavoidable qualification: **this smallest edit removes no kill statement**. It makes the existing default unreachable. A verbatim “reinstatement” of that same default, with the corrected boundary retained, is either no change or unreachable code. No behavioral channel can distinguish it. Consequently, the stated floor cannot be satisfied literally for that mutant. Restoring the **old dispatch and fatal behavior** is distinguishable and should be named separately.

The proposed behavioral rows should use byte accesses, independent initial state, and controlled, distinct host-time samples for clock assertions. These are design expectations, not measured results.
