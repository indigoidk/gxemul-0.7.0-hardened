### 1. The fix is right

`MK48T08_CLKOFF + MK48TXX_ICSR` is the correct lower bound.

After the edit the accept predicate is

```text
relative_addr < 0x1ff8  ||  relative_addr >= 0x1ff9
```

so the switch is reached only at `0x1ff8`. That is exactly `case MK48T08_CLKOFF + MK48TXX_ICSR`. The comparison is strict `<`, so it does **not** swallow the implemented case. For integer offsets in the 8192-byte window this is the same set as `relative_addr != CLKOFF+ICSR`; the two-sided form is the better one to keep, because it still names a window a later case could occupy.

The T08 hardware map matches the header: clock lives in the last sixteen bytes of 8K, and the first eight of those (`0x1ff0..0x1ff7`) are the T59 alarm/watchdog bank, documented as *"available only on more recent MK48Txx models"*. This file says it implements the MK48T08 only. `machine_mvme88k.c` attaches it as `"MK48T08 clock/nvram"` at `0xfffc0000` in the MVME187 arm only — one attach site in the tree. Storage already exists (`reg[MK48TXX_LEN]`). Accepting those eight as RAM is a boundary correction, not new policy.

The `default: exit(1)` arm is now unreachable. Leaving it is a tripwire if a later edit widens the window without adding a case. Do not delete it in this round.

### 2. The upper bound is still right

Leaving `>= MK48T08_CLKOFF + MK48TXX_ISEC` is correct for **this model**, not a second defect.

`0x1ff9..0x1fff` are the time-of-day SRAM cells. `mk48txx_update_regs()` writes them; the access path only has to read and write the same array. That is pre-fix behaviour. The comment’s warrant (*“because update_regs writes into this array”*) is circular as a reason, but the conclusion holds: moving the upper bound is a different change.

- Move it to `CLKOFF+ICSR` → tautology, CSR never reached. Table 1 measured this (`M_ICSR` 47/47, then 47/48). `csr rise` pins it.
- Move it **up** (`ISEC+1` or `+16`) → TOD offsets fall into `default:` and die. `ok rd/wr 1ff9` pin that.

CSR_WRITE / `SEC_STOP` side effects on TOD writes are pre-existing model gaps, not this bound.

### 7. `M_NULL` as run is not the nulled repair the table claims
