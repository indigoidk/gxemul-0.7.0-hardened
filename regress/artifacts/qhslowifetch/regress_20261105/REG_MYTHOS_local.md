P2 (disclosed arms). CHECKED-IN-TREE and REASONED. memory_rw.c has exactly four failure returns reachable from a PowerPC instruction read: a translation failure inside memory_rw (:216, :268, after the exception is delivered), a device that clears running during the access (:591-592), a device returning 0 or less (:595-643, which for PowerPC delivers no exception and just returns 0), and the -T halt past physical_max (:695-698). The second producer reaches arm (c) with running 0, not (d). The third is arm (d)'s only producer. The only in-tree device that declines reads by design is dev_unreadable (dev_unreadable.c:43 returns 0), registered only on mvme88k and sgi, so no in-tree PowerPC machine registers a declining device; whether some PowerPC device returns 0 on a specific offset of a fetchable window on bebox, prep, macppc or mvmeppc is not measured and I did not sweep it. window_sweep.out:19 records WINDOW_SWEEP_ARM_D=NOT_REACHED on pmppc at every offset of every window, and :25 is the one ARM_A=YES cell (cpc700_pci, word 0x23120e00).
