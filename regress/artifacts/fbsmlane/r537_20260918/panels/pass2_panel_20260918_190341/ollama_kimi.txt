## Q1 — premise audit

**(P1) — TRUE (REASONED), but the brief's stated mechanism skips a step that happens not to matter.**
gcc's quoted-include search order is: directory of the current file, then the `-I` list in order. The compile runs in `<mirror>/regress` with the harness named as (effectively) `diff_fbpending_bound.c`, so the *first* probe is `<mirror>/regress/dev_footbridge.c` — which does not exist (the helper mirrors `regress/`'s own contents; `dev_footbridge.c` lives in `src/devices/`). Only then does the `-I` list govern: the helper's three (`../src`, `../src/include`, `../src/include/thirdparty`) hold no `dev_footbridge.c` (READ, the premise itself), so the first hit is EXTRA's `../src/devices` → `<mirror>/src/devices` → the mutated copy. Conclusion holds.
The symlink question is a red herring **in both directions** (REASONED): whether gcc uses the literal path (`<mirror>/regress`) or realpath's it (`GXEMUL-SEC/regress`) for the current-file directory, *neither* directory contains `dev_footbridge.c`, so the `-I` resolution is identical either way. One downstream consistency point: once `../src/devices/dev_footbridge.c` is opened, its own quoted includes resolve from the mirror's `src/devices/` first, so the mutated tree is used coherently (and the 221 linked `build/` objects are deliberately pristine, with `dev_footbridge.o` and `main.o` excluded so no duplicate symbols). P1 stands.

**(P2) — TRUE, internally corroborated.** READ: arm D0 measured 28 rows *with* the depth argument, 27 without, IDENTITY green and `FBBOUND_PASS` in both — so with no args R2 is skipped and the identity row self-adjusts to the shallow count; the pre-fix token string appears 0 times post-fix. **(P3) — TRUE (REASONED) with one honest caveat.** Last `-std` wins, so effective standard is `gnu99` in both builds; `-ffunction-sections -fdata-sections -Wl,--gc-sections` is dead-section GC, no semantic change to linked code; `-D_POSIX_C_SOURCE=200809L -D_DEFAULT_SOURCE` only gates prototype visibility (and `_DEFAULT_SOURCE` roughly restores defaults). Caveat: if the harness or `dev_footbridge.c` selects behavior on `#ifdef __STRICT_ANSI__` / `_POSIX_C_SOURCE`, the measured behavior *can* differ. Not settled by the packet — one grep for those macro names in the two files settles it.

**(P4) — I find the asymmetry WRONG as shipped (REASONED).** Distinguish two SETUPs. SETUP-from-misconfiguration (absolute `-I`, byte-identical binaries, present on every host) *should* red — deterministic defect, host-independent. SETUP-from-absent-`build/` is an *environment* state: `find` returns empty (its stderr is even dev-nulled), both arms fail to link identically, pristine arm never passes → gate reds — so #537 flips gate 2 from green-with-NOTE to red on exactly the hosts the main #442 lane already anticipates skipping. A red on a machine without `build/` is noise against a missing optional artifact, and it trains operators to expect red. The vacuity fear is misplaced here: a NOTE-skip does not "read as a pass" because the NOTE is a distinct printed line, and an attacker cannot exploit it without deleting `build/` — which simultaneously degrades the *main* lane to its own NOTE, a visible double-absence. Recommended shape: test the object list for emptiness up front → empty ⇒ NOTE-skip mirroring the main lane; non-empty but link/pristine fails ⇒ red. That keeps "reds rather than lies" for real defects without charging bare-clone hosts for geography. (If the owner instead rules that gate 2 hosts always have `build/`, then the main lane's NOTE path is the inconsistent half, and the premise to fix is that one.)

**(P5) — Population is right (REASONED from the inlined code); one justification is the wrong reason; one sub-claim is not checkable.**
The derivation filters `EXEMPT` to `MANIFEST[..][0] == CLASS_DETECTOR` with `DATE_RE`-well-formed dates, then takes the earliest. That is exactly the right population **if** expiry is only evaluated for DETECTOR entries — and the derivation aligns with it by construction. Against `d < today` semantics (READ): M5a at earliest−1 expires nothing (green expected, correct); M5b at earliest+1 expires the earliest-dated entries (red expected, correct). But: "the selftest refuses unless every MANIFEST file is on disk, **so** the earliest-dated detector is always present in its copy" — the causal chain is garbled: the derivation reads the static `EXEMPT` dict, not the disk; disk presence governs nothing in the population. The conclusion is true anyway, for a different reason. Two things not checkable from the packet: (i) that the witness branch never reads an `EXEMPT` date — settling fact: the checker's expiry loop body (one look); note the §3 transcript (READ) `--today 2026-09-26` PASS / `--today 2026-09-28` FAIL naming exactly the eleven is consistent with the claim but does *not* prove it (a witness exemption dated ≥ 2026-09-28, or none existing, reconciles identically); (ii) the "refuses to start" selftest preamble itself — settling fact: its SETUP exit path.

- **(d) R4 condition `failures <= 1`:** gate 2 **passes, no line reds.** Pristine has 0 failures (R4 green, verdict PASS); the mutant produces ≥2 (READ: 7 reported) so R4 still reds, pinned row still names it, `SELFMUTANT_OK` still prints.
