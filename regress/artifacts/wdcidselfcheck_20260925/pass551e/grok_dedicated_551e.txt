## 2. The pin that survives one inlining and the conditional reset

Yes. A witness the reset does not write, read in two places, so one inlining leaves the other.

```c
static int cmp_latch;   /* incremented beside cmp_fails++ in BOTH comparators, inline */

static void pin_count(void) {
	if (cmp_latch)
		printf("\n1 failures\n");
}

static void wdc_emit(void) {
	if (cmp_latch && failures == 0)
		failures = 1;
	if (cmp_fails > failures)
		failures = cmp_fails;
	if (!sc_g && failures == 0)
		failures = 1;
	printf("\n%d rows, %d failures\n", rows, failures);
	if (failures == 0 && cmp_fails == 0 && sc_g && cmp_latch == 0)
		printf("WDC_IDENTIFY_PASS\n");
	else
		printf("WDC_IDENTIFY_FAIL\n");
}
```

`selfcheck` saves `cmp_latch` with the other counters and restores it after the probes, so the probe mismatches do not stick. `main` registers `atexit(pin_count)` and then `atexit(wdc_emit)` before any row, and the in-main summary and token printfs come out. Handlers run in reverse order of registration.

`if (failures == cmp_fails) failures = cmp_fails = 0;` does not store to `cmp_latch`.

Inlining one handler away:

- Replace `wdc_emit` with a body that prints `0 failures` and `WDC_IDENTIFY_PASS`. `pin_count` still runs and, when `cmp_latch` is set, prints `1 failures`. The failure grep becomes two numbers. `check()` wants the string `0`. Red. The geometry arm never sets `cmp_latch` (`failures == 1`, `cmp_fails == 0`), so the reset does not fire there, `wdc_emit`'s honest twin is the one that was replaced, and `pin_count` stays silent. The mutant still prints `WDC_IDENTIFY_FAIL` from the remaining honest path only if that path is `wdc_emit`. If `wdc_emit` was the one replaced, the weak body must still print `FAIL` when `cmp_latch` is clear and `failures != cmp_fails`, or the lane goes red and the attack does not keep gate 2 green. A weak body that prints `PASS` whenever the counters are equal, and `FAIL` otherwise, still loses: after the reset the covered run is `(0, 0)` with `cmp_latch` set, and `pin_count` contributes `1 failures`.
- Replace `pin_count` with an empty function. `wdc_emit` still sees `cmp_latch` and will not print `PASS`. Red.

A probed `verdict(failures, cmp_fails, sc_g)` with one call site does not survive. Inlining that call to `failures - cmp_fails == 0 && sc_g` is the whole defeat; the reset is optional. A check of only those two integers, inline or not, dies to the reset placed immediately above it. A latch set inside a one-call `note_fail()` dies if that call is the one that gets inlined. The duplication has to be textual, in both failure arms, and the two readers have to be two registrations.

The same pair of handlers also catches the edit in finding 1. The deferred `chk()` calls are the last `atexit` registration, so they run before either handler and set `cmp_latch`. The score is then printed with the latch already set.
