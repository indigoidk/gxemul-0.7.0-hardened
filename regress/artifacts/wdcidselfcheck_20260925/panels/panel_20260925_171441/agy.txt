#### 3. Disclosing the Both-Tally Reset
**Finding: Disclosing the two-statement reset is correct and sound.**

1. *Infeasibility of cheap closure:* Any additional file-scope tally (e.g. `static int cmp_fails_2;`) merely increases the adversary's statement count from `failures = cmp_fails = 0;` to `failures = cmp_fails = cmp_fails_2 = 0;`.
2. *Scope boundary:* Truly closing tamper resistance against malicious in-file modifications requires refactoring row functions to return error values through the call stack rather than updating global counters. This refactoring is the explicit subject of the pending ticket `wdcidcomparators` (ruled by the project owner: *"24/128 now, file the rest; the rest is `wdcidcomparators'"*).
3. *Adjudication compliance:* Disclosing that a reset of both tallies bypasses the check directly executes Fable 5.1 Ruling 6 ([`fable5_f2b_550_551.md:20`](file:///C:/DocumentNoSnc/cc/GXEMUL/GXEMUL-SEC/regress/artifacts/wdcidselfcheck_20260925/fable_f2b/fable5_f2b_550_551.md#L20)).
