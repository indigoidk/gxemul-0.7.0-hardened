### Question 3: The smallest edit to the F1+F2+F4 design that keeps gate 2 green while a covered row can no longer fail?
**Answer:** There are two distinct minimal edits:

1. **The 1-character conjunction edit in [`row()`](file:///C:/DocumentNoSnc/cc/GXEMUL/GXEMUL-SEC/regress/diff_wdc_identify.c#L514): replace `||` with `&&` (`|` -> `&`):**
   ```c
   - if (got57 != want || got60 != want) {
   + if (got57 != want && got60 != want) {
   ```
   - **Sentinel behaviour:** In the probe `row("@@SELFCHECK@@/row", 1, 2)`, both words are built as 1 (`got57 = 1, got60 = 1`). Since `1 != 2 && 1 != 2` is `TRUE && TRUE`, `row()` fails as expected. The sentinel registers failure, restores counters, and prints the success G text.
   - **Real rows:** In pristine code, `want == sectors`, so `FALSE && FALSE` passes all 8 rows.
   - **The escape:** Word 57 and word 60 are now decoupled. If a defect in `dev_wdc.c` corrupts only word 60 (or only word 57), `got57 != want` is FALSE while `got60 != want` is TRUE. `FALSE && TRUE` evaluates to FALSE! The corruption is completely silenced and the row passes. Gate 2 remains 100% green because Gate 2 has no self-mutant targeting `row()` capacity words.

2. **The 1-token decoupler in [`row()`](file:///C:/DocumentNoSnc/cc/GXEMUL/GXEMUL-SEC/regress/diff_wdc_identify.c#L514): check `sectors != want` instead of inspecting `got`:**
   ```c
   - if (got57 != want || got60 != want) {
   + if (sectors != want) {
   ```
   - **Sentinel behaviour:** Probe passes `sectors = 1, want = 2`. `1 != 2` is TRUE; sentinel observes failure, passes, and prints the G text.
   - **Real rows:** All 8 rows pass `sectors == want`. `sectors != want` is always FALSE.
   - **The escape:** `row()` never inspects the emulated device buffer at all. All 8 covered rows become completely inert against any device bug, while Gate 2 remains 100% green.

## SOMETHING ELSE FOUND (REQUIRED CHANGES TO F4)

1. **First-Run G-Text Emission Leak in F4:**
   - F4 specifies running the sentinel FIRST (before any row) and LAST (after all rows), with each success arm printing the G text via raw `printf`.
   - **The defect:** If the sentinel runs first and succeeds, it prints `ok SELFCHECK the comparator can still fail` into `$LOGDIR/diff_wdc_identify.log`. If a stateful bug or late corruption causes the LAST sentinel run to FAIL, Gate 2's G check ([regress/gate_offline.sh#L2338](file:///C:/DocumentNoSnc/cc/GXEMUL/GXEMUL-SEC/regress/gate_offline.sh#L2338)) uses a bare `grep -q`. It matches the line printed during the *first* run and passes! Gate 2's G check is completely blind to a failure of the last sentinel.
   - **Required Fix:** The G text must be emitted **ONLY** upon completion of the **LAST** sentinel run, conditioned on both runs having succeeded (e.g. `if (sc_first_ok && sc_last_ok)`).
2. **Unidirectional Sentinel Probe in `row()`:**
   - F4 specifies probing `chk()` narrow (1 vs 2) and wide (0x100000000 vs 0), but probes `row()` only narrow in one direction: `row("@@SELFCHECK@@/row", 1, 2)` (`got < want`).
   - An asymmetric comparator such as `if (got57 < want)` or `if (got60 < want)` will satisfy the sentinel, yet be completely blind to high-byte/wrap defects (`got > want`, the exact #405 defect class).
   - **Required Fix:** Probe `row()` bidirectionally: `row("@@SELFCHECK@@/row_lo", 1, 2)` and `row("@@SELFCHECK@@/row_hi", 2, 1)`.
