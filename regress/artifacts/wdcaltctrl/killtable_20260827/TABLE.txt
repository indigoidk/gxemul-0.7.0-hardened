base.out -- the same detector, the fix applied: 94 rows 0 failures.  Same scripts,
opposite colour.

ONE ROW WAS RE-PINNED BEFORE THE CODE CHANGED, which is the whole of the oracle-correction
rule.  It read `cur_command != COMMAND_RESET` -- "a routine 0x08 must not leave the device
in the reset state".  A seat MEASURED that going RED on CORRECT code the moment a power-on
signature is modelled, because then the device legitimately IS in the reset state before
any command runs.  The old oracle conflated "this write did not latch" with "the device is
not latched".  The delta form asks whether the write CHANGED cur_command, which is robust
to that, and its diagnostic states the harm rather than an internal state.

  *** AND THE HARM IS SHARPER THAN THE ROUND'S OWN BRIEF CLAIMED. ***  The brief called
  the wrong bit "a wrongly-timed SIGNATURE rather than a wrongly-performed reset".
  Measured: `0xec -> 0x100` -- a routine Device Control write DESTROYS THE RECORD OF WHICH
  COMMAND IS EXECUTING.  `cur_command` is also the value assigned into
  `write_in_progress`, and that is harmless today ONLY because `wdc__write()` has exactly
  one caller, immediately after the assignment.  An accident, not an invariant: a second
  call site turns this into a data-path defect.

---- WHAT THE PANEL CHANGED, AND THE FIRST ITEM IS THE ROUND'S OWN WARRANT ----

*** THE SHIPPED COMMENT'S REASON FOR B4 WAS MEASURED FALSE. ***  It said edge and level are
"indistinguishable here", on a byte-identical scenario differential.  The opus seat built the
discriminating case with REGISTER WRITES ONLY:

    assert 0x0e -> 8 guest stores to DATA -> rewrite 0x0e -> release
      LEVEL (shipped):  occ 0, DRQ 0     the ring is purged
      EDGE:             occ 8, DRQ 1     the bytes survive the entire reset,
                                          and the status byte still advertises DRQ
    LIVENESS: the same traffic with no reset leaves occ 8, so the 0 is the reset working
    SINGLE ASSERT: occ 8 BOTH  <- WHY THE ROUND SAW NO DELTA

**The round's differential only ever asserted SRST ONCE.**  The forms differ exactly when a
driver HOLDS it across two control writes with something accruing between them.

THE DECISION STANDS AND ITS WARRANT IS NOW STRONGER: the measurable difference FAVOURS
level, rather than there being none.  Two supporting claims also failed:

  * "the abort is idempotent" is true of the helper and does NOT licence the inference.
    Idempotence means REPEATING is harmless; it says nothing about SKIPPING the repeat,
    which is what an edge does, and state accrues between the writes.
  * "no protocol-following driver issues commands while holding SRST" -- the scenario
    ISSUES NO COMMAND.  Plain data-register stores suffice, and a hardening fork does not
    get to assume a protocol-following guest.

And the option set was incomplete: `Mo_edgefree` is an edge form with NO NEW FIELD
(`if (d->cur_command != COMMAND_RESET) ...`) which escapes all 94 rows and reproduces the
same defect.  The prev_ctl/m7 argument never reached it.
