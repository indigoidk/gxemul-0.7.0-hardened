Guest corruption:

* **T2 holds, for `stdu`.** Opcodes `0x3a` and `0x3e` are one primary opcode each (`opcodes_ppc.h:230`, `:238`). The decoder takes `imm = (int16_t)iword` (`cpu_ppc_instr.c:4295`) and treats both as plain `ld`/`std` of 8 bytes (`:4307`, `:4320`) with update never set. DS-form XO lives in the low two bits, so `stdu` stores 8 bytes at EA+1 and does not update RA. The unaligned store is performed (`cpu_ppc_instr_loadstore.c:163-174`); this tree has no PowerPC alignment exception. `ldu` and `lwa` are wrong results of the same decode (`lwa` is also the wrong width). PPC970 is the testppc/bareppc default (`machine_test.c:450`, `:456`; `cpu_ppc.h:87` says 64-bit). Real-mode code reaches this. A PPC970 guest that turns translation on does not: it dies first in the hole below.
* **T4 is latent, not a live image corruption.** Word 49 is stored as 0 (`dev_wdc.c:374-377`), and `wdccylwrap`'s own note already says that means CHS is the only advertised capacity. The LBA formula is inside `#if 0` (`:470-476`, `:562-568`), so `d->lba` is never read for an address. The bit-5 decode (`:2015`) does nothing until that formula is turned on. Filing the row is right. Calling it present-tense guest corruption, and ranking it with the host kills, is not. It is not `wdccylwrap` and not `arcpartlba`.
* **T9 must not be filed again.** `b120` is already "an unknown command is reported to the guest as success", held. WRITE AND VERIFY has no `case` and falls into that same default arm (`diskimage_scsicmd.c:1380-1384`), which sets no status. `dev_asc.c:1284-1287` then pushes `0x00`. The lost write is that held row applied to a data command, not a second defect. On other controllers the same missing status stops the CPU, so one GUEST-CORRUPTION label does not cover every controller.

`crandc` is NAND (`cpu_ppc_instr.c:2722`) and `crorc` is NOR (`:2749`), identical to `crnor` (`:2758`). `ppccrlogicshift` is only the signed `1 << (31-bt)` in those handlers. T18 really is unfiled.

**Found while checking T6, and absent from the 154.** `memory_ppc.c:280-288`: if `bits != 32`, translated access prints `TODO: ppc 64-bit translation` and `exit(1)`. The BAT scan above it runs only for 32-bit. PPC970 is 64-bit, so the first access with MSR IR or DR set kills the host. No `OUTSTANDING_BUGS.md` or ledger row contains that message. Two neighbours in the same function are also unfiled: `TODO: 601` (`:263-265` in the older brief's numbering; the exit is still in this function) and `TODO: BAT exception` when a matching BAT returns 0 for PP=none or a write to a read-only BAT (`memory_ppc.c:69-73` returns 0; the caller exits). The BAT one is a 32-bit guest protection failure that never raises DSI. File all three. Do not treat T6's "return into the ISI" as the fix for any of them.

## Q2 — the batch

T36 before any 88K fault round: yes. `memory_rw.c:614-622` raises the data-access exception and does not write PFSR or PFAR. The translation path does write them (`memory_m88k.c:382-405`), which is why the register is live, and why a bus error still leaves the handler with PFSR 0. The LUNA probe at `dev_luna88k.c:624-627` writes PFSR=`BERROR` and neither PFAR nor an exception. A round that replaces `exit(1)` with `return 0` delivers that empty fault. T1 does not do that. T7's bounds check does not. T7's exit removal does, if the removal is an exception.

Proposed ten, in order:

1. **T1** — user-mode null call. One generator change. Drop ajfa's `xmem` exemption; that exemption is the crash.
2. **T3** — filed user-mode `exit(1)`. The rc-bit cases are illegal forms; the round is the disposition, not a port.
3. **T6** — 32-bit only, reach U. Returning lets the ISI that `memory_ppc.c` already raised proceed. Say in the row that PPC970 does not get here.
4. **T2** — `stdu` corruption. Mask the DS-form XO and decode it. Nothing safe exists to copy.
5. **T36** — bus-error PFSR/PFAR, before any later 88K exception round. Upstream r6542/r6547 is the shape. Do not take the plain-RAM CMMU windows.
6. **T18** — `crandc`/`crorc`, one line each, user mode, a real port.
7. **T120** — primary opcodes with no case hit `cpu_mips_instr.c:5708` `goto bad` and stop the CPU on every MIPS machine, including pmax and arc. JALX and the COP2/COP3 load/store opcodes have no case. Wider than T11, and the `#236`/`#309` exception idiom is already the house style.
8. **T5** — the one zwrite `exit(1)` upstream already replaced. Leave the other three PVR exits in their own rows.
9. **T7 bound only** — stop the off-struct read. Leave the two `exit(1)`s until the disposition is chosen, and if that disposition is an exception, T36 is already in.
10. **T11** — confirmed hpcmips host exit, no port exists, so the round owes the design.

Drop **T4** out of this ten. Queue the row. Do not implement it until word 49 is an explicit decision, and do not key the formula on `d->lba` as this tree defines it. Drop **T10** until a single site is named and the 2^24-byte MEMORY MOVE is excluded. **T8** can follow T7 once its exit disposition is the same choice. **T9** stays out, and stays `b120`.

The new PPC970 translation exit is a host kill on the default CPU, and it is a large design (a page-table walker), not a tenth small round. File it. Do not pretend it is T6.

## Q4 — do not port
