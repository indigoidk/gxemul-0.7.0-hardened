------------------------------------------------------------------------------------------
WHY THIS IS THE DEVICE AND NOT RAM  (device-signature control)
------------------------------------------------------------------------------------------
  s0/s1 read the SAME address twice and returned 0x5a then 0xa5.
  A memory cell returns the last value written (0xa5) BOTH times; only a FIFO
  returns them in push order.  This is the wdc inbuf, not a memory word.
  Status reads returned 0x59/0x51 from +7.  DRDY|DSC|ERR = 0x51 is computed
  by status_byte() (dev_wdc.c:462-478) out of diskimage_exist() and the
  power-on d->error (dev_wdc.c:1655).  The guest never wrote any of it, and RAM
  at 0x180001f7 would answer 0x00.

  RAM liveness (t8=0x55) proves the sb/lbu shapes themselves work, so a
  device row reading 0x00 could not have been blamed on a bad encoding.
