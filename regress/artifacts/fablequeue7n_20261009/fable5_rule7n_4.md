### 3.3 Population 3 -- outside the ruling; "serve the containing word" is refuted; FILE it

**Not reached:** the ruling's contract is "an access the emulator cannot service." A byte at 0x51 is an access the emulator can service -- the datum is in `d->reg[0x14]` -- and merely does not DECODE. That is the `#337`/`#497`/`#529`/`pcc2widthkills` class (an omitted WIDTH of a present register), which this project has disposed four times and never once by FAULT.

**"Serve the containing word" (the queue's "obvious alternative") is a SKETCH that fails the enclosing function, by reading** (`dev_vme.c:85-97`, `memory.c:55-78, :89-109`):
1. a byte/halfword WRITE rounded down to a storing case executes `d->reg[w] = idata` -- the composed 1- or 2-byte value overwrites the WHOLE 32-bit word; three (or two) lanes are clobbered with zeros and the written lane lands in the LOW end, which on this big-endian bus is the highest-address lane (`memory_readmax64` composes `x = x<<8 | buf[i]`);
2. a byte READ at +1/+2/+3 returns `memory_writemax64(len=1, odata)`, i.e. the LEAST significant byte of the word = lane +3, whatever lane was asked for;
3. a byte read at 0x55-0x57 fires T1COUNT's `+= 100` read side effect (`:95`) once per lane read.
The seat's body already said it (`codex_faultreopen:63`): *"Simply rounding the switch address down would be insufficient: current storing cases assign whole words, and T1COUNT has a read side effect."* The queue read the verdict line ("handle register byte lanes separately") and supplied a fix the body refutes -- the carrier's verdict-line hazard, in the queue file.

**"Arguably a worse wrong answer than the host kill it replaces" is rejected.** A localised, survivable guest bus error is not worse than ending the emulator for every guest and every row; the sentence compares a host consequence with a guest one. What IS true: whether a sub-word LCSR access is legal on the real VMEchip2 is NOT ESTABLISHED and cannot be established from disk (ELSE #2) -- the PCCchip2 "can be accessed as bytes (8 bits), two-bytes (16 bits), or four-bytes" sentence at `vmesbcp2.txt:4655-4656` is PCCchip2's, not VMEchip2's, and must not be transferred.

**Disposition:** population 3 is its OWN ROW (name is the main loop's; the shape is `crimectllane`/`pcc2widecompose`). The reopening rule forbids folding it into the FAULT round: different semantic class (width vs. unimplemented register) and a DIFFERENT ORACLE (no exception + unchanged store + one announce, versus an exception). The FAULT round therefore:
* DISCLOSES in its contract that sub-word accesses inside cased words reach the fault, as an emulator limitation, not a hardware claim;
* carries ONE row that pins that interim behaviour and is NAMED as a channel the width row will red and re-derive (exactly how `#529`'s `sw08/sh08` rows are recorded in `crimectllane`);
* records the warrant for deferring rather than repairing: the in-tree guest makes NO sub-word VME2 access (every `vme2reg` field is `u_long`; no `vme2_` reference exists outside `dev/vme.[ch]` -- grep), so FAULT there breaks no in-tree guest path, which population 2 cannot say.
The width row's own default, when it runs, is the house idiom -- width declined BEFORE the switch with a latched announce (`#529`), reads lane-extracted from `d->reg[]` where that is `ACCEPT`-shaped (member 4), COMPOSE for writes filed as the faithful upgrade -- but that is that row's panel to settle, after the VMEchip2 chapter is on disk.

### 3.4 The rule minted, and its bound

> **A disposition ruling binds the population it was argued on.** When an arm is later shown to mix populations, each population not presented is tested against the ruling's STATED WARRANTS, never against its conclusion: a population the warrants reach is covered without re-ruling; a population a warrant CONTRADICTS goes back to the owner with the contradicting evidence inlined; a population the warrants do not touch gets its own row. The partition is read off the code -- the header, the switch, the access width -- so it is finite, and the obligation is one re-ruling or one row PER POPULATION, never per offset.

Warrant in the carrier's own text: the premise-audit rule (*"a stated premise is load-bearing for every seat, and agreement with it is not evidence"* -- here the premise was "probing"); the option-set rule's two greps (the fork's idiom, the SIBLING HANDLERS' disposition -- both run above); the provisional-adjudication companion (grep the round's findings against each warrant element); and the late-dissent discriminator (*can it state a measurable consequence?* -- `vme.c:452`, yes). Bound against `#392`: three populations, one re-ruling, two filed rows, zero rows added to the FAULT round beyond the single channel row an existing precedent already prescribes; population 1 and the FAULT mechanism are not reopened.
