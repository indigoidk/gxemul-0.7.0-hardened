**The source path confirms the finding.**

1. **Guest instruction bytes and register operands enter the implementation.** Instruction decoding reads bytes from a cached host page, or calls `cpu->memory_rw(..., MEM_READ, CACHE_INSTRUCTION)`, then performs `iword = BE32_TO_HOST(iword);` and `main_opcode = iword >> 26;`. (`src/cpus/cpu_ppc_instr.c:4092–4139`.)

   The `PPC_31_MTSPR` decoder selects the source GPR and destination SPR from that word:

   > `rs = (iword >> 21) & 31;`  
   > `spr = ((iword >> 6) & 0x3e0) + ((iword >> 16) & 31);`

   It supplies pointers to `gpr[rs]` and `spr[spr]`; BAT registers take `default:ic->f = instr(mtspr);`. The operative handler is:

   > `/*  TODO: Check permission  */`  
   > `reg(ic->arg[1]) = reg(ic->arg[0]);`

   Thus guest register contents become the BAT words subsequently read by translation. (`src/cpus/cpu_ppc_instr.c:4672–4689`, `2807–2809`; BAT SPR definitions: `src/include/thirdparty/ppc_spr.h:119–134`, `146–183`.)

2. **Guest MSR writes supply relocation and privilege state.** The `MTMSR`/`MTMSRD` decoder selects a source GPR; a set `l_bit` goes to `bad`, while the other branch selects `instr(mtmsr)`. The handler reads that GPR, contains `/* TODO: check permission! */`, and calls `reg_access_msr(cpu, &x, 1, 1);`. The register accessor assigns `cpu->cd.ppc.msr = *valuep;`. (`src/cpus/cpu_ppc_instr.c:4704–4717`, `2888–2905`; `src/cpus/cpu_ppc.c:275–276`.)

   This does not mean every MSR write proceeds to another access: setting `MSR.IP` takes the separate CPU-stop branch, and enabled pending interrupts can invoke an exception. (`src/cpus/cpu_ppc.c:288–310`.)

3. **The access must reach translation.** Ordinary load/store decoding supplies register operands and displacement; the generic handler computes the effective address from the base and index/displacement, synchronizes the faulting PC, then calls `memory_rw` with `MEM_READ` or `MEM_WRITE`. (`src/cpus/cpu_ppc_instr.c:4293–4296`, `4338–4351`; `src/cpus/cpu_ppc_instr_loadstore.c:49–61`, `88–94`, `174–184`.)

   The memory wrapper bypasses translation under:

   > `if (misc_flags & PHYSICAL || cpu->translate_v2p == NULL)`

   Otherwise it calls the translator with the write, exception-suppression, and instruction-access flags. (`src/cpus/memory_rw.c:241–252`.)

   Cached accesses are a qualification: load/store fast paths can use `host_load`/`host_store` directly; the generic path is selected for an unaligned nonbyte access or a missing cached page. Instruction-pointer translation likewise calls the translator after its cache lookup fails. This dossier establishes the translator path, not that every access re-enters it. (`src/cpus/cpu_ppc_instr_loadstore.c:217–240`; `src/cpus/cpu_dyntrans.c:656–680`.)

4. **The translator applies relocation and model gates.** It reads MSR, derives `user` from `PPC_MSR_PR`, and truncates the address for a 32-bit model. This condition bypasses BATs and returns success:

   > `if ((instr && !(msr & PPC_MSR_IR)) || (!instr && !(msr & PPC_MSR_DR)))`

   With the relevant relocation enabled, PPC601 exits earlier. For another 32-bit model, it calls `ppc_bat(...)`. (`src/cpus/memory_ppc.c:248–270`.)

5. **A BAT must participate and match.** Instruction accesses scan `i = 0, 1, 2, 3`; data accesses scan `i = 4, 5, 6, 7`. The register selection is `regnr = base_spr + i * 2`. The resulting pairs are enumerated here rather than inferred from a range:

   | Scan | Upper/lower SPR pairs |
   |---|---|
   | Base instruction | `0x210/0x211`, `0x212/0x213`, `0x214/0x215`, `0x216/0x217` |
   | Base data | `0x218/0x219`, `0x21a/0x21b`, `0x21c/0x21d`, `0x21e/0x21f` |
   | Extended instruction | `0x230/0x231`, `0x232/0x233`, `0x234/0x235`, `0x236/0x237` |
   | Extended data | `0x238/0x239`, `0x23a/0x23b`, `0x23c/0x23d`, `0x23e/0x23f` |

   (`src/cpus/memory_ppc.c:48–53`, `85–90`, `101–117`; `src/include/thirdparty/ppc_spr.h:119–134`, `146–183`.)

   An entry is skipped under each applicable condition:

   > `if (user && !(upper & BAT_Vu))`  
   > `if (!user && !(upper & BAT_Vs))`  
   > `if ((vaddr & ~mask) != (ebs & ~mask))`

   The mask and address calculation are:

   > `uint32_t mask = ((upper & BAT_BL) << 15) | 0x1ffff;`  
   > `*return_paddr = (vaddr & mask) | (phys & ~mask);`

   (`src/cpus/memory_ppc.c:53–65`.)

   A base-BAT result other than `-1` returns immediately. Extended entries are considered only after no base hit, and only when **both** `PPC_HIGH_BAT` and `HID0_HIGH_BAT_EN` are set. (`src/cpus/memory_ppc.c:101–119`.)

**The on-disk manual specifies a storage exception.**

The manual describes a prohibited access after a BAT match as a “block protection violation exception condition (DSI or ISI exception).” (`_scratchpad/ppc_pem32_rev2_2001.txt:13312`.)

Its protection rule says:

> “any access attempted (read or write) when PP = 00 results in a protection violation exception condition.”

It also identifies writes through `PP=x1`—enumerated as `01`, `11`—as violations, while `PP=10` allows accesses. (`_scratchpad/ppc_pem32_rev2_2001.txt:13334`.)

The required classifications are explicit:

> “For data accesses, a DSI exception is generated and bit 4 of DSISR is set.”

> “For instruction accesses, an ISI exception is generated and SRR1 bit 4 is set.”

(`_scratchpad/ppc_pem32_rev2_2001.txt:13335–13336`; Figure 7-9: `13503–13519`.)

Other architectural requirements relevant to the correction are:

- DSI saves the causing instruction’s address in SRR0; DSISR identifies protection and load/store direction; DAR identifies the offending effective address according to the access class. (`_scratchpad/ppc_pem32_rev2_2001.txt:11726,11760–11764`.)
- ISI saves the address of the instruction whose fetch was attempted, including a branch target where applicable, and records the protection cause in SRR1. (`_scratchpad/ppc_pem32_rev2_2001.txt:11792–11801`.)
- The enumerated vector addresses are DSI `0x00000300` or `0xfff00300`, and ISI `0x00000400` or `0xfff00400`, according to IP. (`_scratchpad/ppc_pem32_rev2_2001.txt:11487,11767,11811`.)
- On exception entry, “MSR[IR] and MSR[DR] are cleared for all exception types.” (`_scratchpad/ppc_pem32_rev2_2001.txt:11486`.)
- A BAT invalid for the current privilege level is ignored; it does not itself generate a protection violation. BAT modification is privileged. (`_scratchpad/ppc_pem32_rev2_2001.txt:13107,13170–13171,13494`.)
- `dcbt` and `dcbtst` are exceptions to ordinary faulting accesses: protected translation is aborted and the instruction acts as a no-op. (`_scratchpad/ppc_pem32_rev2_2001.txt:13495,13512–13513`.)

**Disposition 5 fits, but the existing exception machinery is incomplete.**

The nearest precedent is in the same translator: page protection failures already select `DSISR_PROTECT`, populate DAR, add `DSISR_STORE` for a write, and call DSI/ISI rather than ending the process. Its earlier `FLAG_NOEXCEPTIONS` branch returns failure without delivering an exception. (`src/cpus/memory_ppc.c:299–323`.)

The caller precedent is #216: failed `lwarx`/`stwcx.` memory accesses return, with comments explicitly saying to let the DSI proceed “instead of exit()ing the host.” (`src/cpus/cpu_ppc_instr.c:2309–2314,2357–2362`; `CHANGELOG.md:20119`.)

| Member | Assessment for this finding |
|---|---|
| **1 — Delete the terminating call** | Insufficient alone. Falling through would allow page-table processing after a decisive BAT denial. (`src/cpus/memory_ppc.c:273–284`.) |
| **2 — Decline silently** | Appropriate for `FLAG_NOEXCEPTIONS` probes; insufficient for ordinary guest execution. (`src/cpus/memory_ppc.c:299–300`; manual `13335–13336`.) |
| **3 — Decline and announce once** | A latch or `(once)` diagnostic cannot replace the specified architectural exception. Manual `13335–13336` requires fault delivery. |
| **4 — Accept an already-computed value** | Wrong here. The physical-address calculation precedes the separate permission decision; computing it does not authorize access. (`src/cpus/memory_ppc.c:65–75`.) |
| **5 — Architectural fault** | Correct primary disposition: DSI for data, ISI for instruction fetch, with protection state. Manual `13335–13336`. |
| **6 — Invent backing store** | Does not implement the protection rule; the problem is permission, not missing storage. (`src/cpus/memory_ppc.c:65–75`; manual `13334`.) |
| **7 — Implement missing behavior** | Needed to complete the exception delivery supporting member 5, rather than to invent different BAT semantics. (`src/cpus/cpu_ppc.c:318–345`; manual `11486,13336`.) |

The correction must account for these concrete integration issues:

- **Preserve a protection hit as a protection hit.** Do not retry another BAT or the page tables. Do not route it into the PPC603 software-reload branch, which writes `IMISS`/`DMISS`, sets TGPR, and selects exceptions `0x10`, `0x11`, or `0x12`. The BAT result is distinct from the PTE `match` variable, which is assigned later. (`src/cpus/memory_ppc.c:248,270–284,307–323`; manual `13312–13336`.)
- **Supply complete fault state.** `ppc_exception()` saves SRR0 and assigns SRR1 from masked MSR, then clears only `EE | RI | PR`. It neither supplies the ISI protection-cause bit nor clears IR/DR. Setting an ISI cause before that SRR1 assignment would lose it. (`src/cpus/cpu_ppc.c:321–335`; manual `11486,13336`.)
- **Make exception entry survive its callers.** The helper immediately rebuilds execution pointers; the instruction-fetch caller can still exit after a failed read. Generic dyntrans also has a separate exit when exception-handler translation fails. (`src/cpus/cpu_ppc.c:337–344`; `src/cpus/cpu_ppc_instr.c:4115–4119`; `src/cpus/cpu_dyntrans.c:685–732`.) Related recursive-vector debt is already recorded as **`excvecrecurse`**. (`OUTSTANDING_BUGS.md:21950–21951`.)

The option list also omits **stopping only the virtual CPU while preserving the host process**. That mechanism exists in the IP reboot hack, but it is not the specified response to BAT protection denial. (`src/cpus/cpu_ppc.c:288–291`; manual `13335–13336`.)
