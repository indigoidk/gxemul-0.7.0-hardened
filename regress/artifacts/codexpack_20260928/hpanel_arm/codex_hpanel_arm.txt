**H4 — reachable, including from user mode in this implementation.** The decoder selects `mcr_mrc`; its wrapper synchronizes PC and calls `arm_mcr_mrc`. That dispatcher’s gate is only `"if (cpu->cd.arm.coproc[cp_num] != NULL)"`; it contains no privilege check. CP15 is installed unconditionally. The hinge premise—guest instruction dispatch actually reaches this handler—is checked. (`src/cpus/cpu_arm_instr.c:4977`, `src/cpus/cpu_arm_instr.c:948`, `src/cpus/cpu_arm.c:2643`, `src/cpus/cpu_arm.c:2653`, `src/cpus/cpu_arm.c:175`.)

The handler first executes `"cpu->cd.arm.control = cpu->cd.arm.r[rd];"`. It reconstructs the comparison B bit from `cpu->byte_order`, compares that with the newly stored bit, and reaches `"exit(1);"` on disagreement. Thus the comparison is with the configured byte order, not merely the previous stored control bit. (`src/cpus/cpu_arm_coproc.c:135`, `src/cpus/cpu_arm_coproc.c:157`, `src/cpus/cpu_arm_coproc.c:161`, `src/cpus/cpu_arm_coproc.c:177`.)

**H5 — reachable, with a persistently faulting, uncached vector translation.** The hinge premise is that exception delivery resolves the vector synchronously before the failing translation returns. Checked:

1. The generic routine calls `translate_v2p` with `FLAG_INSTR`. (`src/cpus/cpu_dyntrans.c:679`.)
2. ARM translation failure calls `"arm_exception(cpu, ARM_EXCEPTION_PREF_ABT);"`. (`src/cpus/memory_arm.c:268`.)
3. Exception delivery sets the vector PC and immediately calls `"quick_pc_to_pointers(cpu);"`. (`src/cpus/cpu_arm.c:731`, `src/cpus/cpu_arm.c:733`.)
4. Without a cached instruction page, that macro enters pc-to-pointers; without a usable address mapping, the generic routine calls the translator again. (`src/include/quick_pc_to_pointers.h:9`, `src/include/quick_pc_to_pointers.h:16`, `src/cpus/cpu_dyntrans.c:888`, `src/cpus/cpu_dyntrans.c:659`, `src/cpus/cpu_dyntrans.c:679`.)

Enumerated prefetch-abort vector addresses are **V clear → `0x0000000c`; V set → `0xffff000c`**. The exception number is **3**. (`src/include/cpu_arm.h:125`, `src/cpus/cpu_arm.c:731`.)

There is no second-failure guard in that chain. The same-mode warning’s terminating call is literally commented out: `"/*  exit(1);  */"`. The `no_exceptions` bypass exists, but these calls supply `FLAG_INSTR`, not `FLAG_NOEXCEPTIONS`. (`src/cpus/cpu_arm.c:708`, `src/cpus/cpu_arm.c:711`, `src/cpus/memory_arm.c:122`, `src/cpus/memory_arm.c:258`, `src/cpus/cpu_dyntrans.c:680`.)

Consequently, **the fallback exit at `cpu_dyntrans.c:732` is not reached in this persistent recursive-failure case**: the earlier translator call never returns. This does not establish that the fallback is globally unreachable on ARM. Unbounded recursion is established by reading; host stack exhaustion remains a predicted consequence.

The required state is an active MMU translation path whose effective prefetch-abort vector mapping keeps failing, without cache hits bypassing the failure. Merely saying “turn on the MMU” omits those conditions. The handler selects the MMU translator; invalid descriptors enter exception delivery. (`src/cpus/cpu_arm_coproc.c:136`, `src/cpus/cpu_arm_coproc.c:140`, `src/cpus/memory_arm.c:155`.) This ordinarily indicates broken vector/MMU setup, not successful operation of a correctly configured OS. Calling it possible **only** under a faulty OS is too strong, given the ungated guest CP15 access identified under H4.

**H6 — reachable in both USR32 and SYS32.** The hinge premise is that the executable generic path retains `return_flag` for these modes. Checked: the decoder installs `bdt_load`, which calls `arm_pop`; the optimized generator rejects S-bit instructions, and optimized installation requires an exact instruction match. (`src/cpus/cpu_arm_instr.c:4787`, `src/cpus/cpu_arm_instr.c:1957`, `src/cpus/generate_arm_multi.c:86`, `src/cpus/cpu_arm_instr.c:4830`.)

Enumerated outcomes:

- **USR32:** line 1614 clears S inside the already-entered outer block; lines 1616–1618 still set `"return_flag = 1;"`.
- **SYS32:** the user-only test is false; the same PC-list test sets `return_flag`.

The return switch enumerates **FIQ32, ABT32, UND32, IRQ32, SVC32**. Neither **USR32** nor **SYS32** appears, so both reach `"cpu->running = 0;"` and `"cpu->cd.arm.next_ic = &nothing_call;"`. (`src/cpus/cpu_arm_instr.c:1610`, `src/cpus/cpu_arm_instr.c:1784`, `src/cpus/cpu_arm_instr.c:1797`.)

The preceding loads must succeed: a failed memory read returns before this switch. Thus this is an available single-instruction path, not an inevitable outcome for every attempted execution. (`src/cpus/cpu_arm_instr.c:1716`.)

UNPREDICTABLE does not excuse the halt. The manual says `"This instruction is UNPREDICTABLE in User or System mode"` and separately says such instructions `"must not halt or hang the processor, or any parts of the system."` (`_scratchpad/ddi0100i.txt:8168`, `_scratchpad/ddi0100i.txt:45064`.)

The immediate effect is stopping that CPU. Process termination additionally requires all machines to stop and no debugger takeover; those conditions lead out of the run loop to `main()`’s `"return 0;"`. (`src/machines/machine.c:741`, `src/core/emul.c:1052`, `src/core/main.c:821`.)

**Q3. Correction choices and available machinery.**

**H4: member 3 — decline the endian-bit change and announce once per CPU.** Preserve the configured byte order and canonicalize the stored control bit accordingly: **little-endian → B clear; big-endian → B set**. Otherwise readback lies, because the read path directly returns `"cpu->cd.arm.control"`. (`src/cpus/cpu_arm_coproc.c:95`, `src/cpus/cpu_arm_coproc.c:157`.) This is an internally consistent unsupported-feature policy, not an implementation of switching. The current mismatch branch has no once guard; the correction needs one. (`src/cpus/cpu_arm_coproc.c:161`.)

Deleting only the exit is insufficient. Translation-time handler selection and instruction decoding both depend on byte order. (`src/cpus/cpu_arm_instr.c:4822`, `src/cpus/cpu_arm_instr.c:4060`.) Guest privilege validation also needs review; ARM’s Undefined Instruction delivery machinery exists and is already used by `arm_cdp`. (`src/cpus/cpu_arm.c:2677`.)

**H5: member 7 — implement bounded exception/fetch sequencing.** Preserve architectural prefetch-abort state transitions, but defer vector fetching to ordinary bounded dispatch instead of recursively resolving it inside exception entry. Repeated guest aborts must not consume unbounded host stack or trap the scheduler inside one host call. Existing ARM exception-state machinery is available; the present synchronous resolution at `src/cpus/cpu_arm.c:733` is the part requiring redesign. Choosing member 5 alone merely invokes the already-recursive mechanism. (`src/cpus/memory_arm.c:269`.)

**H6: member 5 — deliver Undefined Instruction before loads or writeback.** ARM already has a handler that synchronizes PC and calls `"arm_exception(cpu, ARM_EXCEPTION_UND);"`. (`src/cpus/cpu_arm_instr.c:1020`.) This is my chosen handling of UNPREDICTABLE, not an exception mandated by the LDM description. ARMv7 explicitly permits it: `"An instruction that is UNPREDICTABLE can be implemented as UNDEFINED."` (`_scratchpad/ddi0406.txt:143212`.) The tree lists CORTEX-A5; universal applicability across every older advertised model is **not checked**. (`src/include/arm_cpu_types.h:102`.) H5 must also be corrected so unavailable exception vectors remain contained.

A missing disposition is **controlled suspension of the affected emulation with a host-visible reason**. That can be appropriate for an unsupported configuration, but it is not architectural instruction behavior and is not an acceptable substitute for containing H6 user code. Merely clearing `running` does not ensure the host remains alive under the current run loop. (`src/core/emul.c:1052`.)

**Q4. Ordinary-operation ranking: H4, then H6, then H5.**

This is a qualitative exposure judgment; workload frequencies were **not checked**.

1. **H4:** closest to legitimate feature use—an endian reconfiguration is exactly what the control handler refuses. Same-endian writes do not enter the terminating branch. (`src/cpus/cpu_arm_coproc.c:161`.)
2. **H6:** conforming applications should avoid this UNPREDICTABLE operation, but a functioning OS can encounter faulty application code. (`_scratchpad/ddi0100i.txt:8168`.)
3. **H5:** the failure requires an unusable effective abort-vector translation, indicating broken exception infrastructure under ordinary operation. The fork’s ungated CP15 access weakens any assumption that only kernel bugs can create that state. (`src/cpus/memory_arm.c:269`, `src/cpus/cpu_arm.c:733`, `src/cpus/cpu_arm.c:2653`.)
