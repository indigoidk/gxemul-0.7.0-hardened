Several distinctions matter for these rows:

- **BLX reachability:** immediate decoding produces target low bits `01` for opcode `0xa`, and `11` for opcode `0xb`; neither enters `:451`. Independently, the earlier even-target return prevents `:462` (`src/cpus/cpu_arm_instr.c:4134–4143`, `src/cpus/cpu_arm_instr.c:447–465`). Register branches have low-bit possibilities `00`, `01`, `10`, `11`; only `10` triggers these guards. The manual calls that case **“UNPREDICTABLE”** and lists **“Exceptions … None”**, supporting member 3 rather than claiming a required fault (`_scratchpad/ddi0100i.txt:7135–7153`, `_scratchpad/ddi0100i.txt:7181–7195`). Declining must precede the PC/CPSR/LR changes already present in these handlers (`src/cpus/cpu_arm_instr.c:355–367`, `src/cpus/cpu_arm_instr.c:386–398`, `src/cpus/cpu_arm_instr.c:484–499`).

- **SPSR defaults:** the queue names `` `msr_spsr` / `mrs_spsr` / `bdt_load` `default:` arms `` as `` `running = 0` landmines `` (`OUTSTANDING_BUGS.md:20346–20350`). That records the defaults, but does not explain the directly reachable USR32/SYS32 cases. In `arm_pop`, `"s_bit = 0;"` does not leave the already-entered block; the following PC-bit test still sets `"return_flag = 1;"` (`src/cpus/cpu_arm_instr.c:1610–1618`). User/System SPSR accesses are **“UNPREDICTABLE”** in the manual (`_scratchpad/ddi0100i.txt:1701–1702`).

- **MRS is different:** its handled mode values are `0x10`, `0x11`, `0x12`, `0x13`, `0x17`, `0x1b`, `0x1f`; USR32/SYS32 explicitly return zero (`src/include/cpu_arm.h:108–114`, `src/cpus/cpu_arm_instr.c:926–934`). Checked guest mode-changing routes call `arm_load_register_bank`, whose unsupported-mode arm exits first (`src/cpus/cpu_arm_instr.c:830–847`, `src/cpus/cpu_arm_instr.c:1802–1812`, `src/cpus/cpu_arm_instr_dpi.c:218–232`, `src/cpus/cpu_arm.c:606–608`). Debugger-seeded invalid CPSR state was **not checked**.

- **Reboot:** the intended CATS sentinel is installed by machine setup, but instruction decoding imposes no matching location, machine or privilege restriction (`src/machines/machine_cats.c:89–90`, `src/cpus/cpu_arm_instr.c:4991–5002`). Ordinary SWI handling already delivers `ARM_EXCEPTION_SWI` (`src/cpus/cpu_arm_instr.c:994–999`).

- **Exclusive alignment:** the queue names LDREX/STREX and says **“raising a data abort is a choice under latitude, not a mandated fault”** for the unchecked-alignment configuration (`OUTSTANDING_BUGS.md:4181–4192`). Its older claim that alignment checking is permanently disabled is stale: current initialization sets `ARM_CONTROL_ALIGN` (`src/cpus/cpu_arm.c:128–129`). Preserve the alignment check; merely deleting it exposes the raw unaligned accesses (`OUTSTANDING_BUGS.md:4201–4202`).
