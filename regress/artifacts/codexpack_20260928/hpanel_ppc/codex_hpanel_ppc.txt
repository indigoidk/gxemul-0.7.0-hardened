**H1 — reachable.** The decisive premise is that `ppc_bat()` preserves a denied hit instead of treating it as a miss. Checked: `src/cpus/memory_ppc.c:104-105` says `if (r != -1)` followed by `return r;`. The extended-BAT path also returns the helper’s result directly at `:116-117`.

The producer is `pp = lower & BAT_PP;` (`src/cpus/memory_ppc.c:67`), with mask `0x00000003` and values defined at `src/include/thirdparty/ppc_bat.h:97-101`. For an entry surviving validity and address matching, the complete enumeration is:

| PP | Read/fetch result | Write result |
|---|---:|---:|
| 00 | 0 | 0 |
| 01 | 1 | 0 |
| 10 | 2 | 2 |
| 11 | 1 | 0 |

These are the branches at `src/cpus/memory_ppc.c:69-75`; no matching entry returns `-1` at `:79`. Thus “two cases” means two categories: all accesses to PP=00, and writes to PP=01 or PP=11.

The denied-hit branch contains literal `exit(1);` at `src/cpus/memory_ppc.c:275`, before the `FLAG_NOEXCEPTIONS` test at `:299`. This applies to callers reaching that branch; translation-disabled accesses return earlier (`:258-260`). A debugger dump uses `MEM_READ` with `NO_EXCEPTIONS`, so PP=00 can terminate it, whereas read-only mappings permit the dump (`src/debugger/debugger_cmds.c:716-717`; `src/cpus/memory_rw.c:248-252`).

USER-state access can encounter denial when the BAT is user-valid. A supervisor-only entry is **skipped**, not denied (`src/cpus/memory_ppc.c:56-63`). Furthermore, architectural supervisor-only BAT programming is not enforced here: the generic `mtspr` handler contains `/*  TODO: Check permission  */` followed by the register assignment (`src/cpus/cpu_ppc_instr.c:2808-2809`); the decoder supplies the SPR pointer and selects that handler (`:4676-4688`).

The hardware requirement is independently supported by prose, not merely the extracted figure: `_scratchpad/ppc_pem32_rev2_2001.txt:13312` specifies DSI/ISI for prohibited block access; `:13334-13336` specifies the protection conditions and status bits. |---|---|---|
| Load-reserve | Continues | `exit(1)` |

**Q3. Correction choices and available machinery.**

- **H1: (5), fault**, with nonthrowing failure for `FLAG_NOEXCEPTIONS`. Existing code provides DSI/ISI dispatch and data-fault metadata (`src/cpus/memory_ppc.c:315-323`), but a denied BAT must remain a protection fault, not fall through into page translation or the PPC603 reload path (`:279-284`, `:307-313`). The required protection status is specified at `_scratchpad/ppc_pem32_rev2_2001.txt:13335-13336`.

  Exception machinery exists, but it is incomplete. `ppc_exception()` saves state and redirects execution (`src/cpus/cpu_ppc.c:318-344`), while its MSR update clears only `PPC_MSR_EE | PPC_MSR_RI | PPC_MSR_PR` (`:335`). Moreover, instruction-fetch failure still independently reaches `exit(1);` (`src/cpus/cpu_ppc_instr.c:4115-4119`). A correction must handle status, exception entry, and caller propagation; merely replacing the BAT exit with an exception call is insufficient.

- **H2: (7), implement the missing behavior**, including recording and single-precision rounding. Existing arithmetic handlers and record wrappers provide implementation structure (`src/cpus/cpu_ppc_instr.c:1836`, `:1878`, `:1920`, `:1938`, `:4047-4048`). Simply aliasing double handlers is explicitly rejected by the committed record because narrowing remains unresolved (`CHANGELOG.md:32301-32305`). An exception alone would not implement these legal arithmetic instructions.

- **H3: (5), fault**, for the 2001 invalid-form policy and the malformed store-conditional form. The manual permits a program exception for invalid forms (`_scratchpad/ppc_pem32_rev2_2001.txt:6856`). For a v2.01 target’s reserved load bit, choose **(4), accept**, ignoring that field as its manual requires.

  PowerPC program exceptions are **not currently delivered by the checked paths**. The existing exception constants omit a program exception (`src/include/cpu_ppc.h:251-257`), and the generic entry has no program-cause handling (`src/cpus/cpu_ppc.c:318-345`). Correct program entry requires the saved instruction address, cause status, and architectural MSR changes described at `_scratchpad/ppc_pem32_rev2_2001.txt:12024-12045`. Thus option (5) requires implementation work first.

The list omits **an explicit, diagnosed stop of the affected emulated CPU/machine**. The shared `bad` path already supplies such behavior (`src/cpus/cpu_dyntrans.c:2004-2024`). That is an interim unsupported-operation policy, not a complete correction under this brief’s progress-based HIGH rule.
