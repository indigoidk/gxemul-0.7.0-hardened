### Question 3: What Did All Nine Seats Miss?

1. **Zero Validation of the `reopened` Field in `bad_commits()`**:
   All seats intensely debated how `names()` matches the `reopened` field in D1 and whether it should match leading tokens or prefixes. **Yet every seat missed that [`bad_commits()`](file:///C:/DocumentNoSnc/cc/GXEMUL/GXEMUL-SEC/tools/pipeline/check_commit_attribution.py#L224-L235) validates ONLY the `commits` field.** It enforces that every whitespace-delimited token in `commits` matches `[0-9a-f]{7,40}` and is not a placeholder like `TODO` or `pending`.
   In contrast, `row.get("reopened")` has **zero placeholder or syntax validation anywhere in the pipeline**. If a contributor writes `reopened: "TODO"` or introduces control characters (as seen in `lcaisalane`'s `\b`), `bad_commits()` completely ignores it. Unless a closure commit mentioning that row appears within `DEPTH`, malformed `reopened` values pass through the gates completely undetected.
2. **`check_delete_calls.sh` Succeeded Historically Only Due to Missing Anchoring**:
   In [`test/check_delete_calls.exceptions`](file:///C:/DocumentNoSnc/cc/GXEMUL/GXEMUL-SEC/test/check_delete_calls.exceptions#L1-L10), **every single file entry begins with `./`** (e.g. `./src/include/refcount_ptr.h`).
   In [`test/check_delete_calls.sh:4`](file:///C:/DocumentNoSnc/cc/GXEMUL/GXEMUL-SEC/test/check_delete_calls.sh#L4), `grep -R "delete " src` emits paths starting with `src/` (without `./`).
   In line 10, the test runs `if grep -q $a test/check_delete_calls.exceptions`. Because `$a` is `src/...` and the file contains `./src/...`, `$a` matched only because the grep was an **unanchored substring match**. Had upstream written an anchored check (`grep -Fx` or `grep "^$a$"`), **100% of files—including `refcount_ptr.h`—would have failed**.
3. **`records_only()` Produces False Negatives on Merge Commits**:
   [`check_commit_attribution.py:172`](file:///C:/DocumentNoSnc/cc/GXEMUL/GXEMUL-SEC/tools/pipeline/check_commit_attribution.py#L172) executes `git show --name-only --format= h`. In Git, running `git show` on a merge commit produces a combined diff. For any clean merge commit without conflict resolutions, the combined diff output is completely empty (`paths = []`).
   At line 205, `return bool(paths) and all(...)` returns `False` whenever `paths` is empty. Consequently, any merge commit touching purely documentation or records will fail `records_only()` and be misgraded as code authorship.
4. **Dead Variable in `main()`**:
   In [`check_commit_attribution.py:264`](file:///C:/DocumentNoSnc/cc/GXEMUL/GXEMUL-SEC/tools/pipeline/check_commit_attribution.py#L264), `commits = (row.get("commits") or "").split()` was left behind from the pre-R implementation. While `commits` is tested later for emptiness (`not commits`), line 283 now uses `names(row.get("commits"), full)` directly. The split list is never used for membership checking, creating a subtle behavioral difference where `not commits` checks whitespace tokens while `names()` checks hex tokens.
