## 2. Which disposition is wrong

**F27 — "RECORDED" — is the wrong disposition, and it is the worst one to get wrong.** [REASONED] R's design replaces one growth-sensitive assumption (abbreviation length drifts as the repo grows → the old bug) with another (a 7-char prefix names exactly one commit → silently false as the repo grows). The mechanism that CAUSED the original failure is precisely the mechanism that will eventually break note 1 — and F27 names the fact that nothing trips when it does. This got RECORDED while far more cosmetic findings got FILEs. The tripwire is cheap and already half-written: Opus resolved all 184 unique ledger tokens once; running `git rev-parse --disambiguate=<token>` (or equivalent) per unique ledger token inside the checker, plus a hard stop on any token resolving to zero or two objects, converts "moot today" into "enforced forever." D2's ruling leans on the manual resolution being done; F27 is the observation that it will never be done again. Same defect family, same fix.

Secondary: **F11 is under-weighted** [REASONED] — a fail-open PASS token on subprocess failure is gate-fatal, not one MED bullet among seven. And **F23's correction may still carry a false sentence** (the mirror case), pending the `commits`-binding fact named above [READ/REASONED].

On the 27-accept ratio itself: [REASONED] it is less damning than it looks — most ACCEPTEDs were records/wording corrections, which cost nothing to accept. The honest test is "which RECORDED should have been FILED," and the answer is F27, with F11 promoted.
