## 1. THE DEFECT, MEASURED BEFORE THE EDIT

`d->cnt` is **GUEST-SUPPLIED** — two 16-bit stores to `GDROM_CNTLO`/`GDROM_CNTHI`. The
shipped code was:

```c
		if (d->cnt != 408) {
			fatal("GDROM Read TOC not 408 bytes?\n");
			exit(1);
		}
		alloc_data(d);
```

So an ordinary guest register access ended the host process. **Rung-3 witness, measured on
the committed build at `84f6682` BEFORE any edit**
(`regress/artifacts/gdromexitsix/repro_20260828/PREFIX_committed_84f6682.out`):

## 2. WHY A BARE DELETION IS WORSE THAN THE DEFECT

`alloc_data()` in full:

```c
static void alloc_data(struct dreamcast_gdrom_data *d)
{
	d->data_len = d->cnt;
	CHECK_ALLOCATION(d->data = (uint8_t *) malloc(d->data_len));
	memset(d->data, 0, d->data_len);
}
```

It mallocs `d->cnt`. The TOC writer immediately below uses **HARDCODED** indices:

```
grep -oE 'd->data\[[0-9]+\*4(\+[0-9])?\]' src/devices/dev_dreamcast_gdrom.c
   ->  highest byte index 407   (d->data[101*4+3])
```

so it needs **408 bytes regardless of `cnt`**. Deleting the `exit(1)` converts a host kill
into a **GUEST-CONTROLLED HEAP OVERFLOW of up to 408 bytes**, with `malloc(0)` at `cnt == 0`.
**Therefore the decline must come BEFORE the guarded statement, not after it.**

## 3. THE WHOLE ENCLOSING FUNCTION — every exit path and the common tail

*Inlined in full because a proposed edit is a sketch until it has been run against real
control flow. A recent round had FOUR independent readers propose the same `return` into a
function whose common tail none of them had read.*

```c
static void handle_command(struct cpu *cpu, struct dreamcast_gdrom_data *d)
{
	int64_t sector_nr, sector_count;
	int i, res;

	debug("[ GDROM cmd: ");
	for (i=0; i<12; i++)
		debug("%02x ", d->cmd[i]);
	debug("(cnt=%i) ]\n", d->cnt);

	free_data(d);				/*  #465  */
	d->cur_data_offset = 0;
	d->cur_cnt = 0;

	switch (d->cmd[0]) {

	case 0x14:				/*  Read TOC -- THE SITE  */
		<<< the edit, shown in §4 >>>
		alloc_data(d);
		memset(d->data, 0xff, d->cnt);
		d->data[0*4]   = 0x10;  ...  d->data[101*4+3] = 0x41;
		break;

	case 0x30:				/*  Read sectors  */
		if (d->cmd[1] == 0x24) {
			fatal("GDROM unimplemented data format 0x%02x. Continuing anway.\n", d->cmd[1]);
		} else if (d->cmd[1] != 0x20) {
			fatal("GDROM unimplemented data format 0x%02x\n", d->cmd[1]);
			exit(1);		/*  NOT this round  */
		}
		...
		if (sector_count <= 0 || sector_count > GDROM_MAX_TRANSFER_BYTES / 2048) {
			fatal("GDROM: rejecting sector_count=%i\n", (int)sector_count);
			break;			/*  <-- OB-20 idiom, ALREADY IN THIS FUNCTION  */
		}
		if (d->cnt == 0)
			d->cnt = 2048 * (int)sector_count;
		if (sector_count * 2048 != d->cnt) {
			fatal("Huh? GDROM data_len=0x%x, but sector_count=0x%x\n", ...);
			break;			/*  OB-20: was exit(1)  <-- AGAIN  */
		}
		alloc_data(d);
		...
		break;

	case 0x70:				/*  Mount -- ignored  */
		break;

	default:fatal("GDROM handle_command: unimplemented command 0x%02x\n", d->cmd[0]);
		exit(1);			/*  NOT this round  */
	}

	/*  ***  THE COMMON TAIL -- LOAD-BEARING  ***  */
	if (d->data != NULL) {
		d->cond |= COND_DATA_AVAIL;
	} else {
		d->cnt = 0;
		d->cond &= ~COND_DATA_AVAIL;
	}

	if (d->cnt == 65536)
		d->cnt = 32768;

	SYSASIC_TRIGGER_EVENT(SYSASIC_EVENT_GDROM);
}
```

**`break` and NOT `return`.** `free_data()` at the top left `d->data == NULL`, so the tail
takes its else branch, sets `cnt = 0`, clears `COND_DATA_AVAIL`, and **still fires
`SYSASIC_TRIGGER_EVENT`** — "the command produced no data", reported properly. An early
`return` would skip that event and leave the guest waiting forever. And `case 0x30` already
ships this exact idiom **twice**, in this same function, from a previous round.

+				d->warned |= GDROM_W_TOCLEN;

(A ~30-line explanatory comment accompanies it; elided here, available in the tree.)

**Option set, all four members considered** — this project's de-fatalisation set is
delete / decline / decline+bounded-announce / accept:

* **delete** — REJECTED, measured: guest-controlled heap overflow (§2).
* **accept** — REJECTED, **but the reason given here was WRONG and pass 2 refuted it.**

> ### *** "ACCEPT WOULD OVERFLOW" IS FALSE ABOVE 408, AND THREE PACKET-FED SEATS SAID SO. ***
>
> It is true only for `cnt < 408`.  For `cnt > 408`, `alloc_data()` mallocs MORE than the
> writer needs, the writer stores its 408 bytes, and the tail of the buffer is the `0xff`
> padding `memset` already put there — **safe, and arguably a correct TOC**.  `ollama_kimi`
> quantified the resulting mutant: `!=` -> `<` changes the disposition of **65,527 of 65,536
> possible inputs** while scoring 15/15 on the 15-row detector.
>
> **THE DISPOSITION IS UNCHANGED AND THE WARRANT IS BETTER.**  The right reason to decline
> `cnt > 408` is not memory safety — it is that **a de-fatalisation MUST NOT CHANGE THE ACCEPT
> SET.**  The shipped guard is the original `!= 408`, so the set of values that produce a TOC
> is byte-for-byte what it was before the round: the fix converts the DEATH into a decline and
> touches nothing else.  Widening to `>= 408` would change which requests are honoured, which
> is exactly what this project's accept rows exist to catch — and `over cond` now catches it.
>
> *A wrong reason for a right answer is still a wrong record, and it gets reused.  Corrected
> here rather than quietly dropped.*
>
> (Contrast the footbridge `+0x188` case, where the model already computed the right value and
> the disposition genuinely WAS accept.)
* **decline, silent** — rejected: loses the diagnostic entirely.
* **decline + LATCHED announce** — SHIPPED. N=1 per device instance with an explicit
  `(once)` marker, which is this fork's house idiom (~14 marker sites; `(once)` is the
  plurality spelling) and matches its chronology: `#265/#269`, `#337`, `#460`, `#461` all
  chose latch + `fatal()`.

### *** M7 IS WHY THIS IS THE SECOND TABLE, AND IT IS AN L1 AGAINST MY OWN FIRST DETECTOR ***

The first detector had **13 rows and scored 13/13 against `break;` -> `return;`** — a total
escape, found by a review seat. `bad cond` is **structurally blind** to it: the guest writes

**And the product comment CLAIMED that very property** — *"an early return would skip that
event and leave the guest waiting forever"* — **while shipping no row for it.** That is the
CLAIM -> ROW pre-table check, unrun, on this round's own diff.
