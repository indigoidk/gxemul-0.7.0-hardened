## 2. Q1 — IS THE FIX RIGHT? **Yes, and it is exact.**

Read locally at `_scratchpad/ppc_pem_32and64_2005.txt:29736`:

```
n <- sh[5] || sh[0-4]   r <- ROTL[64](rS, n)   b <- mb[5] || mb[0-4]
m <- MASK(b, 63)        rA <- r & m
```

and `:29737` — *"The rotated data is ANDed with the generated mask."* Post-fix the handler is
`gpr[ra] = ROTL64(gpr[rs], SH) & MASK(MB, 63)`. **That is the RTL, term for term.**

I re-derived the decode against the manual's own split-field diagram (`:29706-29734`, and
`:29734` *"This is a split field"*) rather than trusting the probe:

| field | code | BE bits | correct |
|---|---|---|---|
| RS | `(iw >> 21) & 31` | 6-10 | yes |
| RA | `(iw >> 16) & 31` | 11-15 | yes |
| SH | `((iw>>11)&31) \| ((iw&2)<<4)` | 16-20 ‖ 30 | yes — `sh5` from BE bit 30 into weight 32 |
| MB | `((iw>>6)&31) \| (iw&0x20)` | 21-25 ‖ 26 | yes — `mb5` already sits at weight 32 |
| Rc | `iw & 1` | 31 | yes |

**No UB anywhere in the fixed path**, which I checked because the round's own `M_MASKEND`
mutant has some: `mb` is six bits so `63-mb ∈ [0,63]`, and the loop always runs at least once
so `tmp2 >= 1` — the `& tmp2` can never be a silent zero again. `sh == -1` after the rotate
loop is harmless here because `sh` is dead; it is precisely what breaks `rldimi`.

**One note on the (d) mutant, not a defect in the fix:** `M_MASKEND` uses `1 << (62-mb)`, which
is a **shift by −1 when `mb == 63`** — undefined behaviour that happens to wrap to 63 on x86-64.
The kill survives it (`zx32` and `census wrong` red for mask reasons that do not depend on that
cell), but a clause-(d) mutant should not rest on UB. `while (mb <= 63)` → `while (mb < 63)` is
the same nulled repair with no UB; by derivation it scores 17/19 (`zx32`, `census wrong`).

## 4. Q3 — WHAT ESCAPES? **Two total escapes, measured, not predicted.**

### ESCAPE 1 — `M_SH5`: drop the `sh5` bit from the SH decode. **19/19.**

```c
int sh = ((ic->arg[0] >> 11) & 31) | ((ic->arg[0] & 2) << 4);   /* shipped */
int sh = ((ic->arg[0] >> 11) & 31);                             /* M_SH5   */
```

Every `rldicl` with SH ≥ 32 then rotates by SH−32. **The detector does not notice, at all.**

*Why it is blind, and it is by construction rather than by bad luck:* the census sets
`RS_ONES = M64`, and `ROTL64(all-ones, n) = all-ones` for every `n`. So all 126 SH-varying
census cells compute `all-ones & MASK(MB,63)` **whatever the rotate amount is**. The only
rotate-sensitive `rldicl` rows are `zx32` (SH=0) and `rot8` (SH=8) — **both below 32, so the
`sh5` bit is never load-bearing anywhere in the instrument.**

*Why it matters:* the manual's own simplified-mnemonic table (`:29744`, `:29758`) says
`srdi rA,rS,n` **is** `rldicl rA,rS,64−n,n`, so **every logical right shift by 1..32 has
SH ≥ 32**, as do `rotrdi` and most `extrdi`. Measured on all three machines
(`opus_threemachine.log`): under `M_SH5`, `clrldi` is still **correct** while
`srdi r5,r3,1` returns `0x657f7806ef56df77` instead of `0x6f56df77e57f7806`. The one form the
detector pins is the one form the mutant gets right.

*Two controls that make this a result rather than an anecdote:*
* **`M_MB5`** — the identical edit on the **same line**, dropping `mb5` instead: **16/19,
  killed.** Same anchor, same kind of mutant, one field covered and the other invisible.
* **`M_ROTAMT`** (`while (sh-- != 0)` → `while (sh-- > 1)`): **18/19, killed by
  `rot8 rldicl` and by nothing else.** The rotate-amount axis rests on exactly one row at
  exactly one value.

### ESCAPE 2 — `M_CR0`: feed CR0 the unmasked rotated value. **19/19.**

```c

if (rc) update_cr0(cpu, tmp);                   /* M_CR0            */
```

**This is not a mutant I invented; it is the token that ships, correctly, ten lines below.**
`X(rldicr)` ends `update_cr0(cpu, tmp)` and is right to, because *there* `tmp` **is** the

concluded "NO ROW OWED on parity". **The parity difference extends one statement further,
