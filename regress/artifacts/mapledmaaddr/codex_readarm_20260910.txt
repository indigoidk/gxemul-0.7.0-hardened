1. **Yes: DMA completion updates the field, with more arithmetic than the quoted payload increment alone.**

   The trace is:

   - Initialization zeroes the entire device structure, including `dmaaddr` (649).
   - A write at `0x04` assigns `idata` to the `uint32_t` field (559). Thus the stored value is the input converted to 32 bits, with no alignment masking.
   - DMA starts by copying that field into local `uint32_t addr` (382).
   - Each processed descriptor advances local `addr` by **8 bytes for the control words**, **4 bytes for the command word**, and **`4 * datalen_cmd` bytes for command data** (417, 440, 532).
   - After processing the last descriptor, the routine assigns local `addr` back to `d->dmaaddr` (540), before invoking the DMA-done event macro (543).

   Consequently, for a transfer reaching that tail, with starting field value \(P\) and command-data lengths \(D_i\), the committed value is:

   `C = (P + Σ(12 + 4*D_i)) modulo 2^32`

   Before any completed DMA, the field holds the last programmed value, or zero if nothing has programmed it. After completion it holds `C`, until another writer changes it.

   “Advanced” therefore describes the implemented cursor arithmetic, not necessarily a numerically larger value: unsigned wraparound is possible. Nor does every conceivable completed chain necessarily produce `C != P`.

If a callback reenters the read arm before the completion store, it sees the previously committed field, absent an intervening writer. The files support **no incremental publication by this routine**, rather than an unconditional claim about every possible external callback or concurrent access.

6. **The proposed pair is useful, but insufficient to establish exact reporting of the live field.**

   **Assertion (i), exact readback without DMA, tests the storage/read connection.** Its strength depends on the inputs:

   - A constant can pass a single matching test value.
   - Constant zero passes an initial-zero-only test.
   - Alignment masking passes every test using only aligned values.
   - A separate snapshot of the last programmed address passes this assertion even if it never tracks DMA updates.

   Use several distinct values, including nonzero high bits and nonzero low five bits, and verify successive writes replace what reads report. No DMA is needed for the unaligned-value cases.

   **Assertion (ii), post-transfer inequality, proves only that the returned value differs from `P`.** Even with independent proof that DMA happened, both assertions could be satisfied by an implementation that reads correctly before DMA but afterward returns:

   - Zero, when the tested `P` is nonzero.
   - A fabricated `P + 4`.
   - A stale cursor from an earlier transfer that differs from the current `P`.
   - A masked or otherwise transformed current field that still differs from `P`.

   Independent DMA evidence rules out a skipped transfer; it does not validate the relationship between the returned value and the field. The inequality rejects an unchanged snapshot of that particular `P`, not every stale or fabricated answer.

   To test the read arm without certifying the architectural cursor value, a harness with state access should capture the actual field value `S` immediately before the read and assert:

   - The delivered register value equals `S` exactly.
   - The read leaves the field unchanged.
   - The access returns normally and invokes no read-side diagnostic.

   Apply that check both after ordinary programming and after an independently demonstrated transfer. For the chosen transfer fixture, `S != P` can additionally demonstrate that the fixture exercised the existing field update. It remains a property of that fixture and current implementation.

   For independent DMA evidence, use a supported command and verify a fresh expected response in a receive buffer initialized to distinguishable contents. A newly observed completion event can supplement that. **`MAPLE_STATE == 0` is insufficient:** its read arm always returns zero (592–593), including after an early return. An event alone also establishes less than a valid response, because the descriptor loop can reach completion through paths that do not implement the requested operation fully.

   Finally, value assertions alone do not reject candidate **(c)** if `fatal()` returns. Silence and normal completion must be checked separately.

   Without access to the field or another exact oracle, the proposed pair establishes readback before DMA and change after DMA; it cannot establish exact live-field reporting. Its advancement assertion would also need reconsideration if the separately reviewed cursor policy legitimately changes.
