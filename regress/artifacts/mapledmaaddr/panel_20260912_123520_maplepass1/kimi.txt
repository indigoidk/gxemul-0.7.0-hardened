  ## Q1 — Is ACCEPT right? Yes, and the option walk is not close

  - **DELETE** (drop the whole read arm): read falls to `default:` → `fatal("UNIMPLEMENTED read…")` plus `odata` stays 0. Wrong value *and* noisy — strictly worse than ACCEPT on both axes.
  - **DECLINE / DECLINE+LATCHED**: keeps the process kill, which *is* the defect. The latch never fires twice anyway — the guest dies on the first read.
  - **FAULT**: undeliverable on SH4 (above) and semantically wrong — the register is implemented; there is a stored value to return.
  - **BACKED ACCEPT** (return the field but announce): the read is implemented by the fix, so an "unimplemented" diagnostic is a lie; it violates the switch's own convention (ENABLE/SPEED/STATE read arms are all quiet); the detector's read-quiet row would correctly fail it.
  - **IMPLEMENT**: everything implementable from available evidence *is* ACCEPT. Hardware-true readback semantics are unsettled (premise 1); anything richer is speculation, and anything touching the cursor is the separate row.
  - **ACCEPT**: removes the kill, returns model-true state, matches the sibling arms, adds zero unverifiable claims. Minimal and correct.
