> when its guarded body tests nothing: the floor is clause (b)’s verbatim reinstatement plus the dominating predicates’ accept cell; every re-introduction keyed on a body-read operand the body does not test is clause (e).

After the edit the guarded body is one assignment, `odata = d->dmaaddr;`. It tests nothing.

**Clause (d) enumerates:**

## 3. Which premise is false

**Premise 2.** There is no `DEVICE_ACCESS` caller whose `writeflag` is neither `MEM_READ` nor `MEM_WRITE`.

- `memory.h`: `MEM_READ=0`, `MEM_WRITE=1`, `MEM_DOWNGRADE=128`.
- `memory_rw.c` documents `writeflag` as `MEM_READ` or `MEM_WRITE`. The only device callback is `mem->devices[i].f(..., writeflag, ...)`.
- `MEM_DOWNGRADE` is used only in `cpu_dyntrans.c` on the **TLB** helper (`writeflag & MEM_DOWNGRADE`). It is never passed to `memory_rw` or a device.

The `else` is the house idiom (`MAPLE_ENABLE`, `MAPLE_SPEED`). After ACCEPT, a hypothetical third value assigns `odata` and skips `memory_writemax64` because that call is already `if (writeflag == MEM_READ)` — same as ENABLE. Tightening the arm to `else if (writeflag == MEM_READ)` is not required and would be a different edit than the sibling.

Premise 1 is unanswered, not false; ACCEPT still dominates. Premise 3 is true: `mapledmaadvance` is already split out; this round must not decide the tail `d->dmaaddr = addr`. One correction to older prose: an aborted transfer preserves the **entry** value (which may already be a previous cursor), not a separately saved programmed address; enable is checked before alignment.
