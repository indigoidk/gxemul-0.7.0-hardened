**Landing sites the brief named:**

* **Inside a disassembly line (mnemonic/comment unchecked).** Not reachable from this arm. `sh_cpu_disassemble_instr` writes the full line including `; r1 = 0x…` and the `\n` *before* `I;`. A device `fatal(" injected")` cannot append to that line in the byte stream. `\r` / ANSI do not rewrite a previous line in the buffer; they land on the *next* line (and `\r` trips the bare-CR count).
* **Inside a `print` hex line (`("value", None)`).** The print runs *after* the load. A no-newline diagnostic glues onto `GXemul> print rN`, which is an exact echo match, not a hex match.
* **Prefix-match on a later disassembly (`_DIS` has no `$`).** Reachable in the **one** session that steps twice (`marker survive`). Exact C: `fatal("8c001002:  2432 ");` (no newline) — `_is("disasm")` still accepts the glued second line. The other eleven sessions glue that text onto `GXemul> print …` and red. The 12-session AND still kills it. Not a survivor of the row.
* **Replaces rather than adds.** The debugger still emits every owed line. Printing the next owed line yourself inserts a duplicate; surplus catches it. Swallowing the debugger’s line is not a diagnostic in this arm.

### 2. Is the oracle sound?

**Clean session, false red**

* **1.2 s tail / 0.20 s inter-command window.** If the last `print` (or a `step`) is only partly in the buffer, `tail` is a partial hex/`GXemul>` and is not in `("", "GXemul> ")`. Table 5 ran BASE 37/37 three times on an idle clone; that is not a gate-load sample. Residual, not a diagnostic hole.
* **`CLICOLOR`.** `enable_colorized_output = getenv("CLICOLOR") != NULL`, and a pty *is* a tty, so `color_prompt()` emits `\e[34;1m` in front of every `GXemul> `. Echo is exact equality. A clean session with `CLICOLOR` set reds `read silent`. The probe does not clear it. Table 5’s 37/37 implies it was unset for those runs.
* **First prompt.** `t.find("GXemul> ")` is the start of the first echo line, which is what `owed()` starts with. Fine on this machine (`-V` drops to the debugger immediately). A banner containing that eight-character string would false-red; BASE says this image does not have one.

**Dead session, false green on silence**

* Death *during* the read (exit, `return 0` skip, hang before the print) leaves missing owed lines → red. Good.
* Silence does **not** look at `how`. A child that produced a complete owed transcript and then died on `quit` could pass `read silent` and still fail `exit status` unless the death is `exit(0)`. The `exit status` note is right: `exit(0)` at the read is carried by `marker survive` (incomplete print), not by the status row.

A dead session cannot pass the **detector**; it can pass the silence row only if the owed transcript is already complete.

### 4. Which claims are wrong?
