### 1. Accept-side enumeration (46 × {announced, silent})

**Announced (guard growth) — all 46 caught by `latch said`.**  
`latch x5` appends every `ACCEPTS` entry onto `c` before `lh +0x06` (`crime_width_probe.py`, the `for op, off, val in ACCEPTS` loop then `(("lh", 6), ...)`). `session()` plays that list in order; a later PROM-window redirect cannot drop commands. A conjunct on `len == 8` / `len == 4` drops the cell into the else arm, which **always** announces while `d->warned` is still 0:

```c
if (!(d->warned & CRIME_W_LEN)) {
    d->warned |= CRIME_W_LEN;
    fatal("[ crime: unimplemented len=%i at 0x%x -- declined.  (once) ]\n", ...);
}
goto crime_declined;
```

`said(t, 2, 0x6, ...)` wants **that exact** `len=2 at 0x6` string. No ACCEPTS cell is width 2, so a stolen notice cannot match. Width arm declines **before** the REV pc test, so `lwP/swP/sdP/ldP` announce like any other (G4: `latch said` + `revP sw pc`, 155/157).

A grown guard **cannot** decline an ACCEPTS cell with the latch still clear **and** no announce: that path is the silent bypass (insert `goto crime_declined` before the width test), not guard growth. Measured: C1/G1–G5 red `latch said`; G6 (silent) leaves it green.
