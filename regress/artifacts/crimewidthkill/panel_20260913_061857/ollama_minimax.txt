## Question 2 — which of my 16 accepted dispositions is weakest

**F5 (TIME rows).** READ for the verdict, REASONED for the diagnosis.

Two reasons, in order of severity:

1. **The detector's `time %s ctl` row checks the wrong thing.** `row("time %s ctl" % op, mag(nth(t, "s2", 0)), "large", ...)`. `nth(t, "s2", 0)` returns the absolute value of `s2` (the third `ld`'s result), not a diff. On the fix, with any plausible initial TIME, `s1 = initial + delta` and `s2 = initial + 2·delta` differ by one tick; if `initial < SMALL − delta` both are "small", if `initial ≥ SMALL` both are "large". There is no `initial` for which `mag(s1)=="small"` AND `mag(s2)=="large"` simultaneously. Either `time lb` or `time lb ctl` fails on the fix; the test is only consistent in a window roughly `delta` wide (66–132 µs) where `s1<SMALL≤s2`. The author flagged this row family as "the row most exposed" — and the control row's expected value is structurally inconsistent with the primary row's expected value given that both index absolute values. REASONED.
2. **The "small vs ~1.4e8" split is a timing assumption**, as the author concedes: ticks counted in instructions while stepping, no wall-clock-sized delta between the first `ld` and the refused access. It held at 66/132 in every run so far. REASONED.

I do not claim F5 is *wrong* — the measurement that INTSTAT/INTMASK/TIME fall-throughs are observable is correct. The disposition is correct. The *weakness* lives in the detector's TIME control row's expected value, which the panel accepted along with the rest of F5.
