## Q1 -- Member 3 or 5: count the arguments

**The 4-4 seat split is a 2-vs-5 argument split.** Two of the four FAULT seats rest on a false premise about the fix space:

- **minimax**: "Members 1-4, 6, 7 run the switch. Member 5: no -- return 0 exits before the switch." **deepseek**: "FAULT is the smallest non-terminating change that avoids executing the switch side effects." Both are arguments *against fall-through*, not *for a bus error*. The tree already contains a decline that skips the switch -- `dev_sgi_re.c:1214-1219` `goto de_declined`, label at `:1438` (READ) -- and Opus MEASURED it: `rows_decline.out` shows `sh CTL+08 0x800 halted=no`, `sb CTL+08 0x01 ctlmsg=0`, `revhack lb pc=0xbfc05184`. Packet-fed seats could not see `#498`; that is a brief limitation, not a seat failure, but the argument does not survive contact with the tree. Remove those two and FAULT has codex and kimi-k3.

**The arguments that remain for 5, ruled on individually:**

1. **`crimereg.h:39` "all registers 64-bit access"** (codex). READ. It is a comment on `CRIME_BASE` in NetBSD's *driver* header -- it describes the discipline the driver follows, not what the ASIC does on a narrower cycle. And it is not even true of the guests: the file's own TODO at `dev_sgi_ip32.c:327-328` records NetBSD 1.6.2 writing 4 bytes at `0x00c`, and the model serves `len == 4` today. codex's own sentence: "does not establish the hardware's rejection behavior." **Ruling: caution about implementing lanes (against member 7); zero warrant for a bus error.**
2. **"A decline answers 0 from the memory/interrupt controller, which also asserts unestablished behaviour"** (codex, kimi-k3's asymmetry: a byte read of INTSTAT returning "nothing pending" is a lie). True that both dispositions assert something no document supports. But the asymmetry cuts both ways -- FAULT's guest-visible consequence for that same access is a DBE, which for a kernel interrupt path is a panic, not a wrong value -- and it is unevidenced in exactly the way the premise-audit rule warns about: it is a *plausible* story about a device class, not a fact about CRIME. Meanwhile the 8- and 4-byte reads of INTSTAT/INTMASK remain correct, so a narrow-read 0 corrupts no modelled state. **Ruling: symmetric and unevidenced; it cannot overturn a house policy adjudicated twice on this machine with a measured precedent.**
3. **"The IP32 guest ecosystem already absorbs DBE (ten `dev_unreadable` slots)"** (kimi-k3, inherited from the brief). READ and REFUTED by codex, confirmed by me: the ten `device_add("unreadable ...")` sites are at `machine_sgi.c:241-247` (IP20) and `:345-351` (IP22/24), each after an unconditional `fatal("TODO..."); abort();` at `:219-220`, `:267-268`, `:275-276`. **IP32 installs none.** Nothing in this tree's IP32 model depends on DBE delivery. The premise was mine in the pass-1 brief and it was false as a live statement.
4. **"FAULT uses the architectural failure path."** It uses *an* architectural path. Whether real CRIME raises a bus error, ignores the cycle, or serves a lane is not established (premise 6 holds: `ls _scratchpad/*.pdf` has no CRIME document; the author's "On my real O2" note at `:193-198` is about mirrors and silent on width).

**The arguments for 3:**

1. **The `#498` precedent transfers, and the objection to transfer is aimed at the wrong thing.** The shape is identical -- width guard, accept set {4,8}, side-effecting switch, common tail -- and the *warrant* recorded at `dev_sgi_re.c:440-447` and `:1183-1212` is device-independent: "A guest choosing an access width is not an emulator error" and "`return 0` would ... raise EXCEPTION_DBE -- turning a refusal into a guest bus error." "RE is graphics, CRIME is the memory controller" is an argument about the *cost of a wrong disposition*, and that cost is unevidenced in both directions (point 2 above). What transfers is the warrant; what would block transfer is a CRIME-specific fact, and there is none.
2. **Observability under free running.** MEASURED (`rows_fault.out` freerun row: `txt_after_continue ... failed=0`): FAULT's only host-side trace is `memory_rw.c:604`'s `debug()`, suppressed when free-running. The house rule is not merely "a guest-drivable diagnostic needs a latch"; its premise is that a refused guest action *announces itself once and survives `-q`* so that a real guest doing this is discoverable. Under pure FAULT a real guest that ever issued a narrow CRIME access would show as an unexplained guest panic with nothing on the host. kimi-k3's "5 + latched announce" repairs this -- but then 5+latch and 3 differ only on DBE-vs-0, which is point 2 again.
3. **Guest liveness is the fork's objective.** Decline keeps the guest running (`pc+4`, no exception); FAULT vectors it. With no guest known to issue these accesses (READING, all file-reading seats), the difference matters only for a buggy or hostile guest, and the fork's disposition for that case has been decline-once on this machine six times over (`#497`'s six guards, `#498`).
4. **`return 0` already has a meaning in this tree: "nothing is here"** (`dev_unreadable.c`). CRIME is present and answering at two widths. Borrowing the absent-device signal for a present-device width refusal is a wrong statement about the machine (kimi CLI, Opus, grok all made this point independently).

## Q2 -- Placement: at the width arm with `goto` (Opus), not the early guard (codex)

What a refused access executes under the Opus diff (`diffs/decline.diff`, READ against `dev_sgi_ip32.c`): `:207` HARDINT snapshot; `:210-211` `idata` decode (writes only; no side effect); `:223-229` REV/CONTROL/INTSTAT refresh; `:238-254` RAM-size checks; `:256-267` bank loop; the else arm at `:290` -- latch test, `fatal` once, `goto crime_common_tail`; the tail `:384-390` -- HARDINT restore (no-op, nothing changed it), INTSTAT recompute (idempotent), `memory_writemax64(..., 0)` on reads, `return 1`.

**Does executing the prelude on a refused access matter? No, and it is measured rather than reasoned:** the prelude is a pure function of `use_fb`, SOFTINT, HARDINT, `physical_ram_in_mb` and `reg[BANK0]`, so a refused access leaves exactly the state any accepted access leaves. `acc 8/4 r+w` is byte-identical across all nine binaries, and `sb +0x37`/`sh +0x36` after an accepted `sw` read back the unchanged word in every build. The only thing the prelude *does* on a refused access that codex's hoist would avoid is the `-M` divisibility kill -- which fires on the first CRIME access *of any width*, so hoisting merely changes which access trips a launch-config defect. That is a behaviour change unrelated to this round, in a round that should be minimal.

**Three reasons against the hoist:** (i) `goto` forward past `int mb_per_bank; int flag_for_128MB; size_t total_mb;` is legal C99 (no VLA) but is exactly the kind of thing a reviewer stops on; (ii) codex's hoist was argued for FAULT, where skipping the tail is harmless because nothing needs delivering -- under DECLINE the tail must be on the path, and `#498`'s comment records why a private `return 1` "diverges the day the tail grows"; (iii) the guard-in-place is the smaller diff and the shape already adjudicated at `:1214-1219`.

**Latch shape:** Opus's `int warned_len` works (`malloc`+`memset(0)` at `:406-407` zero-inits it). I direct a **`warned` bitfield with a `CRIME_W_LEN` bit** instead -- same cost, and side finding (b) below will want `CRIME_W_CTL` without a second struct edit. Separate bits per site, never shared (`#498`'s `mC` 23/25).

## Q4 -- Side findings: file, severities, none owed as code

- **(a) CONTROL lane/label** -- restated, because the brief's sentence would send a round to the wrong line: the 4-byte arm is internally consistent (BE halves). The defect is the **switch**: `case CRIME_CONTROL` matches only the exact label `0x08` and tests raw `idata`, so a NetBSD-style 32-bit write at `0x00c` -- where bit 11 of a 64-bit BE register actually lives -- never reaches the reset/watchdog logic (`rows_*: sw CTL+0c 0x800 halted=no`, all builds). Guest-visible functional gap (a guest reboot through CRIME_CONTROL at `0x00c` does nothing). **MEDIUM, file as `crimectllane`.** Records obligation *this round*: the detector contract must say that the `sh CTL+08` row's channel exists **because** of this defect; a lane fix moves it.
- **(b) `[ CRIME_CONTROL: unimplemented control ]` unlatched** -- guest-drivable `fatal()` per write, cannot be silenced by `-q`: the flood class. **MEDIUM, file under `floodclass`.** Not this round (different class from a kill; the one-site scope rule), but the bitfield latch shape above is the zero-cost preparation.
- **(c) `-M 48` lazy kill** -- host-set value, guest-set timing. The `> 1024` check in the handler is dead (`machine_sgi.c:479-481` rejects it at construction, READ); the divisibility check is live. **LOW**; disposition is member 7 at `dev_crime_init` with a rung-2 construction witness.
- **(d) Bank interleave** -- READ: the loop writes contiguous `0x208..0x240`; `crimereg.h:141-148` names CTRL1 `0x218`, CTRL2 `0x210`, CTRL3 `0x228`, ... With `-M 64` a guest reading per the header sees bank 2 populated and bank 1 a duplicate of bank 0. Whether NetBSD/OpenBSD memory sizing survives that (they may sum populated banks regardless of index, or use ARCBIOS descriptors) is **not established -- needs a boot witness before ranking**. File as `crimebankorder`, provisionally LOW-MEDIUM.
