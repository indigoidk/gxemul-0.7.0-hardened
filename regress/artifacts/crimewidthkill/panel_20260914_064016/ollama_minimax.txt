## Q2. Floor gap

The edit `if (writeflag == MEM_READ) d->warned |= CRIME_W_LEN;` inserted in the
accepted path (after the width branch, before the switch) scores **141/141**.
Reasoning:

- **Rearm session** iterates ACCEPTS in order. First kind is `("sd", 0x00, 0)` —
  a write. The pre-set doesn't fire. First `lb +0x06` refusal: latch clear, fires,
  count = 1, sets bit. Second kind `("ld", 0x00, 0)` — read, pre-set fires, but
  latch is already set; refusal silent. All subsequent refusals silent. Total
  count = 1. `rearm once` expects 1 — passes.
- **Latch x5** has the same ACCEPTS prologue. First kind write; pre-set silent;
  first refusal `lh +0x06` fires, count = 1. Pre-set fires for later reads but
  latch is set. Count = 1 — same as base.
- **Warm once** is `refuse, accept reads, refuse`. First refusal fires before any
  pre-set can fire (the accepted reads come after). Count = 1. Same as base.
- **Free-running sessions** have no prologue of accepted accesses — pre-set
  never fires. Each fires once, count = 1. Same as base.
- **Gate session** accepted accesses are reads (ld at +0x18, +0x28, etc.), so the
  pre-set fires and sets the latch before the refused `sh 0x0800`. But the gate
  rows check `gate hardint`, `gate line`, `gate run`, `gate lb v0`, `gate lh v0` —
  none check the announce count for the gate session, and the answer is unchanged.
  Gate session passes.
- **Answer, channel, landing rows** are unaffected (the edit only sets the bit).

The row I expected to catch it: **`rearm once`** (count == 1). Why it cannot:
ACCEPTS's first kind is `sd 0x00` (write). A pre-set keyed on `writeflag == MEM_READ`
does not fire for the first accepted access. The first `lb +0x06` refusal fires
before any read pre-set can fire, setting the latch. Subsequent read pre-sets fire
into an already-set latch.

The asymmetry: **re-arms on reads are caught** (a re-arm clears the latch, so the
refusal after the first read ACCEPTS kind announces, count = 2). **Pre-sets on
reads are not caught** (a pre-set sets a latch that's already set).

## Q3. Wrong statement

The header's claim — "the class closed on its single axes after two passes found
members … closing pass: keyed on … address parity" — is wrong for the **direction
axis on pre-sets**. The brief presents the cross as covering every single axis
including `writeflag`, but a pre-set keyed on `writeflag == MEM_READ` in the
accepted path is not detected: the prologue's first kind is a write, so the
pre-set doesn't fire before the first refused access announces.

A symmetric gap exists for latch mutants in the decline arm keyed on address
parity (`d->warned |= CRIME_W_LEN << (relative_addr & 1)`): for even refused
accesses bit CRIME_W_LEN is set and the check passes once; for odd refused
accesses bit CRIME_W_LEN is never set, so they always announce. The latch x5
session's first refusal is `lh +0x06` (even) — sets CRIME_W_LEN, fires, count = 1,
same as base. The free-running rows are split: `free said` at +0x07 (odd) fires
once (base behavior), `free 2r said` at +0x1f8 (even) fires once (base behavior).
No row distinguishes the mutant from base.
