## The gap (Q2) — the expected catcher, and why it cannot catch

REASONED (from the inlined probe source): The mutant's effect: an *accepted* CONTROL write carrying bit 0x200 silently arms `d->warned`, so the first genuinely declined access later announces **zero** times. That undoes the fix's "announced once" behaviour.

The row that should catch it: **`latch x5`** (count of `-- declined.` == 1 in the session whose prologue reaches the CONTROL arm before its first refusal). It cannot, because:

* READ: the latch session's prologue CONTROL write is `("sw", 0x08, 0x01)`. idata = 0x01 does **not** enter the DOG_ENABLE branch. The mutant's line never executes there.
* READ: the only accepted CONTROL write in the whole instrument that *does* carry 0x200 is the rearm session's `sw 0x08, 0x0201` — and it sits at position 12 of KINDS, *after* that session's first refusal (lb +0x07) has already announced and set the latch. `|=` on an already-set bit is a no-op. `rearm once` stays 1.
* READ: the other accepted CONTROL writes are sw 0x01 (`sw08 msg ctl`) and sw 0x800 (`sw08 halts`, and it stops the CPUs anyway). The sh08/sh08b 0x0201-carrying accesses are *refused*, never reaching the arm.

So no counted session executes an accepted DOG_ENABLE-carrying CONTROL write while `warned == 0`. Every row reads exactly as on the fixed build. 121/121.

DISCLOSED does not cover this: the only branch-level pre-set disclosed is the HARD_RESET branch, disclosed precisely *because* it is unrowable ("nothing can follow it") — which by the brief's own logic implies the other follow-able branches' pre-set cells are intended to be rowed. This one is rowable but unrowed. One added prologue line (`sw +0x08, 0x0201` instead of 0x01 in the latch session; the 0x01 residue still exercises the text branch) closes it.
