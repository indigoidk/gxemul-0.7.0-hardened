## 2. Floor gap

Exact edit, `dev_sgi_ip32.c`, `DEVICE_ACCESS(crime)`, CONTROL write arm:

```c
if (idata & CRIME_CONTROL_DOG_ENABLE) {
    d->warned |= CRIME_W_LEN;   /* add this line */
    idata &= ~CRIME_CONTROL_DOG_ENABLE;
}
```

This is the dual of table 5’s `c2_rearm_dog` (`d->warned = 0` in the same `if`), which was a second-closing finding. `|=` pre-silences the first refusal after an accepted CONTROL write that takes the branch — the same shape as `pre4` / `c2_pre_rev`, which the last two closing passes treated as floor.

**Row that should catch it:** `latch x5` (accepted CONTROL write, then five refusals, want one `-- declined.`).

**Why it cannot:** the only accepted CONTROL write *before* a first refusal is `latch x5`’s `sw +0x08, 0x01`. `0x01` does not have `CRIME_CONTROL_DOG_ENABLE` (`0x200`). `rearm once` does `sw 0x0201` and *does* enter the branch, but only after `lb +0x07` has already set the bit, so `|=` is a no-op. `sh08b`’s `0x0201` is a **refused** `sh` — the `goto` skips the switch, so the body never runs.

The same 121/121 shape, one `if` over, is `d->warned |= CRIME_W_LEN;` as the first statement of the REV `pc`-window `if`. Debugger `pc=` on the next op makes that cell rowable (`lw` from `PROBE_PC`, then a refusal); nothing in the 121 rows does that *first*.

Repair is one accepted `sw +0x08, 0x0201` (or `0x200`) in the `latch x5` prologue, plus the matching REV-redirect accepted access if that cell is closed in the same diff — the class-closure form, not another single cell.
