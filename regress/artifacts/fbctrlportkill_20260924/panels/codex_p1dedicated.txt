4. **The access producer supports all four widths; byte lanes are not ordinary register aliases.**

   Reading [cpu_mips_instr_loadstore.c:127](C:/DocumentNoSnc/cc/GXEMUL/GXEMUL-SEC/src/cpus/cpu_mips_instr_loadstore.c:127), [memory.c:55](C:/DocumentNoSnc/cc/GXEMUL/GXEMUL-SEC/src/core/memory.c:55), and [memory_rw.c:480](C:/DocumentNoSnc/cc/GXEMUL/GXEMUL-SEC/src/cpus/memory_rw.c:480):

   - The CPU serializes the low `len` register bytes in guest byte order.
   - Device dispatch subtracts the device base and passes the starting offset unchanged.
   - `memory_readmax64()` reconstructs an **unsigned** value from all supplied bytes.
   - Neither canonical register access crosses the device boundary, so neither is length-clamped.

   For ordinary aligned loads/stores, offsets below are hexadecimal and relative to `0x12f00000`:

   | Width | PORT case | DATA case | Other aligned offsets reaching the access function’s `default` | Write `idata` |
   |---|---|---|---|---|
   | 1 | `00` | `10` | `01–0f`, `11–1f` | Register value modulo `2^8` |
   | 2 | `00` | `10` | `02,04,06,08,0a,0c,0e,12,14,16,18,1a,1c,1e` | Modulo `2^16` |
   | 4 | `00` | `10` | `04,08,0c,14,18,1c` | Modulo `2^32` |
   | 8 | `00` | `10` | `08,18` | Full 64-bit value |

   Misaligned ordinary halfword, word and doubleword accesses raise an address exception before the callback, as shown at [cpu_mips_instr_loadstore.c:57](C:/DocumentNoSnc/cc/GXEMUL/GXEMUL-SEC/src/cpus/cpu_mips_instr_loadstore.c:57).

   For bytes `b[0]…b[n−1]`, the exact reconstruction is:

   - BE: `Σ b[i] × 256^(n−1−i)`
   - LE: `Σ b[i] × 256^i`

   Thus the same numeric ordinary store produces the same `idata` in either byte order. Every **read** enters the callback with `idata = 0`; signed-load extension occurs after the callback. An `sb` at `+00` supplies its unsigned byte value as the entire selector, even on BE.

   **Unaligned left/right instructions need a separate enumeration.** [cpu_mips_instr_unaligned.c:44](C:/DocumentNoSnc/cc/GXEMUL/GXEMUL-SEC/src/cpus/cpu_mips_instr_unaligned.c:44) aligns the address down to 4 or 8 bytes. Consequently:

   - Word left/right accesses at `00–03` reach PORT; `10–13` reach DATA.
   - Doubleword left/right accesses at `00–07` reach PORT; `10–17` reach DATA.
   - Loads make one aligned read, with `idata = 0`.
   - Stores first read the aligned register, merge bytes, then make one aligned write of the full width.

   The merge is exact: with byte offset `k` within an `n`-byte aligned word, left stores consume register bytes from byte `n−1` downward; right stores consume bytes from byte 0 upward.

   | Store | Memory byte positions overwritten |
   |---|---|
   | BE left | `k` upward through `n−1` |
   | BE right | `k` downward through 0 |
   | LE left | `k` downward through 0 |
   | LE right | `k` upward through `n−1` |

   Unwritten bytes retain the preceding device-read result. Decoding that merged buffer with the formulas above gives `idata`; the proposed guard still checks the entire result.

   Successful SC/SCD stores use the same 4/8-byte value domains; failed conditional stores make no device write. Coprocessor transfers reuse the load/store machinery.

7. **The RAM counterfactual is wrong, although the device-signature control remains useful.**

   In plain RAM, the described control writes `123` to `base+0x10`, then writes command value `2` to that **same address**. Changing the value at `base+0x00` does not bank ordinary RAM. Its final read therefore returns **2**, not 123.

   A banked register implementation that omitted command execution would retain 123. That is a different counterfactual.

   The real device returns zero because the non-X11 GET_RESOLUTION branch explicitly clears X1 and Y1 at [dev_fbctrl.c:87](C:/DocumentNoSnc/cc/GXEMUL/GXEMUL-SEC/src/devices/dev_fbctrl.c:87). The zero expectation is conditional on `x11_md.in_use == 0`; with X11 it returns the framebuffer dimensions.
