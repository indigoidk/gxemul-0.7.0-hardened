VERDICT: SHIP WITH CHANGES

The changes owed are to the instrument's contract text, not to `dev_fbctrl.c`: the repair's behaviour is unchanged since F2, and on this evidence it is sound. Two clauses of the probe's CATCHES sentence claim coverage the rows do not have.

**1. §6 — the smallest edit (REASONED).** Change the PORT arm's predicate to `else if (idata >= DEV_FBCTRL_NPORTS && idata != 10)`. Enumerating every PORT write from §4b: C{5,1,2,0}, A{0–7}, P{5,7; 8,9,16,0xff,0x100,0xffffffff,0x200000000,0x100000003,0xffffffffffffffff}, R{5,9,0}, K{5,9}, F{9}, V{0–7; 9,16,0x100000003,0xff}, W{5,6; 0,7,8,0x8000000000000000} — 10 is never stored to PORT, so **all 73 rows stay green** (rc=0, CONTROL=OK, 73/73: the base_fix signature). Intended behaviour is broken: `sw 10` is stored, and the next DATA access hits the kept tripwire (10 ≥ 8) and exit(1)s — the pre-#549 process kill survives for one value. This is the header's own NOT CLAIMED (3), and it is not among the 62: §5a's eight rc=0 rows are M_noguard, M_static, N_acc32, N_datard16, N_datawr8, N_order, N_rdmask7, T_D9c_serial1. (`&& idata % 10` is the same disclosed shape in three tokens.)

**2. A second escape genus — NOT disclosed (REASONED; the real defect).** The announce-count rows exist only in P, R and F, and those sample a narrow context: P keeps selector 5 (7 once); R's inter-refusal traffic is one DATA write and a NOP command; F reads only PORT. V and W execute refusals with no count row at all. Hence all three of these pass 73/73 and none is among the 62:
- (a) `if (!d->warned_port || idata == 0x8000000000000000)` — re-announces on the one refused value only W writes; W's buffer would hold 2 announces, no row counts it, and P/R/F never write that value;
- (b) `d->warned_port = 0;` in the DATA arm's read path — the sessions that read DATA after a refusal (K, V) carry no count row, and P/R/F never read DATA between refusals;
- (c) the same statement in the command-2 (GET_RESOLUTION) path — R's only command is NOP, and V's GET_RESOLUTION runs before its first refusal.

Each breaks "announces once per device". (a) falsifies the CATCHES clause "keyed per value" as written (M_perval's kill rests on P's nine distinct values); (b)/(c) falsify "cleared by DATA or command traffic" (R exercises only a DATA write and a NOP). That extra announce lines do not red the disassembly rows is READ from §5a itself: M_latchcnt and M_perval print multiple announces in P and their disassembly rows stay green.

**3. The changes (REASONED).** Minimum: reword those two CATCHES clauses to what is measured and move (a)–(c) into NOT CLAIMED. Recommended closure: three additions — a count row for V, a count row for W, and, in R between its two refusals, a DATA read of port 5 plus a GET_RESOLUTION alongside the NOP (R never touches the X1/Y1 cells, so the zeroing is harmless there; in V it would not be). These add kills without disturbing existing ones (T_X_w8, N_datarearm, T_D4b stay red on their current rows). Consequences either way: rows 73→~76, gate pins, probe md5 and table3 denominators re-stamped.
