### Finding 2: Struct Layout / Off-by-One Phrasing in Probe Contract
* **Citation:** [`regress/fbctrl_port_probe.py:280-282`](file:///C:/DocumentNoSnc/cc/GXEMUL/GXEMUL-SEC/regress/fbctrl_port_probe.py#L280-L282)
* **Claim:** Probe docstring states: `warned_port sits right after port[8], so an index of 8 that got past a broken PORT arm would land on the latch itself`.
* **Evidence:** Look at [`src/devices/dev_fbctrl.c:48-53`](file:///C:/DocumentNoSnc/cc/GXEMUL/GXEMUL-SEC/src/devices/dev_fbctrl.c#L48-L53):
  ```c
  struct fbctrl_data {
      struct vfb_data *vfb_data;
      int     current_port;
      int     port[DEV_FBCTRL_NPORTS]; /* DEV_FBCTRL_NPORTS is 8 */
      int     warned_port;
  };
  ```
  In C, `port[8]` defines an array of 8 integers indexed `0` to `7`. With standard struct layout, `warned_port` immediately follows `port[7]`. Therefore, `&d->port[8] == (int *)&d->warned_port`. Index 8 *is* `warned_port`. It does not sit "right after `port[8]`" (which would be offset `sizeof(int) * 9`, or index 9).
* **Impact:** Section 0 (line 20) correctly says: `port[8] (which, after this diff's struct change, is the warned_port latch)`. The probe header sentence is self-contradictory ("sits right after `port[8]`" vs "an index of 8 ... would land on the latch itself"). Change `sits right after port[8]` to `sits right after port[7] (aliasing port[8])`.
