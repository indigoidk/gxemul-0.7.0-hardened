**The single defect I would raise against the packet itself:**

The enumeration in §4a's CONTRACT lists, for "the first refusal announces once, the rest are silent", the value-named axis only as "the value named: 0x8 (P), 0x9 (F), the wide 0x100000003 (X3)". That is the VALUE-OF-THE-FIRST-REFUSAL axis (which the announce must print), not the CONDITION-ON-IDATA axis (which gates whether the announce fires). The latter is the axis my threshold edit lives on, and it is not enumerated. The closing pass's own rule says one-axis cells must each be held by some row; for the predicate `if (!warned_port && idata < K)` with K above every first-refusal value, no row holds the cell that would catch it, because no first-refusal value trips the conjunct. Adding one row whose first refusal is a value ≥ 0x200000000 (e.g., a fresh device X8 refusing 0x200000000 by sd after PORT=5) would close this. Without it, the disclosure's class-level claim ("no finite row set closes value-conditioned edits") is true, but the probe does not demonstrate it for the threshold form.
