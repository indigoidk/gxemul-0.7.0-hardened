**9. Question 2 — is B's aggregate enough?** REASONED. B reads PORT once per width, after all refusals of that width. A narrowing that lets through *only* later values (e.g., bit 5 ignored: 8 refused, 16 becomes 0 accepted, but for sb 8 is the first refusal and 16 is the second; with bit 5 ignored 8→0 accepted, so the first refusal leaks and the row fails). For a narrowing that lets through *only* early values (e.g., bit 63 ignored: 2^63 becomes 0 accepted, but for sd the last refusal is 2^63; the first refusal 8 is unaffected, so the latch announces once and the count row passes, but PORT reads 0 at the sd width — the sd row fails). B catches any narrowing that lets *any* single-bit value through at *any* width, because each width's row reads after all of that width's refusals and a leaked value persists. A joint width-and-bit edit (e.g., refuse bit 5 only by sw) would not be caught by B alone — but the one-width narrowings (MKW_*) measure exactly that. The two together cover the joint space. ✓
