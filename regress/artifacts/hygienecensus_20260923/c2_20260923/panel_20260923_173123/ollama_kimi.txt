## The blocker (REASONED from the inlined deriver)

- `printf '%s' "$RULING" | grep -qE '^[0-9]{4}-[0-9]{2}-[0-9]{2}: .{16,}$'` — grep splits its input on newlines, so a multi-line ruling passes if ANY line matches. The `case` guard's charter is `"` `\` `$` `` ` `` — no newline, no `#`. REASONED and checked against the inlined code twice.
- Consequence path: `note = "#  RULING %s -- %s (tools/...)\n" % (ruling, need.strip())` is inserted verbatim by `re.subn` above each moved pin. Trailing NEED text always contains parens, so an *accidental* multiline paste kills the gate loudly (syntax error — fail-safe), but a `#`-terminated second line is valid shell and silent: executes each run AND swallows the warrant. Reachable only by whoever runs `--write --ruling` — i.e., self-inflicted or pasted-from-chat — which is exactly the record-integrity threat this round exists to close.
