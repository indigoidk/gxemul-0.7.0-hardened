### Q1 — Does the F3 repair do what it claims?

**(a) NEWLINE kept — legitimate calls lost?**  
REASONED. Python grammar forbids a line break between `.` and the method name without a backslash. Bracket‑splitting or backslash continuation does not insert a NEWLINE token between `.` and the NAME. The triple `d.string == "."`, `a.string == ENDS_WITH`, `b.string == "("` remains contiguous for any valid method call. No legitimate readiness call is lost.

**(b) `.` required — legitimate calls lost?**  
REASONED. An unbound `str.endswith(s, "GXemul>")` is still a method call (tokens `str` `.` `endswith` `(`) and is recognized. A `getattr(buf, "endswith")("GXemul>")` form has no NAME token `endswith`, so the classifier fails closed: the probe becomes promptless and the names row reds. Acceptable.

**(c) Ruling checks — non‑comment line or blank warrant?**  
REASONED. The ruling check rejects any control character (`*[[:cntrl:]]*`), quotes, backslashes, `$`, backticks, and requires ≥16 non‑blank characters. A newline cannot carry live shell; a blank or malformed warrant is refused before `--write`.

**(d) Name checks and exact release**  
REASONED. The case pattern `*[[:space:]]*|*'*'*|*'?'*|*'['*` refuses names with whitespace or common glob characters (`*`, `?`, `[`). `--release` now removes names by word (split‑line), so `foo.py` inside `pref-foo.py` survives. No name the list can hold is wrongly refused or accepted.
