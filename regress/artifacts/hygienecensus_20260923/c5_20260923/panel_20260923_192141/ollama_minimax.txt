## Q1 -- do the F5 checks refuse exactly what they say?

**(a) Every input, byte-exact?**

Three inputs are listed: the ruling text, the name arguments, the tree's file names (via the census). I see no fourth.

**(c) The anchored writer and the reader:**

## Q2 -- smallest input/tree state that gets past F5 and does harm

1. **A whole-full file named with `:`** (e.g., `foo:bar.py`): passes M6's allow-list, lands as `foo:bar.py:N` in `WHOLE_FULL_FILES`. Under `%%:*` / `##*:` split, name = `foo`, count = `N`; the `bar.py` half is lost. Latent until such a file exists; the F5 check does not prevent it.

Denominator for (1): zero current whole-full files with `:` (presumed; not enumerated in the packet). Denominator for (3): ruling validation is form, not content -- the header's "printable ASCII only" is the only place that line is written.
