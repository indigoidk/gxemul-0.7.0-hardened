## Q3 -- F6b/F6d's shim and `astcall` under REAL use

**Shim** (`python3() { command "$PY" "$@" | tr -d '\r'; }`):
- Under WSL: PY=python3; `command python3` bypasses the function and calls the external binary. The pipe's status is `tr`'s, which is the defect N16 names -- fixed by adding `command "$PY"` in F6d's pywrite.
- Under git-bash: PY=python (the fallback after the Store stub fails); there is no function named `python`, so `command python` is a no-op bypass. The `tr -d '\r'` strips the CRLF the fallback writes.
- Heredoc + MSYS: the canary heredoc is `<<'PY'` (quoted), so no expansion. Under MSYS argument conversion, `"$_cd/zz_canary_call.py"` is a single quoted argument; `$_cd` is a `mktemp -d` path that MSYS leaves alone (it does not start with `/c/` after `mktemp -d`).
- CRLF in the heredoc body: impossible (the heredoc is literal).
- A probe that does not parse: `ast.parse` raises, `sys.exit(2)`. The grandfather check refuses (rc != 1); the release check refuses (rc != 0) with message "the parser finds no readiness call in it (rc 2): it is still promptless" -- **the message is misleading** (it says "no readiness call" when the real reason is "cannot parse"), but the refusal is correct.
- A probe deleted from the tree: `--release`'s `if [ -e "$HERE/$f" ]` guard skips astcall and proceeds. Correct.

**`astcall`**: `command "$PY" - "$1" <<'PY' ... PY`. Reads `sys.argv[1]` with `encoding="utf-8"`. Under git-bash, if the probe file is CRLF, Python's text mode (default `newline=None`) translates to LF before `ast.parse` sees it. Correct under both shells.
