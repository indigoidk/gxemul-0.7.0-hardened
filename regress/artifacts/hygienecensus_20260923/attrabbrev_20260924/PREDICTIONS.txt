THE DEFECT.  tools/pipeline/check_commit_attribution.py (precommit section L) reads `git log --format=%h` and tests
`h in commits` (exact list membership) and `h in reopened` (substring).  The ledger's commits/reopened fields hold
the 7-character abbreviation git printed when each row closed.  After #545 (4264ee20) git's automatic abbreviation
grew to 8 characters (`git log -1 --format=%h` -> 4264ee20; with core.abbrev=7 -> 4264ee2), so neither test can
match any 7-character ledger sha and the #546 commit attempt hard-failed section L on six rows the ledger attributes
correctly.  Section F's receipt check already matches by PREFIX for the same reason (precommit_check.sh, its
"PREFIX match, not equality" comment).

THE FIX.  Read %H beside %h and test whether a 7-40 character hex token in the field is a PREFIX of the full hash;
display keeps %h.

4264ee2 under it, 4264ee20 without it).  Ledger = the working ledger unless stated.
