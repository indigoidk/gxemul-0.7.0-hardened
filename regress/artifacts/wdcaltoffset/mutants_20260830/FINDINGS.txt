TABLE B -- the READ side IS cheaply witnessable                           (TABLE_B.txt)
----------------------------------------------------------------------------------------------
No datasheet is required.  status_byte() in dev_wdc.c reads d->drive, the ring pointers,
write_in_progress, d->error and the atapi fields -- IT NEVER READS d->head.  A Drive
Address Register is by definition a function of the head select.  So the two registers are
separated by an INVARIANCE, with no numeric expectation anywhere:

      read 0x3f6 head=0    51        read 0x3f7 head=0     51     D1  byte-identical
      read 0x3f7 head=15   51        SDH readback  af             D2  invariant under head
      read 0x3f7 DRQ set   58        read 0x3f6 DRQ set    58     D3  tracks the status reg

  L1 (SDH reads back 0xaf) proves the head write LANDED, so D2's invariance is not a store
  that never happened; L2 (0x3f6 unchanged by the head write) proves it is not merely that
  nothing in the device moved.

  => "the read side is unwitnessed" was true; "unwitnessable without hardware documentation"
     is FALSE.  Three rows, one rig, no manual.

----------------------------------------------------------------------------------------------
  * NO guest exception, NO halt, the write is DROPPED and the guest parks normally.
  * every access emits `[ memory WRITE: to non-existant paddr=0x00000000180003f7 len=1
    pc=... ]` -- measured 2 writes -> 2 messages (Table A) and 3 reads -> 3 messages
    (Table B), so there is NO latch and NO counter.  memory_warn_about_unimplemented_addr
    (src/core/memory.c) has only a `paddr < physical_max + 0x40000` early-out.
  * a READ of 0x3f7 then returns 0x00, not the alt status -- a different wrong answer,

  * under `-T` (halt_on_nonexistant_memaccess, src/core/main.c:466) the SAME access takes
    the verbosity to ERROR, sets running = 0 on EVERY cpu and returns MEMORY_ACCESS_FAILED.

  => narrowing is safe for the guest and NOT free: it trades a silent corruption for an
     UNBOUNDED, UNLATCHED, guest-drivable WARNING flood at default verbosity, plus a hard
     emulator stop under -T.  That is the floodclass shape, and it argues for decoding the
     offset rather than narrowing the region.

arm (867c697^, dev_wdc.c:497-498) is:
