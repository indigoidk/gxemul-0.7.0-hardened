**Q1 — Premise 6, attacked**

REASONED. Three layers:

(a) *Internal contradiction.* P2 says `ioc_conf` is consumed: `bus = d->ioc_conf & 1` drives PCI bus selection. CONF's guard condition is `idata & ~1`, so every rejected value has bit 0 equal to the opposite of some accepted value. Concrete case, from the packet's own #506 example: guest writes `0x2` — under A, `ioc_conf = 2` lands, `bus = 0`, PCI routing flips, readback returns `0x2`. The model has now *acted* on a value the implementation explicitly disclaims. That is RCR1's shape: stored state diverges from honored state. Premise 6 ("the model implements window translation for NO value") covers at most the four window registers plus `tlb_enable`. It cannot carry CONF, and A is specified "from all six."

(b) *The sound restatement.* For the five pure-storage arms, the argument works, but the "the lie is pre-existing and value-independent" version is the weak version — as the author suspects, it proves too much (it would license keeping every store before every guard in any partially-implemented device). The strong version, using the tree's own taxonomy from the inlined #447 census: RCR1's danger criterion is divergence between stored state and *state the model otherwise honors*. ICR's cell is "no state to corrupt." The five arms sit in a cell the census doesn't name — stored, readback-able, never consumed — but the corruption criterion is vacuous there because honored state is the empty set. The consumer test is the firewall that keeps the reasoning from generalizing; any formulation that skips per-field consumer counts is the unsound one.

(c) *Even where sound, it licenses less than A claims.* A specifies "nothing else changes — no mask, no default, no new state." The argument above licenses dropping the host-kill; it does not license dropping the announcement. The guard's values are not "implemented values" (P2: nothing is implemented) — they are values *observed from real guest traffic*, which is what a tripwire guarding an untested envelope looks like. Deleting it silently converts "untested divergence → host stops" into "untested divergence → invisible." The same logic supports A-plus-announce, which is identical in guest-visible state and strictly better on signal.

**Q2 — A or B?**

REASONED (decidable from the packet *if* P2 is taken as given; the one fact that decides it locally is whether any rejected value reaches an honored consumer — and the one packet-unverifiable fact behind *that* is the `bus = d->ioc_conf & 1` consumer in `lca_pci_conf`, named above).

- **CONF: B, or mask-and-accept.** Rejected values drive a live consumer (bit 0). This is the RCR1 cell; #447 already wrote this project's answer.
- **The five: A-plus-announce.** B is dominated. B's only benefit is envelope-signaling, which an announce provides without cost; B's cost is that readback stops being truthful about the register file — and B does **not** remove the lie the author worries about: write `0x700000`, read `0x700000`, window inactive — that survives B unchanged. Only IMPLEMENT removes it. The inlined `W_T_BASE0/1` siblings (READ: store, TODO, no guard) already behave as A would make all eight behave: store any value, return it, no effect. That is the faithful partial model of registers whose function is unimplemented. The author's stated cost of B is real and is the deciding asymmetry: write X / read back old-value is a brand-new observable that no hardware exhibits, whereas A's "register truthful, effect absent" is what partially-implemented hardware actually looks like.

The fork as posed — A-uniform vs B-uniform — is a false dichotomy for this file. The brief quotes the census line "Check it per site" and then asks for one answer per file.

**Q3 — Option set**

Nothing is "obviously right" as a single uniform answer; the per-arm split in Q2 is the recommendation. The once-only latched announce costs new state (one flag bitmask in `struct lca_data`) — A's "no new state" is a self-imposed constraint, not a property of the code.
