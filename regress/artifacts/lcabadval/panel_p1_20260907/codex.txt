The six, with the value each accepts:

Codex confirmed store-before-guard in **all six**, with a per-arm table of readback/store/guard
lines. This is not a generalisation from one arm.

**2. Five of the six fields are PURE STORAGE; `ioc_conf` has exactly ONE functional consumer.**
I re-verified this over the whole tree and the counts are decisive -- each field occurs exactly
three times (declaration, readback, store):

    window_base_0  3    window_mask_0  3    tlb_enable  3
    window_base_1  3    window_mask_1  3    ioc_conf    4

`ioc_conf`'s fourth occurrence is `bus = d->ioc_conf & 1;` in `DEVICE_ACCESS(lca_pci_conf)`.
**There is NO DMA-translation consumer anywhere in the tree** -- nothing reads a window base or
mask to translate an address. The window registers are write-to-nowhere plus a readback.

**3. Codex's sharpening of my own wording, which I had blurred.** Extra CONF bits are discarded
*for bus selection*, but **the IOC readback returns the STORED value**. So masking the store would
not merely be an unlicensed addition -- it would change READBACK POLICY, which is guest-visible.

**4. `fatal()` does NOT terminate.** It calls the returning printer `va_debug()`; the explicit
`exit(1)` ends the process. `debug()` additionally applies verbosity filtering and can be silenced
by `-q`; `fatal()` cannot.

And the RCR1 arm's own comment:

```
 *  #447: *** THE STORE WAS UPSTREAM OF THE GUARD. ***  It ran first and the guard second,
```

A third site says it from the other direction -- DMATCR's comment notes its store is downstream
*"unlike RCR1 and unlike every arm of `dev_sh4_pcic_access()`, where the store runs first and a

**So the tree holds two precedents where store-runs-first means the fix is NOT "just drop the
exit": RCR1 MOVED THE STORE BELOW THE GUARD, and `#443` ADDED A RESTORE.**

**6. MY ARGUMENT THAT LCA IS NEVERTHELESS DIFFERENT -- ATTACK THIS.**

RCR1's stored value has a meaning the model otherwise honours: for accepted values the model acts
on `rtc_rcr1`, so reading back `CIE|AIE` tells the guest something specific and false.

I claim LCA is not like that, because **the model implements window translation for NO value at
all**. If that is right then:

* the guest ALREADY writes `0x700000`, reads `0x700000` back, and believes the window is
  programmed -- and it is not, because nothing consumes it;
* so the silent state corruption `#447` warns about is **PRE-EXISTING and VALUE-INDEPENDENT**;
* removing `exit(1)` therefore does not CREATE a false belief. It stops killing the host over one
  wrong value while continuing to tell the same lie about the accepted one.

**Is that sound, or am I excusing a new instance of a defect because an old instance already
exists?** I can see the shape of the counter-argument and cannot tell how strong it is.

    B  DECLINE the write: move the store BELOW the guard, exactly as #447 did for RCR1, so a

The sibling registers `LCA_IOC_W_T_BASE0` and `LCA_IOC_W_T_BASE1` -- the TRANSLATED-window

**A cost of B I want weighed:** real hardware reads back what was written. B makes the readback lie
in a DIFFERENT way -- write `X`, read back the old value -- which no hardware does. A keeps the
readback truthful about the register file and false about the window being active.

	if (writeflag == MEM_WRITE)
		idata = memory_readmax64(cpu, data, len);

	/*
	 *  1. Decompose the address into a tag.
	 *
	 *  According to NetBSD's lca_pci.c, the address is composed like this:
	 *
	 *	addr = tag << 5 | (regoffset & ~0x03) << 5 | 0x3 << 3
	 */
	reg = (relative_addr >> 5) & 0xfc;
	tag = (relative_addr >> 5) & ~0xff;

	/*
	 *  2. Decompose the tag into bus, dev, and func.
	 *
	 *  The tag can be constructed in one of two ways. On the primary
	 *  bus (nr 0):
	 *
	 *	tag = (1 << (device + 11)) | (function << 8);
	 *
	 *  and on other busses, the tag is a normal:
	 *
	 *	tag = (bus << 16) | (device << 11) | (function << 8)
	 */
	/*  printf("tag = 0x%x\n", (int)tag);  */
	bus = d->ioc_conf & 1;

	if (bus == 0) {
		for (dev=0; dev<21; dev++)
			if (tag & (0x800 << dev))
				break;
		if (dev >= 21) {
			/*  fatal("[ LCA: No bus 0 device? TODO ]\n");
			exit(1);  */
			dev = 0;
		}
	} else {
		fatal("TODO. Non-zero bus.\n");
		exit(1);
	}

	func = (tag >> 8) & 7;
	/*  printf("bus=%i dev=%i func=%i reg=%i\n", bus,dev,func,reg);  */

	/*  Pass PCI accesses onto bus_pci:  */
	bus_pci_setaddr(cpu, d->pci_data, bus, dev, func, reg);
	bus_pci_data_access(cpu, d->pci_data, writeflag == MEM_READ?
	    &odata : &idata, len, writeflag);

	if (writeflag == MEM_READ)
		memory_writemax64(cpu, data, len, odata);

	return 1;
}


DEVICE_ACCESS(lca_isa)
{
	unsigned int ofs, i;
	uint8_t byte;

	relative_addr >>= 5;

	ofs = relative_addr & 3;
	if (ofs > len) {
		fatal("[ ofs=%i len=%i in lca_isa access function. "
		    "aborting ]\n", ofs, len);
		exit(1);
	}

	if (writeflag == MEM_WRITE) {
		byte = data[ofs % len];
		return cpu->memory_rw(cpu, cpu->mem, LCA_ISA_BASE +
		    relative_addr, &byte, 1, writeflag, CACHE_NONE);
	}

	cpu->memory_rw(cpu, cpu->mem, LCA_ISA_BASE + relative_addr,
	    &byte, 1, MEM_READ, CACHE_NONE);

	for (i=0; i<len; i++)
		data[i] = i == ofs? byte : 0x00;

	return 1;
}

		    no other machines/OSes don't need this.  */

	}

	if (access_style == MC146818_DEC) {
		/*  Station Ethernet Address, on DECstation 3100:  */

			ether_address[i] = 0x10 * (i+1);

		d->reg[0x01] = ether_address[0];
		d->reg[0x05] = ether_address[1];

		d->reg[0x0d] = ether_address[3];
		d->reg[0x11] = ether_address[4];

		d->reg[0x29] = ether_address[5];
		d->reg[0x2d] = ether_address[4];
		d->reg[0x31] = ether_address[3];

		d->reg[0x39] = ether_address[1];
		d->reg[0x3d] = ether_address[1];
		d->reg[0x41] = ether_address[0];
		d->reg[0x45] = ether_address[1];
		d->reg[0x49] = ether_address[2];
		d->reg[0x4d] = ether_address[3];
		d->reg[0x51] = ether_address[4];
		d->reg[0x55] = ether_address[5];
		/*  TODO:  59, 5d = checksum bytes 1,2 resp. */
		d->reg[0x61] = 0xff;
		d->reg[0x65] = 0x00;
		d->reg[0x69] = 0x55;
		d->reg[0x6d] = 0xaa;
		d->reg[0x71] = 0xff;
		d->reg[0x75] = 0x00;
		d->reg[0x79] = 0x55;
		d->reg[0x7d] = 0xaa;

		/*  Battery valid, for DECstations  */
		d->reg[0xf8] = 1;
	}

	/*
	 *  uip_threshold should ideally be 1, but when Linux polls the UIP bit
	 *  it looses speed. This hack gives Linux the impression that the cpu
	 *  is uip_threshold times faster than the slow clock it would
	 *  otherwise detect.
	 *
	 *  TODO:  Find out if this messes up Sprite emulation; if so, then
	 *         this hack has to be removed.
	 */
	d->uip_threshold = 8;

	if (access_style == MC146818_ARC_JAZZ)
		memory_device_register(mem, "mc146818_jazz", 0x90000070ULL,
		    1, dev_mc146818_jazz_access, d, DM_DEFAULT, NULL);

	dev_len = DEV_MC146818_LENGTH;
	switch (access_style) {
	case MC146818_CATS:
	case MC146818_PC_CMOS:
		dev_len = 2;
		break;
	case MC146818_SGI:
		dev_len = 0x400;
	}

	memory_device_register(mem, "mc146818", baseaddr,
	    dev_len * addrdiv, dev_mc146818_access,
	    d, DM_DEFAULT, NULL);

	mc146818_update_time(d);

	machine_add_tickfunction(machine, dev_mc146818_tick, d,
	    MC146818_TICK_SHIFT);
}

int dev_pckbc_init(struct machine *machine, struct memory *mem,
	uint64_t baseaddr, int type, char *keyboard_irqpath,
	char *mouse_irqpath, int in_use, int pc_style_flag)
{
	struct pckbc_data *d;
	int len = DEV_PCKBC_LENGTH;

	CHECK_ALLOCATION(d = (struct pckbc_data *) malloc(sizeof(struct pckbc_data)));
	memset(d, 0, sizeof(struct pckbc_data));

	d->translation_table = 2;

	if (type == PCKBC_8242) {
		len = 0x40;
		d->translation_table = 3;
	}
	
	if (type == PCKBC_JAZZ) {
		type = PCKBC_8042;
		len = DEV_PCKBC_LENGTH + 0x60;
	}

	INTERRUPT_CONNECT(keyboard_irqpath, d->irq_keyboard);
	INTERRUPT_CONNECT(mouse_irqpath, d->irq_mouse);

	d->type              = type;
	d->in_use            = in_use;
	d->pc_style_flag     = pc_style_flag;
	d->rx_int_enable[0]  = 1;
	d->rx_int_enable[1]  = 0;
	d->output_byte       = 0x02;	/*  A20 enable on PCs  */

	// Default is ENABLE keyboard but DISABLE mouse port:
	d->scanning_enabled[0] = 1;
	d->scanning_enabled[1] = 0;

	d->console_handle = console_start_slave_inputonly(
	    machine, "pckbc", d->in_use);

	memory_device_register(mem, "pckbc", baseaddr,
	    len, dev_pckbc_access, d, DM_DEFAULT, NULL);
	machine_add_tickfunction(machine, dev_pckbc_tick, d,
	    PCKBC_TICKSHIFT);

	return d->console_handle;
}

   The strongest counterargument to A is this: **a guest is itself a consumer of readback.** Previously, a rejected write ended execution before subsequent guest code could observe that value. A creates that observation and allows the guest to make further decisions from it. Existing incomplete behavior for accepted settings does not establish that these newly admitted executions are equally harmless.

   There are two further gaps:

   - No field reads rules out translation *controlled by those fields*. It does not, by itself, exclude fixed address handling that happens to agree with particular settings. My targeted checks did not establish such an implicit implementation.

   The defensible distinction is narrower: five LCA fields have no direct device-side effects beyond readback. That limits one kind of risk; it does not prove value-independent behavior.

2. **B for this pass. The deciding fact: A expands the register values observable by a continuing guest.**

   B avoids that expansion while removing the six process exits. That fits the project’s stated rejection policy. Both choices introduce continuation where execution previously terminated; B is therefore a deliberate recovery policy, not preservation of an already implemented successful transaction.

   **Hardware fidelity cannot be settled from this packet.** The single missing reference is the 21066/LCA specification’s write and readback semantics for these six registers, including valid configurations outside the emulator’s accepted set and reserved bits. The assertion that hardware necessarily echoes every written value is not established here.

   Also, `IOC_CONF` needs its own justification: it has a functional consumer. A can change its bus-selection bit during a write that B declines entirely. The window argument does not cover that difference.

   For B, moving the assignment textually below the guard is insufficient unless rejection actually skips it. Preserve the enclosing switch’s common tail. B still returns successful completion for an ignored write; it does not deliver a guest-visible error.

3. **The option set misses controlled guest stopping and deferred validation.**

   Additional choices include:

   - Stop or pause the affected emulated machine while retaining the host process.
   - Accept register programming, then reject an operation when it actually requires unsupported translation.
   - Apply different policies to different registers or fields.

   These are design alternatives, not claims that suitable helpers already exist here. Controlled stopping is particularly relevant if host survival is required but continuing with unsupported behavior is unacceptable. Deferred validation requires an actual consumer and failure path.

   Announcement policy is a separate decision from acceptance policy. A bounded, latched diagnostic can accompany either A or B; it does not make either semantically correct.

   Nothing makes masking, an invented status error, or an unmapped-space fault automatically correct here. WDC’s command-abort protocol does not establish an LCA register-write error protocol. **Beyond the packet’s code excerpt:** the failed-device branch in `MEMORY_RW_ONE_PAGE`, [memory_rw.c](C:/DocumentNoSnc/CC/GXEMUL/GXEMUL-SEC/src/cpus/memory_rw.c:603), confirms the cited MIPS/M88K exception handling and absence of an Alpha equivalent there.
