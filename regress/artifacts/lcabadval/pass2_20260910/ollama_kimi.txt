**Q1(a) — the field rule. REASONED (enumerated).**
`(f & (f+1)) == 0` accepts exactly f ∈ {0,1,3,7,15,31,63,127,255,511,1023,2047,4095}. Check: if f = 2^k−1 then f+1 = 2^k and f & 2^k = 0; conversely f & (f+1) clears f's trailing ones and keeps the rest, so a zero result forces f to be all trailing ones, i.e. 2^k−1. Over 12 bits k = 0..12 → exactly 13 values; k=13 (8191) is out of range. f = 0xfff corner: f+1 = 0x1000 computed in uint64, no wrap, passes. So the predicate is **exactly** the thirteen contiguous-low-ones encodings — *conditional on S2's claim that Table 6-6's thirteen values are those* (manual not in packet; taken as stated).
Caveat the brief did not state: the extraction `v = idata & 0xfff00000` silently drops idata bits <63:32> and <19:0>, so the accepted *input* class is larger than thirteen values — correctness of that depends on the RES type of W_MASK's non-field bits. Not settleable from packet. Single fact that settles it: the HRM's type for W_MASK bits outside <31:20> (if type X, the normalization is right).

**Q1(b) — IOC_CONF & 0x3 vs lca_pci_conf. REASONED.** (idata & 0x3) & 1 ≡ idata & 1, so bit 0 — the claimed consumer — is identical for every input. For the old accepted set {0,1} (S1, verified against the old predicate `idata & ~1`) the stored value is unchanged. Whether *any other* site reads d->ioc_conf above bit 0: not settleable from packet (the consumer list of `d->ioc_conf` is the named fact), but moot for regressions since old code killed the process on any value ≥ 2.

**Q1(c) — 0x240000000 WEN-set. REASONED (enumerated).** 0x240000000 = 0x200000000 | 0x40000000 = bits {33, 30}. Bit 33 = WEN per S2/Figure 6-9 ✓; bit 30 ∈ <31:20> ✓, so it round-trips the store mask (0x3fff00000) intact → `wbase1 wen` want of 0x240000000 is consistent. `wen once`'s other write, 0x280000000 = bits {33, 31}, also has WEN ✓, so D4 really does issue two WEN writes. One dependency: the numeric values of IOC_W_BASE_W_BASE/SG/WEN are not inlined; bit *positions* are (S2), and the detector's reported round-trips are internally consistent with mask = 0x3fff00000.

**Q1(d) — +0x1e0 and the default arm. REASONED from packet-internal evidence; raw fact not checkable.** I cannot see DEVINIT's window bounds or alpha_lcareg.h. **Q2 — smallest breaking edit that passes all 40.**
**M20_def_echo itself** — e.g. one line in the default arm making a read return the written/last value. Every row stays green, specifically **`def read0` stays green**, and here is the mechanism (REASONED, walking `seq`): `seq` emits `step n; print t3` after *every* phase. D5's phases are `[[st, st], [ld]]` — phase 0 contains **no load**, so `vals[0]` is the print of t3 in its reset/stale state (0x0 on the fix build — the reported 40/40 proves the stale value matches want "0x0"), and `vals[1]`, the actual read-back, **is consumed by no row**. `def read0` reads `nth(vals, 0)`. This is precisely the vacuity PRETABLE §4 claims to have excluded ("no row's channel is fixed under its named mutant") — they caught the same shape for `wbase1 stored` and missed it here. Consequence: Table 1's M20 cell will record a spurious "survived". One-line repair: `nth(vals, 1)`, or give D5 phase 0 a trailing `ld`. Single measurement I'd want but cannot take: run M20_def_echo against the probe and watch `def read0` stay green (or just dump `vals` for the D5 session).
Three further one-edit all-green mutants (cells the enumeration does not contain): **remove the DEF_R latch guard** (D5 performs only ONE read, so removing the read latch still announces exactly once — `def r once` pins *shared*, not *removed*); **drop IOC_W_BASE_SG from both W_BASE masks** (every read-back constant in the detector — 0x280000000, 0x240000000, 0x0 — has bit 32 clear; the only SG-carrying write, accepted-first 0x300800000, is overwritten before any read); **widen the conf mask** (e.g. `& 0xffffffff`: the only out-of-field bit any conf row writes is bit 32 of 0x100000002, which any ≤32-bit mask drops anyway → all conf rows green — "widened" sits between their {narrowed, dropped} cells and is unnamed).

**Q4 — the floor: cells with no channel-varying row. REASONED.**
Not "none". In the author's framing (6 arms × {kept/narrowed/dropped} × {store/no-store} = 36; W_MASK rule {kept/weak/strong} × {order} for two arms ≈ 12; latches {kept/removed/shared} × 6 bits = 18; ~66 cells), the cells with no varying row:

3. **W_BASE mask {SG-dropped}** — no read-back constant exercises bit 32 (above). M11 pins WEN, M12 pins truncation to 32 bits; the SG-only drop is a distinct unnamed cell.
4. **conf mask {widened, bits 2–31 kept}** — no conf write carries bits 31:2 (above); unnamed by the {kept/narrowed/dropped} trio.
5. **cross-arm latch sharing** (conf↔wen, mask↔wen, def↔wen, …): `wmask1 indep` and `def r once` arm a sibling's bit first *within* a pair; no session arms a third party's bit before the firing write, and D3/D4/D5 are separate sessions. A one-#define collision (e.g. CFG1 == WEN bit) survives.
