The crucial distinction is that **the predicates govern writes, not all possible stored states**:

- Initialization assigns zero without evaluating a guard.
- Reads return the stored value without evaluating a guard.
- Writes assign the new value **before** evaluating the guard.

Consequently, the current model can return zero at reset while refusing a subsequent write of zero. That asymmetry is established; it is not a logical contradiction.

Under reconstructed B, reset is zero and each write replaces the stored value. Under C, reset is zero and a declined write leaves that zero unchanged. Both are well-defined. For C, the correct description is **“previous value,”** not “last accepted value,” because initially there has been no accepted write.

Reset alone does not establish that the guard misstates hardware behavior. There is additional local evidence against interpreting it as hardware validity: the header explicitly names zero as `IOC_W_MASK_1M`. That demonstrates a declared encoding beyond the mask guards’ accepted values; it does not establish complete register semantics. [Window-mask definitions](C:/DocumentNoSnc/CC/GXEMUL/GXEMUL-SEC/src/include/thirdparty/alpha_lcareg.h:85).

[Base handling](C:/DocumentNoSnc/CC/GXEMUL/GXEMUL-SEC/src/devices/dev_lca.c:225), [translation-base handling](C:/DocumentNoSnc/CC/GXEMUL/GXEMUL-SEC/src/devices/dev_lca.c:303), [default and common return](C:/DocumentNoSnc/CC/GXEMUL/GXEMUL-SEC/src/devices/dev_lca.c:351).

Thus the sibling evidence supports **both** discarding writes and retaining shadow state. It does not select a universal policy.

C applies discard behavior conditionally: accepted writes keep their existing behavior; out-of-set writes preserve prior state. That requires moving each store behind its guard, as RCR1 does. I prefer it for the narrow repair because it preserves existing successful accesses without extending storage acceptance to every value. The old whitelist’s correctness remains open.

Changing `default:` would require a separate decision: it has no previous register value to preserve. Removing its exit would leave zero reads and discarded writes, alongside its diagnostics.
