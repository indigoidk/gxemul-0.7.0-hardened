At committed HEAD `3c36526`, #518 is justified, but **P1 and P4 describe repaired history**, and the shipped disposition combines acceptance with decline. References below use committed source, not the working copy.

- **P1 — Refuted at HEAD; historically real.** Both interrupt callbacks now announce once per instance and return (#516, `74daefd`). The ISA PIC wiring remains. Historically, an interrupt reaching either callback could confound an exit-status oracle; “ANY interrupt” overstates this because PIC masking affects delivery. Arm-specific text identifies the path, but text alone cannot establish termination: `fatal()` prints and returns (`src/core/debugmsg.c:384`). Current checks need continuation/state evidence, and warning suppression must be accounted for.
- **P2 — Confirmed: six historical value-guarded arms.** CONF, TB_ENA, W_BASE0, W_BASE1, W_MASK0, W_MASK1. The translated-base registers and IOC default arm are separate cases.
- **P3 — Confirmed for the existing failed-device-access mechanism.** `src/cpus/memory_rw.c:603` invokes guest exceptions only under `MEM_MIPS` and `MEM_M88K`, then returns `MEMORY_ACCESS_FAILED`. Returning failure from this device does **not** deliver an Alpha bus error. ACCEPT/DECLINE are available local dispositions; IMPLEMENT remains possible with additional architecture support. This is an emulator limitation, not an Alpha hardware limitation.
- **P4 — Historically true, already fixed.** #506 (`7a41b3f`) replaced the narrowing `%x`/`(int)idata` diagnostic before #518. HEAD’s announcement helper uses `PRIx64` (`dev_lca.c:322`). The old defect undermined numeric-value matching, while the arm-specific message still identified the arm.

Widening was correct, but **unconditional acceptance is not the rule for all six arms**. The manual supports thirteen mask encodings, requires initialization of both window bases to zero, and specifies that type-X fields ignore writes. [DEC hardware reference manual, conventions and §§6.3.2, 6.4.14](https://openwatcom.org/ftp/devel/docs/21066_66a_hrm.pdf).

|---|---|
| CONF | Stores `idata & 3`; announces once when bit 1 is set. |
| TB_ENA | Stores only TEN, bit 7. |
| W_BASE0 | Stores base bits 31:20, SG and WEN; announces unmodelled translation when enabled. |
| W_BASE1 | Same, including acceptance of zero. Both bases share the WEN warning reason. |
| W_MASK0 | Stores a valid masked field; otherwise preserves the previous register and announces once. |
| W_MASK1 | Same, with its own warning latch. |

For both masks, `f = (idata & 0xfff00000) >> 20`, and acceptance requires `(f & (f + 1)) == 0`. That admits exactly `2ⁿ−1` for `n = 0…12`. I checked all 4,096 field encodings arithmetically: exactly thirteen pass.

Thus an **unsupported mask encoding is already declined today**: the previous register survives, the first occurrence is announced, and the device callback returns success (`dev_lca.c:503`). Subsequent occurrences remain declined silently. Reserved-bit writes are masked away. The manual calls the other mask encodings *unsupported*; preserving the previous value is the emulator’s chosen disposition, not a specified hardware fault response.

What remains owed:

- **CONF bit-1 handling needs a downstream disposition.** The register stores both bits, but `lca_pci_conf` uses only `d->ioc_conf & 1` (`dev_lca.c:195`). Consequently, encodings `10/11` follow the ordinary type-0/type-1 decoding paths. The announcement does not prevent PCI backend access. This needs explicit unsupported-cycle handling before claiming those configurations are declined.
- **Interrupt delivery remains an IMPLEMENT task.** Alpha’s pending flag has setters but no delivery consumer; dyntrans lacks the Alpha dispatch path. Forwarding the callbacks alone would accomplish nothing. Pending-state handling, IPL checks and PAL entry remain subsystem work. Removing these callbacks’ host exits is already complete.
- **DMA/window and TLB behavior remains unimplemented.** Stored register values do not establish working translation; TBIA and translated-base behavior also remain placeholders. Additionally, HEAD does not enforce the manual’s window-alignment and nonoverlap requirements. Those are configuration relationships, requiring a policy that accommodates register-programming sequences. [HRM §§6.3.2 and 6.4.9](https://openwatcom.org/ftp/devel/docs/21066_66a_hrm.pdf).
- **The IOC default-arm exit is already gone.** HEAD declines writes, returns zero on reads, and announces once per direction. Implementation remains owed for documented registers caught there, including STAT0, STAT1, SFT_RST and PAR_DIS. HAE is another omission: its explicit base-address arm simply ignores it (`dev_lca.c:336`).
- **A separate host exit remains in committed `lca_isa`** (`dev_lca.c:286`). It is outside the six IOC value guards and should retain its separate accounting.
