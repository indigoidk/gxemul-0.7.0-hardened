**Verdict: return the old context pointer in `ALPHA_V0` (`$0`). The one-character edit is correct. There is one demonstrated ABI defect: this wrapper already permits `a0` to be clobbered.**

**Q1.** The full [in-tree wrapper](/C:/DocumentNoSnc/CC/GXEMUL/GXEMUL-SEC/src/include/thirdparty/alpha_cpu.h:448) is:

```c
static __inline unsigned long
alpha_pal_swpctx(unsigned long ctx)
{
	register unsigned long a0 __asm("$16") = ctx;
	register unsigned long v0 __asm("$0");

	__asm volatile("call_pal %2 # PAL_OSF1_swpctx"
		: "=r" (a0), "=r" (v0)
		: "i" (PAL_OSF1_swpctx), "0" (a0)
		/* clobbers t0, t8..t11, a0 (above) */
		: "$1", "$22", "$23", "$24", "$25", "memory");

	return (v0);
}
```

`=` declares an output; `r` requests a register. The explicit register declarations determine which physical registers these operands use. A numeric input constraint matches an output operand’s location. These are GCC’s [constraint rules](https://gcc.gnu.org/onlinedocs/gcc-12.5.0/gcc/Extended-Asm.html#InputOperands) and [local-register binding rules](https://gcc.gnu.org/onlinedocs/gcc-8.4.0/gcc/Local-Register-Variables.html).

| Operand | Constraint/expression | Location and role |
|---|---|---|
| 0 | `"=r" (a0)` | `$16`: output whose resulting value is discarded |
| 1 | `"=r" (v0)` | `$0`: output returned by `return (v0)` |
| 2 | `"i" (PAL_OSF1_swpctx)` | Immediate PAL number substituted for `%2` |
| 3 | `"0" (a0)` | Input tied to **operand 0**, hence `$16`, carrying `ctx` |

Thus `"0"` refers to **output operand zero**, which here occupies **register sixteen**. It neither selects physical `$0` nor transfers the result into it. The emulator’s [register definitions](/C:/DocumentNoSnc/CC/GXEMUL/GXEMUL-SEC/src/include/cpu_alpha.h:75) agree: `ALPHA_V0 = 0`, `ALPHA_A0 = 16`.

**Q2.** One defect with two register-state effects. The existing assignment leaves `v0` without the required result and overwrites `a0`. But that overwrite is **permitted by the wrapper’s constraints**: `a0` is an output tied to an input, so its incoming value need not survive.

The smallest edit at [line 251](/C:/DocumentNoSnc/CC/GXEMUL/GXEMUL-SEC/src/cpus/cpu_alpha_palcode.c:251) is:

```diff
-		cpu->cd.alpha.r[ALPHA_A0] = cpu->cd.alpha.ctx;
+		cpu->cd.alpha.r[ALPHA_V0] = cpu->cd.alpha.ctx;
```

This supplies the return value and removes that `a0` overwrite. No separate preservation handling or wrapper change is needed. Preserving `a0` becomes this implementation’s behavior, without becoming an ABI requirement.
