
Operand 0 is `$16` (a0), in-out. Operand 1 is `$0` (v0), a pure output. `"0" (a0)` ties the input to operand 0, **not** to v0. The function `return`s `v0`. ### Q4. The PREFIX *reading* does the job. The scored row does something else, and that something has a third explanation.

**PREFIX `a0 == C` ∧ `v0 == S`, on the shipped binary, does separate “second PAL wrote a0 and not v0” from “second PAL never ran after a correct load of N”.** Never-ran-after-LDQ-N is `a0 == N`, `v0 == S`. Leftover from call 1 on the **broken** handler is `a0 == 0x10100` (the init PCBB), not C. So PREFIX `a0 == C` is not first-call leftover.

POSTFIX `a0 == N` on the same guest program closes the remaining fork “second LDQ loaded C and PAL did not run”: that program’s displacement-8 load produces N when PAL does not clobber a0.

**What the brief overclaims is the row as wired.** `a0 land` asserts `want == N` on every run, including the post-fix 4/4. That is not attribution. Attribution is a PREFIX-only diagnostic. When the row is green it means “a0 still holds the incoming N”, which is:

- the project’s stated policy at the bottom of this file (“easier to just leave the registers as they are”), **and**
- “the handler never ran”, **and**
- the architecture’s UNPREDICTABLE-may-remain-unchanged.

A third explanation of a **green** `a0 land` is therefore “PAL never executed.” The defect row is what breaks that tie (`v0 == C` vs `v0 == S`). The brief’s “one observation, two hypotheses” is true of PREFIX `a0 == C`, not of the 4/4.

The cost of scoring `want == N`: a legal PAL that clobbers a0 to C, to 0, or to anything else — including “write both registers,” which an earlier design brief on this same handler already named — fails `a0 land` while implementing the ABI the round claims to pin. That is a probe over-constraint, not a product miss.
