5. **The ARC option set is incomplete.**

Exact descriptor membership is a locally supported option. The pointer-validation search found [GetConfigurationData:1480](C:/DocumentNoSnc/CC/GXEMUL/GXEMUL-SEC/src/promemul/arcbios.c:1480), which initializes an error result and accepts its node only when the guest pointer exactly equals a registered component pointer. Conversely, GetPeer/GetChild/GetParent use different validation patterns; there is no universal ARC policy to inherit blindly.

The meaningful alternatives are:

- Range-check before division, retaining rounding within the table if that compatibility behavior is deliberate.
- Require an in-range pointer **exactly on a descriptor boundary**.
- Compare against registered descriptor addresses directly, avoiding input-derived index arithmetic.

I recommend boundary membership: normalize the pointer according to the ARC ABI; handle NULL; reject below-base input; compute an unsigned wide difference; reject a nonzero remainder and an out-of-range index; then return the successor only when one exists. Perform bounds checks before multiplication.

Include NULL, first/last descriptor, `base-1`, `base-s`, `base-2*s`, an interior misaligned pointer, and large-offset aliases in the acceptance rows.

Also settle [the low-32-bit NULL test:1565](C:/DocumentNoSnc/CC/GXEMUL/GXEMUL-SEC/src/promemul/arcbios.c:1565): it currently treats nonzero ARC64 values such as `0x100000000` as NULL. Merely widening the final multiplication fixes neither that alias nor the original narrowing.
