## Q3 — smallest edit that keeps gate 2 GREEN while a covered row can no longer fail (not the disclosed stateful test)

The disclosed case is rows-keyed pre-`rows ++`. The smallest edit of a different shape is **name-keyed**, placed *before* `rows ++`:

```c
static void chk(const char *name, long long got, long long want) {
    if (!strstr(name, "@@SELFCHECK@@")) return;   /* silence non-SELFCHECK */
    chk_calls ++;
    rows ++;
    ...
}
```

or the same in `row_cmp()`. Mechanism: the SELFCHECK probes carry the substring `@@SELFCHECK@@`; the comparator treats that substring as the no-compare case, leaves every other name to be silently dropped. The SELFCHECK probes themselves go through the normal path and `failures` increments as the SELFCHECK expects; the SELFCHECK's `failures != sc_f + (cg[i] != cw[i])` check passes; the G text prints; `WDC_IDENTIFY_PASS` lands at the bottom. `rows` does not increment for silenced calls (the comparator returns before `rows ++`), so the final `X rows, Y failures` row reads a smaller X — but no gate 2 row counts X. The row I expect to stay green is the first covered row that calls `chk()` or `row_cmp()` from a non-`@@SELFCHECK@@` site (e.g., one of the 24 covered rows in `row_anchor`/`row_ring_occupancy_sound`/etc. — I cannot name the specific row without reading the file).

Why the FIRST+LAST placement does *not* close this: both SELFCHECK runs carry the substring, so the comparator passes them through; the regular rows between the runs do not, so they are silenced; the FIRST+LAST placement sees no problem because its probes went through normally.

The byte-identity property is preserved for the regular rows' output, since the comparator returns before printing anything. The cost is one `strstr` per call, and a return before the printf — byte-identical output for the *unsilenced* rows (the SELFCHECK ones), and silence for the others.

## Q4 — Is the G row an adequate sole carrier for `scnoforce + chk()` stubbed?

The measured result in §4 is: with `scnoforce` applied, `chk()` stubbed alone produces no G line, no `failures` increment, `128 rows, 0 failures`, `WDC_IDENTIFY_PASS`. The run goes RED only because gate 2's G row greps for `SELFCHECK the comparator can still fail` and the string is missing.

The G row is **adequate** as a sole carrier — it is a separate grep on stdout that the run must satisfy, and removing it would require editing `gate_offline.sh`, not `diff_wdc_identify.c`. The F2 ruling's expectation that `failures` also catches this case is **not met**: the `failures = sc_f + 1` increment lives inside the `if (sc_bad)` arm and is exactly the line `scnoforce` removes. If belt-and-suspenders were wanted, the smallest change is to move `failures = sc_f + 1; rows = sc_r;` out of the `if (sc_bad)` arm and gate it on `(where[0] != 'f') && sc_bad` (or unconditionally for the last run when sc_bad > 0). That costs nothing on the byte-identity of the regular rows (the SELFCHECK is new code; touching it does not affect `row()` or the 8 callers) and would make the run go RED through `failures` AND the G row for the `scnoforce + stub` case. But the G row is functionally sufficient; I would not block on this.
