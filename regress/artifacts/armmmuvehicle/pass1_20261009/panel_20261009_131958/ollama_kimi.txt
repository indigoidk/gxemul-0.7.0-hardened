## 1. Premise audit

**1a | REASONED: every plausible path reaches the handler.** VA `0x10` → section 0 identity → PA `0x10`, in RAM (RAM base 0 per §1.2's stub arithmetic at `0x03fff020` with -M 64). ## 2. Mutant that breaks the fault path and stays all-green

Enumerating the candidate list against the rows, the swap/shift/drop candidates mostly die on the pins: FAR drop, `domain<<4` drop, TRANS_S/P swap, PREF/DATA swap, `retaddr+=4` drop — all redden `data trans` / `domain` / `pref trans` ✓. Section-mask narrowing reddens `remap` ✓. Coarse-shift change reddens `page map` ✓. c8-no-op reddens `remap` (stale identity delivers PA `0x00200000`'s word where the row pins PA `0x00300000`'s — REASONED, contingent on 1b) ✓. **Three survive:**

- **PRIMARY: delete `|| cpu->cd.arm.ttb != cpu->cd.arm.last_ttb` from the re-resolution test.** TTB is then resolved once (the `== NULL` arm remains) and a mid-session TTB switch silently keeps the old table's host pointer — a genuine fault-path break for any real OS. The vehicle arms TTB exactly once per process and never re-arms, so **every row stays green**. Fix row: after arming, re-arm with a second TTB (an alt table whose section-0 entry faults, or whose identity is at a different PA), re-flush c8, then load LIVE — expect a fault / distinct word only if re-resolution works.
- Drop c2's `& 0xffffc000`. The guest writes `0x4000`, already aligned; stored and read-back values are identical under mutant and correct code; the walk's `ttb & 0x0fffffff` is likewise unaffected. `ttb rd` and all rows green. Fix row: write TTB = `0x00005FFF` *before* enabling M, `MRC c2` must read `0x4000`, then write the clean value; never walk with the dirty TTB.
- Delete `domain = 0;` in `case 0:`. Observable only when a type-0 descriptor has nonzero bits 5–8; the design's fault entry is literally `0`, so `domain = (0>>5)&15 = 0` without the line, and **zeroing is a no-op for every row**. Fix row: plant an L1 entry `0x00000060` (type 0, domain 3) and pin FSR `0x05` vs `0x35`. This pins a GXemul convention (ARM ARM leaves the domain field invalid for translation faults) — fine for a regression table.

## 4. Session plan

- **Controls share one process** (`live`, `mmu bit`, `ttb rd`, `remap`, `page map`, the AP=0 accept load, `hole dump`) — READ §2.8 one-way door; none of these aborts. `enc ok` is static, no emulator.
- **Five abort processes** (`data trans`, `pref trans`, `page trans`, `domain`, `perm` — the perm row's accept LOAD runs before the faulting STORE in the same process, so perm is one process, not two). Six invocations total.
- **Step formula** (arm-state stimulus assumed): arming A = 6 (c2, c3, c1-read, ORR, c1-write, c8). `data/page/domain`: A + 2 (`MOV` addr-reg + faulting LDR) + H. `pref trans`: A + 2 (`MCR c5`, `MCR c6` sentinels) + 1 (single PC-relative `B`, range fine) + H. `perm`: A + 3 (MOV + accept LDR + faulting STR) + H. **H = handler instruction count ending at `b .` is NOT in the packet** — handler bodies are specified only by content ("records LR, CPSR, FSR, FAR, ends b ."), so exact integer N is not computable from this brief; the probe author must publish H alongside the handler listing (a minimal handler is ~11 instructions: base-reg MOV, 4 record stores with their loads, magic MOV+STR, `b .`).
- **Marker sufficiency | REASONED yes, and the asymmetry is the point:** make the handler's last store a row-unique magic to DEST+n. Stores to the same mapped, writable, AP=3 page are program-ordered with no possible fault, so magic present in `dump DEST` ⇒ every earlier handler store executed ⇒ N ≥ required. Overrun is absorbed by the idempotent `b .` (it writes nothing, and its page is mapped — §2.11's prefetch-abort trap exists only for a handler that *falls off its end*, which `b .` prevents). Underrun ⇒ magic absent ⇒ row red. The marker double-serves as "this abort was actually taken" (control processes show no magic). Combined with the LR pin, it is enough; it is also what makes the unknown faulted-instruction step-accounting (item 3.iv.4) harmless.

## Trailing item (out of scope; is the Thumb-LR claim true?)

**REASONED: true from the inlined lines, with one caveat.** §1.5's composition in Thumb state: data abort `retaddr = pc + 4 (data-abt adjust) + 2 (T bit) = pc + 6`; DDI 0100I's data-abort LR = faulting instruction + 8 in both states. So +6 vs +8 — the T-side `+2` should be `+4` (the pipeline offset does not shrink in Thumb). Symmetrically, prefetch abort in Thumb gives `pc + 2` vs the required +4 — same defect, and likewise `armthumbabortkill`'s property. Caveat: this presumes `cpu->pc` equals the faulting instruction's address at exception time (consistent with the ARM-state pins pc+8/pc+4 matching DDI); settling fact if challenged: dyntrans's PC convention at the faulting instruction.
