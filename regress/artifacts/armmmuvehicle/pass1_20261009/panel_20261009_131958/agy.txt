### Part 2: Answers to the Questions (§5)

#### 1 | Premise Audit

- **1a | Vector Fetch After Data Abort:**
  - When `arm_exception(cpu, ARM_EXCEPTION_DATA_ABT)` sets `cpu->pc = 0x10`, it invokes `quick_pc_to_pointers(cpu)` ([`src/cpus/cpu_arm.c:783`](file:///C:/DocumentNoSnc/cc/GXEMUL/GXEMUL-SEC/src/cpus/cpu_arm.c#L783)).
  - At abort time, `phys_page[0]` is NULL because page 0 has not yet been executed in this process.
  - Execution falls into `DYNTRANS_PC_TO_POINTERS_GENERIC` ([`src/cpus/cpu_dyntrans.c:622`](file:///C:/DocumentNoSnc/cc/GXEMUL/GXEMUL-SEC/src/cpus/cpu_dyntrans.c#L622)). Since `host_load[0]` is NULL (cleared by `MCR c8`), it calls `cpu->translate_v2p(cpu, 0x10, &paddr, FLAG_INSTR)` ([`src/cpus/cpu_dyntrans.c:679`](file:///C:/DocumentNoSnc/cc/GXEMUL/GXEMUL-SEC/src/cpus/cpu_dyntrans.c#L679)).
  - This calls `arm_translate_v2p_mmu()` for `vaddr = 0x10`. Because section 0 is mapped (`0x00000c02`, AP=3, domain 0), translation succeeds (`ok = 2`), returning `paddr = 0x10`.
  - It does **not** hit the "could not find physical address of the exception handler" exit ([`src/cpus/cpu_dyntrans.c:730`](file:///C:/DocumentNoSnc/cc/GXEMUL/GXEMUL-SEC/src/cpus/cpu_dyntrans.c#L730)), does not use an unmapped/physical bypass, and uses the exact same L1 translation table.

- **1b | Scope of `MCR c8` Invalidation:**
  - `MCR c8` with `opcode2 == 0` calls `arm_invalidate_translation_caches(cpu, 0, INVALIDATE_ALL)` ([`src/cpus/cpu_arm_coproc.c:237`](file:///C:/DocumentNoSnc/cc/GXEMUL/GXEMUL-SEC/src/cpus/cpu_arm_coproc.c#L237)).
  - In [`src/cpus/cpu_dyntrans.c:1276-1288`](file:///C:/DocumentNoSnc/cc/GXEMUL/GXEMUL-SEC/src/cpus/cpu_dyntrans.c#L1276-L1288), `DYNTRANS_INVALIDATE_TC` loops over all valid `vph_tlb_entry` slots and clears `host_load`, `host_store`, `phys_addr`, and marks the TLB entry invalid.
  - **However, `MCR c8` does NOT invalidate compiled instruction translation blocks (`translation_cache` / `DYNTRANS_INVALIDATE_TC_CODE`).** Compiled basic blocks are only flushed upon entering the debugger via `cpu_create_or_reset_tc()` ([`src/debugger/debugger.c:793`](file:///C:/DocumentNoSnc/cc/GXEMUL/GXEMUL-SEC/src/debugger/debugger.c#L793)).
  - Because `host_load` is cleared, no load from an unmapped page can be serviced by a stale entry from before the M bit. Stale instruction code pages inside a single `step N` are not an issue here because stimulus, handlers, and vectors all reside in section 0 (which remains mapped).

- **1c | Implicit Unmapped Address Accesses:**
  - **None.**
  - `0x03fff020` (testarm halt stub): The guest handlers end in `b .` inside section 0. With bounded `step N`, `LR` is never jumped to.
  - Console device: Located at PA `0x10000000` ([`src/include/testmachine/dev_cons.h:11`](file:///C:/DocumentNoSnc/cc/GXEMUL/GXEMUL-SEC/src/include/testmachine/dev_cons.h#L11)). Never accessed unless the halt stub is executed.
  - `step` disassembly: [`src/cpus/cpu_dyntrans.c:287`](file:///C:/DocumentNoSnc/cc/GXEMUL/GXEMUL-SEC/src/cpus/cpu_dyntrans.c#L287) reads `cached_pc = cpu->pc` using `CACHE_INSTRUCTION`. For prefetch abort (`B 0x00100000`), the branch instruction's `quick_pc_to_pointers_arm()` faults during translation and diverts `cpu->pc` to `0x0c` before the next step's disassembly begins; `0x0c` is mapped.
  - Register display: Reads CPU register structures directly, without memory translation.

- **1d | `prom_emulation` Setting and Impact:**
  - `machine->prom_emulation` is initialized to `1` by default in [`src/machines/machine.c:85`](file:///C:/DocumentNoSnc/cc/GXEMUL/GXEMUL-SEC/src/machines/machine.c#L85), and is set for `-E testarm` (cleared only if `-Q` is passed, [`src/core/main.c:443`](file:///C:/DocumentNoSnc/cc/GXEMUL/GXEMUL-SEC/src/core/main.c#L443)).
  - It does **not** matter for this vehicle: in [`src/cpus/memory_arm.c:88-100`](file:///C:/DocumentNoSnc/cc/GXEMUL/GXEMUL-SEC/src/cpus/memory_arm.c#L88-L100), if `prom_emulation` is 1, `ARM_CONTROL_S` is set (`s=1, r=0 -> case 1: user ? 0 : 1`), returning `1` for privileged accesses (`user == 0`). If `prom_emulation` were 0, `ARM_CONTROL_R` is set (`s=0, r=2 -> case 2: 1`), returning `1`. Privileged read-only behavior is identical in both cases.

- **1e | FSR Enumeration:**
  - From [`src/cpus/memory_arm.c:266-381`](file:///C:/DocumentNoSnc/cc/GXEMUL/GXEMUL-SEC/src/cpus/memory_arm.c#L266-L381) and [`src/include/thirdparty/armreg.h:387-392`](file:///C:/DocumentNoSnc/cc/GXEMUL/GXEMUL-SEC/src/include/thirdparty/armreg.h#L387-L392):
    1. `data trans` (unmapped section): `case 0:` sets `domain = 0`, `fs = FAULT_TRANS_S (0x05)`. $\text{FSR} = (0 \ll 4) \mid 0\text{x}05 = \mathbf{0x05}$.
    2. `page trans` (coarse entry 1 = 0): `case 1:` coarse table has descriptor `0x00005001` (domain 0). Sub-table `case 0:` sets `fs = FAULT_TRANS_P (0x07)` without touching `domain`. $\text{FSR} = (0 \ll 4) \mid 0\text{x}07 = \mathbf{0x07}$.
    3. `domain` (domain 1, DACR=0): `case 2:` sets `fs = FAULT_DOMAIN_S (0x09)`. Descriptor `0x00500c22` has domain 1. $\text{FSR} = (1 \ll 4) \mid 0\text{x}09 = \mathbf{0x19}$.
    4. `perm` (section AP=0 store): `case 2:` sets `fs = FAULT_PERM_S (0x0d)`. Domain is 0. $\text{FSR} = (0 \ll 4) \mid 0\text{x}0d = \mathbf{0x0d}$.
  - **Coarse descriptor naming domain 3:** If the coarse descriptor at `0x4010` named domain 3 (`0x00005061`), `domain = (d >> 5) & 15 = 3`. Because coarse `case 0:` does **not** zero `domain`, $\text{FSR} = (3 \ll 4) \mid 0\text{x}07 = \mathbf{0x37}$, **not** `0x07`.

- **1f | Handler Nested Abort Risk:**
  - **None**, provided the handler avoids stack pushes to uninitialized `SP_abt` and writes only to `DEST = 0x9000`.
  - The handler resides at `0x8400`/`0x8500` and writes to `0x9000`; both are within section 0 (identity mapped, AP=3, client domain 0). `MRS` to `spsr` and `MRC` to CP15 c5/c6 are privileged operations valid in ABT32 mode.

- **(i) Packaging:**
  - Must be a single importable gated detector: `regress/arm_mmu_probe.py` (`CLASS_DETECTOR`).
  - [`tools/pipeline/check_probe_wiring.py:3898-3928`](file:///C:/DocumentNoSnc/cc/GXEMUL/GXEMUL-SEC/tools/pipeline/check_probe_wiring.py#L3898-L3928) requires all Python files in `regress/` to be registered in `MANIFEST`. - **(ii) Row Set:**
  - For `armthumbabortkill`: The consumer needs to enter Thumb mode under the MMU. Adding a control row that executes `BX` to a mapped Thumb stub in section 0 that returns cleanly establishes that MMU + Thumb state works before attacking the fault path.

- **(iii) Collision with Defects:**
  - `armdesc3kill`: Descriptors use types 0, 1, and 2 only. Type 3 is never planted.

- **(iv) Thumb Data Abort Return Address Finding:**
  - **Confirmed True:** In [`src/cpus/cpu_arm.c:713-717`](file:///C:/DocumentNoSnc/cc/GXEMUL/GXEMUL-SEC/src/cpus/cpu_arm.c#L713-L717):
    ```c
    case ARM_EXCEPTION_DATA_ABT: retaddr += 4; break;
    ...
    retaddr += (cpu->cd.arm.cpsr & ARM_FLAG_T ? 2 : 4);
    ```
    In Thumb mode, `retaddr = pc + 4 + 2 = pc + 6`.
    Per ARM DDI 0100I §A2.6.6, Data Abort `LR_abt` is $\text{PC} + 8$ in **both** ARM and Thumb states. GXemul's computation of `pc + 6` in Thumb state is an architectural defect.

#### 4 | Session Plan

1. **Process Sharing:**
   - Controls (`live`, `mmu bit`, `ttb rd`, `remap`, `page map`, `hole dump`) can share a single process because none transition to ABT32 or fault.
   - Abort rows (`data trans`, `pref trans`, `page trans`, `domain`, `perm`) **must each run in an isolated process** to avoid inherited ABT32 mode and corrupted SPSR/FAR/FSR state.

2. **Step Count $N$:**
   - Arming: 6 instructions (`MCR c2`, `MCR c3`, `MRC c1`, `ORR`, `MCR c1`, `MCR c8`).
   - Stimulus: 1 instruction (faulting `LDR` / `STR` / `B`).
   - Vector jump: 1 instruction (`B` at `0x0c` / `0x10`).
   - Handler: 8 instructions (store `LR`, read/store `SPSR`, read/store `FSR`, read/store `FAR`, write marker).
   - Tail: 1 instruction (`b .`).
   - Total $N = 17$ steps.

3. **Step Count Verification & Integrity:**
   - The DEST marker at `0x9010` is necessary but not sufficient on its own.
   - The harness must implement **Poisoning + Marker verification** (Repair R2 of `arm_msrmode_probe.py`): plant poison (`0xdeadbeef`) across `0x9000-0x901c` via `put w` prior to stepping, and verify the marker word at `0x9010` after stepping.
