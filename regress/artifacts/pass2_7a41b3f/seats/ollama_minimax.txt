## Per-round audit

### #505 sgirergbroundtrip — SHIP
- **Arithmetic, READ**: Pre-fix `*color = (buf[1]<<24)+(buf[2]<<16)+(buf[3]<<8)`. For PUT output buf=[R,G,B,pad], this returns G at [31:24], B at [23:16], pad at [15:8], 0 at [7:0] — the channels shift one slot left and R is dropped. Post-fix returns R/G/B at [31:24]/[23:16]/[15:8], 0 at [7:0]. Round trip preserves the three channels with low byte zero, which the comment explicitly states is the design.
- **UB concern, REASONED**: `buf[i] << 24` on a `uint8_t` is UB for byte values 0x80–0xFF on a 32-bit `int` target. The fix changes indices, not the shift, so the UB is untouched. **The fix's correctness as an off-by-one repair is independent of the UB.** Disposition is unchanged; the UB is a separate filed issue.
- **Comment, REASONED**: The cross-reference to `dev_sgi_gbe.c`'s scanout and CRMFB_MODE_TYP_RGB8 channel positions, the "RGBA and ABGR PUT arms independently agree" claim, and the PUT-arm description are all outside the packet. The PUT arm itself is the load-bearing premise and is NOT in the diff.

### #506 lcaconfwidth — SHIP (with one unverified type premise)
- **Arithmetic, READ**: For idata = 0x100000000, `idata & ~1` is truthy (guard trips), `(int)idata` is 0 on 32-bit-`int` targets, so the diagnostic prints "0x0" — a value the guard would have ACCEPTED. The fix prints full 64-bit width via `%" PRIx64 "`. The defect is real iff `idata` is genuinely 64-bit.
- **Cast necessity, REASONED**: If `idata` were 32-bit, the fix would be a cosmetic no-op (a real-but-not-bug repair). **The declared type of `idata` in `DEVICE_ACCESS(lca_ioc)` is the single premise that decides whether this is a defect or a stylistic rewrite.** I cannot read the declaration.
- **Count, REASONED**: "Two sites" is supported by the diff. The parenthetical "(Not the file's only narrowing site -- the default arm below has the same cast, and this round fixes it too.)" is ambiguous — the "default arm" might be site 2 or a third site not shown. Cannot settle.

### #507 alphaswpctxptbr — SHIP (with one unverified premise)
- **Visible defect, READ**: The line was `apcb_ptbr = new_flags`. If `new_flags` belongs on `apcb_flags`, the LHS is wrong, period. The fix changes LHS to `apcb_flags`.
- **"Three lines up" claim, REASONED**: The comment asserts `apcb_ptbr` is correctly assigned earlier in the block. The diff does not show that line. **If the earlier assignment does not exist, the original code had two bugs (wrong LHS here AND `apcb_ptbr` never loaded) and the fix addresses only one.** I cannot verify.
- **Visible context, READ**: Every other field in the shown block (`apcb_cpc`, `apcb_asn`, `apcb_unique`, `apcb_decrsv0`, `apcb_decrsv1`) is assigned exactly once. The "exactly once" claim holds for the visible portion.

### #508 alphapfnoffset — SHIP (with full disclosure)
- **Arithmetic, READ**: `(PFN << pageSizeShift) | (vaddr & ((1ULL << pageSizeShift) - 1))`. The PFN shift clears bits [pageSizeShift-1:0], and the mask extracts exactly those bits of `vaddr`. OR and ADD are equivalent here; the comment's claim is correct.
- **Scope, READ**: The fix addresses only the dropped offset. The `// TODO.` line and `return 2` are preserved. The fix comment explicitly discloses: flags ignored, protection untested, every walked page reported writable. **Disclosure was made** — the question of whether the round "owes" a separate disclosure is moot because one is in the commit.
- **Stylistic note, REASONED**: "this function already has TWO names for 13" is the author's gloss; the substantive point — use the computed mask, not a literal — is sound regardless of whether the local is always 13.

## One thing the brief did not ask but I noticed

The #508 comment ends with "the protection bits untested, and `return 2` still reports every walked page writable." If a guest writes through a walked page that the architecture marks read-only, the walk will return success and the write will proceed. This is not a defect of #508 — it is a defect of the surrounding function that predates and outlives #508. But it means the witness for #508, which measured a `ldq`, may have observed the page-offset fix without ever exercising the protection path. That does not undermine #508; it does mean the witness does not overclaim (and the comment correctly does not overclaim either).
