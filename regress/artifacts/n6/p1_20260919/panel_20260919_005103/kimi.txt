  ## Q2

  One framing note first: the sites probe reads registers **once**, at arm end (:188-196). A mutant that kills the host mid-arm (f, g) leaves no reg dump, so *every* value row reds with `got=-`; "reds first" for those is the killing step in execution order. Record it that way in the pretable, or the kill table overclaims precision.

  - **(a)** delete `odata`: E0 passes (0 == 0); **E1 reds first**.
  - **(b) `irq_status`, (c) `irq_status & irq_enable`, (d) `fiq_enable`**: all three fields are 0 throughout this arm (nothing asserts; no `+0x190` case exists; no FIQ state) — all present identically to (a), **E1 reds first**, and the table cannot *distinguish* them.   ## Q4

  The corrected classification (premise-finding 1) dissolves the panel's split: there is no seven-site DECLINE group — there are two more ACCEPTs (`+0x100`, `+0x104`, needing two new state words since the write arms discard) and five true DECLINEs. A natural campaign is round 2 = the SDRAM pair, round 3 = the five. Under that order, a `+0x100` control dies *next round* — the move buys almost nothing.

  **Recommendation: build the permanent control now, in this commit, and skip the +0x100 bridge.** Every piece already exists in the probes' own harness:

  - *Exit-status leg (replaces sites-probe arm K):* spawn the binary once with a bad argument (unknown `-E` machine). The process exits 1 before any prompt; the wait loop sees EOF immediately, so this is fast. It pins the same plumbing K1 pins (`exit == 1` detection) with zero dependence on any model defect.
  - *Mid-session death leg (replaces drain/witness kill arms):* after the prologue steps, send debugger `quit` — a clean, device-independent, mid-session host death. Require `s.dead` on the next interaction **and** bound status `== 0` (the Q1(e) binding). This is *stronger* than today's arms, which cannot see status at all, and it directly exercises the #538-class fix.
  - The "guest actually reaches the device" function of the old kill pair is already subsumed by value rows — A1/A2 today, and E2's `|=` accumulation is a device-state signature as strong as the mask row. Say so in the rewritten probe headers; the "nothing can die" rationale becomes "death detection is pinned by the harness legs".

  If the panel judges that diff too large for a one-site round, the `+0x100` move is verified-sound (Q1b) — but then the commit must name its retirement date explicitly, because under the corrected classification that date is probably next round, not the campaign's end.
