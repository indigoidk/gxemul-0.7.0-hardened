## 2. Defects found in the brief itself

1. **Q contradicts itself (REASONED).** §5.3's mutant bullet says "Q becomes `0x60000000` (bits 29 AND 30) so E2 wants `0x60002002`", and all E-row arithmetic uses that. But the same section's "Proposed:" line still says `Q = 0x20000000` (bit 29 only), and Q1(c) asks about "Q (bit 29)". One of these is stale. Given the rationale, `0x60000000` is intended — but the packet contains both, and a seat implementing from the "Proposed" line would write rows that red correct code.

2. **Dangling mutant reference (REASONED).** The Q rationale cites "(Q2(l))" — Q2 ends at (k). The described mutant (diagnostic reinstated only when bits 30/31 of the read value are set) exists only in that sentence. Name it properly and add it to the Q2 enumeration or the kill table.

3. **E5/E6 ordering is underdetermined and the listed order breaks E6 (REASONED).** E6 wants `0x2002` from an `ldrh` "after E2" — true only while `irq_enable == P|Q`. E5 clears P, leaving `Q = 0x60000000`, whose low halfword is `0x0000`. If rows execute in the listed order (E3, E4, E5, E6), E6 reds on *correct* code. Pin the execution order E0,E1,E2,E3/E6,E5 (E4 anywhere after the first read), or change E6's want. This is exactly the kind of premise an author who already believes the design would not re-check.

4. **Load-bearing premise not derivable from the packet: `SDRAM_BA_MASK == 0x100`.** No probe inlined here currently reads 0x100, so unlike 0x188 → IRQ_ENABLE_SET (proven by three probes observing the "ENABLE SET" fatal today), the +0x100 mapping rests on an unattributed header define. If it is wrong, the read falls to `default:` (745–747), which calls `fatal()` **without** `exit(1)` — the new kill arm would print text and *survive*. Mitigation: the failure is loud in all three probes (K1 reds; drain/witness kill arms report SURVIVED), so a bad premise cannot pass silently. Still: the one fact that settles the round's central move is the `#define SDRAM_BA_MASK` line in `dc21285reg.h`. Not checkable from the packet.
