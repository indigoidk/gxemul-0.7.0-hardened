### §3. WHAT ALL NINE SEATS MISSED (Q3): LOAD-SENSITIVE FLAKES IN THE BOUNDED REAP

There are concrete states where the new bounded reap produces a **WRONG VERDICT on a HEALTHY run under load**:

1. **The SIGHUP Race on Master PTY Close Under Load:**
   In [`regress/fbpending_drain_probe.py:414-422`](file:///C:/DocumentNoSnc/CC/GXEMUL/GXEMUL-SEC/regress/fbpending_drain_probe.py#L414-L422) and [`regress/fbpending_witness.py:353-361`](file:///C:/DocumentNoSnc/CC/GXEMUL/GXEMUL-SEC/regress/fbpending_witness.py#L353-L361):
   ```python
   deadline = time.monotonic() + patience
   while True:
       left = deadline - time.monotonic()
       if left <= 0 or not self.rd(min(0.1, left)):
           break
   try:
       os.close(self.fd)
   except OSError:
       pass
   ```
   If a healthy emulator run takes more than 5.0 seconds to finish flushing state under host CPU/disk contention or ASAN checks, the drain loop hits `left <= 0` and calls `os.close(self.fd)`. Closing the master pty sends `SIGHUP` to GXemul. Because GXemul has no SIGHUP handler, it terminates with signal 1 (`SIGHUP`).
   The subsequent reap yields `st` where `os.WIFSIGNALED(st)` is True and `os.WIFEXITED(st)` is False (`code = None, sig = 1`).
   The oracle in [`fbpending_drain_probe.py:667-668`](file:///C:/DocumentNoSnc/CC/GXEMUL/GXEMUL-SEC/regress/fbpending_drain_probe.py#L667-L668) requires:
   ```python
   def survived(a):
       return a["status"] == "SURVIVED" and a.get("exit") == 0
   ```
   Because `a.get("exit")` is `None`, `survived(a)` evaluates to `False`. **A completely healthy emulator run fails rows R0, C1, A1, A2, and K.**

2. **SIGKILL Timeout on Slow Process Exit:**
   Even if the process survives pty closure, the reap loop gives it only 5.0 seconds:
   ```python
   while pid == 0 and time.time() - t1 < 5.0:
       ...
   if pid == 0:
       os.kill(self.pid, signal.SIGKILL)
   ```
   Under extreme load, an ASAN teardown or buffer flush exceeding 5.0 s triggers `SIGKILL`. `code` is `None`, `sig` is 9, and `survived()` returns `False`.

3. **`rd(0.1)` Flaw in `footbridge_sites_probe.py`:**
   In [`footbridge_sites_probe.py:185-187`](file:///C:/DocumentNoSnc/CC/GXEMUL/GXEMUL-SEC/regress/footbridge_sites_probe.py#L185-L187):
   ```python
   r, _, _ = select.select([fd], [], [], t)
   if fd not in r:
       return True
   ```
   When `select` times out with no data available, `rd()` returns `True`. Therefore, in lines 275–277:
   ```python
   t1 = time.time()
   while time.time() - t1 < 5.0:
       if not rd(0.1):
           break
   ```
   `if not rd(0.1):` is `False`. The loop does not break on inactivity; it spins for the entire 5.0 seconds every time unless the child has already closed the pty slave.

4. **Non-Monotonic Clock Usage:**
   `footbridge_sites_probe.py` lines 274 and 284 use `time.time()` rather than `time.monotonic()`, exposing the loop to NTP step jumps.
