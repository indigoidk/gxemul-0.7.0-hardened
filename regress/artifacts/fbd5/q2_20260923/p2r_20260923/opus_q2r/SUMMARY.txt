1. METHOD
=====================================================================================================================
driver.py makes each one-line variant by exact string replacement on the FROZEN device.  The anchor must match exactly
once, or the variant is recorded as ANCHOR-ERROR (none happened).  The driver writes the variant into
/tmp/opusq2r/src/devices/dev_footbridge.c behind a /tmp/opusq2r/.MUTANT sentinel, builds it, runs the 491 rows and
records the row count, the failures, the first failing row, and whether the binary is identical to the baseline.
Every log and every one-hunk diff is in variant_logs_and_diffs.tar.gz (436 logs, 434 diffs).
At the end of each run the driver restored the device from the FROZEN copy, checked it with cmp, rebuilt, re-ran
491/0 and confirmed the binary md5 matched the baseline.  Only then did it clear the sentinel.  This held on all four
runs.  final_check.sh then did the same checks independently (see section 9).

CONTROLS.  The brief's Q1..Q5 (the a_pos rows below) go red on exactly the rows and counts the brief reports:
3, 3, 3, 3 and 2 rows, all "X9 ... (all-zero, latches clear)".  The driver therefore reproduces the committed
measurement.  The first 8-variant validation run is in results_subset.tsv.

Notation: A0 = IRQ_STATUS +0x180, A1 = IRQ_RAW_STATUS +0x184, A2 = IRQ_ENABLE_CLEAR +0x18c, A3 = FIQ_STATUS +0x280,
A4 = FIQ_RAW_STATUS +0x284.
  "dir"  = the direction test: `writeflag == MEM_READ`, or `writeflag == MEM_WRITE` at A2.
  "flag" = the latch test `!d->warned_<own site>`.
  F = one of irq_status, irq_enable, fiq_status, fiq_enable.
  L0..L4 = the latches of A0..A4.  A latch is "later" if its site comes after the edited site in the fixed order
  that every multi-site sequence in the harness uses: A0, A1, A2, A3, A4.

3. EVERY GREEN, CLASSIFIED BY AN IN-PROCESS DIFFERENTIAL (wit_main.c + wit_tu.c; per-variant output in wit/)
=====================================================================================================================
Method.  One binary links the FROZEN device (as base_) and the VARIANT (as var_).  Both get the same access sequence.
After every step it compares:
  the handler's return value,
  the whole read buffer,
  the CPU irq LINE LEVEL,
  the announce count,
  the raw ASSERT/DEASSERT call counts,
and at the end all internal fields.
Search from RESET: EXHAUSTIVE over all 8,040,200 sequences of length 1..3, then 2,000,000 random sequences of length 4..6.
The alphabet has 200 ops:
  reads: 8 registers (0x180-0x18c, 0x280-0x28c) x widths 1/2/4;
  writes: the same, x data {0, 0x10, 0x70, 0x400, 0x10000, 0x80000000, 0xffffffff};
  device lines 4 (timer 1), 10 (cats ISA), 11 (netwinder ISA) and 18 (cats PCI, dec21143), each + and -.
These four lines are wired in the tree: DEVINIT connects the timers, and bus_pci.c routes "footbridge irq 10" and
"int 18 = PCI" for cats and ISA line 11 for netwinder.  fiq_status has no writer anywhere in the product, so it is 0
in every reachable state.
CONTROLS.  BASE against itself: 0 divergences of any kind.  Q1 (a_pos_A0_irq_enable): 298,788 announce divergences
and 0 guest-visible divergences.  So the brief's Q1..Q5 shape is visible to the HOST ONLY: the read value it
returns is right in every state where the conjunct fires.

8. SOMETHING ELSE (outside #545's diff; frozen model, measured in dom_witness.txt, "model check" block)
=====================================================================================================================
The model's CPU irq line can stick high.  Sequence: `line10+` (while disabled), then `W188/4=0x400`, then `line10-`.
Afterwards the line is still 1 and IRQ_STATUS reads 0.  Cause: the IRQEnableSet and IRQEnableClear arms call
INTERRUPT_ASSERT without setting irq_asserted, and footbridge_interrupt_deassert() deasserts only when irq_asserted is
set.  A consequence for this round: a variant that skips or adds a redundant ASSERT/DEASSERT becomes guest-visible
only in that inconsistent state.  The harness counts calls, so it sees such variants anyway.
