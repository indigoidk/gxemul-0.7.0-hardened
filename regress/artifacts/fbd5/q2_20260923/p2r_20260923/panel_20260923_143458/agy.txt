##### **(b) X9 expectations vs handler for the eight enable writes across all three states**
In [`dev_footbridge_access`](file:///C:/DocumentNoSnc/cc/GXEMUL/GXEMUL-SEC/src/devices/dev_footbridge.c#L593-L658), IRQ enable Set/Clear update `irq_enable` and drive `d->irq` via `if (d->irq_status & d->irq_enable) INTERRUPT_ASSERT(d->irq); else INTERRUPT_DEASSERT(d->irq);`. FIQ enable Set/Clear update `fiq_enable` only, calling neither assert nor deassert.

In [`regress/diff_footbridge.c#L1020-L1029`](file:///C:/DocumentNoSnc/cc/GXEMUL/GXEMUL-SEC/regress/diff_footbridge.c#L1020-L1029), X9 asserts:

- `!fiq`: enable updated, other enable intact, `(is & ne) ? (asserts == a0 + 1 && deasserts == d0) : (asserts == a0 && deasserts == d0 + 1)`.

We enumerate all $8 \times 3 = 24$ operations:

1. **State: Seeded** (`is = 0x18`, `ie = 0x30`, `fs = 0x60`, `fe = 0xc0`):

   - `FIQ Set 0`: `ne = 0xc0 | 0 = 0xc0`. Interrupt callbacks: **NEITHER**. Matches X9.
   - `FIQ Set 0x70`: `ne = 0xc0 | 0x70 = 0xf0`. Interrupt callbacks: **NEITHER**. Matches X9.
   - `FIQ Clear 0`: `ne = 0xc0 & ~0 = 0xc0`. Interrupt callbacks: **NEITHER**. Matches X9.
   - `FIQ Clear 0x70`: `ne = 0xc0 & ~0x70 = 0x80`. Interrupt callbacks: **NEITHER**. Matches X9.

2. **State: All-Zero** (`is = 0`, `ie = 0`, `fs = 0`, `fe = 0`):

   - `IRQ Clear 0x70`: `ne = 0`. `is & ne = 0` $\rightarrow$ **DEASSERT**. Matches X9.

#### **Q2 -- The Smallest Change That the 491 Rows Cannot See**

**Target Arm**: [`case IRQ_STATUS:`](file:///C:/DocumentNoSnc/cc/GXEMUL/GXEMUL-SEC/src/devices/dev_footbridge.c#L570-L581)

**Specific Change**:
```c
	case IRQ_STATUS:
		if (writeflag == MEM_READ && !(d->irq_status & 1))
			odata = d->irq_status & d->irq_enable;
		else if (!d->warned_irq_status_w) {
			d->warned_irq_status_w = 1;
			fatal("[ WARNING: footbridge write to irq status? (once) ]\n");
		}
		break;
```

**Why it escapes the 491 rows**:
Bit 0 of `irq_status` is `0` across every state exercised by the offline differential:
- Seeded: `0x18` (bits 3, 4 set; bit 0 is 0)
- All-zero: `0x0` (bit 0 is 0)
- Wide: `0x80010018` (bits 3, 4, 16, 31 set; bit 0 is 0)

Therefore, `!(d->irq_status & 1)` is identically TRUE for all 491 rows. Every row in the test suite stays green.

**What stays green**:
`X9 legal len 4 read of IRQ_STATUS (seeded, latches clear)` and `X9 legal len 4 read of IRQ_STATUS (wide, latches clear)` stay completely GREEN.

**What is broken**:
In a running system where bit 0 is asserted on `d->irq_status` (such as a parity error or peripheral interrupt mapped to line 0), any legal guest read of `IRQ_STATUS` evaluates `!(d->irq_status & 1)` as FALSE. The legal read is diverted into the decline branch, sets the warn-once latch, logs a phantom complaint, and returns 0.

*(A second valid structural escape within the decline body itself is conditioning a store on data bits above byte 0, e.g. `if (idata & 0x80) d->irq_status = idata;` in the decline branch. Because declined writes in P1-P5, X1, X6, X7, and X9 write exclusively `0` or `0x70`, this data corruption is 100% blind to all 491 rows).*
