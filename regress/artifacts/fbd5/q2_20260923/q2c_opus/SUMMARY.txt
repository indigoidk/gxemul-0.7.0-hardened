5. SOMETHING ELSE
=====================================================================================================================
(a) WIDTH 8 IS A LIVE INPUT.  cpu_arm_instr.c decodes the `(iword & 0x0e000090) == 0x00000090` space with no architecture
    check, so LDRD/STRD run on cats' SA-110; cpu_arm_instr_loadstore.c issues them as datalen 8 after `addr &=
    ~(datalen - 1)`; memory_rw.c passes len through untouched (it truncates only at the device's end).  So +0x180 and
    +0x280 (and +0x188/+0x288) receive len 8; +0x184/+0x18c/+0x284 never do.  THE SPACE says "the width", X6's widths are
    1, 2, 4, and NOT COVERED does not mention 8.  N_L06, N_L07, N_L10 pass.
(b) THE HARNESS'S INSTANCES ARE NOT RESET-FAITHFUL.  calloc leaves timer_control/timer_load/pending_bound at 0 where
    DEVINIT sets TIMER_MODE_PERIODIC/0xffffff/1, and irq_asserted is written only by footbridge_interrupt_assert(),
    which the harness stubs.  Every condition on those fields therefore passes offline; 13 of the 28 are this class.
    The reset-value ones (N_T04, N_T05, N_F09, N_T09) diverge from the first access after DEVINIT, so the 37-row guest
    probe may catch them -- I did not run it.

    value, and it is guest-visible: W188/4=0x20 W18c/4=0x20 R188/4 reads 0x20, not 0 (replay).
