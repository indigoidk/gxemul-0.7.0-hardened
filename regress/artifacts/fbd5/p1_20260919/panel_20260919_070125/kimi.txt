  **(c) The K1/K2 legs, quoted helpers.** "Fails with `dead`" is observable as written in all three launchers: `send()` sets `dead` and returns False on write EIO (sites `:225-235`; drain `:338-351`; witness `:268-278`), and `rd()` sets `dead`/returns False on EOF/EIO (sites `:192-206`; drain `:295-308`; witness `:225-238`), with `wait()` returning False through the same path. Together they re-establish the kill arm's two halves. The one thing **not** re-pinned is their conjunction — "guest steps, then the process dies with exit 1" — and that is acceptable, because every new D row requires its arm to survive with exit 0, so a mid-session death reds a D row through the same `dead` path. One gap in coverage, not of the legs: **no gate runs the drain or witness probes** — `gate_arm.sh:1072-1125` runs only the sites probe, and `gate_offline.sh:1269` says the drain probe "is NOT run here". The two gate checks replacing "the one-instruction kill arm still dies" (`gate_arm.sh:1104-1105`, which greps the row ID `^K1 .*ok$`, not the complaint text) can pin only the sites probe's legs. In drain and witness the legs must be wired into each probe's own verdict rollup (`ok` at drain `:675-681`, witness `:595-600`) or their retirement is self-greening.

  **(d) Post-round exit enumeration in `DEVICE_ACCESS(footbridge)`:** exactly two remain — `:714` (guest read of +0x100) and `:739` (guest read of +0x104). The DEVINIT pair (`:843/:879`) is construction-time; `footbridge_isa`/`footbridge_reset`/`footbridge_pci` have none (bus-255 returns 1 after its fatal, `:476-481`).   ## Q2 — which red, which escape

  - **(a) exit kept at one site** → red: that site's D row dies at the first access (exit 1 + complaint, no continuation); the witness rung stays red post-fix.
  - **(b) unlatched** → red: two accesses in one arm yield count 2 ≠ 1. Topology-independent.
  - **(c) one bit shared by two sites** → **ESCAPES as specified**, and this is a real pass-2 action item. The latch is per instance; if each D row is its own `run_arm` (fresh process → fresh DEVINIT → bit clear), the shared bit is invisible. Caught only if one session touches ≥2 of the five sites. Specify either a single arm walking all five, or one extra two-sites-in-one-session row.
  - **(d) +0x18c decline keeping `odata = d->irq_enable`** → red: D3 reads 0x30 where 0 is required.
  - **(e) write-decline storing into `irq_status`** → red via D1's state check (raw/status reads back 0x10) — valid only if D1 actually re-reads state after the writes; pin that.
  - **(f) decline swallowing the legal direction (IRQ_STATUS read returns 0 always)** → **ESCAPES.** In the sites probe nothing ever makes `irq_status` nonzero: no row asserts a footbridge interrupt line, the stepped arms never enable a timer (reset `timer_control` has no TIMER_ENABLE, `:889`), and IRQSoft (+0x190) is unimplemented (write falls to the default arm). So A1's correct value is 0 and a constant-0 mutant passes A1/A4 (and A2/A5 catch only `= irq_enable`, not `= 0`). The AND semantics are pinned only against OR-for-AND. Close it offline in `regress/diff_footbridge.c` (set `d->irq_status` directly, call the access function) — the stepped probe structurally cannot.
  - **(g) misnamed register in the text** → red **iff** the D rows count the site-specific text. The sites probe's existing `fatals` regex (`:289`) is a generic `[...footbridge...]` bucket; counting that bucket lets (g) escape. The rows must match e.g. `write to irq status\? \(once\)` per site.
  - **(h) K1 passing on any nonzero exit** → hollow: greens on a wrong-reason exit 2. The spec's `WEXITSTATUS == 1` exactly, plus the diagnostic naming the input, is the pin; keep both halves.
  - **(i) K2 passing when the child died before the prologue** → excluded by the spec's prologue-verified-live requirement (CP15 bit 0 clear, RAM 0x11223344, VENDOR 0x1011, load-back 0x00345678) — sound as written; the hollow variant is the Q4 risk.
  - **(j) latch cleared by a read** → D3 catches it trivially (its two accesses *are* reads: count 2). For the four write sites it is caught **only if the state-check read is interleaved between the two writes**; write-write-then-read escapes. Pass 2 must interleave.
  - **(k) legs in one launcher only** → escapes unless pinned per launcher: drain/witness delete row K, and with no legs appended their rollups stay green. See Q1(c) — no gate runs those two probes, so per-probe rollup wiring is the only pin.

  ## Q3 — option-set completeness

  The set is complete. DELETE falls to the default arm's *unlatched* per-access print — strictly worse than member 3 and loses site specificity. ACCEPT and IMPLEMENT have no datasheet warrant for any of the five (no defined value, no defined effect). BACKED ACCEPT for +0x18c is precisely the leak the round removes, and the "nonexistent CSR reads zeros" rule weighs against inventing readable state at a WO address. FAULT is unavailable on ARM (Q1(a)) and datasheet-unwarranted ("no error action is taken"). Sibling dispositions agree: `dev_unreadable` declines silently; the latched `(once)` decline is the house shape for guest-drivable diagnostics. Member 3 stands for all five.

  ## Q4 — the hollow-leg edit, and the row that stays green

  The smallest green-but-vacuous edit: implement **K2 as "send `quit`; reap; require WIFEXITED && status == 0"** — no prologue liveness `reg`, no post-quit interaction. Every healthy run passes it (it is just the teardown the probes already do), it never proves the session was alive, and it never exercises the `dead` path a mid-session product death relies on. The row that stays green: **`gate_arm.sh`'s "footbridge: every row green"** (`grep -c FOOTBRIDGE_SITES_PASS`, `:1085-1086`) — if the legs print but are never appended to the probe's `results[]`, the aggregate PASS is untouched by a vacuous leg, and a gate pin that merely greps the leg's *presence* (a `^K2 ` line) greens too. The two replacement gate checks must therefore pin the legs' discriminating content — K1: named-input diagnostic **and** exit == 1; K2: prologue values **and** dead-before-cleanup **and** exit == 0 — and the probes must append the legs to their verdict sets.
