## Weakening map (Q2)

- **(a) exit(1) kept at one site:** that site's own D row reds — "missing continuation", exactly as designed.
- **(b) unlatched announce:** first D row reds (count = 2 across the two accesses).
- **(c) one bit shared by two sites:** the *second* site's D row reds (count = 0). Not the first. Pin order matters, so per-site bits it must be.
- **(d) +0x18c decline keeps `odata = d->irq_enable`:** D3 reds (0x30 ≠ 0). Verified against the inlined tail: lines 756–757 write `odata` back on any read that survives, so the leak is real post-decline.
- **(e) write stores into `irq_status`:** D1's readback reds (raw/status 0x10).
- **(f) decline also swallows the legal read (IRQ_STATUS always 0):** **ESCAPES every new row.** All A-row expectations are computed with `irq_status = 0`, where 0 is the *correct* value — A1 only distinguishes AND from OR (0x30). No new row raises a status bit, and with IRQSoft unmodelled the packet shows **no guest-writable path that sets `d->irq_status`** (timer-expiry code is not inlined). Settling fact: what sets `d->irq_status`, so a row can be built that raises a bit and re-reads +0x180. This is the one weakening with no red row.
- **(g) misnamed announce text:** reds iff the D-row count matches the exact expected string. The packet says "a COUNT of the announce text" but not the match expression. Settling fact: the literal grep pattern in the D rows.
- **(h) K1 accepts any nonzero:** escapes all detector rows — the leg *is* the check. Only the gate's leg pins or review catch it.
- **(i) K2 passes on early death:** reds only because the spec'd prologue verification (fresh `reg`: MMU bit, RAM 0x11223344, VENDOR 0x1011, timer mask) fails on a dead child. A leg that *drops* the liveness-verify escapes.
- **(j) latch cleared by a read:** for write sites, reds only if the D row interleaves its state-check read between the two writes; if the readback comes after both writes, count stays 1 and it escapes. Step order inside D1 is not stated in the packet — name it. For D3 (a read site), a per-read clear gives count 2 — reds.
- **(k) legs in one launcher only:** escapes the product rows entirely; the other two probes lose their K arms with no replacement. Reds only if `gate_arm.sh`'s two new leg-pins are per-probe. Not inlined — name it.
