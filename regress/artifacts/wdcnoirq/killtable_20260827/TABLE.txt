*** FOUR OF SEVEN READ ABRT+NO-irq = 0.  THEY PASS LEG 1 ENTIRELY. ***  That is the
measured proof that the two-observable sweep this round FIRST designed was below the
floor -- it would have shipped green against four plausible maintainer edits, one of
which sends a spurious completion interrupt on every disk write a real guest issues.

Each leg exists because of one measured escape:

  M9  the repro called wdc_command() and ran the tick BY HAND, so it could not see a
      fix whose repair depends on dev_wdc_access()'s tail tick.  Leg 1 drives the real
      register path -- a command STORE.
  M4  one `int_assert = 1` hoisted after the switch reads ABRT+NO-irq 0 and passes any
      count oracle, while asserting at DISPATCH for the three DEFERRED opcodes.  So the
      silent set is pinned as an IDENTITY {0x30, 0xa0, 0xc5}, not as a count.
  M5  the assert moved inside `if (!d->warned_unimpl_cmd)`: only the FIRST unknown
      command per device interrupts.  A sweep with one fresh device per opcode CANNOT
      SEE IT at any oracle width -- the latch is 0 on every leg.
  M7  the STATUS read stops clearing the request.  int_assert is a LEVEL, so the tick
      re-raises it every ~16k instructions forever.
  M8  SET_FEATURES asserts only on its abort sub-case.  The sweep varies the command
      byte and never `precomp`, so its SUCCESS path never ran.  INPUT COVERAGE IN ONE
      DIMENSION IS NOT INPUT COVERAGE.

THE INVARIANT THE FIX RESTORES, derived over all 256 opcodes rather than from a few
neighbours: every command wdc_command() FINISHES raises the completion interrupt.  The
only silent opcodes are the three that hand control back for a data phase -- WDCC_WRITE,
ATAPI_PKT_CMD, WDCC_WRITEMULTI -- each of which asserts when its data phase drains.
