==========================================================================================
THE THREE CONTROLS
==========================================================================================
LIVENESS      `live ec irq`.  0xEC WDCC_IDENTIFY already asserted before #485, so it must
              deliver on BOTH builds -- and it does, at the same vector, in the same
              script.  That is what separates "the fix works" from "this script cannot
              deliver anything", and it is the row that makes the two silences above
              meaningful.

ATTRIBUTION   `attrib noram`.  The same `mov.b r8,@r7`, the same sr/vbr/breakpoint, the
              same free-run -- with r7 pointing at RAM instead of at the command
              register.  Nothing is delivered on either build, so the deliveries above
              are not the RTC, the SCIF or a timer.  It carries its own execution proof:
              the store is STEPPED and DUMPED (0x000000f5 read back through the debugger)
              before the pc is rewound and the identical instruction is free-run, so
              "silent" here cannot mean "the guest never ran".

DEVICE SIG    `devsig err`.  A guest load of the ERROR register before and after a 0xF5
              store reads 0x01 then 0x04.  0x01 is DEVINIT's power-on `d->error = 1`;
              0x04 is WDCE_ABRT.  RAM at 0xb4000002 answers 0x00 and cannot CHANGE as a
              result of a command, so the responder is the device and not memory.
              *** READ UNCONDITIONALLY. ***  It runs in its own stepped session on both
              builds rather than inside the interrupt handler: reading it only when the
              interrupt lands would make it unmeasurable on the build where the interrupt
              does not land, and the row would then fail for two reasons at once.
              `ram live` backs it up from the other side -- the identical mov.b store/load
              pair against plain RAM returns 0x5a -- so a device row reading 0x00 could
              not have been blamed on a bad hand-assembled encoding.

==========================================================================================
"SILENT" IS A POSITIVE READING HERE, NOT AN ABSENCE
==========================================================================================
An absence proves nothing until the stimulus is known to have arrived.  Each delivery leg
is broken back into the debugger with SIGINT after its spin (emul.c installs
debugger_activate as the SIGINT handler) and the ERROR register is then read BY A GUEST
LOAD.  On the PRE-FIX build both defect legs report, in one session:

    ERROR == 0x04   the free-running store reached wdc_command() and the arm set ABRT
    no BREAKPOINT   and no interrupt was delivered

The 0xAA leg carries a second, independent proof on a different channel: the
un-silenceable `[ wdc: WARNING! Unimplemented command 0xaa ... ]` fatal() appears in the
FREE-RUNNING transcript, count exactly 1.  Two channels, one fact.

The delivery oracle is `BREAKPOINT: pc = 0x8c020600`, printed by cpu_dyntrans.c through
fatal(), which has no quiet_mode early-out -- so it is un-silenceable and it NAMES THE
ADDRESS.  The rows compare that address against the interrupt vector rather than asking
the weaker question "did the process come back to a prompt", which a hundred other things
also satisfy.

==========================================================================================
THE NEGATIVE CONTROL, AND IT IS THE TRAP THIS WITNESS MOST EASILY FALLS INTO
==========================================================================================
wdc_command() opens with a no-disk early return that ALREADY sets `d->int_assert = 1` on
both builds.  Run the identical rows with no `-d` (WDCNOIRQ_NODISK=1), on the PRE-FIX
binary:

    sec f5 irq        0x8c020600  ok        <-- GREEN ON THE UNFIXED BUILD
    unimpl aa irq     0x8c020600  ok        <-- GREEN ON THE UNFIXED BUILD
    unimpl aa warn    0           FAIL      <-- and this is the row that says why
    WDCNOIRQ_RESULT=8/9

So a witness built without a disk image would have reported the unfixed binary as fixed on
exactly the two rows the round is about, and only the fatal()-count row would have
objected.  Measured, not reasoned: rows_pre_nodisk.out.
