**Q1. Scope and cost.**

| Choice | Implementation and validation cost | Benefit |
|---|---|---|
| General retrofit | Audit execution boundaries and dependencies in every converted probe; validate each conversion. Automatic inference adds another execution model to maintain. | Broad savings, with the largest upfront and continuing cost. |
| New probes only | Establish a case contract and selector checks; structure future probes around it. | No immediate saving on the expensive existing detector. |
| **New probes plus one targeted conversion** | Shared validation/reporting plus one explicit case inventory, boundary audit, equivalence assessment and negative-control panel. | Immediate, bounded opportunity to validate the claimed saving. |
| Do not build | No implementation cost. | Retains the supplied full-rerun expense for each relevant iteration. |

For the targeted conversion, a case owns its setup, sessions, computations and assertions. Requesting a row selects its complete case, including sibling assertions, plus required controls. Session ordinals, dummy results, lazy transcript proxies and source inference should not constitute the production selector.

The cost includes a full validation of the conversion; subsetting cannot supply its own initial equivalence evidence. There is no supplied basis for a credible development-hour estimate.

Also, a filtered measurement establishes results for its declared subset. Combining it with earlier results into a full table requires compatible provenance: executable and kernel identity, case commands, oracle/parser and capture settings. A changed executable cannot inherit unmeasured rows merely because their names stayed unchanged.

**Q2. The five guards are insufficient.**

A concrete counterexample is an **`accept8` filter with an incomplete producer mapping**:

1. It recognizes the existing name `accept8`.
2. It executes all three required controls.
3. It executes only the first of `accept8`’s eight sessions, substituting empty text and `alive=True` for the other seven.
4. It reports four rows out of 62.
5. Its unset path is unchanged.

All five proposed guards hold. Nevertheless, a failure detectable only in an omitted session disappears. The [actual aggregate](/C:/DocumentNoSnc/CC/GXEMUL/GXEMUL-SEC/regress/gdrom_default_probe.py:767) checks accumulated diagnostics and survival; neutral substitutions can make it green. This is a constructed counterexample, not a measured mutant result.

Guard 5 also permits a separate lie: retaining **one** passing control and dropping two required controls satisfies its “hard-fail on empty” alternative.

The contract needs these additional obligations:

- **Validate before execution against a declared inventory.** Reject empty requests and every unknown name, including unknown names mixed with valid ones. Automatically included controls must not rescue an empty match.
- **Declare the complete execution plan.** Record requested rows, expanded cases and sibling rows, required control identities, and all producer instances. `accept8` requires eight producers.
- **Reconcile execution with that plan.** Require each planned row exactly once and every planned producer accounted for. Missing rows, duplicate rows and skipped producers cannot shrink the denominator or become successful defaults.
- **Separate passing from coverage.** Report passed/planned rows separately from planned/full inventory coverage. Required controls must all complete and pass; an invalid apparatus must not be scored as a product kill.
- **Separate partial and full records.** Filtered results and completion tokens must not match legacy full-run tokens. Preserve the unset output and semantics, not merely its denominator. Keep existing full-run pins.

The current GDROM consumer [ignores process status and pins the denominator to 62](/C:/DocumentNoSnc/CC/GXEMUL/GXEMUL-SEC/regress/gate_sh_rounding.sh:513). Preserve that protection. The dissent’s substring-token warning also remains valid: appending `_FILTERED` to a legacy token does not make it distinct to a substring search.

**Q3. Gate complete cases before their sessions execute.**

Row-level filtering alone demonstrably saves no emulator invocations here. A bare label on `session()` is also insufficient: multiple assertions share sessions, while `accept8` and `dma accept` aggregate multiple sessions.

Independence needs both an auditable structure and supporting measurements:

- **Audit each case’s boundaries.** It must own its transcript variables, accumulators and setup. Shared configuration should be immutable. Audit writable files and other external state as well: a fresh emulator process does not reset host files or Python globals. Preserve intentional command sequences within a session.
- **Trace actual execution.** Associate every launch and outcome with its case and producer identity. Check expected arguments, settings and session multiplicity. The existing [fork-and-exec boundary](/C:/DocumentNoSnc/CC/GXEMUL/GXEMUL-SEC/regress/gdrom_default_probe.py:435) provides process isolation, but does not prove the surrounding case is self-contained.
- **Compare equivalent executions.** For unchanged inputs, compare full-run row observations with the same cases run individually and in changed orders. Include known failing witnesses, not just an all-green baseline. Verify that the union of individually executed cases reproduces the full result by row identity.

The separate panel should deliberately drop a required control, omit one aggregate producer, duplicate or omit a selected row, interrupt execution, and attempt to make a partial record satisfy the full-result parser. Each should produce an explicit invalid or incomplete assessment.

The remaining performance measurement is **real launch count and elapsed time for a selected case plus controls across the relevant table**. For this probe, a single-session case should require four launches; `accept8` should require eleven, versus 55 unfiltered. Their elapsed times must be measured separately. That establishes whether twenty minutes is attainable and whether the conversion earns its maintenance cost.
