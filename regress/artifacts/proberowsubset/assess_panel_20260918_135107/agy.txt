### Executive Summary & Review Findings

The proposal to retrofit general row subsetting across existing probes using the "Five Guards" is structurally flawed and rests on several stale or factually inaccurate premises. 

1. **The premise for Guard 5 is false in current source**: [`regress/gdrom_default_probe.py:570-571`](file:///c:/DocumentNoSnc/CC/GXEMUL/GXEMUL-SEC/regress/gdrom_default_probe.py#L570-L571) already contains `rows and all(...)` (repaired under #490). It does not evaluate to OK on an empty list; it prints `DEAD`. However, the five guards remain **wholly insufficient** to prevent measurement lies.
2. **The brief conflates source call sites with executed sessions**: `gdrom_default_probe.py` contains 41 `session()` call sites (38 module-level + 3 loop sites), which execute **55 emulator sessions** per run—not 39.
3. **Row-level filtering saves 0.0% runtime**: Because 38 of 41 session calls occur at the top-level module scope, statements execute before [`row()`](file:///c:/DocumentNoSnc/CC/GXEMUL/GXEMUL-SEC/regress/gdrom_default_probe.py#L427-L432) receives control.
4. **Every cited file:line reference in Codex's prior dissent has drifted**: Lines `:621`, `:1206`, `:1155`, and `:424` are all stale or mispointed due to subsequent insertions and denominator increases (e.g. `gate_arm.sh` denominator raised from 35 to 44, then to 46).
5. **A general retrofit across existing probes is a maintenance trap**: Probes must not be retrofitted with dynamic proxying or implicit dependency engines. Instead, case selection should be **required only for new probes** (and opt-in for heavily reused existing probes rewritten into explicit case functions).

### Adversarial Answers to Review Questions

#### Q1: Build it, build it narrower, or not at all? What does each cost?

1. **BUILD-IT (General Retrofit Across Existing Probes) — REJECT**:
   - **Cost**: Unacceptably high engineering and soundness cost. In `gdrom_default_probe.py` alone, 38 module-level session calls must be refactored. Shifting them into functions or behind lazy proxy objects risks subtle variable scoping regressions (e.g. cross-session accumulation in `t += tt` for `accept8` and `dma accept`, or status sharing via `alive = alive and aa`).
   - Gate contracts (e.g. [`gate_arm.sh:1307`](file:///c:/DocumentNoSnc/CC/GXEMUL/GXEMUL-SEC/regress/gate_arm.sh#L1307)) hardcode literal emitted row counts (`46`), so running subsets inside CI breaks existing gates unless separate gate modes are introduced.
2. **DO-NOT-BUILD — REJECT**:
   - **Cost**: Perpetuates the 4-hour mutation table bottleneck and leaves authoring patterns unstructured, encouraging future probes to duplicate the un-subsettable module-level anti-pattern.
3. **BUILD-IT-NARROWER (Adopt Codex's Proposed Strategy) — ACCEPT**:
   - **Cost**: Near zero for legacy probes (they remain untouched, stable, and preserve their historical kill-table logs).
   - **Contract for New Probes**: Require **explicit case functions or table-driven cases** where each case owns its session(s), assertions, and declared dependencies (exemplified by [`m88k_idle_probe.py:178`](file:///c:/DocumentNoSnc/CC/GXEMUL/GXEMUL-SEC/regress/m88k_idle_probe.py#L178)).
   - **Targeted Exceptions**: An existing probe may only be converted when an individual, repeatedly expensive round explicitly justifies it, ships its own dedicated refactoring panel, and proves permutation invariance.

#### Q2: Are the five guards sufficient? Name a filter that passes all five and still makes a measurement lie.

**THE FIVE GUARDS ARE NOT SUFFICIENT.** They define an incomplete execution and validation contract. Here are four concrete filters that pass all five guards while generating measurement lies:

1. **The Incomplete Control Set Lie (Surviving Sub-Control)**:
   - In [`gdrom_default_probe.py:534-560`](file:///c:/DocumentNoSnc/CC/GXEMUL/GXEMUL-SEC/regress/gdrom_default_probe.py#L534-L560), controls require three distinct operations: `live` (RAM), `devsig` (IPRD reset), and `impl ok` (CNTHI +0x94 readback).
   - Filter request: `--rows=live,rd_lo`.
   - *Guard check*: Matches 2 rows (Guard 1 pass); named rows exist (Guard 2 pass); prints `2 of 62` (Guard 3 pass); unset path untouched (Guard 4 pass); `live` is a control row so control set is non-empty (Guard 5 pass).
   - *The Lie*: `rows and all(...)` at line 571 evaluates to True on `[('live', True)]` and prints `GDROM_DEF_CONTROL=OK`. But `devsig` and `impl ok` never ran! A mutant that completely breaks register window decoding reports `GDROM_DEF_CONTROL=OK`, certifying the run on an apparatus whose device dispatch was never tested. Non-empty control set $\neq$ Complete control set.
2. **The Multi-Session Partial Execution Lie (`accept8` / `dma accept`)**:
   - [`accept8`](file:///c:/DocumentNoSnc/CC/GXEMUL/GXEMUL-SEC/regress/gdrom_default_probe.py#L769-L774) expects a message count of `0` across 8 implemented offsets.
   - Filter request: Selection includes `accept8`, but session gating filters out 7 of the 8 sessions.
   - *The Lie*: The 1 executed offset produces no default-arm message (`len(SAYS.findall(t)) == 0`). `accept8` reports `ok` (PASS). All five guards pass, but the probe completely misses a mutant that broke any of the other 7 offsets.
3. **The Companion Assertion Omission Lie (Liveness vs. Value)**:
   - In [`gdrom_default_probe.py:582-595`](file:///c:/DocumentNoSnc/CC/GXEMUL/GXEMUL-SEC/regress/gdrom_default_probe.py#L582-L595), one session produces transcript `t` used by both `rd lo` (wants `survived`) and `rdlox1` (wants count `1`).
   - Filter request: `--rows=rd_lo` (omitting `rdlox1`).
   - *The Lie*: On a hung emulator, `alive` remains True (as documented under `probetimebased` in [`tools/pipeline/matrix.html:2902`](file:///c:/DocumentNoSnc/CC/GXEMUL/GXEMUL-SEC/tools/pipeline/matrix.html#L2902)). `rd lo` reports `ok` (PASS). The companion value assertion `rdlox1` that would have failed with count `0` was omitted. The run passes all guards on a wedged emulator.
4. **The Legacy Gate Token False Completion Lie**:
   - At [`regress/gate_arm.sh:1242,1246`](file:///c:/DocumentNoSnc/CC/GXEMUL/GXEMUL-SEC/regress/gate_arm.sh#L1242-L1246), the gate runs the probe with `|| true` and tests `grep -q "OPUS497T_DONE"`.
   - *The Lie*: If a filtered run emits `OPUS497T_DONE_FILTERED`, the unanchored substring grep in `gate_arm.sh` matches and returns success. A partial run passes CI with 90% of rows unexecuted.

#### Q3: Session-gating vs row-gating, and proving row group independence

- **Which Granularity?**
  - **Neither raw session-gating nor raw row-gating is sound.** 
  - Gating must operate at the **Case level** (a named execution unit that binds one or more sessions to one or more rows, declaring its companion assertions and required controls).
  - Row-gating is inert in module-level scripts. Session-gating in isolation fails because 1 row can require $N$ sessions (`accept8`), and $M$ rows can share 1 session (`rd lo` + `rdlox1`).
- **How Must a Retrofitted Probe Prove Row Groups Are Independent?**
  A retrofitted probe cannot declare independence by assertion or code reading. It must provide **three empirical proofs**:
  1. **Permutation Invariance**: Running all cases in reverse and randomized orders yields byte-identical row output and vector hashes.
  2. **Isolation Invariance**: Executing each case individually in an isolated process produces the exact same `got` value and status as when executed within the full batch.
  3. **Lexical Isolation**: No case reads from or writes to mutable module-scoped variables (`t`, `alive`, `how`, `rows`) populated by other cases.

### Final Verdict

**GO-WITH-CHANGES**

*(Note: If evaluated strictly as a mandate to implement the 5-guard specification across legacy probes, the verdict is **NO-GO**. It is **GO-WITH-CHANGES** solely under Codex’s narrower architecture with the following mandatory changes applied):*

1. **Do not retrofit existing probes wholesale**: Keep legacy probes intact. Apply row/case selection strictly to new probes, and permit conversion of legacy probes only on an individual, opt-in basis backed by an explicit refactoring panel.
2. **Replace Guard 5**: Discard the false premise that `rows and` evaluates to OK on `[]`. Replace Guard 5 with a requirement for **exact control identity execution**: a filtered run must execute 100% of defined mandatory controls (`live`, `devsig`, `impl ok`), or hard-fail.
3. **Enforce Pre-Execution Inventory Validation**: Unknown row names, empty selections, or requests where controls auto-rescue a zero-match filter must fail immediately with a non-zero exit before any emulator session spawns.
4. **Mandate Distinct Completion Tokens**: Filtered runs must emit a completion sentinel that cannot substring-match legacy tokens (e.g. `OPUS497T_FILTERED_RUN_COMPLETE`, ensuring `grep -q "OPUS497T_DONE"` fails loudly).
5. **Enforce Case-Level Boundaries**: The scheduling unit must be an explicit Case function owning its session(s), sibling assertions, and dependencies.
