## Q2 — The five guards are not sufficient

The guards police **row bookkeeping and denominators; none of them constrains session provenance**, which is where the feature actually operates.

**Named filter that passes all five and lies:** request `accept8`. A session-gating filter attributes only the one directly-assigned session to that row — the other seven sit in the module-level loop call sites (READ, codex) and are attributed to no selected row. Skipped sessions contribute "empty text and alive" (READ, codex's failure table); accept8's eight-way aggregate passes on **one real emulator run**. Guards 1–5 all pass: nonzero match, name exists, "1 of 39" printed, unset path untouched, controls exempt. In a kill table this silently flips a mutant's status. All elements are in the packet.

Two cheaper ones: (i) Guard 5 is an **OR** — an implementation choosing "hard-fail on empty control set" can drop 2 of 3 controls; `all(rows)` over the survivor prints OK (codex: "nonempty still does not mean complete"). Exemption must be mandatory, and control *sessions* force-included, which the row-worded guards never say. (ii) Guard 1's "nonzero" is ambiguous about whether auto-included controls count — if yes, a zero-match request is rescued by controls. Also guard 3 never pins M's referent (a filtered "5 of 5" is the "convincing denominator" codex warns of), and **no guard addresses the completion token**: the gate ignores exit status with `|| true` and substring-searches `OPUS497T_DONE` (READ), so a filtered run emitting that token (or a superstring) is logged as a full completion. Add codex's four contract items plus a distinct, non-colliding token as guards 6–9. ## Q3 — Sessions, with a caveat; and how a retrofit proves independence

The granularity claim **survives testing**: a row()-level filter passes all five guards by construction (they only constrain requests and printed bookkeeping) and saves nothing *given* module-level eager sessions — which both sources assert and which eager argument evaluation independently supports (READ codex, REASONED valid). But the brief's framing is incomplete: session gating is not thereby "the fix"; it is only sound with a correct row→session closure, which the guards never check. The hard part is the closure, not the gate.

A retrofitted probe proves independence three ways, in descending strength: (1) **structural** — the closure is explicit (case functions, or a reviewed inventory), with a runtime invariant that every executed session is claimed by a selected row or the control set; an unclaimed session is a dependency bug and fails loudly; (2) **behavioral negative control** (absorbable into the owner's mandated controls): subset-equivalence — selected rows' printed lines must byte-match the unfiltered run on fixed binaries including ≥1 mutant, plus a fresh-fork count equal to closure size; (3) honest limit: equivalence on sampled binaries is a control, not a proof — a missed dependency that doesn't change output on tested binaries passes — so the proof must remain structural, re-run per probe revision, not per table run.
