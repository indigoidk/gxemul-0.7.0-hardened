## Q1. Build it / narrower / not at all — and what each costs

**Not at all** keeps the measured bill: a kill table cannot re-score three sessions, so five new rows still cost a full probe × every mutant. Measuring seats already dodge this with throwaway probes; that workaround does not accumulate. New probes will keep being written in the expensive idiom (this tree is still doing that). Cost: zero code, unbounded table time, and a policy that will be re-litigated the next time a 4-hour table shows up.

**Build the general retrofit** (env/`--only` inside `row()` or a skip inside `session()` across the module-level family) is the option the five guards describe, and it is the one that lies. Getting selection without editing ~41 gdrom call sites means dummy results, lazy proxies, or source analysis. Codex’s three rejections hold when checked against this file:

* Dummy `("", True, …)` into `accept8` / `dma accept` keeps a **want-0 count** green after one real session.
* `t, alive, how = session(...)` unpacks before `row()` runs, so a filter in `row()` cannot un-fork.
* `argv[2]` is not a free selector slot. On gdrom it is the **kernel path**. Copying `m88k_idle_probe.py`’s `ONLY = sys.argv[2]` onto gdrom would treat the kernel as a row name, match nothing, and print `0/0`. `fbpending_drain_probe.py` already uses `_opt("--only")`; `mips_fold_probe.py` uses argv[3]. There is no common flag grammar to hang a “general” filter on.

Cost of the general form: a hidden second execution model in every probe reviewers currently understand by reading top to bottom, plus a gate-token audit, plus kill-table drivers taught to pass `--only`. The typing saved at 41 call sites is not the cost.

**Narrower (this verdict)** is three separate deliverables, not one feature:

1. **A selector helper with the strengthened contract below**, used by new table-driven probes. Negative controls belong in **this** round: unknown name mixed with valid names; empty selection not rescued by auto-included controls; filtered completion token that does **not** substring-match the legacy token; unset path byte-identical, including no new `FULL` banner.
2. **Policy:** new probes select **named cases**. A case owns its sessions and its assertions. A requested row expands to its case plus the required control identities. Sibling assertions on an already-built transcript are free and should run. Do not copy `m88k_idle_probe.py` / `mips_fold_probe.py` as the validation contract — they are the in-tree negative controls.
3. **No conversion of `gdrom_default_probe.py` in the filter round.** A later table that would otherwise re-run ~55 sessions may convert **that** probe to cases, as its own diff, with the independence test in Q3. That is targeted investment, which the evidence supports.

**Recording/replay** is the one cheap mechanism that does not need per-site edits: wrap the per-probe `session()` so a new assertion that needs no new debugger commands can re-score a retained transcript. Ordinary row output is not a transcript. The cache key must be mutant identity + probe version + commands + kernel + settle — **not** binary pathname (the table reuses pathnames). This is evidence reuse, not live row selection. It covers the half of “add a row” that is a new `row()` on an old session; it does not cover `accept8`’s eight forks.

The owner’s “own round, own panel, own negative controls” still applies. It does not license a tree-wide skip hook.

## Q2. The five guards are not sufficient

They constrain the **filter API**. They do not constrain producers, completion tokens, what `M` is, or which controls are required. A filter can pass all five and still make a measurement lie.

**Lie A — shrinking `M` (Guard 3 names a shape, not a meaning).** `--only accept8`, controls exempt. Prints `GDROM_DEF_RESULT=1/1` (or `3/3` with controls). Nonzero matches, names exist, `N of M` is printed, unset path untouched, controls ran. A kill table that scores `passed == len(rows)` reports a clean sweep of a 1-row instrument. The weekly gate is saved only because `gate_sh_rounding.sh` pins the denominator at **62**; kill tables do not.

**Lie B — dummy remainder of a want-0 aggregate (the `accept8` / `dma accept` shape).** Session-gate on the row name; run one of eight (or one of five); skipped sessions return empty text and `alive`. Concatenation preserves a SAYS/DMA_SAYS count of 0, which is the want. Guards 1–5 never look at producer cardinality. This is a measurement of one offset claiming to be a measurement of eight.

**Lie C — Guard 5’s own `OR`.** “Controls exempt” (always run the declared control identities) is the strong form. “Hard-fail on an empty control set” is not equivalent: `--only live` leaves `GDROM_DEF_CONTROL=OK` with `devsig` / `live64` never executed. Codex’s “nonempty still does not mean complete” is the remaining hole after the `rows and` repair. `sgi_de_width_probe.py` is closer (`rows and rows[0][1] and rows[1][1]`) and still keys **position**, not identity — a filter that skips the first two rows makes that line certify whatever landed in slots 0 and 1.

**Lie D — completion substring, outside the five guards.** `grep -q "OPUS497T_DONE"` matches `OPUS497T_DONE_FILTERED`. Same shape at `OPUS498T_DONE`. Gdrom’s `GDROM_DEF_RESULT=` is safer because of the `=`, and then a filtered `GDROM_DEF_RESULT=3/3` still satisfies the **completion** grep; only the literal-62 pin fails the gate. A filtered kill-table log that emits the legacy result line looks complete.

**Lie E — skipped rows counted as measured.** `row()` emits `got=SKIPPED want=SKIPPED ok`. Denominator looks full. `fbpending_drain_probe.py` already feeds `dict(status="SKIPPED", ...)` into the same print/score path its live arms use.

Guards the spec still owes, if anything ships:

* Validate against a **declared inventory before execution**; unknown mixed with valid is a hard fail; auto-included controls must not rescue a zero-match request.
* Print **intent** first: requested names, expanded case set, planned row identities, full inventory `M`, planned session count.
* Complete against that **plan**: those identities **exactly once**, not `passed == len(rows)`.
* Filtered runs use a completion token that **does not contain** the legacy token; unset output stays byte-identical, including the absence of a new banner.
* Required **control identities** (names, not `len(rows) > 0` and not `rows[0]`).
* `M` in `N of M` is the **full inventory** on the unset path and a **distinct** filtered record otherwise — never a silently shrunk pin.

## Q3. Session-gating vs row-gating — tested, not accepted

**Row-gating saves nothing on this idiom.** `row()` only appends and prints. Every `session()` in `gdrom_default_probe.py` runs at import/module-body time, before any later `row()` could refuse it. I did not accept the 36/39 figure; I counted call sites in the current file (41, all module-level). The cost model is sessions × settle, and `row()` is not on that path.

**Session-gating is necessary and not sufficient.** The scheduler needs the **row → producer set** relation:

* one row, many sessions: `accept8` (8), `dma accept` (5)
* one session, many rows: trigger loop (`rd lo` + `rdlo x1`), `scan` + `scan uniq`, `pcc2` `genctl ctl` + `genctl ctlq` on one `t`, `c040 kill` + `c040 attrib` on one `t2`

A label on `session()` without that expansion is how Lie B is built.

**How a retrofitted probe would prove row groups are independent** (this is the missing discharge, not a vibe):

1. **Static split.** A group is the smallest set of `session()` calls whose `cmds` or whose `row()` gots read another member’s `t` / `alive` / `how`. Device state is already split by `pty.fork()`. Python accumulation is the only coupling that matters. `accept8` is one group, not eight; `dma accept` is one group, not five.
2. **Dynamic slice.** Full run, save `(name, got, want, ok)` **by name** (never `GDROM_DEF_VECTOR` position — that line is a bitstring with no names). Run only group S. For every name in S, the tuples must match the full run. Merge by name.
3. **Negative control the want-0 aggregates require.** Step 2 is **blind** for `accept8`: dummy empty sessions produce `got=0` just like the real eight. The independence test must also pin **planned session count** (or a per-offset positive observable). A group whose channel cannot vary when producers are dropped is vacuous by construction — the CHANNEL line, aimed at the selector.

Until (1)–(3) hold for a given probe, its rows are not composable and `--only` on that probe is not licensed, five guards or not.

## Disposition relative to the 2026-09-08 dissent

Codex’s **mechanisms** stand: no cheap general retrofit, dummy/lazy/AST shortcuts fail, producer relation is the real scheduler, replay is a different (cheaper) tool, `m88k_idle` is existence of a boundary rather than a contract, filtered completion must not substring-match the legacy token.

What I would not copy is the **close-as-documented-only** half, if that means new probes keep shipping without a case boundary. The tree already grew three inconsistent selectors (`m88k_idle`, `mips_fold`, `fbpending --only`) with shrinking denominators and dummy SKIPPED records. “Required for new probes” with no helper is how a fourth incomplete selector lands.

So: **BUILD-IT-NARROWER** — helper + new-probe policy + strengthened contract, in the owner-ordered own round, with the negative controls above. Existing module-level probes stay unchanged until a named conversion. Do not fold this capability into `probeslow`; that row withdrew `--only` for **gate** reasons (pinned denominator, battery clock). Kill-table re-measurement is a different consumer, and it is the one that still cannot score one row.
