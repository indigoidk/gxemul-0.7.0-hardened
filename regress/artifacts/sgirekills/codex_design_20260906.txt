The four disabled exits are **not a sound blanket precedent**:

- **`unimplemented dst_mode … horrible_getputpixel`:** logs on every call, assigns `*color = random()`, then returns. A put writes nothing but mutates its caller’s color; a failed source get supplies random data that the caller can subsequently write elsewhere. Replace this with explicit failure propagation and a latched announcement.
- **`if (!(tileptr & 0x80000000))`:** returns before memory access, without changing `*color`. This avoids aliasing an invalid pointer to tile zero. It safely suppresses a put, but a get leaves foreground/background—or the previous copied pixel—in place. Callers initialize these values; the defect is stale/substitute color, not an uninitialized caller variable. Failed reads must prevent the dependent destination write.
- **`unimplemented XFER addr_src`:** this is in `draw_primitive()`, **not `DEVICE_ACCESS`**. It logs and continues. `step_y` and the stride registers do not govern the subsequent traversal; non-linear copying advances using primitive directions. Implement those semantics or decline the command.
- **`unimplemented dst_y_step`:** logs and continues; the value never controls stepping. Tiled transfers derive direction from endpoints, while linear transfers fill contiguously. That is not a faithful arbitrary-stride fallback.

By source tracing, the six read exits and five transfer exits are guest-reachable. The latter include named features; there is no basis here for asserting that “no driver does this.” The twelfth exit is impossible for **any** driver.

`horrible_getputpixel()` is per-pixel, called inside line, rectangle, and tiled-MTE loops, sometimes repeatedly per pixel. **None of the twelve uncommented exits is inside it.** Use distinct per-device `d->warned` bits, following `SGIRE_W_UNMAP_RD/WR`; validate command-wide restrictions before loops and propagate pixel failures.

Operationally, however, only **11** exits are reachable: seven mentions are comments, and an eighth is unreachable code.
