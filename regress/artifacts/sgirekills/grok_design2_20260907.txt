## Q2 — each ACCEPT read returns the store’s inverse; the read path does not index today

`odata` is already `= 0` at handler entry. SGI is `EMUL_BIG_ENDIAN`. Deleting `exit(1)` and falling through is **member 2** (silent 0), not member 4.

Index is computed **only on WRITE**. A guest `ld` never reaches it. Out-of-range on the read-kill path: there is no index, so there is no OOB behaviour to preserve. Guest `len==8` writes are in bounds at every window (8-byte alignment is supplied by the MIPS core / unaligned helper). Debugger `put d` is the `sgilinearoob` / TLB-loop exception and is not a guest path.

**TLB_A/B/C** — `uint16_t[256]`, `tlbi = ((relative_addr & 0x1ff) >> 1) & 0xff`, four BE halfwords per `sd`:

```c
i = ((relative_addr & 0x1ff) >> 1) & 0xff;
odata = ((uint64_t)d->re_tlb_a[i]     << 48) |
        ((uint64_t)d->re_tlb_a[i + 1] << 32) |
        ((uint64_t)d->re_tlb_a[i + 2] << 16) |
         (uint64_t)d->re_tlb_a[i + 3];
```

Same for `_b` / `_c`. Last guest slot `+0x1f8` → indices 252..255, in range. Naive `odata = d->re_tlb_a[i]` keeps 16 of 64 bits.

The store uses `data[hwi]*256 + data[hwi+1]` (bus bytes), not `idata`. On this BE machine they agree; the packing above is the inverse of that byte loop through `memory_writemax64`.

**LINEAR_A/B** — `uint32_t[32]`, `tlbi = ((relative_addr & 0x7f) >> 2) & 0x1f`, split of `idata`:

```c
i = ((relative_addr & 0x7f) >> 2) & 0x1f;
odata = ((uint64_t)d->re_linear_a[i] << 32) | d->re_linear_a[i + 1];
```

Last guest slot `+0x78` → 30 and 31, in range. Naive `odata = d->re_linear_a[i]` drops `[i+1]`. Claim scope: *returns what the store recorded*, including the PROM’s sign-extended pattern the comments already describe. Not “hardware-faithful LINEAR readback.”

**TEX** — if declined: `odata` stays 0, tail runs (same as a `#497` `lw`). If ACCEPT after `sgitexindex`: same four-halfword pack with `i = ((relative_addr & 0xff) >> 1)` over `[0x1600, 0x16e0)`. Mirrored `>> 3` is the form already rejected.

## Q3 — the `lcabadval` asymmetry is real for `ld` value rows, false for `lw` / survival / inherited `ld kill`

`lcabadval`: legal writes survive with the guards in place, so an accept-only suite is green on HEAD *and* under verbatim reinstatement.

- New `ld` + packed-value row: **red on HEAD** (host dies vs want stored word). Floor (a) holds.

- Inherited `ld kill` with want `exit1+txt`: **green on HEAD**, red after a correct fix. Re-pin first, measure the committed binary red, then edit.

**Reinstating any one of the six reddens the detector only if that arm has its own row.** One row per arm is required. A single “any RE `ld` survived” session can miss a site-omission mutant.

- delete `exit(1)`, do not assign `odata` → host lives, guest sees 0
