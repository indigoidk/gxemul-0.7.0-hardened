| Windows | Backing array | Starting index | Complete result |
|---|---|---|---|

The numeric reconstruction is:

```c
/* TLB_A/B/C */
odata = ((uint64_t)H[i]     << 48) |
        ((uint64_t)H[i + 1] << 32) |
        ((uint64_t)H[i + 2] << 16) |
         (uint64_t)H[i + 3];

/* LINEAR_A/B */
odata = ((uint64_t)W[i] << 32) |
         (uint64_t)W[i + 1];
```

Cast **before** shifting. These formulas invert the stores for this SGI machine’s configured big-endian ordering. Preserve the [common tail](/C:/DocumentNoSnc/CC/GXEMUL/GXEMUL-SEC/src/devices/dev_sgi_re.c:665), which serializes `odata` and returns success. Writing `data` directly without changing that tail would let the tail overwrite the result.

For aligned accesses, TLB starts range through 252 and LINEAR starts through 30, so the complete groups fit. Length alone does not establish those bounds for arbitrary callback callers. Also, your single-element warning needs a small qualification: it preserves **16 bits for TLB, 32 bits for LINEAR**.

There is no unique “smallest escaping edit” without specifying the row’s address, value and surrounding state. Concrete weaknesses are:

| Check or mutation | What one round-trip row establishes—or misses |
|---|---|
| Omit a packed lane | Distinct, nonzero expected lanes expose this; zero-filled lanes can conceal it. |
| Read starting at `i + 1` | Distinct adjacent lanes expose the read-only indexing error. |
| Change TLB read mask `0x1ff` to `0xff` | A one-token defect passes a row at `+8`, while aliasing the upper half of the window. LINEAR has the analogous `0x7f` → `0x3f` escape. |
| Change store and read indexing consistently | Round trips can remain correct despite wrong cell placement. Even numerous round trips cannot disprove a shared permutation without an independent position anchor. |
| Move the tested address into the catch-all | A completed read returns zero. A nonzero full-value expectation catches this; survival or zero-only expectations do not. |
| Shrink a boundary away from the tested address | An interior row remains green; boundary coverage is needed. |

The existing `ACC_VAL`, `0x1122334455667788`, also leaves every halfword’s highest bit clear. A repair that clears bit 63 passes that value. Use varied values, including high bits, distinct adjacent groups, and retain independent cell-position checks. These are arithmetic/source-derived outcomes, not measured emulator mutation results.
