## Q1 -- IS THE FIX RIGHT? Yes, block by block.

The DIRECTION SPLIT is the right shape. `idata = memory_readmax64(...)` is the big-endian composed value, so at `len>1` the low lane `(uint8_t)idata` is the highest-address neighbour's byte; a bare `idata & mask` store would corrupt (`st.h 0xAABB` to GENCTL -> `0xBB`, VECBASE's lane). DECLINE is the honest, conservative disposition for all twelve byte-register blocks; COMPOSE needs lane semantics not on disk (correctly filed).

- **Reads ACCEPT by fall-through is right.** The top-of-function `memcpy` serves raw bytes in address order (width-correct). Every store sits under `if (writeflag == MEM_WRITE)`, so a fall-through read never stores. SCCRXIACK (0x27) is the 13th arm -- no width guard, ignores `idata`, INT-clear side effect width-invariant -- correctly excluded from the twelve. IPL's read-side print is width-invariant too. No block's read has a side effect the memcpy skips.
- **`break`/tail:** the enclosing tail is a bare `return 1;`; every decline `break`s to it, nothing common skipped (I read all exits), return value stays 1 (handled).
- **Latch is per-instance and per-block as claimed** (`d->warned` uint32_t, auto-incremented enum, one bit each). One announce per block per instance is the right granularity (#497 reasoning). The compile-time typedef tests the *actual* field via `sizeof(((struct pcc2_data*)0)->warned)` -- it fixes the pass-noted "bare `<=32` tests a literal" hole and fails the build if `warned` is narrowed below 12 bits.
- **Reachability holds:** m88k alignment-checks non-byte accesses before `memory_rw` (`cpu_m88k_instr_loadstore.c:168`), `relative_addr %= PCC2_SIZE` keeps parity -> six even declined blocks (GENCTL 0x2, T2CTL 0x16, T2ICR 0x1a, SCCERR 0x1c, SCCTX 0x1e, IPL 0x3e) guest-reachable at len 2; only SCCERR is 4-aligned; six odd blocks operator-only (measured).
- **What a real guest would be refused: nothing.** OpenBSD 2.2 (clock.c, cl.c, if_ie.c) accesses every fix-declined register as `volatile u_char` (byte). Its only *wide* accesses are u_long writes to `t1cmp`/`t1cntr`/`t2cmp`/`t2cntr` (offsets 0x4/0x8/0xc/0x10) -- the `memcpy`-ACCEPT arm, **not one of the twelve**. Had the fix declined that arm it would have broken the clock. This is the strongest evidence the split is drawn in the right place.
