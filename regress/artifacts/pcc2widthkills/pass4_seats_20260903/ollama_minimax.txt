## 2. THE SMALLEST EDIT THAT BREAKS THIS AND PASSES 96 ROWS

**Edit:** `d->warned |= (1u << bit);` → `d->warned |= 1;` (remove `<< bit`, 7 characters; or equivalently `|= (1u << 0)`, 3 characters changed).

**What it breaks:** The latch for sites 1-11 (VECBASE, PSCALEADJ, TxCTL/TxICR, SCCERR, SCCICR, SCCTX, SCCRX, SCSIICR, IPL, MASK, plus T1CTL/T1ICR labels). With `|= 1`, only bit 0 is ever set. Sites 1-11 check bits 1-11 which are never set, so their `!(d->warned & (1u << bit))` is always true — they announce on every wide write, not just the first. The stated property "dropped `|=` floods (same site twice must announce ONCE)" is violated for 11 of 12 sites.

**Why it passes 96 rows:**

- **`latch all` (12 `put h 0x0003`):** site 0 announces once (bit 0 set after first write); sites 1-11 each announce once (one write per site in this row). Count: 12. **Stays green.** This is the row the brief asks me to name.
- **`latch same` (2 × st.h to GENCTL):** first write announces (bit 0 set); second write checks bit 0 (set), doesn't announce. Count: 1. Passes.
- **`latch two` (st.h to GENCTL then T2CTL):** GENCTL announces (bit 0 set); T2CTL checks bit 1 (still 0 with `|= 1`), announces. Count: 2. Passes. (Order-dependent — if T2CTL were first, GENCTL's second write would not announce; but the probe fixes the order.)
- **All `dcl` rows:** each does one write per site; each announces once. Pass.
- **All readback / survival rows:** unaffected.

**REASONED.** No row tests *repeated* writes at the same non-GENCTL site, so the latch break is invisible.
