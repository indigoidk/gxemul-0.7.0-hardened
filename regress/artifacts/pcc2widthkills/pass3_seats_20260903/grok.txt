### (b) `latch all` is a sound cardinality row — with the session as the warrant

Re-derived, not taken from PRETABLE:

- `d->warned` is written only in `pcc2_width_decline` (`|=` once in the file). Init `memset` zeroes it. `DEVICE_TICK` only calls `reassert_interrupts`.
- Debugger `put h`: warns if `addr & 1`, then **one** `store_16bit_word` → one `memory_rw(len=2)` (`debugger_cmds.c` ~1512–1523, `memory.c` ~818–828). Not two byte stores.
- `BLOCKS12` is twelve offsets, one per **block** (T2CTL 0x16 not T1CTL 0x17). Twelve first-time announces ⇒ 12. A shared bit ⇒ 11. Measured: M1 77/78 `latch all` 11; `M_IDATA_GENCTL` 80/82 `latch all` 11.
- BASE `latch all` = 12 (`M_IDATA_GENCTL.out` on the fix side, and the 82/82 BASE) proves this session contributes **zero** extra `DECL` strings and **zero** pre-set bits. Boot traffic cannot hide an alias: a pre-set bit would already have made BASE 11.
- Two blocks on one bit cannot still read 12 in this session: twelve puts, each offset once, no second touch, `DECL` is the specific `"-- declined.  (once) ]"` tail. Compensation would need a 13th matching print. There isn’t one.

`latch same` is still required for a dropped `|=` (each block once still counts 12). The pair is the latch axis, as the builder wrote. I agree.

### (c) `op pscale noig` is a real channel; 0 is right on the fix

The body is only:

```c
fatal("[ pcc2: write to PSCALEADJ ignored (value 0x%02x) ]\n", (int)idata);
```

`fatal()` returns. The row counts `"PSCALEADJ ignored"`. That substring is **not** in the decline line (`PCCTWO_PSCALEADJ -- declined`). Session is a single `put h 0x0303` — no legal byte write that would print it on the fix. On the fix the `break` runs first ⇒ 0. Measured: BASE green; `M_FALL_PSCALEADJ` 81/82 got **1**. Channel is real.

### (d) The three new readbacks are correct on the fix; they red as a **readback**, not a death

Walked, not estimated:

- `memory_readmax64` / `store_16bit_word` are big-endian: `put h 0xaab8` ⇒ `idata = 0xaab8`, `(uint8_t)idata = 0xb8`.
- SCCICR: `0xb8 & 0x1f = 0x18`. **Measured** (`p3c_M_FALL_SCCICR.out`: `rb sccicr` got `0x18`, want `0x1f`, **FAIL**, host lived).
- SCCRX / SCSIICR: `0xb8 & 0xdf = 0x98`.
- Legal `st.b 0x1f` is in-mask for both `0x1f` and `0xdf`. On the fix the `put h` is declined, byte stays `0x1f`. BASE 82/82 includes all three green.

**Would `reassert_interrupts` kill the host?** Only `GENCTL & PCC2_C040` (`0x04`) does `exit(1)`. Init sets `GENCTL = 0x00`. These sessions never write GENCTL. `PCC2_IRQ_INT` is `0x20`; neither `0x1f` nor `0x18`/`0x98` has it, and SCCRX’s store mask `0xdf` **clears** bit 5. SCCICR is not even read by `reassert_interrupts` (only T1/T2 ICR, SCCTX, SCCRX, SCSIICR). So a landed FALL reds the value, it does not take `pcc2c040kill`. The row already prints `"died"` if `alive` is false; the measured FAIL is `0x18`, not `died`. The record should say that.
