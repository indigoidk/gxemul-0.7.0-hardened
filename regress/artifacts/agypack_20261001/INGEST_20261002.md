**CHECKED HERE: two of codex's five gdromdma flags, both TRUE.**  (1) The dossier says all four recognised SH names can
be forced on the Dreamcast; `src/include/cpu_sh.h:62` makes SH7708R architecture 3 and `src/cpus/cpu_sh.c:207`
registers the CPU's interrupts only when `arch == 4`, so the ASIC's interrupt lookup has nothing to connect to.  agy's
audit restates the true half (four names are recognised) and never tests the false half.  (2) The dossier says a
non-Dreamcast machine lacks the device; `src/core/emul_parse.c:659-673` accepts `device(...)` entries from a
configuration file for any machine.  So agy ratified where codex audited: this is the carrier's "locally-true
restatement" shape, and **codex's twelve flagged sentences stand** (two verified, ten unrefuted).  Read the codex audit
beside each dossier before its round, as before.

What agy's dossier answers DO add is in their machinery sections, each worth one line in the round's brief:
* **ppcbat:** `ppc_exception()` overwrites SRR1 unconditionally (`cpu_ppc.c:327`), so an ISI cannot carry its SRR1
  bit-4 cause without a change to the delivery function itself -- the BAT round is not only a call-site change.
* **ppcllsc / ppcfused:** no program-interrupt machinery exists (six exceptions defined, no 0x7), and enabled FP traps
  are never delivered (`cpu_ppc.c:1941-1942` says so) -- agrees with the codex and Opus readings.
* **armvector:** the unbounded re-entry is not only the prefetch path: the data-abort delivery (`memory_arm.c:273`) and
  the IRQ delivery from the dyntrans loop (`cpu_dyntrans.c:209`) reach `quick_pc_to_pointers()` the same way.
* **armbyteorder / armldmuser / armcoproc:** a per-CPU warn-once latch does not exist in `struct arm_cpu`
  (`cpu_arm.h:136-288`; `warned_undef` at `cpu_arm_instr.c:4698` is a file static), so every ARM "decline and announce
  once" round has to add one.
* **gdromdma:** device-access exception delivery in `memory_rw.c:603-625` exists for MIPS and M88K only, so FAULT is
  not available to an SH device round.
