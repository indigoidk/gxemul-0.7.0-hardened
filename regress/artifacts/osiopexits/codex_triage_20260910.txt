The manual supports the distinction between legal unimplemented operations and illegal transfer-control combinations. Treating every unsupported instruction as hardware IID would therefore conflate two different conditions. [SYM53C710 manual, chapter 5](https://datasheet4u.com/pdf/1312314/SYM53C710.pdf)

The status obligations need one qualification: **status and interrupt are overlapping obligations, not separate populations.** The existing `osiop_update_sip_and_dip()` exposes pending controller status even when interrupts are masked; `osiop_reassert_interrupts()` applies the masks. A repair must preserve both polling and interrupt-driven observation.

Conversely, **none of the fourteen exits intrinsically owes a fabricated SCSI target status byte or COMMAND COMPLETE message.** A sequencer error can require controller-level recovery while a command remains outstanding. It must preserve that command’s state or terminate it through an explicit recovery contract. It must not report GOOD, free the transfer as successfully completed, or continue with invented results.

The actual target-status and completion sequence lives in `STATUS_PHASE` and `MSG_IN_PHASE`. The backend-failure branches marked `#118/#119` are already de-fatalized and are outside this fourteen-site census. Thus the audit’s blanket E3 description overstates the obligation for the register default and redundant equality check.

For the top two, these are the smallest honest fixes:

| Row | Option-set member | Available here? | Required scope |
|---|---|---|---|
| **Register default** | **Decline + latched announce** for unsupported writes; preserve existing read responses with an explicit fallback policy | **Yes**, but not through a bare deletion | Reject writes before mutation, or restore the complete affected value. Preserve computed `odata` and its serialization. A readable backing value does not prove that every corresponding write implements the register’s behavior. |
| **Redundant table-MOVE equality check** | **Delete** | **Yes** | Remove the equality restriction and its now-unused `ofs1` local. Continue through the existing table-descriptor path. |

The first row has a concrete trap: the generic byte path stores before dispatch, and the word path also stores to registers such as DNAD and ADDER before reaching the unhandled-register default. Restoring only `oldreg` would not undo those word stores. A blanket backed-accept repair would also enable SOCL writes and change the reserved-phase reachability finding below.

For the second row, the manual identifies the first word’s table-MOVE count field as unused and takes the descriptor displacement from the second word. The implementation already uses that second-word displacement. The equality check supplies neither address validation nor a transfer bound. [SYM53C710 manual, pp. 5-5–5-7](https://datasheet4u.com/pdf/1312314/SYM53C710.pdf)

**FAULT is technically deliverable on M88K but is the wrong disposition for both top rows.** [memory_rw.c](C:/DocumentNoSnc/CC/GXEMUL/GXEMUL-SEC/src/cpus/memory_rw.c) converts failed device callbacks into M88K access exceptions. That does not justify treating an implemented controller’s unsupported register as absent. The same reasoning from the previous reviews applies. A SCRIPTS decoding limitation also is not a failed CPU access; execution can occur later through the controller tick.
