**The clean sweep (REASONED).** In `reassert_interrupts`, change:
```c
if (d->software_interrupt_status[cpu]) status |= (1 << 26);
```
to:
```c
if (d->software_interrupt_status[cpu] && !d->irqActive[cpu]) status |= (1 << 26);
```
This is squarely in the (d) joint-cell enumeration (`{pending: sw} × {irqActive: 1}`). On the first walk the latch is 0, so the bit is set, `status & enable` is true, `INTERRUPT_ASSERT` fires, the cpu enters VBR+8 — every delivery row (slot0/sio5/both/cpu1/cpu3) passes. On any subsequent walk while `software_interrupt_status[cpu]` is still 1 and no device line is pending (the steady state for every probed session once the cpu is parked at `br .` with IND set), the bit is suppressed, `status & enable` is 0, the else branch runs, `irqActive[cpu]` is still 1 from the first walk, `INTERRUPT_DEASSERT` is called, `irqActive[cpu] = 0`. The IRQ line is now low while SW is still pending. The probe never observes this: handlers are `br .` with IND set and never `rte`, so the falling edge is invisible. Session D (control, no SW store) does not catch it because with the mutant SW-suppresses-only-when-latch-set, and session D's MASK1-only state never latches. No row in the 27 catches it.
