  - Delivery sets `cpu->cd.m88k.irq_asserted = 1` (`grep -nF 'm88k_irq_interrupt_assert' src/cpus/cpu_m88k.c`). **No debugger command prints it**: `m88k_cpu_dumpinfo` prints name/endian only; `debugger_cmd_machine` has no irq output. Channel "irq_asserted" is *not* observable with stock commands.
  - Vector entry **cannot be observed while single-stepping**: `src/cpus/cpu_dyntrans.c`, anchor `Do not cause interrupts while single-stepping` — the m88k exception (`irq_asserted && !(PSR & M88K_PSR_IND)` → `m88k_exception(cpu, M88K_EXCEPTION_INTERRUPT, 0)`) is inside `if (!single_step)`. The witness works *despite* this because W1's death is synchronous inside the stepped store, not via exception delivery.
  - MASK1 readback bits 31..29 **cannot prove delivery**: the read path uses machine-wide `interrupt_status & currentMask` and never ORs `software_interrupt_status[cpunr]` — the soft bit is invisible there, and the line bits are connection-independent.

  So the accept row needs the **free-running shape**: `focus 1` (the debugger's cpu switch, `debugger_cmds.c` anchor `debugger_cmd_focus`), get cpu 1 to clear PSR.IND (reset PSR is `M88K_PSR_MODE | M88K_PSR_IND`, `cpu_m88k.c` — plant an `stcr` on cpu 1 and step it; stepping executes instructions, it just suppresses exceptions), arm MASK1 with bit 26 only (`0x04000000` — avoids clock interference during the free run), store SOFT_INT1 from cpu 0, breakpoint at cpu 1's vector (`pc = cr[VBR] + 8 * vector`, vector `M88K_EXCEPTION_INTERRUPT = 1` → VBR+8, VBR reset 0), `continue`. Break-hit *on cpu 1* with slot 0 masked off attributes the delivery to the SOFT_INT1 route. This is the measuring seat's build; I name it because the plan's stepped channel does not exist.

  **Load-bearing consequence for §5**: this free-running accept row is the *only* planned row that kills **M_STOREBUTNOREASSERT**. In a stepped cold debugger, that mutant (store lands, reassert skipped) is observationally identical to a correct fix — SOFT_INT readback still returns the stored word, no assert is ever visible. Without the accept row, that mutant ships.

  ## Q5 — SEVERITY: HIGH STANDS

  Reachability is two ordinary supervisor-mode word stores on the *default* configuration of the machine the project boots (rig command verified, no `-n`). The witness is measured on a committed unmodified binary with attribution controls (C1 RAM liveness, C2 device signature, A1 the identical sequence surviving on connected slot 0, A2 the arming store alone surviving). Ranked on ordinary-instruction reachability per the `pcc2defaultkill`/`m88kexcdeliver` precedent, nothing checkable argues it down. The corollary strengthens it: on a *running* guest, a single arming store (es438's own D4 value `0x84000100` sets bit 31) makes the next clock tick fatal — the SOFT_INT1 route is merely the deterministic form.
