## Q1 THE PREMISE AUDIT

**Held, after re-derivation:**

* **`interrupt_status` is one machine-wide word; software interrupts are per slot.** `struct luna88k_data` has a single `uint32_t interrupt_status` and `software_interrupt_status[MAX_CPUS]`. `luna88k_interrupt_assert` does `|= (1 << (line + 25))`; reassert copies that word then `|= (1 << 26)` only for that slot’s software latch. Confirmed.
* **Default cpu count is 1, and the probe/rig use it.** `emul.c`: `if (m->ncpus == 0) m->ncpus = 1`. `main.c` `-n` is `parse_int_option(..., 1, 256)`. The witness argv is `-V -e luna-88k` with no `-n`. `machine_luna88k` and `DEVINIT(luna88k)` both `exit(1)` if `ncpus > 4`. Reachable luna populations are **{1,2,3,4}**.
* **Nothing else connects `cpu_irq[1..3]`.** The only `cpu_irq` writes in this file are `INTERRUPT_CONNECT` on slot 0 always, and slots 1/2/3 under `ncpus >= 2/3/4`. No other file names this array. `memset(d, 0)` leaves those function pointers NULL.
* **The macro has no NULL check.** `interrupt.h`: `INTERRUPT_ASSERT(istruct)` is `(istruct).interrupt_assert(&(istruct))`. Same for `DEASSERT`.
* **Store arms do not compare `cpunr` to `ncpus`.** Domain of `cpunr` is the four case labels, not “any address”: `INT_ST_MASK0..3` at `0x65000000/04/08/0c` give `cpunr ∈ {0,1,2,3}`; `SOFT_INT0..3` at `0x69000000/04/08/0c` the same. `addr = relative_addr + LUNA88K_REGISTERS_BASE` then `switch (addr)` — unaligned offsets do not enter this arm.
* **`d` has no `machine` pointer.** `grep` of `struct machine` in `dev_luna88k.c` is empty. Option (a) needs a stored `ncpus` (or a pointer).
* **Not shipped.** `CHANGELOG.md` has 0 hits for `lunaabsentcpu`. `regress/` has `luna_intmask_probe.py` only; the new probe lives in `regress/artifacts/lunaabsentcpu/` and `_scratchpad/lunaabs/`.
* **D4 really arms bit 26.** `0x84000100` = bit 31 + bit 26 + bit 8 (`INT_SLAVE_MASK` / `INT_SET_LV5` plus bit 8). After D4, slot 1 stays armed for the rest of that session. The “bit 26 CLEAR” draft was wrong; the correction is right.
* **Witness log matches the packet** (`witness_head_20260905_2130.out`): 4/5, W1 `signal 11`, no diagnostic.

**Wrong or incomplete premises:**

1. **“The tree has no noop-interrupt helper.”** The brief’s grep (`noop.*interrupt|dummy.*interrupt`) missed `src/core/interrupt.c`: `static void no_interrupt_assert` / `no_interrupt_deassert`, filled in on empty-name lookup. **They are not a usable idiom:** the empty-name arm does not `return`, so lookup still `abort()`s, and `INTERRUPT_CONNECT("")` does not exist anywhere. (c) stays rejected; the grep result is false.
2. **`dev_mp.c` is two idioms, not one.** `which_cpu >= ncpus` → silent `break` is a **guest index into `cpus[]`** (OOB). `for (i = 0; i < ncpus; i++)` at the PAUSE and IPI arms is a **walk bound**. Reassert is a walk over interrupt pins, not an OOB index: `interrupt_enable[4]` is in-range for `cpunr` 0..3. Transferring the *decline* is a category error; transferring the *walk* is the house match (`RESET_CPU_ALL`, `add_cmmu_for_cpu`, the connect guards).
3. **MASK1 `highestCurrentStatus` does not show a software interrupt.** The read path uses `interrupt_status & currentMask` only. The `1 << 26` overlay lives in reassert’s local `status` and is never written into `interrupt_status`. A MASK1 readback cannot be the delivery oracle for SOFT_INT1.
4. **OpenBSD/luna88k is absent from `_guest-src-openbsd22/`** (no `sys/arch/luna88k`; `mvme88k` is a different board). The on-disk header is an OpenBSD 6.2 import (`luna88k_board.h`) and names all four MASK/SOFT registers plus `INT_SLAVE_MASK` (“slave can only enable 6 and 1”). Whether a UP kernel *writes* MASK1 is still unsettled. The rig booting to login only proves it does not currently arm slot 1 **and** leave a pending bit.

**Bit/line domain (enumerated, not reasoned):**

| line | `1 << (line+25)` | connected as |
|------|------------------|--------------|
| 1 | bit 26 | software overlay; no separate device on `.luna88k.1` |
| 2 | bit 27 | (registered, unused in DEVINIT) |
| 3 | bit 28 | SCSI |
| 4 | bit 29 | le |
| 5 | bit 30 | sio |
| 6 | bit 31 | timer |

`0xfc000000` = bits 31..26 = `INT_SET_LV0`/`LV1`. SOFT_INT write of `1` is truthy → slot’s bit 26. Enable with bit 26 set AND software latch nonzero → `INTERRUPT_ASSERT`. MASK1 store alone: `interrupt_status==0` and software latch 0 → no call. That is why A2 survives and W1 dies.

## Q4 THE ACCEPT SIDE

**Configure with `-n 2`.** `main.c` `-n` is live; `MACHINE_SETUP(luna88k)` unpauses every cpu; DEVINIT then `INTERRUPT_CONNECT("machine[0].cpu[1]", d->cpu_irq[1])`. A cold-debugger probe does not need a boot (`-V` is “start paused in the interactive debugger”). `focus 1` switches `debugger_cur_cpu`. Machine description allows 2 (and 3, 4); it `exit(1)` above 4.

**A stepped row cannot observe delivery to cpu 1.**

* `irq_asserted` is set synchronously in `m88k_irq_interrupt_assert` during the store (device dispatch has no single-step guard). It is **not** in `CPU_SETTINGS` (`pc`, GPRs, CRs, FCRs only). `reg` will not print it. No debugger command names it.
* MASK1 bits 31..29 do **not** include the software overlay (Q1.3).
* SOFT_INT1 readback proves the latch stored, not that ASSERT ran.
* Survival is not delivery. `ncpus = 1` hardcoded **survives** `-n 2` and fails to assert cpu 1.

**Free-running shape that can:** `-n 2 -V -e luna-88k`, `focus 1`, clear `PSR.IND` (`M88K_PSR_IND` is **set** at `cpu_new`: “Start in supervisor mode, with interrupts disabled”), point `VBR` at RAM, plant a handler at `VBR + 8*M88K_EXCEPTION_INTERRUPT` = **VBR+0x8**, breakpoint there, MASK1 arm + SOFT_INT1, `continue` (not `step` — `cpu_dyntrans.c` suppresses dispatch while stepping). Channel: cpu 1 `pc == VBR+8`. Negative control: the same sequence on **1-cpu** must neither die nor take that vector.

`timer1` as a stepped row: **N/A**. `luna88k_timer_tick` is a host-timer callback; `timer_stop()` while the debugger is interactive. Do not ship a survival-only timer row. SOFT_INT is the synchronous stand-in for “armed enable + pending bit”. The running-guest clock-after-D4 kill is the same loop; (a) closes it by not walking the slot.

**MASK1 readback `0x00fc0000` is a store-landed row**, valid on both 1-cpu and 2-cpu under (a). It does not discharge the accept-side obligation.

## DETECTOR (what I would actually row)
