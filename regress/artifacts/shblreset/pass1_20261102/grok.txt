## Q3 — weakenings

(a) Verbatim `expevt = EXPEVT_RESET_POWER` is not equivalent. `tlbm bl general` reads H'000 and `tlbm bl multihit` reads H'000. Floor.

(b) Deleting the block is not equivalent. TRAPA stays H'160 (`bl general` red). Multiple-hit stays H'140 (`bl multihit` green by construction). Floor, carried by the general row.

(c) Always MANUAL is not equivalent. TRAPA is green. Multiple-hit reads H'020. Floor, `bl multihit`.

(d) `expevt != EXPEVT_TRAPA` is not equivalent. TRAPA stays H'160 and the multiple-hit becomes H'020. Both rows red. Floor.

(e) The written predicate is not the parenthesis. `expevt < 0x100` does not name the reset-category codes. H'140 is greater than H'100, so the multiple-hit is rewritten to H'020 and `bl multihit` reds it. The same predicate also keeps real general codes that sit below H'100 (TLB miss H'040/H'060, protection, modification, load address error H'0E0), which 5.5.3 sends to manual reset. A predicate that actually keeps `{H'000, H'020, H'140}` is guest-visible-equivalent on this tree: nothing passes H'000 or H'020 in as an exception, and the interrupt's 0 is discarded before the latch. No row separates that widening from the fix.

(f) `if (expevt == EXPEVT_TRAPA) expevt = EXPEVT_RESET_MANUAL` is not equivalent, and both proposed rows are green. First difference is any other general exception with BL set: `EXPEVT_RES_INST` stays H'180, a TLB miss stays H'040/H'060, a misaligned load stays H'0E0. This is the clause (e) escape.

A second BL-set general row should ride. Make it a misaligned load, `EXPEVT_ADDR_ERR_LD` (H'0E0), via `SH_ALIGN_CHECK_LD` at `cpu_sh_instr.c:209-213`. That kills (f), and because H'0E0 is below H'100 it also kills (e)'s over-exemption. `EXPEVT_RES_INST` kills (f) only. A TLB miss kills both and needs the MMU.

## Q5 — vehicle

Committed rows do not re-pin. Initial SR is `SH_SR_MD | SH_SR_IMASK` (`cpu_sh.c:123`), BL clear. `tlbm sr` pre-sets `0x40008000`, which is MD|FD, BL clear. The new body is inside the BL test, and the shared arm is untouched.

`0x500000f0` is MD|BL|IMASK=0xf, RB clear, FD clear. MD is the bit the multiple-hit program needs: a user store to P4 becomes a TLB miss in `memory_sh.c` before the UTLB device runs. IMASK=0xf is not observable on an `expevt`-only row.

RB clear matches the committed rows. It is not what routes the seeds. Debugger `sr=` writes `cpu->cd.sh.sr` through `CPU_SETTINGS_ADD_REGISTER32` and does not call `sh_update_sr`, so it does not swap banks. `mov.l` reads `r[]`, and the probe writes `r0`–`r7` after the poke. Those are the values the stores use.

`session()` cannot express the general row. With `trigger=True` it always plants the three stores and `step 3`. On the fixed build that latches H'140. A general row appended as `session(pre=["sr=0x500000f0"])` fails the correct fix. The helper has to take a program and a step count. TRAPA #1 is `put h` of `0xc301` and `step 1`.

The gate pin `6` is `gate_sh_rounding.sh:254`, and the name loop is `:256-259`: `count` of `^$v  .*ok$` (`lib.sh:326`, two spaces). `row()` prints with `%-14s`. That width is a minimum, so a longer name gets only the one space in the format string, and the two-space anchor matches nothing. `tlbm bl general` is 15 characters and `tlbm bl multihit` is 16. Both per-row checks would be red on a correct run. `rows run` would still pass.
