The brief asserts: *"MIPS, ARM, PPC and SH move the PC to a real handler before returning, so they get past the retry."* This assumes the exception vector translation always succeeds. A full audit of all architecture translators reveals:

#### 3. "Is `nothing_call` usable from inside `pc_to_pointers`, or only from an instruction handler?"
**`nothing_call` CANNOT BE USED FROM INSIDE `pc_to_pointers` WITHOUT MODIFYING `run_instr`.**
[`nothing_call`](file:///C:/DocumentNoSnc/CC/GXEMUL/GXEMUL-SEC/src/cpus/tmp_alpha_head.c#L66) is an instruction callback ([`tmp_alpha_head.c:60-64`](file:///C:/DocumentNoSnc/CC/GXEMUL/GXEMUL-SEC/src/cpus/tmp_alpha_head.c#L60-L64)) designed to execute inside `I;` to consume one dispatch slot without advancing `ninstrs` or `pc` (`cpu->cd.alpha.next_ic--; cpu->ninstrs--;`).
If `pc_to_pointers` points `next_ic` to `&nothing_call`:
1. In single-step mode, `memory_rw` fails at `:287`, and `:325` runs `nothing_call`.
2. In normal mode ([`cpu_dyntrans.c:351-374`](file:///C:/DocumentNoSnc/CC/GXEMUL/GXEMUL-SEC/src/cpus/cpu_dyntrans.c#L351-L374)), the loop runs 120 unrolled `I;` calls per iteration. Each `I;` executes `nothing_call` which decrements `next_ic`, executing hundreds of dummy iterations until `n_translated_instrs >= N_SAFE_DYNTRANS_LIMIT`.
3. **PC corruption in the epilogue**: At line 395 ([`cpu_dyntrans.c:395-400`](file:///C:/DocumentNoSnc/CC/GXEMUL/GXEMUL-SEC/src/cpus/cpu_dyntrans.c#L395-L400)), `low_pc = (next_ic - cur_ic_page) / sizeof(...)`. If `cur_ic_page` was set to `nothing_call`, `low_pc == 0`, which clears the in-page offset of `cpu->pc`. If `cur_ic_page` was stale heap memory, `low_pc` is arbitrary garbage that clobbers `cpu->pc`.
