**For Site A, the post-decrement premise is exact.** [The handler](C:/DocumentNoSnc/CC/GXEMUL/GXEMUL-SEC/src/cpus/cpu_ppc_instr.c:2521) decodes a signed `int sh` in `0..63`. Its final condition evaluates the old value zero and then decrements it to −1. This happens even for `SH=0`. Consequently, the existing mask always covers architectural bits `MB..63`.

The [rldimix RTL](C:/DocumentNoSnc/CC/GXEMUL/_scratchpad/ppc_pem_32and64_2005.txt:29908) requires `MASK(MB,63-SH)`. The manual’s [mask definition](C:/DocumentNoSnc/CC/GXEMUL/_scratchpad/ppc_pem_32and64_2005.txt:6878) makes both endpoints inclusive and wraps through bit 63 to bit 0 when the beginning exceeds the end.

That exposes two problems with “save `sh`, then retain the mask loop”:

- Its condition compares the **incremented** position with the inclusive endpoint. It stops one bit early where it terminates normally.
- It never wraps. Other operand combinations can run beyond bit 63 and evaluate invalid shift counts.

The verdict’s condition uses the position **after** the endpoint, modulo 64. Together with the modulo increment and existing `do` body, it handles ordinary, singleton, wrapping, and full-width masks in 1–64 iterations.

I favor keeping the architectural operand intact—preferably declaring `sh` as `const`—and consuming a separate counter. Merely saving another copy while continuing to destroy `sh` leaves the future-reader hazard you identified. Applying the separate-counter change to `rldicl` and `rldicr` would preserve their current results: neither uses `sh` afterward. It is optional cleanup, not a necessary repair at those sites.

**The detector needs mutant-specific observability.** The proposed “vacuous exactly when the selected source window is zero” rule does not hold generally for insert instructions.

For correct mask `M`, rotated source `R`, and initial destination `D`:

- A no-op differs precisely when `((R ^ D) & M) != 0`.
- A wrong-mask mutant using `N` differs precisely when `((R ^ D) & (M ^ N)) != 0`.
- A zero-writing mutant differs when the correct complete destination is nonzero.

A zero source window can therefore be useful when the operation should **clear seeded destination bits**. Conversely, a nonzero window can be useless against a no-op when the destination already matches it.

For Site B’s contamination, differing source halves are necessary but insufficient. The extra high-half contribution must set a selected bit that the correct rotated word leaves clear. In particular, no single source can both make every possible singleton low-word window nonzero and discriminate this contamination: that would require an all-ones rotated low word.
