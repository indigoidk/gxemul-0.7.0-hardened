## 1. Is `0x800U` sufficient, and is anything else perturbed?

**REASONED — sufficiency: yes.** `0x800U` is unsigned; C99 6.5.7p4 defines unsigned `<<` as ×2^E2 mod 2^width. Values 2^11..2^31 all fit in 32-bit unsigned; shift counts 0..20 < 32. No residual UB in this expression.

**READ — `tag`'s type is not in the packet.** Nothing inlined declares it. The brief asserts "already a wider unsigned quantity." Now apply the promotion rules, as requested:

- **REASONED: if `tag` is 32-bit** (`uint32_t` or `int`): usual arithmetic conversions give identical bit patterns for old-as-compiled and new masks at all 21 iterations. The claim is literally true. (But then "wider" in the comment is false — it's same-width.)
- **REASONED: if `tag` is 64-bit (either signedness)**: at dev 0..19 the positive int mask and the unsigned mask both convert value-preservingly — identical. At dev == 20 the old code is UB, so "unchanged" can only mean unchanged from *as-compiled* behavior; as compiled on two's complement, `0x800 << 20` is `INT_MIN`, which under `&` with a 64-bit `tag` converts per 6.3.1.3p2 by adding 2^64 → mask `0xFFFFFFFF80000000`. The new mask converts value-preservingly → `0x0000000080000000`. **The tested bit-set differs** (bits 31–63 vs bit 31 only), observable iff tag has bits 11–30 and 31 clear but some bit ≥32 set.

So the author's two sentences — "tag is a *wider* unsigned quantity" and "truth value unchanged at *every* iteration" — are jointly true only under an **unstated runtime invariant `tag < 2^32`**.
