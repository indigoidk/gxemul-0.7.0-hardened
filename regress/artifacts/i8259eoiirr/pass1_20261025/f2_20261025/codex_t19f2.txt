**Q3. What the shared review missed**

1. **G2 can leave a pending cascade request with CPU output low. [READ/DERIVED]**

   PIC2’s output invokes the ISA2 callback. That callback captures the current master request state, and `isa_interrupt_common` suppresses propagation when its before/after values agree. G2 precomputes the cascade bit *before* invoking this callback, destroying the transition it needs to observe. [ISA aggregation and callbacks](C:/DocumentNoSnc/CC/GXEMUL/GXEMUL-SEC/src/devices/bus_isa.c:52)

   With two slave requests pending, the proposed master acknowledgment can clear cascade IRR2 and lower CPU output. The slave acknowledgment consumes one request, then pre-sets master IRR2 for the remaining request. Its callback observes no change and leaves CPU output low. Repeated assertions of that remaining source also compare equal.

   This is worse than HEAD’s temporary cascade loss after master EOI: HEAD leaves master IRR2 clear, allowing a subsequent source assertion to restore delivery. G can leave IRR2 **set while output remains low**.

   Direct slave polling has the converse risk: pre-clearing the last cascade request can leave CPU output asserted. **Cascade coverage is mandatory**, and a lone slave-request row does not cover the multiple-pending case.

2. **The unconverted machines are affected by G1. [READ/DERIVED]**

   PReP’s IACK remains a plain `last_int` read while its ISA setup includes the common PIT. Footbridge likewise returns a vector without consuming a request; it serves both CATS and NetWinder. Removing shared EOI consumption therefore leaves those paths without the proposed replacement. [PReP reader and ISA setup](C:/DocumentNoSnc/CC/GXEMUL/GXEMUL-SEC/src/devices/dev_prep.c:56), [footbridge vector reader](C:/DocumentNoSnc/CC/GXEMUL/GXEMUL-SEC/src/devices/dev_footbridge.c:432)

   Actual guest-boot regressions are **NOT CHECKABLE** here. The structural dependency is already established; lack of a witness does not discharge it.

3. **G3 turns uncommanded reads into acknowledgments and retains sticky polling. [READ/DERIVED]**

   `current_command` initially equals zero. HEAD’s default read is nondestructive; G3 would consume a request, set ISR and potentially retire a PIT event without a poll command. Furthermore, `0x0c` remains selected, so subsequent reads continue acknowledging. [PIC command/read handling](C:/DocumentNoSnc/CC/GXEMUL/GXEMUL-SEC/src/devices/dev_8259.c:96)

   The datasheet specifies acknowledgment on the **next** read and explicitly excludes polling from remembered status-selection behavior. Define ordinary reads and one-shot poll state separately. Merely matching HEAD’s returned byte does not justify adding destructive side effects. [Datasheet poll and status semantics](C:/DocumentNoSnc/cc/GXEMUL/_scratchpad/i8259/8259A.txt:604)

4. **The design does not apply F17’s ISR requirements to itself. [READ/DERIVED]**

If that is corrected, EOI can release a blocked request and must cause the appropriate output recalculation. These are requirements of the newly live service state, not reasons to retain the obsolete IRR-comparison guards. [Datasheet nesting and EOI rules](C:/DocumentNoSnc/cc/GXEMUL/_scratchpad/i8259/8259A.txt:521)

[PIT counter](C:/DocumentNoSnc/CC/GXEMUL/GXEMUL-SEC/src/devices/dev_8253.c:105), [host timer callback dispatch](C:/DocumentNoSnc/CC/GXEMUL/GXEMUL-SEC/src/core/timer.c:283)
