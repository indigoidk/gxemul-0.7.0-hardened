(ii) No supported guest wants the poll byte on a second read. DERIVED from F2 1.7/1.8 plus the datasheet. ## Q3 -- The real diff

(a) The hybrid consume is the right contained form. READ. The legacy `else` already recalculates only when the unmasked set changes (`old_irr & ~d->ier` versus the value after `irr &= ~bit`). A masked bit is not in that set, so a masked legacy EOI does not touch the line. `masked eoi` pins the consume. No further guard is needed.

(b) Lowest-numbered is "highest priority" while rotation is unimplemented. READ. `8259A.txt`: after init, IR0 is highest and IR7 lowest; a non-specific EOI resets the highest IS bit of those set. `d->isr & -d->isr` is that lowest set bit (the `uint8_t` promotes before the negation; bit 7 clears cleanly). The rotate arms (`0xc0`–`0xc7` empty, `0xe0`–`0xe7` falling into the specific arm) do not implement rotation. `i8259ocw2nonspec` stays filed; it is not this diff.

(c) Two slave requests are not left pending with the CPU line low once the slave acknowledge runs. READ, walked.

Start: pic2 IRR has two unmasked bits, `isa_interrupt_common` has set pic1 bit 2, the CPU line is high. `pic8259_acknowledge(pic1)` takes n=2, clears pic1 bit 2, sets ISR bit 2, and `INTERRUPT_DEASSERT(pic1->irq)` drops the CPU line while pic2's IRR is untouched. That gap is real and matches the chip (master INT falls at the acknowledge; edge mode will not re-latch IR2 until a new edge). No guest instruction runs inside `case GT_PCI0_INTR_ACK`. On the poll path NetBSD is already in `pcib_intr` and polls the slave next.

`pic8259_acknowledge(pic2)` then leaves one slave bit set and calls `INTERRUPT_ASSERT(pic2->irq)`. That object is the `isa.2` registration in `bus_isa_init`, so the handler is `isa_interrupt_assert`. The macro in `interrupt.h` calls the handler every time. `old_isa_assert` is sampled with pic1 bit 2 already clear, the assert ORs bit 2, and `isa_interrupt_common` sees a 0-to-nonzero mask and asserts `bus_isa`'s irq. The second request is presented. The F2 pre-fold (set bit 2 before the assert, so the mask does not change and `isa_interrupt_common` returns) is not in this diff.

A later slave tick before the slave poll also re-folds, because `isa_interrupt_assert` / `isa_interrupt_common` set pic1 bit 2 again whenever pic2 still has an unmasked request. The low window does not survive that tick.

(d) `pic1 == NULL` is reachable. `n2 < 0` is not, on a machine whose fold is intact. READ. `machine_new` memsets the machine. `MACHINE_MVMEPPC_5500` calls `dev_gt_init` and never `bus_isa_init`, so `isa_pic_data.pic1` stays NULL and the read returns `last_int`. `n2 < 0` would need pic1 bit 2 set while pic2 has no unmasked request. `isa_interrupt_common` clears bit 2 in that case on every ISA assert and deassert, and an OCW1 write that empties pic2's unmasked set `INTERRUPT_DEASSERT`s pic2's irq, which clears bit 2 too. PRETABLE's "unreachable short of a masking race" is right. The cell is still the correct total function: return 2, do not invent a slave line.

(e) A second line that arrives while one is in service is raised immediately, same as HEAD. READ. `isa_interrupt_assert` / `isa_interrupt_common` key the CPU line off `irr & ~ier` and never consult ISR. The helper's own recompute is the same test. Versus HEAD the new guest-visible shape is the acked line: its IRR is clear and, if it was the only request, the CPU line is low until something else asserts. That is the A10 disclosure (more generous than edge silicon, where a held level does not make a second edge). It is not a regression against HEAD, which had no in-service mask either. `i8259priority` stays open.
