**(i) `d->isr & bit` discriminator** — DERIVED correct. The helper is the only setter of ISR; an ISR bit is set exactly when the line has been acknowledged and is in service. Therefore a guest cannot reach the legacy branch on a line that is in service, nor the ISR branch on one that is not, because ISR bit tracks in-service state precisely.

**(ii) One-shot poll latch** — DERIVED correct. NetBSD’s poll sequence reads once per OCW3; Linux uses the GT IACK read, not the poll byte. No supported guest expects a second poll byte without re-issuing OCW3.

**(iii) GT IACK return value** — NOT CHECKABLE from packet. The fix returns `n` (0–15), while the packet states real PIIX4 returns `irq_base + n` (vector byte). Whether Linux’s `mips_pcibios_iack` expects the line or the vector byte is not in the packet. Single fact that would settle it: the source or quoted return-value convention of `mips_pcibios_iack` in F2_RULINGS 1.7/1.8.
