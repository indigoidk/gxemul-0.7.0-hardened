## S4 — the two things that could have collapsed this

### Encoding: `0xE321F014` is correct

Verified against `to_be_translated` (`cpu_arm_instr.c`), not against a mnemonic.

| Field | Bits | Value | Check |
|---|---|---|---|
| cond | 31:28 | `1110` = AL | reaches execute |
| main_opcode | 27:24 | `0011` = 3 | falls in `case 0x0..0x3` |
| I (immform) | 25 | 1 | `iword & 0x02000000` → `msr_imm`, not `msr` |
| R / s (SPSR) | 22 | 0 | not `msr_imm_spsr` |
| bits 23:20 | | `0010` = `0s10` | MSR shape |
| field mask | 19:16 | `0001` | **c only** → `arg[1] = 0x000000ff` |
| SBO | 15:12 | `1111` | required by the match |
| rotate_imm | 11:8 | `0000` | `r8 = 0` |
| imm8 | 7:0 | `0x14` | `arg[0] = 0x14` (loop never runs) |

Decoder match, in order, so nothing steals the word first:

```
(iword & 0x0fb0f000) == 0x0320f000     # 0xE321F014 & 0x0FB0F000 = 0x0320F000
```

ldrex/strex/mul/bx/swp/clz/smul* all miss. Then:

```
imm = iword & 0xff;          # 0x14
while (r8-- > 0) ...         # r8=0, body never runs
ic->arg[0] = 0x14
ic->arg[1] = 0x000000ff      # bit 16 only
ic->f = cond_instr(msr_imm)
```

`X(msr_imm)`: current mode is not USR32, so the flags-only mask does not fire; `mask & ARM_FLAG_MODE` is `0x1f`; `0x13 != 0x14`; save on SVC32 returns; the write lands; load sees `0x14` and `exit(1)`.

Generic constructor, rotate 0, c-bit only:

```
msr_c_imm(m) = 0xE321F000 | (m & 0xff)
```

`0x14 → 0xE321F014`, `0x15 → 0xE321F015`, `0x10 → 0xE321F010`, … `0x1f → 0xE321F01F`. `enc ok` must check **imm, rotate, c-bit, SPSR-clear**, not merely the MSR mask. A mask-only check would bless `MSR CPSR_c, #0x10` (USR32, modelled, **green on a live defect**).

The translator rotate (`>>2` × `r8`) and the disassembler rotate (`>>1` × `(iw>>7)&30`) are the same function. At rotate 0 they agree.

### `#0` — the packet’s fake-green is true of DDI 0100I and **false of this emulator**

There is no PrivMask in `msr_imm`. `#0` with the c-byte mask `0xff` writes mode **`0x00` (USR26)**. Load’s `default:` still fires: `unimplemented mode 0`. A `#0` probe would still go **red** on HEAD. That is the wrong hole (26-bit, named in the header, not implemented) and the wrong decimal (`0` not `20`). Keep the ban; change the reason.

### Boot mode: SVC32 privileged survives the span that could have changed it

`arm_cpu_new` is not the whole story. The span that would contain a later change, in order:

| Site | What it does to `cpsr` |
|---|---|
| `cpu_arm.c` create | `cpsr = I\|F` (`0xC0`), then **both** prom and non-prom arms `\| ARM_MODE_SVC32` → **`0xD3`**. MMU bit is not set. `flags = cpsr >> 28` = 0. |
| PROM hook (`prom_emulation` defaults **on**, `machine.c`) | `store_32bit_word` of `0xef8c64be` (a SWI) at `RAM-8`. **No `cpsr` write.** |
| `MACHINE_SETUP(testarm)` | SP = `R-4096`, LR = SP+32, three-word halt stub at LR. **No `cpsr` write.** `default_test` only adds devices. |
| `emul.c` load | `cpsr \|= ARM_FLAG_T` **only if `pc & 1`**. Plant at `CODE=0x8000` is even. **Mode bits untouched.** |
| `-V` | `single_step = true` (and `-K`). Nothing executes until `step`. Interrupts are suppressed while stepping; MSR is synchronous inside the instruction. |
| `arm_setup_initial_translation_table` | **Not called** for testarm. That is the cats/MMU line. Irrelevant here. |

At the first `GXemul>` prompt: `cpsr = 0x000000d3`, mode `0x13`, privileged (not USR32), MMU off, T clear, SP = `0x03fff000` (`-M 64`). Debugger `print cpsr` is `PARSE_SETTINGS` → `cpsr = 0xd3`. Mode bits live in `cpsr` itself, not in `flags`, so they are not the stale-NZCV bug. **Still read them with guest `MRS`**, because that is the architectural path and it is the signature.

The probe must never assign `cpsr=...`. A debugger write of a reserved mode would skip Load and let the next guest `MSR` hit Save — a state a guest cannot occupy on HEAD. That is laundering Save’s unreachability.

## S3 — one session per MSR row. That is not a 2× multiplier

A process that `exit(1)`s cannot run the next row. **`acc usr` is one-way** (the USR32 mask then strips the c-byte). Sharing a process is how both traps fire.

**Do what `run_word()` in BFX already does: one fresh `-V` process per data row** (live and `pc adv` share one session, as BFX does). Kill rows do not sit last in a shared session; they do not share with anyone.

| Accounting | Count |
|---|---|
| Scored rows | **16** (15 data + identity) |
| Guest sessions | **12** (enc ok and identity have none; live+pc adv share) |
| Arming prefix per MSR session | **not a scored row** — if the prefix fails, that row’s got is `unarmed` and it FAILs. Silent fake-green is the thing this exists to stop |
| If arming were scored per session | ~28. That is the tidy-looking number. Do not write it |

**Cost to the accept rows: zero.** They never share a process with a kill, and `acc usr` cannot poison `acc fiq`. Twelve process starts of a handful of `step`s is the same shape as BFX. Cheap.

Do not debugger-write `cpsr` to reach Save. Save’s `default:` is unreachable on HEAD (Load dies first) and stays unreachable after a **before-save** decline (reserved mode never lands). A Load-only skip-memcpy that leaves `cpsr` reserved is a clause-(d) mutant of the Load repair; row it in the **detector** as `save 2s` (MSR `#0x14` then MSR `#0x13`; channel is `arm_save_register_bank: unimplemented mode 20`). It is vacuous as a HEAD-vs-POST witness row (same colour as `kill 14` on both sides). Disclose, do not score it here.

## The two ladder controls (this is a CPU, not a device)

The footbridge failure was “0x0 everywhere, RAM control green.” Here RAM is the instruction word at `CODE`.

**Liveness — `live`.** `mov r0,#0x2a` through the same `put w` / `step` / dump path. Want `0x2a` at DEST. RAM at `CODE` is `0xe3a0002a`, not `0x2a`. If this is `SENT`/`None`, the harness never executed. **`pc adv`:** pc is `CODE+4`. An untranslatable word does not quietly return 0x2a.

**Signature — `armed`.** Guest `MRS r0,cpsr` stored at DEST, plus `STR sp` at DEST+8, before any MSR.

| Observed | Cannot have come from |
|---|---|
| DEST = `0x000000d3` | RAM at `CODE` (`0xe10f0000`), or r0 planted 0 |
| bits 4:0 = `0x13` | USR32 (`0x10`) — that is the fake-green: the c-byte mask fires, nothing switches, kill rows go green while Load’s `default:` is live |
| DEST+8 = `0x03fff000` | `barearm` (never writes SP) or a machine that is not `MACHINE_SETUP(testarm)` |

`0xd3` is I|F|SVC32. Privileged is the same fact: mode is not USR32. Require **exactly `0x13`**, not merely “privileged” — SYS32 is privileged and is not the boot mode.

If `live`, `pc adv`, or `armed` is red: print `ARMMSRMODE_CONTROL=DEAD` and `ARMMSRMODE_RESULT=0/0` and **stop**. That is setup failure, not “no defect.”

That is the USR32 fake-green caught at the moment of decision, on the process that is about to issue the MSR. Scoring it once as `armed` proves the vehicle; the prefix stops a later session that somehow is not that vehicle.

## Oracle for a dead process — EOF plus the **decimal** line, not EOF

`exit(1)` closes the pty. `running = 0` does not (`-V` implies `-K`; the prompt returns). A crash closes the pty with no Load line.

| | pty | process | line |
|---|---|---|---|
| **this defect** | EOF mid-`step` | dead | `arm_load_register_bank: unimplemented mode 20` |
| `running = 0` | prompt returns | alive | no such line; `print pc` still works |
| crash / other `fatal; exit` | EOF | dead | **no** that line |
| member 3 | prompt returns | alive | one `(once)` line; MRS still `0x13` in bits 4:0; SP still `BOOT_SP` |

`fatal()` is raw `va_debug` — **no** `cpu0:` prefix. `%i` prints **20**, not `0x14`. A hex grep matches nothing and reports a clean, confident, wrong answer. Key on the function name **and** the decimal. `mode 0` is a forgotten-register or `#0` plant; treat it as `unarmed` / setup fail, not as this defect.

EOF alone is vacuous under a crash mutant. The line alone is vacuous under a mutant that keeps the print and drops `exit(1)` (alive, mode possibly reserved). **Both, together, are the channel.** POST additionally requires mode still `0x13` (the decline refused the write) and SP still `BOOT_SP` (Load did not run). The `(once)` is the member-3 pin, not the death pin; a silent member-2 decline would hold the mode and omit it.

`fatal()` cannot be silenced by `-q`; `-V` ignores `-q` anyway. Do not key on `{ arm memory fault:`-style quiet-gated text.

## Accept rows — all six are reachable from SVC32 by this store

The USR32 mask tests **current** mode `== ARM_MODE_USR32`. Boot is SVC32. The c-byte mask is `0xff`, which contains `ARM_FLAG_MODE`. From SVC32 a guest `MSR CPSR_c, #imm8` can write every modelled mode:

| imm | mode | reachable from SVC32? | one-way? | SP after Load (fresh process, banks are BSS zero) |
|---|---|---|---|---|
| `0x10` | USR32 | **yes** | **yes** — later c-bit MSRs become flags-only | `0` (USR/SYS bank r13 was never saved; SVC save writes 5 words) |
| `0x11` | FIQ32 | **yes** | no | `0` (fiq r13) |
| `0x12` | IRQ32 | **yes** | no | `0` |
| `0x13` | SVC32 | yes, but **same-mode skip** — save/load **not** called | no | **unchanged** `BOOT_SP`; I\|F **cleared** (`#0x13` writes the whole c-byte) |
| `0x17` | ABT32 | **yes** | no | `0` |
| `0x1b` | UND32 | **yes** | no | `0` |
| `0x1f` | SYS32 | **yes** | no | `0` (same bank as USR) |

26-bit `0x00..0x03` and holes `0x14/15/16/18/19/1a/1c/1d/1e` are reserved and kill today. They are not accept rows.

**SP dropping from `BOOT_SP` to 0 is the bank-Load signature.** A mutant that writes the mode bits and skips `memcpy` would MRS-read the new mode with SP still `0x03fff000`. Mode-only accept rows are blind to that. Row both.

`same svc` does **not** call Load (modes equal). It pins “writing `0x13` is still legal” against a before-save decline that grew to reject SVC32. Against a `default:`-arm growth it is inert — disclose that. I\|F become 0; want mode `0x13`, **not** `0xd3`.

**Order:** with per-session processes, scored order does not matter. Inside a session, never issue `acc usr` and then another mode write except `usr mask` (which is that sequence on purpose).

**Failability (de-escalation, measured kill, not existence).** The latch is a per-CPU `warned` flag, not a mode mask, so guard-only is the non-equivalent form. For each `acc X`, the mutant is **delete `case ARM_MODE_X` from the whitelist** (or add `&& mode != X` to `arm_mode_ok`). That row must go red: mode stays `0x13`, SP stays `BOOT_SP`. One mutant per accept row. `same svc` reddens only if the decline inspects the **new** mode **before** the same-mode skip.
