**Q2 — `M_msr_argmask`:**

The fix's own comment ("ic->arg[] is a cached translation") acknowledges the cache, but the corrected NOT CLAIMED explains why the probe cannot exercise it: every re-execution in the probe follows a debugger interaction, and `debugger()` clears dyntrans translations (per the cited `src/debugger/debugger.c` loop), so a write to `ic->arg[]` never reaches the next execution. If the debugger-clears-cache claim is false, the fix is incomplete; but the claim is stated as a correction found by reading the code, and the author investigated the escape rather than papering over it. I would not block ship on this. A belt-and-suspenders fix would also strip `ic->arg[0]`'s mode bits (or assert), but that is a judgment call, not a floor breach.

**Q4 — Gate 14:**
REASONED. The gate parses correctly: it requires exactly one `ARMMSRMODE_RESULT=` matching `(0|[1-9][0-9]*)/(0|[1-9][0-9]*)$`, one `ARMMSRMODE_CONTROL=(OK|DEAD)$`, one `ARMMSRMODE_REDS=`, and exactly one line that is `ARMMSRMODE_DONE` (strict `grep -cx`, so trailing whitespace would fail — worth noting if the probe is edited). On parse failure it short-circuits to a single "no" check and a tail, which is clean.

On score: the checks are `CONTROL=OK`, `mrc=0`, `${mres#*/} == 47` (run), `${mres%/*} == 47` (correct), `grep -cE '^  [^ ].* got=.* want=' == 47` (emitted), `REDS=none`. On the fixed log (47/47, CONTROL=OK, REDS=none, exit 0) all pass. On the HEAD log (18/47, CONTROL=DEAD, REDS=29 names, non-zero exit) the parse succeeds but four of the six score checks fail — exactly the desired behavior.

One subtlety: the `rows emitted` regex requires `got=` before `want=` on the same line. The brief says rows do not end in their status token (a note follows), so the format is `  rowname … got=X want=Y note…` (or similar). The regex `'^  [^ ].* got=.* want='` is greedy and will match as long as `got=` precedes `want=`. If the probe's emitter ever puts `want=` before `got=`, this check silently reports 0 and fails with a confusing message. Low risk; worth a one-line comment in the probe's emitter to lock the order.

The FAIL-row display grep (`grep -E ' want=' | grep -E ' FAIL '`) is for human display only; the source of truth is `ARMMSRMODE_REDS`, which the gate checks. This is the right design given the "note follows status token" format.
