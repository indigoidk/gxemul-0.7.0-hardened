#### 2. Masking of `CONTROL=DEAD` by Missing `ARMMSRMODE_REDS` in `report_dead()`
In [`regress/arm_msrmode_probe.py#L543-L551`](file:///C:/DocumentNoSnc/cc/GXEMUL/GXEMUL-SEC/regress/arm_msrmode_probe.py#L543-L551):
```python
def report_dead(why):
    print("arm_msrmode_probe -- binary=%s label=%s machine=testarm" % (BIN, LABEL))
    print("ARMMSRMODE_CONTROL=DEAD")
    print("ARMMSRMODE_RESULT=0/0")
    print("  *** SETUP FAILED (%s) -- the vehicle is not the vehicle.  NOT 'no defect'. ***" % why)
    for nm, got, want, note in rows:
        print("  %-11s got=%-16s want=%-16s %s" % (nm, got, want, note[:56]))
    print("ARMMSRMODE_DONE")
    raise SystemExit(0)
```
`report_dead()` does **not** print an `ARMMSRMODE_REDS=` line.
However, Gate 14's parser requires `[ "$(grep -c '^ARMMSRMODE_REDS=' "$MSRLOG")" != "1" ]` to be false for all parses.
Consequently, if a probe setup fails and triggers `report_dead()`, the gate triggers the parse failure arm:
```sh
check "msrmode probe output parses" "no" "yes"
```
and the `else` branch with `check "msrmode controls" "$ctrl" "OK"` is **never reached**. While the gate still halts and fails, the control failure diagnostic is masked as a syntax/parse error. `report_dead()` should emit `ARMMSRMODE_REDS=none` (or `dead`), or the parser should allow `ARMMSRMODE_REDS` to be absent when `CONTROL=DEAD`.
