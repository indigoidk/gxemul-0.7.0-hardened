## Q1 — It runs. It does not score.

Step counts match the plants. `classify()` is not reading the slots those plants write.

**`dumped()` is the vehicle-kill.** Two independent misses, both already measured in this tree:

1. **Line labels are 16-byte aligned.** `debugger_cmd_dump` does `addr = addr_start & ~0xf` and prints that aligned address. `dump 0x9004` / `0x9008` / `0x900c` / `0x8008` emit `0x00009000` / `0x00008000`. The regex hunts `0x0*9004` etc. and returns `None`.
   `arm_bdt_probe.py` recorded this on 2026-09-11: an unaligned dump still labels the aligned base and blank-pads the leading groups. Its `read_mem32()` always dumps `addr & ~0xF`. This probe does not.

2. **Little-endian byte string, not a word.** The dump prints memory order (`%02x` per byte). `0x0000002a` at `0x9000` is `2a000000`. `dumped()` then does `int(..., 16)` with no swap.
   `arm_flags_probe.py` has `sw()` for this exact reason and warns that comparing the dump string to `deadbeef` reads the sentinel’s parity as a measurement.

`DEST=0x9000` is aligned, so `live` *does* match a line — and then wants `0x2a` against `0x2a000000`. `armed` dumps `DEST+4` and `DEST+8` (both unaligned) → `?/?`. Either one alone is `CONTROL=DEAD`. Together they make the named-red path unreachable.
