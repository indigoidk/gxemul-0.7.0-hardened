## Q3 — where the decline lives

**At the writers, before the `switch_register_banks` computation / CPSR assignment:**
- Caller 1: before line 830, on `(mask & ARM_FLAG_MODE) && !modelled(new_value & ARM_FLAG_MODE)` → clear mode bits from `mask`, announce. Then `switch_register_banks` computes false, Save is skipped, other fields apply at 841–842, Load is skipped. Nothing after Load is disturbed.
- Caller 2: before line 1802, substitute mode bits in `new_cpsr`; the compare at 1802 then yields no switch.
- Caller 3: substitute after the SPSR select. Save at 218 already ran — on the *current* (valid) CPSR, so it is safe — and Load then round-trips the same bank, an identity.

**Rollback-inside-Load is not viable** [READ]: Load receives a CPSR that caller code has already overwritten and holds no copy of the old mode; rolling back requires each caller to stash CPSR anyway — at which point you have re-implemented writer-side guards with more state. **Both** leaves: writer guards everywhere + backstops that announce-and-no-op; the backstop is then reachable only from a future unguarded writer or store corruption of the cpsr field.
