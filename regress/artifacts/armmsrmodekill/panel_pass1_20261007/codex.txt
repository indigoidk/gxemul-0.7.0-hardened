## 1. The defect (a design question; the reproduction is being repaired separately)

`arm_save_register_bank()` and `arm_load_register_bank()` in `src/cpus/cpu_arm.c` each switch on
`cpsr & ARM_FLAG_MODE` (5 bits) over the six modelled modes and end in

    default: fatal("arm_..._register_bank: unimplemented mode %i\n", cpsr & ARM_FLAG_MODE);
             exit(1);

so a guest that puts a RESERVED mode in CPSR ends the emulator PROCESS.  The ARM ARM calls a reserved M[4:0]
UNPREDICTABLE, not fatal.  A privileged `MSR CPSR_c, #0x14` (word `0xE321F014`) on `-E testarm` is the filed
trigger.

## 2. SETTLED PREMISES (re-inlined so nobody spends an answer re-deriving them; CHALLENGE any you doubt)

* **Save is not the first hit for MSR** -- in `msr_imm`, Save runs on the OLD mode (e.g. SVC32, modelled) and
  returns; CPSR is then rewritten; Load runs on the NEW (reserved) mode and dies.  A Load-only fix therefore makes
  the NEXT mode switch die in Save (CPSR now holds the reserved mode).  -- row `armmsrmodekill`, grok trace 2026-09-17.
* **Callers write CPSR BETWEEN Save and Load** (all four callers below).  So a decline placed only inside Load
  leaves CPSR holding the reserved mode unless Load also rolls it back.  -- same row.
* **Member 1, DELETE (just drop the `exit(1)`), is WRONG**: CPSR stays reserved and `r[]` stays on the previous
  bank -> silent wrong-bank execution, then the next switch hits Save's default.  -- same row.
* **Member 5, FAULT, is available on ARM but wrong for MSR**: the ARM ARM lists MSR as "Exceptions: None".
  -- same row.  (For the SPSR-restore callers the question is open -- see §4.)
* **`fatal()` does not exit**; it prints regardless of `-q`.  A guest-drivable `fatal()` needs a LATCH (house idiom
  `N = 1` per instance + a `(once)` marker in the text), not a verbosity flag.  -- carrier rule.
* **Has it shipped?**  `grep -c armmsrmodekill CHANGELOG.md` = 0; the three files last changed in `#524`
  (`4dfc7165`).  No fix exists.

## 4. The question: which disposition, and where?

The project's option set for a guest-drivable host kill has seven members; please consider every one, and say if
there is an eighth:

1 DELETE · 2 DECLINE (silent) · 3 DECLINE + LATCHED ANNOUNCE (`(once)`) · 4 ACCEPT · 5 FAULT · 6 BACKED ACCEPT ·
7 IMPLEMENT.

The row's working position (challenge it): **member 3, and the decline must happen BEFORE Save** -- i.e. a reserved
mode is never allowed into CPSR at all -- because every caller writes CPSR between Save and Load.  That suggests one
shared helper, e.g. `int arm_mode_is_modelled(uint32_t mode)`, consulted by each caller before it writes the mode
bits, plus the two `default:` arms changed from `exit(1)` to a latched announce as a backstop.

2. **The three files did not all last change in #524.** Individual file histories give `cpu_arm.c`: `2c615c3c` (#367); `cpu_arm_instr.c`: `4dfc7165` (#524); `cpu_arm_instr_dpi.c`: `a06e92fb` (#311–313). The reviewed defaults still contain `exit(1)`.
3. **“Exceptions: None” does not establish that FAULT is forbidden for an UNPREDICTABLE operand.** MSR explicitly classifies reserved mode writes as UNPREDICTABLE. Arm’s current glossary expressly permits implementing an UNPREDICTABLE instruction as UNDEFINED. That is not evidence of actual SA1110 behavior, but it defeats the categorical inference. [ARM ARM, A4-77–79](https://kib.kiev.ua/x86docs/ARM/ARMARMv5/DDI0100I.pdf), [Arm Glossary, p.54](https://documentation-service.arm.com/static/64bea01c38511951cb7a0949)
4. **“Must decline before Save” is stronger than the bank invariant requires.** Saving a valid old bank and then declining before committing CPSR is safe. Conversely, declining immediately before Save is already too late for a *whole-instruction* decline in the two restore callers.

The arithmetic domains matter here.

Both register MSR and immediate MSR can produce every low-five-bit value; unrotated immediates alone establish that. The complete partition is:

| Bank-switch treatment | Mode values, hexadecimal |
|---|---|
| Modelled: **7** | `10 USR`, `11 FIQ`, `12 IRQ`, `13 SVC`, `17 ABT`, `1b UND`, `1f SYS` |
| Unmodelled: **25** | `00 01 02 03 04 05 06 07 08 09 0a 0b 0c 0d 0e 0f 14 15 16 18 19 1a 1c 1d 1e` |

Do not call that entire second row “architecturally reserved” across all supported CPU names: [cpu_arm.h](/C:/DocumentNoSnc/cc/GXEMUL/GXEMUL-SEC/src/include/cpu_arm.h:103) names `00–03` as legacy 26-bit modes. A modelled-mode predicate measures emulator capability, not architectural validity for every processor.

The actual MSR decoder emits these **16 byte masks**, in field-selector order `0–f`:

```text
00000000 000000ff 0000ff00 0000ffff
00ff0000 00ff00ff 00ffff00 00ffffff
ff000000 ff0000ff ff00ff00 ff00ffff
ffff0000 ffff00ff ffffff00 ffffffff
```

Zero becomes NOP, leaving **15 masks reaching handlers**. USR restriction reduces the effective mask to `{00000000, ff000000}`. Consequently, `mask & ARM_FLAG_MODE` is only `{0, 1f}`: **there is no partial-mode-bit producer in this decoder**. Validate the effective write after privilege masking; arbitrary low operand bits in a flags-only write must not cause rejection. See [the decoder](/C:/DocumentNoSnc/cc/GXEMUL/GXEMUL-SEC/src/cpus/cpu_arm_instr.c:4319).

Thus **yes, arbitrary SPSR mode bits can be stored and restored later**. Invalid restore input also need not originate in an explicit poisoning write. For disposition, I recommend a documented emulator policy: **decline the entire invalid instruction’s architectural effects, announce once per CPU, and continue sequentially.** This is a policy choice, not behavior uniquely prescribed by ARM.

The architecture references do not mandate applying the remaining fields after an invalid mode request. Changing CPSR.T through MSR is independently UNPREDICTABLE; MOV also lists “Exceptions: None,” undermining the proposed MSR-versus-MOVS distinction. LDM(3) specifies SPSR restoration and a PC transfer, with Data Abort listed, but no required reserved-mode fault. [ARM ARM, A4-40–42, A4-68–69, A4-77–79](https://kib.kiev.ua/x86docs/ARM/ARMARMv5/DDI0100I.pdf)

Applied to each caller:

| Caller | Recommended behavior and required placement |
|---|---|
| **MSR CPSR** | After privilege masking, reject the whole effective write if it requests an unmodelled mode. Preserve logical flags, I/F, T, mode, and banks. Flags-only writes and USR-masked control writes retain their ordinary behavior. Preflight before the existing synchronization/Save/commit sequence. |
| **LDM exception return** | Reject the whole instruction before memory reads, register commits, and writeback. Preserve registers, CPSR, flags, and the sequential continuation; do not branch to the loaded PC. |
| **Data-processing S-to-PC** | Preflight before operand helpers or carry changes. Reject without updating flags or taking the computed branch. |
| **Exception entry** | With a valid current mode, proceed: its destination is already modelled. An invalid current mode is an invariant failure requiring explicit containment; declining the destination mode cannot repair it. |

A mode-only decline is another possible policy: preserve old M while applying permitted remaining fields. But that deliberately allows an exception-return target to execute in the old mode. I prefer whole-operation rejection because its state transition is easier to specify and review. FAULT is also a possible chosen response; I found no architecture basis for preferring it only for the restore callers.

All seven members, plus an eighth:

| Member | Assessment |
|---|---|
| **1 DELETE** | Insufficient. Removing both exits leaves unresolved mode/bank correspondence. Save subsequently reaches its default, although it no longer exits if that exit was also removed. |
| **2 DECLINE silently** | Can preserve state correctly, but omits the requested diagnostic. |
| **3 DECLINE + latched announce** | Recommended at instruction preflight, with explicit rejection scope. |
| **4 ACCEPT** | Unsupported without defined bank behavior. Continuing with reserved CPSR and the previous bank is not coherent acceptance. |
| **5 FAULT** | Possible implementation policy for UNPREDICTABLE input; requires correct exception entry and suppression of ordinary instruction continuation. |
| **6 BACKED ACCEPT** | Meaningful only with defined storage and semantics for the accepted state. Spare storage alone does not define reserved-mode behavior. |
| **7 IMPLEMENT** | Appropriate for a real missing architectural mode, such as a separately scoped legacy-mode implementation. Reserved encodings have no missing standard bank semantics to implement. |
| **8 CPU stop/debugger handoff** | Useful containment for an unexpected internal state, distinct from an architectural guest exception or normal decline. It must preserve host control explicitly. |

The omitted surrounding control flow changes the implementation requirements:

- **MSR copies cached flags before Load**, at line 844. A Load rollback that restores only CPSR can leave `flags` inconsistent.
- **LDM has already committed registers and writeback** at 1749 onward and 1777–1778. After Load, it writes `cpu->pc` at 1817 and invokes `quick_pc_to_pointers_arm` at 1825. A return inserted near Save produces partial execution.
- **DPI writes PC before Save**, at 215. Earlier register-shifter evaluation and immediate handling can already change carry. After Load, it updates translation pointers at 241; an odd PC can then set T and replace `next_ic` at 243–246.
- **Exception entry continues after Load** by writing LR/PC and translation pointers at 730–733.

Therefore I recommend **both caller preflight and defensive bank-helper checks**, with different responsibilities. A shared predicate avoids divergent mode lists; callers define the instruction’s transaction. Bank helpers report failure, and callers must propagate that failure before further state or continuation writes.

Save/Load cannot implement reliable rollback with their present signatures: they receive neither the old CPSR nor a complete snapshot. Merely setting a stopping continuation inside a helper is also insufficient because subsequent PC helpers can overwrite it.

The defaults are **not globally dead** while direct debugger CPSR writes remain possible. Even accepting a modelled value through that route can bypass the required bank transition. Route such writes through coherent state-setting logic before claiming the invariant holds globally.

Keep explicit defaults, but **latched logging followed by ordinary return is not a sufficient backstop**. Use a per-CPU diagnostic latch and an explicit failure result. A function-static latch incorrectly shares suppression between CPUs; inside generated DPI specializations, separate statics can instead multiply announcements. `fatal()` itself indeed returns and bypasses the quiet-mode check: [debugmsg.c](/C:/DocumentNoSnc/cc/GXEMUL/GXEMUL-SEC/src/core/debugmsg.c:384).

For the smallest edit that breaks the proposed contract while staying green: **change the per-CPU announcement latch into a function-static latch**. That breaks “once per instance”; `kill 14` should remain green because the current probe uses a fresh, single-CPU process for each executing row. This is a source-based prediction, not a measurement.

The more substantial coverage gap is an omitted SPSR-restore preflight: the MSR-only `kill 14`, `kill 15`, and `save 2s` rows do not establish coverage of either restore family. Also, [classify()](/C:/DocumentNoSnc/cc/GXEMUL/GXEMUL-SEC/regress/arm_msrmode_probe.py:231) checks whether `(once)` appears, not its occurrence count.

The advertised **17 rows** do enumerate correctly: `enc ok`, `live`, `pc adv`, `armed`, `no cbit`, `kill 14`, `kill 15`, `save 2s`, `acc usr`, `acc fiq`, `acc irq`, `acc abt`, `acc und`, `acc sys`, `same svc`, `usr mask`, `row count`.

Before accepting the eventual fix, I would want measurements of mixed-field rejection, both SPSR-restore continuations, exception entry after rejection, CPSR/cached-flags/PC agreement, and diagnostic isolation between CPU instances. None of those outcomes is established merely by the listed 17-row floor.
