## 1. Premise that is wrong

"Both `default:` arms are reachable only by a debugger `cpsr=` assignment" is false. The same sentence is in the probe header and in both backstop comments in `cpu_arm.c`.

`cpsr` is a raw settings word (`CPU_SETTINGS_ADD_REGISTER32("cpsr", cpu->cd.arm.cpsr)` in `arm_cpu_new`). The assignment stores the integer and returns. It does not call `arm_save_register_bank` or `arm_load_register_bank`.

What reaches the defaults is the next bank call while `M[4:0]` is already unmodelled:

- `dbg save` reaches Save from the guest `MSR CPSR_c,#0x13`. The immediate is modelled, so the new MSR guard does not run. `switch_register_banks` is true because the current mode is `0x14`. Save's `default:` announces and returns.
- `dbg both` reaches both defaults from the guest `MOVS pc,lr`. Mode `0x14` has no SPSR, so `spsr_copied` stays 0, the DPI guard does not run, and the DPI template still calls Save and then Load.
- `arm_exception()` calls `arm_save_register_bank()` at `cpu_arm.c:711` before it replaces `M[4:0]` (`:739-740`) and before Load (`:762`). A SWI, undefined instruction, prefetch abort, data abort, or a non-single-step IRQ taken while `M` is unmodelled hits Save's backstop, then continues into a modelled exception mode.

The parenthetical in Save's comment ("msr_imm and both SPSR restores decline an unmodelled mode first") describes the value being written. It does not describe the current mode. `dbg save` is a guest `msr_imm` that enters Save's `default:`.

## 2. Guards against real control flow

The three new guards sit where the rows need them.

- `msr_imm`: the mode bits are cleared from the local `mask` at `cpu_arm_instr.c:846`, and `switch_register_banks` is computed from that mask at `:849`. The register form `msr` writes `ic->arg[0]` from Rm and tail-calls `msr_imm`, so it is covered. `arg[0]` is the rotated immediate (`:4349-4352`), and a c-field mask is the whole low byte, so `M[4:0]` is either all written or not written.
- `arm_pop`: on the FIQ/IRQ/SVC/ABT/UND path the new block does not return. The PC load at `:1851` is outside `if (return_flag)` and still runs. The pre-existing `default:` at `:1814` still sets `cpu->running = 0` and returns before that load.
- DPI: `cur_mode` is sampled, `new_cpsr` starts as the current CPSR, `spsr_copied` is cleared only in the `default:` (USR, SYS, and any unmodelled current mode). The guard runs only when an SPSR was copied. `cpsr` is assigned at `:247`, then `flags` at `:248`, then Load. The PC was stored before this block. There is no return between the guard and Load.

No guest write of a reserved mode through these three writers still reaches `exit(1)`. The bank `default:` arms return. `fatal()` only prints.

`running = 0` is still reached when the current mode is already outside FIQ/IRQ/SVC/ABT/UND: `arm_pop`'s `default:`, `msr_imm_spsr`'s `default:`, and `mrs_spsr`'s `default:`. That set includes a reserved current mode and USR/SYS. After this fix a guest MSR, `LDM {pc}^`, or S-to-PC cannot install that current mode. A debugger poke followed by `LDM {pc}^` or `MSR/MRS SPSR` still stops the CPU. The same poke followed by `MOVS pc,lr` hits the backstops and stays alive. `arm_exception` index 5 still `exit(1)`s, and nothing in `src/` calls it.
