For question 6, **the distinction between `sgirandomcolour` and `sgirebufuninit` survives**.

They protect different invariants:

- `sgirandomcolour`: an unsupported PUT performs **no store**.
- `sgirebufuninit`: every byte consumed by an actual transfer or colour reconstruction is **initialized**.

A mutant can violate both simultaneously. That does not make the invariants interchangeable.

An early return fixes the unsupported PUT path but leaves the accepted-width cases above. Initialization prevents disclosure through those bytes but does not make an unsupported store correct.

GET adds another independent initialization problem: RGB reconstruction consumes three bytes; RGBA, ABGR and the default reconstruction consume four. Depth-one and depth-two reads can supply fewer bytes than those expressions consume. The callback’s return value is also ignored, although the permitted files do not establish its failure/partial-read guarantees.

Neither supplied probe exercises this helper’s GET packing path. CPU loads of destination RAM and reads of RE register arrays are not calls to the pixel GET branch.

Three oracle issues remain material.

**First, every existing depth-eight decline assertion observes only four bytes.** `cell_op()` paints one word and reads it with `lw`; `printed_seq()` normalizes to 32 bits. The `d8` names do not change that. [Cell operation and parser](C:/DocumentNoSnc/CC/GXEMUL/GXEMUL-SEC/regress/sgi_re_colourdefault_probe.py:434)

I would strengthen the existing `tA`, `tB`, `tC` and `lin ycrcb d8` assertions to paint and compare all eight bytes, using distinct nonzero contents across the two words. This need not add logical rows or sessions.

The named distinguishing control for each is `TAIL_WRITE(mode)`: an incorrect declined operation changes the upper-addressed four bytes while preserving the first four. The existing channel cannot vary under that control; the strengthened channel can.

**Second, unchanged paint is not proof of no store.** Uninitialized bytes can happen to equal the paint. Therefore, the proposed eleven rows and existing disclosure rows have a nonvacuous destination channel, but a source-only review cannot promise that each will kill its mutant on a particular build.

A test harness observing **zero write callbacks** would establish the refusal effect without copying or depending on uninitialized bytes. Such a harness is not present in these files. It is a separate testing capability, not something I can claim the existing sessions already provide.

**Third, the anchor and latch claims have narrower scopes than some comments suggest.**

`xy anchor t0` watches tile zero’s word at offset zero. It does not watch every offset in tile zero. A translation error preserving a nonzero offset can leave that anchor unchanged; the per-cell accept rows provide the relevant detection for those ordinary misrouting cases.

Similarly, `allbits` establishes **other latches first, colour second**. The width probe’s two-order TEX/unmapped example does not establish colour-first independence.

I would add one aggregate `colour/others` assertion to an existing colour-first session: after the colour announcement, drive the twelve other sites and require each expected announcement. Its named control family is `SET_OTHER(j)`: the colour warning update also sets another site’s bit. The observable is the missing announcement from site `j`. The current other-first sequence can remain green under that error because the other bit was already set.

That adds one assertion and needs no new process. It complements, rather than repeats, the existing shared-bit control. [Existing colour priming](C:/DocumentNoSnc/CC/GXEMUL/GXEMUL-SEC/regress/sgi_re_colourdefault_probe.py:326), [Width probe’s ordering precedent](C:/DocumentNoSnc/CC/GXEMUL/GXEMUL-SEC/regress/sgi_re_width_probe.py:570)

Finally, extending coordinates across depths requires recomputing and validating the selected entry and destination. Reusing C1’s fixed vertex at another depth can select another tile; changing only the mode can consequently turn a proposed decline test into an earlier invalid-pointer return. Each added address/depth setup needs an accepting control that proves that same mapping reaches its intended destination.

The concrete review recommendation is therefore an unconditional default-arm return, an explicitly warranted treatment of buffer initialization, and a contract that names its actual partitions. The **eleven missing mode/depth/latch cells, one reverse-latch assertion, and strengthened four depth-eight assertions** are a bounded, reviewable improvement.
