## 1. The repair is right

**Encoders.** `LD_HU = enc(0x02,…)` and `ST_H = enc(0x0a,…)` match `cpu_m88k_instr.c` (`case 0x02: ld.hu`, `case 0x0a: st.h`) and the width probe. Decode is `op26<<26 | d<<21 | s1<<16 | imm16` with `d=(iword>>21)&0x1f`, `s1=(iword>>16)&0x1f`. `rs1=2` is the PCC2 base. Same layout the width rows already run.

**Register plan / endian / 0x78.** T1CMP write is `memcpy` of guest bytes (`dev_pcc2.c` T1CMP arm). m88k is big-endian (`memory_readmax64` shifts `buf[0]` first), so `st.w 0x12345678` at 0x04 lays `12 34 56 78`. Then:

| insn | what |
|---|---|
| `ld.bu r4, 0x05` | 0x34 — `srvd val` / first latch bit (0x05 only) |
| `ld.hu r6, 0x06` | 0x5678 — aligned (even); announces; sets bit **0x06 only** |
| `st.h r7=0xaabb, 0x06` | silent (bit already set), **declined** — handler memcpy is READ-only, so the array is untouched |
| `ld.hu r6, 0x06` | still 0x5678 — `half wr rdawr` |
| `ld.bu r8, 0x05` | 0x34 — `srvd rd latch` |
| `st.b r7, 0x07` | **first** access at 0x07 (len-2 at 0x06 does not set bit 0x07); announces; declined; idata = 0xbb |
| `ld.bu r9, 0x07` | **0x78** — the T1CMP byte the word store left |

`srvd wr latch` want 0x78 is not a guess: BASE.out is 46/46 with that value, and M_BACKEDLOW.out shows the discriminator (`srvd wr latch` 0xbb, `half wr rdawr` 0xbb78) when a low-offset store actually lands. `uint8_t` assignment of idata 0xaabb stores 0xbb at 0x06 only, so the halfword becomes 0xbb78 — that is why M_BACKEDLOW and full memcpy-M_BACKED (0xaabb) part ways.

**Alignment.** 0x06 is 2-aligned; 0x07 and 0x21 are bytes. A guest `ld.w` at 0x05 never reaches this arm (alignment is checked before `memory_rw`).

**Text anchors do not collide.** Read format is `-- served 0x%02x`; write format is `: 0x%x -- declined`. `srvd half text` keys on `0x6 (len 2) -- served 0x56`. The len-2 write in that session is silent, so no `0x6 (len 2): 0xaabb -- declined` line exists to steal the count. `wr val text` (`0x30 (len 1): 0x5a -- declined`) and `wide wr val` (`(len 4): 0x5a5a5a5a -- declined`) live in other sessions.

**Product.** Two comment sentences, no code. Tick write-back is T1COUNT/T2COUNT only (`pcc_timer_tick` `write32` at those two labels), under CEN, which is off at init. `timer_tick` *is* the SIGALRM handler and calls `timer->timer_tick` directly (`timer.c`). Fable’s “ticks run between instructions” premise stays refuted; the COUNT-word / end-span comment is the right reason `data[0]` stays the operand.
