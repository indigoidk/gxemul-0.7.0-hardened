*** WHAT THIS ROUND IS FOR: #479's DETECTOR COULD NOT SEE ITS OWN CALL. ***

#479 shipped wdc_new_command_reset() and a detector that kills 13 of 13 mutants of that
helper's BODY.  Three one-line edits to WHETHER IT IS CALLED swept all 80 rows with
BYTE-IDENTICAL output: M11_sameop (`if (!same_cmd)`), M4_afterguard (move below the two
early-return guards), M23_exemptfill (exempt the ring-filling opcodes).

THE STRUCTURAL REASON, and it is the transferable part: every #479 reproduction row
called wdc_command() DIRECTLY, with stub_disk_exists = 1, using two DIFFERENT opcodes.
No row was in a position to notice a condition appearing in front of the call.  The blind
spot was a property of how the rows were CUT, not of what they asserted.


*** THE GENERALISATION WENT THROUGH THREE FORMS.  The third is the opus seat's and it is
    the one to carry forward, because the first two EXCLUDED THIS ROUND'S OWN HEADLINE
    MUTANT. ***

  v1  "...at least one row that reds if that call BECOMES CONDITIONAL."
      M4 is a RELOCATION, not a condition -- so the round's headline mutant was not an
      instance of the round's own rule.  Named by the kimi-k3:cloud seat.

  v2  "...conditioned, OR MOVED BELOW A DECISION POINT."
      Covers M4.  Still existential: "at least one row" is discharged by ANY single
      condition, and the shipped detector satisfied it while FOURTEEN other
      conditionalisations of the same call escaped.

  v3  A detector for a fix that adds an unconditional call owes a row for each way the
      call can STOP RUNNING ON A PATH THE FIX CLAIMS:
        (i)  a condition in front of it, enumerated over THE CLASSES THE ENCLOSING
             FUNCTION DISPATCHES ON -- for a command dispatcher that is the switch's
             arms, not the opcodes some row happens to use; and
        (ii) a MOVE BELOW ANY EARLY RETURN in the same function -- one row per return.

v3 is what this round is built to.  For wdc_command() it enumerates 20 case labels plus
default, and 2 early returns, both readable straight off the source -- so it stays closed
over the diff's own hunks and cannot become #392.  It is discharged by TWO rows.


*** THE TWO ROWS, AND WHY EACH WAS NECESSARY RATHER THAN TIDY. ***

row_absent_drive_resets -- clause (ii), the early return nobody covered.

  MEASURED CAUSE: all seventeen wdc_command() calls across all rows ran with
  stub_disk_exists = 1, so THE NO-DISK GUARD FIRED IN NO ROW ANYWHERE.  Moving the call
  below that guard ONLY -- strictly smaller than M4 -- escaped everything:

      HEAD   ok    absent-drive command resets   0 cmd(s) flag 0 abrt 1
      PRE    ok    absent-drive command resets   0 cmd(s) flag 0 abrt 1
      p1     FAIL  absent-drive command resets   1 cmd(s) flag 1 abrt 1

  Note the PRE column: this is a WOULD-BE regression past the pre-#479 baseline, on the
  most common path there is -- every ATA bus scan probes absent drives.  An abandoned CDB
  survives, stray bytes complete it, and a SCSI command is dispatched on a command the
  device has just aborted.

row_every_opcode_resets -- clause (i), and it exists because A KILLED MUTANT'S FAMILY IS
  NOT KILLED.

  M23_exemptfill is scored KILLED, and THREE OF ITS FOUR CONJUNCTS ESCAPED ALONE.  Two
  seats reached this independently and named different smallest members -- fable
  `!= WDCC_READ`, opus `!= ATAPI_IDENTIFY_DEVICE`.  The structural reason (fable, by
  reading): across all rows the only opcodes ever issued through wdc_command() over a
  DIRTY device were WRITE, IDENTIFY, ATAPI_PKT_CMD and ATAPI_SOFT_RESET.  READMULTI and
  ATAPI_IDENTIFY_DEVICE never passed through it at all.

      *** SO THE TABLE KILLED THE MEASURED MUTANTS AND NOT THEIR FAMILIES. ***

  ATAPI_IDENTIFY_DEVICE is the sharper escape: it shares a case label with WDCC_IDENTIFY,
  fills the ring identically, and is THE STANDARD ATAPI PROBE -- the more reachable half
  of the mutant, while row_refill_cmd_resets uses WDCC_IDENTIFY only.

  THE ORACLE THAT COLLAPSES TWENTY ROWS INTO ONE is `occ % 512 == 0`: a command that

  unflushed 100-byte residue makes both impossible whatever the opcode does afterwards.
  Seven sole kills for one row.
