### (a) Findings that are wrong or overstated

Furthermore, `goto bad` does not terminate the host emulator; during normal execution it reaches `cpu_dyntrans.c:2014`, setting `cpu->running = 0` (stopping CPU progress), while speculative read-ahead bypasses it at `cpu_dyntrans.c:1990–1991`.
2. `cpumipsinstr:F2` (overstated consequence and filing state): Astra reported this as an unfiled CODE defect that unconditionally selects `reboot`. The defect is already filed by prose at `OUTSTANDING_BUGS.md:2668–2671` (`BREAK-reboot-sentinel`) and `:2604–2605` (`#235`). Moreover, execution does not unconditionally halt or reboot: `cpu_mips_instr.c:2614–2617` first checks `if (!cop0_availability_check(cpu, ic)) return;`. Severity is LOW.
