1. **Overbroad precedent — dossier:174**

   > “The nearest precedent is in the same translator: page protection failures already select `DSISR_PROTECT`, populate DAR, add `DSISR_STORE` for a write, and call DSI/ISI rather than ending the process.”

   This needs two qualifications. The `PPC_603` branch selects software-reload exceptions instead; only the non-603 **data-access** branch populates DAR and DSISR. The instruction branch calls ISI without supplying its protection cause. (`src/cpus/memory_ppc.c:307–323`; `src/cpus/cpu_ppc.c:323–327`.)

   **Corrected sentence:** “For unsuppressed page-protection failures outside the `PPC_603` path, data accesses populate DAR and `DSISR_PROTECT`, add `DSISR_STORE` for writes, and call DSI; instruction accesses call ISI without supplying its protection-cause bit.”

   Dossier:190–191 recognizes these limitations, but that does not make the unqualified sentence accurate.

**(a) Member 5 is right; delivery code exists but is incomplete.**

A matched BAT denial currently reaches the explicit `exit(1)` before the suppression check. The manual requires DSI for prohibited data accesses and ISI for prohibited instruction fetches. Suppressed probes require a failure return. (`src/cpus/memory_ppc.c:273–275,299–300`; manual:13312,13334–13336.)

The actual delivery machinery is `ppc_exception()`:

- SRR0 receives `cpu->pc`: `src/cpus/cpu_ppc.c:321`.
- SRR1 receives masked MSR: `src/cpus/cpu_ppc.c:323–327`.
- Only EE, RI and PR are cleared: `src/cpus/cpu_ppc.c:333–335`.
- The vector PC is selected and execution pointers rebuilt: `src/cpus/cpu_ppc.c:337–344`.

Thus this is an existing delivery implementation, not merely exception constants. However, the dossier correctly identifies missing ISI protection state and uncleared IR/DR. Its warning about downstream termination is also supported: failed instruction reads still exit, and dyntrans has an exception-handler-translation exit. (`src/cpus/cpu_ppc_instr.c:4115–4119`; `src/cpus/cpu_dyntrans.c:720–732`.)

The integration discussion also omits other exception-entry state: the manual requires clearing POW, FP, FE0, FE1, SE and BE, and copying ILE into LE. The helper’s mask does none of those. This is an omission, not another false sentence, because the dossier does not claim its integration list is exhaustive. (`src/cpus/cpu_ppc.c:335`; manual:11751–11757,11803–11809.)

Vector arithmetic checks out: DSI is `3 × 0x100 = 0x300`; ISI is `4 × 0x100 = 0x400`. Adding the IP base `0xfff00000` produces `0xfff00300` and `0xfff00400`. (`src/include/cpu_ppc.h:252–253`; `src/cpus/cpu_ppc.c:337–339`; manual:11767,11811.)
