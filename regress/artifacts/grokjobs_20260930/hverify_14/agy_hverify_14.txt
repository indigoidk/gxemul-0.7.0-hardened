### (a) Findings wrong or overstated

1. **`hgdromdefaultprobe:F3` is WRONG and OVERSTATED.**
   - Finding text: *“With a supplied KERNEL already containing byte 0x10 at DMA_DST_P1, accept data returns 0x10 both with and without the DMA copy. Only register r4 is poisoned; destination memory is never initialized or checked.”*
   - Rebuttal: Under the actual committed test kernel at HEAD (`vmlinux-landisk`), the bytes loaded at destination `DMA_DST_P1` (`0x8c008000`) before the DMA transfer hold `0xea`. As explicitly recorded and measured in [regress/gdrom_default_probe.py:1360-1372](file:///C:/DocumentNoSnc/cc/GXEMUL/GXEMUL-SEC/regress/gdrom_default_probe.py#L1360-L1372):
     ```python
     #    * `mov.b` SIGN-EXTENDS.  0xea has bit 7 set, so it arrives as
     #      0xffffffea.  0x10 does not, which is why the ran-case is clean.
     #  The row still discriminates -- 0x10, 0xffffffea and 0x5a are three
     #  distinct values -- so the ROW is sound and only its stated REASON was
     #  wrong.
     ```
     If the DMA copy is omitted or broken, `MOV_B_AT_R1_R4` reads `0xea`, returning `0xffffffea`. That fails against the expected `"0x10"`. The check therefore CAN and DOES fail on an omitted transfer. The finding manufactures an escape by postulating an external hypothetical kernel image containing `0x10` at that address rather than analyzing the tree at `db8b1a33`.
