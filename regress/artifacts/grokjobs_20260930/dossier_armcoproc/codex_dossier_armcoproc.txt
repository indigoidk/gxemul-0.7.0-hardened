The false sentence is at **dossier line 141**:

> “A disposition absent from the list is **stop the virtual CPU and enter the debugger while retaining the host process**; the shared decoder's unsupported-instruction path does this.”

The decoder **requests** debugger entry; it does not guarantee debugger entry or host retention.

- It sets `about_to_enter_single_step`, clears `cpu->running`, and resets debugger stepping state. (`src/cpus/cpu_dyntrans.c:2002`, `:2014`, `:2021`.)
- When all CPUs have stopped, `machine_run()` returns false. (`src/machines/machine.c:741–746`.)
- When no machine remains running, the emulation loop breaks unless `debugger_enter_at_end_of_run` is enabled. This happens before the next iteration could process the debugger request. (`src/core/emul.c:1033–1039`, `:1052–1059`.)
- That setting defaults to false. After emulation returns, `main()` performs cleanup and returns zero. (`src/debugger/debugger.c:72`; `src/core/main.c:807–821`.)

**Corrected sentence:** “The shared decoder stops the virtual CPU and requests debugger entry; when no machine remains running, the emulation loop instead ends unless end-of-run debugger entry is enabled.”

The following sentence—“It remains a CPU stop, not continued execution or an architectural exception”—is still supported by the decoder’s implementation. (`src/cpus/cpu_dyntrans.c:2002–2024`.)
