### Adversarial Verification of Settled Premises (§4)

1. **Premise 1: `ofs = (relative_addr & 3) % len` and write arm forwards `data[ofs]`**
   * **Source Evidence:** [`dev_lca.c:280`](file:///C:/DocumentNoSnc/CC/GXEMUL/GXEMUL-SEC/src/devices/dev_lca.c#L280) performs `relative_addr >>= 5;`, transforming the sparse address offset into the ISA port $P$.
   * [`dev_lca.c:297`](file:///C:/DocumentNoSnc/CC/GXEMUL/GXEMUL-SEC/src/devices/dev_lca.c#L297) computes `ofs = (relative_addr & 3) % len;` (which is $(P \ \& \ 3) \pmod{\text{len}}$).
   * [`dev_lca.c:308-310`](file:///C:/DocumentNoSnc/CC/GXEMUL/GXEMUL-SEC/src/devices/dev_lca.c#L308-L310) takes `byte = data[ofs];` and forwards it via `cpu->memory_rw(cpu, cpu->mem, LCA_ISA_BASE + relative_addr, &byte, 1, writeflag, ...);`.
   * **Verdict:** **VERIFIED**. For $\text{len} = 16$, $(P \ \& \ 3) \pmod{16} = P \ \& \ 3 \in [0, 3]$, indexing `data[0..3]`.

2. **Premise 2: [`store_buf`](file:///C:/DocumentNoSnc/CC/GXEMUL/GXEMUL-SEC/src/core/memory.c#L837-L857) chunk decomposition $\{1024, 256, 64, 16, 4, 1\}$ and GETENV transfer length**
   * **Source Evidence:** [`memory.c:839-853`](file:///C:/DocumentNoSnc/CC/GXEMUL/GXEMUL-SEC/src/core/memory.c#L839-L853) initializes `psize = 1024;`, checks alignment `(addr & (psize-1)) == 0`, loops while `len >= psize` forwarding `psize` bytes, and divides `psize >>= 2;` per iteration.
   * For the 4 configured cells in [`CELLS`](file:///C:/DocumentNoSnc/CC/GXEMUL/GXEMUL-SEC/regress/lca_widewrite_probe.py#L203-L208) with $a_3 = 16$ and 16-char string $s$, $\text{len} = \min(a_3, \text{strlen}(s) + 1) = 16$.
   * Addresses $SP(P) = 0\text{x}1c0000000 + (P \ll 5)$ for $P \in \{0\text{x}2\text{ff}, 0\text{x}2\text{fc}, 0\text{x}021, 0\text{x}2\text{fe}\}$ satisfy `(addr & 15) == 0`. Even though ports $0\text{x}2\text{fc}$ and $0\text{x}2\text{fe}$ are aligned to 64 bytes (`0x5f80` and `0x5fc0`), `len >= 64` evaluates to false, so chunking bypasses 64 and emits exactly one 16-byte chunk at $\text{psize} = 16$.
   * **Verdict:** **VERIFIED**.

3. **Premise 3: Single session per cell required because read-arm fall-through zeros [`store_buf`](file:///C:/DocumentNoSnc/CC/GXEMUL/GXEMUL-SEC/src/core/memory.c#L837-L857)'s source**
   * **Source Evidence:** In [`memory.c:844-846`](file:///C:/DocumentNoSnc/CC/GXEMUL/GXEMUL-SEC/src/core/memory.c#L844-L846), [`store_buf`](file:///C:/DocumentNoSnc/CC/GXEMUL/GXEMUL-SEC/src/core/memory.c#L837-L857) passes `(unsigned char *)s` (the host boot string) as `data` into `cpu->memory_rw`.
   * When mutant `M2_len8` (`&& len <= 8`) declines a write with $\text{len} = 16$, execution falls through into the read arm in [`dev_lca.c:317-318`](file:///C:/DocumentNoSnc/CC/GXEMUL/GXEMUL-SEC/src/devices/dev_lca.c#L317-L318):
     ```c
     for (i=0; i<len; i++)
         data[i] = i == ofs? byte : 0x00;
     ```
     This directly overwrites the caller's source string `s` in host RAM with zero bytes. If subsequent cells shared the process, the boot string would be corrupted and truncated.
   * **Verdict:** **VERIFIED**. One isolated emulator process per cell is mandatory.
