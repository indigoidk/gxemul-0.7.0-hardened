## Q3 — What all nine of us missed

1. **Silent-pass under heavy load is not pinned by any row.** The contract discloses "below N = 763 it would pass SILENTLY", but the gate only pins the *predicted* uncapped backlog (3052) — the *actual* N is not pinned. A future CI machine with 12+ busy loops already drops N from 3051 to 1183; one more loop drops it under 763 and the removed-bound mutant goes green undetected. This is a real environmental fragility, and it is not in F1–F32.

2. **F12 / F13 over-claim gating.** `fbdrainxdisable` and `fbboundmodes` are FILED, not GATED. M_f16 "passes every row here and in gate 2" is a probe-side claim with no gate 14 row pinning it. If the flagship seat reads F12/F13 as "these are now exercised by the gate," that is wrong.

3. **`trough2` is dead.** Declared and written by both drives, never read. Compilers with `-Wunused` will warn; the disposition (F29 REJECTED) does not own this.

4. **The row() format-on-PASS assumption is the silent joint of F8 and F32.** Without it, both pins return 0 on every base run and the gate is permanently red. The panel should have asked the author to pin this contract in writing.

5. **ARM X's specific behavior is not gate-pinned.** The 12-distinct-green-ids check is coarse. A sophisticated mutation that *replaces* ARM X's row with a different-ID row passing the verdict leaves 12 ids and passes the coarse check. This is the F4 class and is filed; but the gap is real.

6. **`--expect-cap` is pinned only via the BOUNDED print.** If the probe changes its default for `--expect-cap`, the BOUNDED line changes and the pin fires — fine. But if someone deletes the `--expect-cap 762` from `gate_arm.sh` entirely, the probe becomes REPORT-ONLY; the verdict guard catches this only if the probe does *not* print PASS in report-only mode. Worth a one-line confirmation.

The most consequential miss is **#4** (row() format-on-PASS). Everything else is documentation-quality. The action set is correct; the contract behind it is under-specified.
