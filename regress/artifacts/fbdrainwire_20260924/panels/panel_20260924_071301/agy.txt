## 4. What Did All Nine Seats Miss? (Question 3)

Across passes 1 and 2, all nine seats overlooked the following concrete issues:

1. **Python Operator Precedence Flaw in [`fbpending_drain_probe.py:825`](file:///C:/DocumentNoSnc/cc/GXEMUL/GXEMUL-SEC/regress/fbpending_drain_probe.py#L825)**:
   ```python
   print("FBDRAIN_CLOCK_DEAD=%s" % ("D " if deadD else "") + ("X" if deadX else ""))
   ```
   In Python, `%` binds tighter than `+`. This parses as:
   `("FBDRAIN_CLOCK_DEAD=%s" % ("D " if deadD else "")) + ("X" if deadX else "")`
   While it happens to output `"FBDRAIN_CLOCK_DEAD="` when both clocks are alive, `"X"` is string-concatenated to the formatted string rather than formatted via `%s`. If `deadX` is true and `deadD` is false, it prints `"FBDRAIN_CLOCK_DEAD=X"`. If both are true, it prints `"FBDRAIN_CLOCK_DEAD=D X"`. It functions by accident of concatenation rather than proper tuple formatting:
   ```python
   print("FBDRAIN_CLOCK_DEAD=%s%s" % ("D " if deadD else "", "X" if deadX else ""))
   ```
