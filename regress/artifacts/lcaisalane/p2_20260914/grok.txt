### 1. The fix is right

`len` is `size_t`. After `if (len == 0) return 0`, `ofs = (relative_addr & 3) % len` is in `0 .. len-1`. No `% 0`, no `data[ofs]` past the caller buffer, no `exit(1)` left in this function. Nested forward is `LCA_ISA_BASE + port` (`0x1d0000000`), outside the sparse map (`0x1c0000000` .. `+0x200000`), so it cannot re-enter `lca_isa`. Handler `return 0` is `MEMORY_ACCESS_FAILED` with no Alpha exception; a load keeps the destination (`cpu_alpha_instr_loadstore.c`). `fatal()` only prints.

Let `P = port & 3` after `>>= 5`. Position is `P % len` on **both** arms, which is disposition B.

| len \ P | 0 | 1 | 2 | 3 | guest producers |
|---|---|---|---|---|---|
| 1 | 0 | **0** | **0** | **0** | `ldbu`/`stb` (measured) |
| 2 | 0 | 1 | **0** | **1** | `ldwu`/`stw` (measured) |
| 3 | 0 | 1 | 2 | **0** | 1 KB split head (not this probe) |
| 4 | 0 | 1 | 2 | 3 | `ldl`/`stl` (reads as `ofs* wide`) |

Bold cells are the ones HEAD got wrong: `(1,1)` and `(2,2)` reads discarded the fetched byte (`ofs == len`); `(1,2)`, `(1,3)`, `(2,3)` reads and writes hit `ofs > len` and `exit(1)`. Writes of `(1,1)` and `(2,2)` already used `data[ofs % len]` on HEAD; the new `data[ofs]` is the same index once `ofs` is folded.

For len 4 and 8, `P % len == P`, which is the lane HEAD already used on the hardware-legal widths. For len 2, `(2,3) → position 1` is the same rule as the served `(2,1)` cell (`r21` = `0x6000` on HEAD and after). `ALPHA_FEATURE_BWX` is a `#define` and is never read under `src/`.

No cell I can produce still ends the host, indexes OOB, or divides by zero.

### 3. Wrong statements

**The #530 comment (and the probe header’s “K0SEG, untranslated” reason) are the ones that do not survive a re-read.**

1. **Fix comment:** *“the old `ofs > len' exit(1) ended the host on a guest byte/word access to a port 2 or 3 mod 4”*. Word + port 2 is `(2,2)`: `2 > 2` is false. HEAD does **not** die there; the read discards the byte (`r22` = 0 in `HEAD_det.out`) and the write already lands (`w22` = `0xf0`). Death is `(1,2)`, `(1,3)`, `(2,3)` only. The next sentence about `ofs == len` is the correct one; the first sentence contradicts it.

2. **Probe contract / PRETABLE:** *“this probe runs on K0SEG, untranslated”* as the reason split heads are unreachable. K0SEG still calls `alpha_translate_v2p` (identity, return 2). `MEMORY_RW` splits whenever `translate_v2p != NULL` and the flag is not `PHYSICAL`. Guest loads use `CACHE_DATA`, so an unaligned `ldl`/`ldq` that straddles a 1 KB boundary **would** split on this probe’s machine. What actually keeps len 3/5–7 off the instrument is the instruction stream: every sparse access is `disp=0` on a 32-byte slot, `LCA_PCI_SIO` is 1 KB-aligned, and the last slot in a granule is at `0x3e0` so even an 8-byte access stays inside the granule. Unrowed by construction, not because K0SEG skips the split.

Lesser nits, not load-bearing: POSTTABLE’s gloss *“six host-death cells + two discarded-byte reads + the witness’s three reds”* is 11 names, not the 18 in the PRETABLE list (it drops the death-cell value rows and `w13 roundtrip`). `r22`’s row note says it kills “C/HEAD’s discarded byte”; `m_declbeyond` still folds after a `P > len` miss, so `(2,2)` is green under that mutant (PRETABLE’s channel line is the one that is right).
