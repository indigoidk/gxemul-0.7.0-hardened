## THE WHOLE HANDLER

```c
DEVICE_ACCESS(lca_isa)
{
	unsigned int ofs, i;
	uint8_t byte;

	relative_addr >>= 5;

	/*
	 *  #530: the byte for ISA port P sits at buffer position (P & 3) % len
	 *  on BOTH arms -- the lane for the 21066's own len 4/8 accesses, and
	 *  the rule the write arm already applied wherever the old guard let
	 *  it run.  That guard's `ofs > len' exit(1) ended the host on a guest
	 *  byte access to a port 2 or 3 mod 4 or a word access to a port 3 mod
	 *  4 (ungated BWX; and at a port 3 mod 4 also the 1- or 2-byte head
	 *  of an unaligned load or store that memory_rw splits at 1 KB),
	 *  and the read arm discarded the
	 *  fetched byte at ofs == len.
	 *  One byte is forwarded whatever len is (the size field a<4:3> is
	 *  not decoded here).  len 0 has no producer; refuse it before the %.
	 */
	if (len == 0)
		return 0;
	ofs = (relative_addr & 3) % len;

	if (writeflag == MEM_WRITE) {
		byte = data[ofs];
		return cpu->memory_rw(cpu, cpu->mem, LCA_ISA_BASE +
		    relative_addr, &byte, 1, writeflag, CACHE_NONE);
	}

	cpu->memory_rw(cpu, cpu->mem, LCA_ISA_BASE + relative_addr,
	    &byte, 1, MEM_READ, CACHE_NONE);

	for (i=0; i<len; i++)
		data[i] = i == ofs? byte : 0x00;

	return 1;
}
```

## 2. Channels: the named mutants work, but architectural coverage has another limitation

For the specific overwriting-RD2 and fallthrough forms described, the new constructions are coherent:

- Stub comparisons detect one extra access; chaining does not cancel a preceding failure. The liveness comparison detects loss of the flat-read toggle.
- CMOS masks the clock-dependent high nibble and extracts the correct lane.
- Queue controls support the intended pop-count discrimination.
- `iirr2` calls `iir_arm()` separately for each width.

**However, CMOS and IIR do not detect a duplicated read that preserves the first returned byte.** Insert the duplicate forward **after** the read arm’s `for` loop. The guest buffer already contains the first result; the second result overwrites only the now-unused local `byte`.

Consequently:

- `cmos r*` still returns the expected `0x0f`.
- `iir lca rd*` still returns the expected TXRDY bits.
- The corresponding stub rows detect the extra access.

Thus, for this duplication form, the stub becomes the sole carrier of the lane-1 and lane-2 read cells. That violates [RB1’s explicit carrier requirement](C:/DocumentNoSnc/CC/GXEMUL/_scratchpad/panel_20260915_072943/brief_sent.md:564). These variants need an architectural observation sensitive to the additional read even when its returned byte is discarded.
