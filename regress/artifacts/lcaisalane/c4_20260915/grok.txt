### 2. Floor gap

The 111-row instrument catches unconditioned RD2 (`probe_RD2.raw`: `iir lca rd` 0x1 vs 0x2, 110/111) and **only** that row. 4j is the only lca **read** of IIR. Every other lca read of a side-effect port is 8042 0x60 (`live`, `tailr *`), where a second forward of an emptied queue returns `last_scancode` — the same 0x55 — which Opus measured as 93/93 on the sessions repair 4 did not change.

So this edit to the **fixed** handler:

```c
	cpu->memory_rw(cpu, cpu->mem, LCA_ISA_BASE + relative_addr,
	    &byte, 1, MEM_READ, CACHE_NONE);
	if (len != 1)
		cpu->memory_rw(cpu, cpu->mem, LCA_ISA_BASE + relative_addr,
		    &byte, 1, MEM_READ, CACHE_NONE);
```

in place of the single read-arm forward.

* **Why `iir lca rd` cannot catch it:** that row is LDBU, `len == 1`; the extra forward is skipped.
* **Guest-visible:** an LDL/LDQ of SP(0x3fa) after the same `iir_arm()` (Opus c3’s discriminator, different width). First forward acknowledges TXRDY; the delivered byte is IIR `& 3 == 0x1` instead of 0x2. SP(0x3fa) does not cross the 1 KB split (`0x7f40 & 0x3ff == 0x340`).

This is closing pass 3’s W1, on the read arm: the contract names “the read arm’s forward DUPLICATED” and rows it at one width. The write-arm sentence now says “that edit, **and the same edit gated on the width or the lane**”; the RD2 sentence does not. It is not on the disclosed list.

It is not a (d) DEPENDS-ON of the ofs-fold (the fix never touched the read forward). It **is** a contract-named forward-count cell left open after a class-closure repair of that class — the `#499` shape the last two passes already paid for. Cost to close: LDWU/LDL/LDQ of IIR in 4j (three phases). Scoping RD2 to `(1,2)` only would be option (a) for this arm, which pass 3 rejected for the write arm.

Not offered as the GAP (disclosed or out of contract as written): data-class (`data[ofs] ? data[ofs] : data[0]`), a<4:0>, exact-port, lane-1-only write fallthrough, lane-3-direct, forward-return equivalents, len-0.
