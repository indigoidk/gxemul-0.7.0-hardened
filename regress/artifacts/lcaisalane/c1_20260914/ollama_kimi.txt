## Q1 — the floor gap (REASONED, with one unsettled premise)

The edit: write arm forwards correctly first (`byte = data[ofs];`, nested write still happens), then falls through to the read arm, which issues a **second, phantom device read** at the same ISA port, clobbers `data[0..len-1]` with that read, and returns 1.

Why no row can see it:
- Every store row verifies the *forwarded* byte, and the forward still happens before the fall-through. So `w11/w22/w23`, `st4 lane0`, `st4 lane3`, `st8 lane3`, `h3 stq` all keep their expected values. (Reasoned)
- All probe writes target UART registers whose *reads* are side-effect-free in probe state: SCR, MCR ("stores and returns its low bits"), MSR, LCR, IER, and LSR with no error flags ever set. (Read from packet: port set inferable from UART_MCR=0x3fc plus lane labels → SCR=0x3ff.)
- The print path's THR (0x3f8) writes trigger the phantom RBR read, but sessions consume all typed input during boot, so the RX FIFO is empty during phases. (Reasoned from session()/dsession structure.)
- The data clobber is harmless: it happens after the forward, and for split writes the head clobbers only its own sub-range before the tail (bytes 3..7) is used. Return-value forced to 1 differs from the fix only when the nested write fails (unmapped 0x400 tails), where nothing is mapped either way. (Reasoned)

But the guest-visible outcome changes in general: with this edit, **any guest write to THR while serial input is queued consumes a pending input byte** (RBR read pops it), and a write to FCR reads IIR, acknowledging a pending THRE interrupt. Real input loss / interrupt loss on writes that should not read at all.

Row expected to catch it and why it cannot: the store round-trip class (w2x/st4/st8). It cannot, because the stored value is unchanged; no row writes to a port whose read mutates state that a later row observes (none writes FCR with IER.THRE armed, none leaves RX pending).

**The unsettled premise:** that this tree's UART model (dev_ns16550 or equivalent) consumes queued input on RBR reads / acknowledges interrupts on IIR reads. That is near-structurally forced for any functional console UART, but it is **not checkable from the packet**. Settling fact: the read-path of the UART device source for registers 0x3f8/0x3fa.
