## 1. D1: B, and A’s warrant is the weak one

**Warrant for B.** The write arm already implements fold: `byte = data[ofs % len]`. For every hardware-legal LDL/STL (`len` 4 or 8, `ofs` 0–3) that modulo is a no-op. Its only live effect is the equality cells, where it forwards `data[0]` to the named port. That is member 4 **in place since upstream**, not a newly chosen contract. Mirroring it on the read pack (`data[ofs % len] = byte`) and deleting the guard is applying one formula to both arms. The nested call still names `LCA_ISA_BASE + relative_addr` (the right ISA port). Nothing is fabricated. That is not member 6.

**A, attacked from A’s side (pass 1 was mine).**

- The addition licence constrains *additions*. A **adds a refusal** of stores that land today: `stb` to every port 1 mod 4 (PIC IMR `0x21`/`0xa1`, UART IER `0x3f9`, RTC `0x71`) and `stw` to every port 2 mod 4. “The HRM is silent on BWX” is an absence. Absence licenses A, B, and C equally. It does not license *removing* a behaviour the function already implements.
- Member 3 on the equality cells is not de-fatalisation. Those cells do not call `exit(1)`. Writes work; reads false-zero. Dressing a behaviour change in the house idiom does not make it de-fatalisation.
- `ofs >= len` as “lane must be in the buffer” mis-models `ldbu`/`stb`. For a byte instruction the payload **is** `data[0]`; `ofs` is the port’s sparse lane, not the guest’s buffer index. `1 % 1 == 0` is the unique byte-access contract, and it is exactly what the write arm does at (1,1) today. A refuses a well-formed byte because a longword-lane index does not fit in a 1-byte buffer.

**B’s weakest claim (the one to keep eyes on).** Transferring “the write arm accepts equality” onto the three EXIT cells, where that arm **never runs**, is the step that is a principle rather than a measurement. The principle is fable5’s: if the lane folds onto the buffer at equality, it folds beyond it too. That is modulo arithmetic, not the 21066. The (2,3) cost is real: `stw`/`ldwu` of a port 3 mod 4 picks `data[1]`, the high half of the word. Disclose it. Do not use it to go back to A. The handler already forwards **one** byte to **one** port (F7 / `lcaisasize`); it is not doing ISA-word semantics at (2,3) or anywhere else. For `len==1` — the cells that matter, including UART LCR `0x3fb` and IIR `0x3fa` — fold is `data[0]` and is the right byte.

**C, attacked as requested.** C is A on one side of `>` and B on the other. The line *is* the off-by-one that is the bug. (1,1) `stb` to IER lands; (1,2) `stb` to IIR is refused. Both are byte stores to the same UART. Round-scope (“smallest edit, no regression”) is not a hardware contract and not the function’s contract: the function already folds writes and drops reads at equality. C preserves that asymmetry and **ships F2**. The probe’s own comment forbids that: *“What a fix may NOT do is keep answering a false zero.”* After C, IER writes work, LSR `ldbu` returns 0, LCR `stb` is declined. That is a worse debugging trap than HEAD, which at least dies on the neighbouring cells. F1 and F2 are two faces of one predicate in one function; one design covers both. Deferring F2 is not round-scope, it is leaving the witnessed false success in place.

Sketch obligation if B is taken: `len == 0` makes `% len` undefined. No producer; still write `if (len == 0) return 0;` before the modulo. Do not swallow F6 (`PHYSICAL`) or F7 (`a<4:3>`) into this round.

## 4. What we missed

**S4 is the load-bearing overclaim.** Lack of a booting OS is not lack of a discriminating observable. The existing rung-3 probe already separates the three:

| observable | A | B | C |
|---|---|---|---|
| `ofs2`/`ofs3` process | alive | alive | alive |
| `ofs1 answer` (sentinel vs completed) | faulted (sentinel kept) | completed | completed |
| `ofs1 zero` (LSR byte) | see below | **0x60** | **0** (false success) |
| equality write to IER, read back flat | **does not land** | lands | lands |
| `stb` to LCR `0x3fb` (1,3) | declined | **lands `data[0]`** | declined |
| (2,3) `stw` byte | declined | **`data[1]`** (the high-half cost) | declined |

That is a measurement, not an argument. Run it on three mutants of one function.

**Second miss, and it is a vacuity.** `SENT = 0x0bad1dea`; `SENT & 0x60 == 0x60 == LSR_FIXED`. Under A, `ofs1 zero` **false-greens**: the decline leaves the sentinel, the mask cannot tell sentinel from LSR. Only `ofs1 answer` sees A. The first ruling’s re-pin was trying to paper over a row that cannot observe the decline it wanted. B is the only option that greens `ofs1 zero` for the right reason (the device byte in `data[0]`).

**Third.** Fable5 named IER/IMR/RTC as the equality-write regression. The EXIT **byte** cells are IIR `0x3fa`, LCR `0x3fb`, MSR `0x3fe`, scratch `0x3ff`. If “don’t break UART programming via `stb`” is the reason A is rejected, it is also the reason C is rejected. C still refuses the store that sets baud.

**Fourth.** `amask` is disassembly-only (`cpu_alpha.c` mnemonic, no handler). A guest cannot probe for BWX the architected way. The only producer is a binary that *assumes* BWX on a 21066. That is emulator policy, and B is the policy that makes those instructions do the one-byte-to-the-named-port thing the write arm already does.
