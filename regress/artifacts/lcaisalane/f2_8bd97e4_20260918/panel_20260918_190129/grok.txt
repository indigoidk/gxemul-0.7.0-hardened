### 3. What all nine missed

1. **Covering ≠ closure.** `{mc2, kbc1024}` detects every mutant in the table and is still blind to a body-legal lane-1 exemption. The author asked for a cell set if L2; that pair is not it.

2. **GETENV is capped by the host string.** `len = min(a3, strlen(boot_string_argument)+1)`. `a3` is a guest register; the string is `-o`. C=256/1024 are not freely guest-reachable. Does not change the four-lane floor; it does mean `kbc1024` is a weak pin to lean on.

3. **A `len > 8`-gated write-arm fallthrough** (`if (len <= 8) return nested;`) still writes the destination byte, then the read arm clobbers the host boot string. Every destination-only width row, including the four-lane set, stays green. The parent catches only the **ungated** fallthrough. Channel gap, disclose it; do not grow the floor for it.

4. **`vf` is equivalent at lane 0.** A lane-0-only strengthening would drop the one listed variant the shipped row actually kills. Lane 3 was the right cell for `vf` and the wrong sole cell for `vc`. Another reason the four-lane set is the unit, not “add whatever reds in section 3.”
