## The planted wrong premise (§1(e))

READ: the guard is `if (ofs > len) { fatal(...); exit(1); }`. REASONED: for (len=2, ofs=3), `3 > 2` is **true** — that cell exits before either arm. The write arm's `data[ofs % len]` is only ever reached when `ofs <= len`, and `ofs % len` differs from `ofs` **only** at `ofs == len` (cells (1,1) and (2,2), where it clamps to `data[0]`). So the modulo is not "tribyte/word lane semantics"; it is a clamp that exists solely to serve the two equality cells, and it does so on the write side only. The brief's parenthetical is the kind of statement seven seats would ratify without walking the guard.

A corollary nobody stated: today the arms are **asymmetric** at the equality cells. (1,1) and (2,2) **writes** already forward `data[0]` to the device and return its status — they work. The same cells on **read** drop the byte and return false success. Whatever option ships, the current state is not a defensible instance of any of S3's seven members; it's two different ones welded together.

## 2 — smallest breaking edits, and the row that falsely stays green

The brief's six, plus these I can add:

1. **`return 0` → `return 1` in the decline branch** (text kept, byte not packed). Every liveness row stays green (`live`, sentinel, once-text); only the register/downstream-count channel catches it — a channel currently blocked on 1(d). This is the most dangerous one-character mutant on the list.
2. **Guard evaluated on the pre-shift address** (`relative_addr & 3` before `>>= 5`): sparse addresses are `<<5`, so low bits are always 0, `ofs'` is always 0, nothing ever declines. `live`, all accept rows, even `devsig` stay green; only decline rows catch it.
3. **Downstream read-result check polarity inverted** (`if (ok) return 0`): caught *for free* by `live` — every served read declines. Name it so nobody spends a row on it.
4. **Failed-write status swallowed to `return 1`** in the write arm: on Alpha a store has no result register, so with the latch already spent there is *no guest-observable channel at all* — vacuous without host-side observation (see Q4).
5. **The one-character `>` → `>=` *keeping* `exit(1)`**: equality cells convert from false success to death. Everything before the first refused access stays green; only the `LCAISALANE_DONE` sentinel row catches it. Concur with Codex: this mutant must be in the kill table precisely because it's the obvious patch.
6. **`data[ofs % len]` → `data[ofs]` alone, without the write-side decline**: out-of-bounds read of the caller's 1- or 2-byte buffer at refusal cells. Caught by the decline rows plus any sanitizer build; worth naming because it's the "tidy-up" a tired author applies.
