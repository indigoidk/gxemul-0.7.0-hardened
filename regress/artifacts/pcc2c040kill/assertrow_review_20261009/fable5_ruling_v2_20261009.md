## X -- `assert = 0;` -> `assert ^= 1;`  => FLOOR, one row owed, regress-only follow-up

What it does. When the C040 test runs, `assert` is 0 or 1. The fix forces it to 0. X flips it. If a request is pending above the mask and MIEN is on (assert = 1), flip gives 0 -- identical to the fix. If nothing is pending (assert = 0), flip gives 1 -- the arm drives the CPU interrupt line on a C040 write that should have left it down.

Why every shipped row passes it (measured 18/18, probe_xor.raw). The four delivery rows (`irq live`, `c040 noassert`, `c040 noassert2`, `c040 recover`) all raise the SCC TX line through the clmpcc IER store BEFORE the C040 write -- that precondition was added on purpose to catch the `return` variant -- so they only ever enter the arm with assert = 1, where X equals the fix. The stepped rows (`c040 kill`, `says`, `once`, `predirty`) DO enter the arm with assert = 0 (GENCTL = 0x04, nothing pending), but they single-step, dispatch is suppressed while stepping (cpu_dyntrans.c:206), the line state `irq_asserted` has no guest-readable reflection (cpu_m88k.c:415/420), and their oracles are alive / announce text / count. So the state is reached and the channel cannot vary. Under X nothing in the table moves.

Why it is floor, not debt. The table's claim is "with C040 set, the line is not asserted." That claim has exactly two input cases -- something pending, nothing pending -- and the table pins only the first. The second is the device's reset state (IPL 0, MASK 0, no INT bits): a single byte store of 0x06 to GENCTL in a fresh machine reaches it, which makes it MORE reachable than the rowed case, not less. X is a one-token change to the repair's own assignment that is wrong in half of that assignment's reachable domain. That is a mutation of the repair, not of some remote input, and its guest-visible consequence (a spurious interrupt while C040 is set) is the exact behaviour the fix exists to prevent, reached from the idle side instead of the pending side. [Clause (d): guard kept, repair perverted. The joint cell {C040 set} x {assert entering = 0}: `assert` is the repair's write target and the function's own `if (assert)` three lines below splits it {0, nonzero}, so the 2x2 is the diff-closed floor; (clear,1), (set,1) and clear-after-set are rowed, (set,0) is the open symmetric cell -- the #499 shape. The "derived local, data-flow chasing" reading that would make it clause (e) fails because `assert` is not an upstream input chased through the function; it is the variable the repair writes, consumed by the next statement.]

The row. `c040 idle`: the `assert_row()` shape with the clmpcc IER store removed (SCCTX armed IEN|level 3 but no INT, so nothing is pending), final GENCTL = 0x06 (MIEN|C040, to keep MIEN out of it), breakpoints at the interrupt vector (0x8) and at completion; want pc == completion. Companion control `c040 idle scctx`: the r11 readback must be 0x13 (IEN set, INT clear), proving the line was idle when the C040 write landed, so "completion" means "the arm left an idle line down" and not "the setup failed". One session, two rows. PREDICTED: base -> completion, X -> 0x8. To be measured in the follow-up. The commit is regress-only (`pcc2_c040_probe.py` + the `gate_arm.sh` row list and pins), does not touch dev_pcc2.c, and owes its own pass 2.

## W -- `d->warned |= (1u << PCC2_W_C040);` -> `d->warned = (1u << PCC2_W_C040);`  => DEBT, file and disclose

What it does. Assignment instead of OR: the first C040 announce sets the C040 bit and clears the other thirteen once-only bits (the twelve width declines and the rest). The C040 arm's own behaviour is unchanged -- it still announces exactly once and still suppresses -- which is why every C040 row passes (measured 18/18, probe_eq.raw); `c040 predirty` passes because its latch test reads `warned` before the clobber and checks only the C040 announce. The consequence lands elsewhere: any other warning that had already fired fires again after a C040 write, so a guest can re-arm every once-only warning in the device with one byte store and none of them is once-only any more.

Why it is debt, not floor. This arm's code reads and tests exactly one bit of `warned`; the other bits belong to other arms, and the once-ness of those arms is pinned by their own rows (pcc2_width_probe.py), not by the C040 table. The C040 table's obligation on `warned` is the C040 bit in both states, and both are held (`c040 once`, `c040 predirty`). Outbound damage to bits this arm never reads is outside what this detector promises. [The DEPENDS-ON bound stops at the enclosing function and at fields the guarded body reads; bits the body never tests are marginals, clause (e). The shared-bitfield question -- "who else writes this field, can they set my bit" -- is the inbound direction and is rowed; the outbound direction is this, and a write-time check can reject or repair a row but never demand one.] It is still a real one-token hazard with a real consequence, so: file it MED, disclose it in the probe's contract (the contract does not currently mention it), and the pin is the re-fire row.

The row, when worked. Extend the `c040 predirty` session: ST_H(GENCTL) [latches PCC2_W_GENCTL_LEN], ST_B(0x04) [C040], ST_H(GENCTL) again; count the "unimplemented len=2 write to PCCTWO_GENCTL" announces, want 1 (mutant 2). Zero extra sessions. Not a member of the X follow-up's obligation; it may ride that commit but must not gate it.
