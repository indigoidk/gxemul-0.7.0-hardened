**Q1:** Choose DECLINE + LATCHED ANNOUNCE **for the unsupported interrupt-delivery operation**. The register write has already been accepted; describe that distinction explicitly.

The idiom exists in this file’s `pcc2_width_decline()` and, more directly, in `dev_sgi_re.c`: per-instance warning state, latched `fatal()`, then an unconditional return outside the warning latch. `fatal()` itself is a printing function here. | Disposition | Assessment |
|---|---|
| DELETE | Removing the branch permits ordinary delivery; removing only the exit also leaves repeated diagnostics. Neither establishes C040 semantics. |
| DECLINE, silent | Conceals an unsupported mode that can prevent guest interrupt handling. |
| **DECLINE + LATCHED ANNOUNCE** | Makes the limitation visible while bounding repeated diagnostics from ticks and callbacks. |
| ACCEPT | Ordinary interrupt routing is not established as a valid substitute for C040 routing. |
| FAULT | M88K device-access exceptions **are available**, but this is an implementation limitation, with no established hardware access fault. Tick/callback callers also lack a faulting transaction. |
| BACKED ACCEPT | GENCTL already has backing storage. Readback alone cannot implement its interrupt-delivery effect. |
| IMPLEMENT | The faithful eventual solution, requiring delivery semantics and appropriate wiring that this source does not supply. |

FAULT’s availability is confirmed by the M88K dispatch in `memory_rw.c` and implemented DATA_ACCESS handling; rejecting it here is a semantic decision. [Fault dispatch](C:/DocumentNoSnc/CC/GXEMUL/GXEMUL-SEC/src/cpus/memory_rw.c:603), [CPU handling](C:/DocumentNoSnc/CC/GXEMUL/GXEMUL-SEC/src/cpus/cpu_m88k.c:713).

Use a dedicated latch per PCC2 instance for this mode. The latch should suppress subsequent **messages**, never subsequent **refusals**.

**Q2:** **The scoped source does not settle hardware-correct behavior.** Its comment identifies EIPL output as the missing mechanism. The implemented tail instead calculates IPL, compares MASK, applies MIEN, and drives the connected CPU interrupt. That does not establish whether real C040 mode retains the same internal register calculations, or how its mode transitions behave.

For the proposed refusal contract, I favor returning before ordinary recalculation and delivery, with the modeled CPU output explicitly deasserted. Treat that as a documented approximation.

A bare return does **not** mean “nothing remains asserted.” The CPU callback stores persistent `irq_asserted` state; only its deassert callback clears it. Returning with local `assert = 0` never invokes that callback. It also leaves existing IPL/vector state untouched. Thus the contract must distinguish suppressing new assertions from withdrawing an existing one. [Persistent CPU IRQ state](C:/DocumentNoSnc/CC/GXEMUL/GXEMUL-SEC/src/cpus/cpu_m88k.c:412).

**Q4:** **A survival-only row is nonvacuous against the existing process termination, provided it actually reaches the operation.** That differs from a refusal-effect test where both alternatives survive.

Its contract remains narrow. Survival alone cannot distinguish the chosen refusal from ordinary fallthrough or a swallowed write. The stronger oracle should establish:

- Guest progress after the access and retained GENCTL readback.
- The declared interrupt-output behavior with pending work and MIEN enabled.
- Withdrawal of an existing assertion and recovery after leaving C040 mode.
- Continued refusal after the announcement latch is set, with bounded announcements.

A concrete instrumentation trap exists: debugger byte writes use `NO_EXCEPTIONS`, and `memory_rw()` skips this `DM_DEFAULT` device under that flag. Such an attempted setup can survive without reaching PCC2. The neighboring default probe already names this as the control row **`put b ctl`**. **Q5:** There is no existing C040 detector row to certify; the width probe prints `NOROW`.

A smallest static counterexample is **whole-register equality replacing C040 bit membership** in the proposed refusal condition. A proposed **`c040 idle`** survival row using only the brief’s single value would stay green. The refusal would then depend on companion GENCTL bits, including MIEN, which the ordinary delivery body reads. Other C040 configurations could fall through.

Existing **`rb4 genctl`** and **`rb8 genctl`** would also remain green because they deliberately keep C040 clear. These are static expectations, not measured results. Coverage must vary MIEN and meaningful pending-interrupt state and observe disposition; extra survival checks alone do not close this gap.
