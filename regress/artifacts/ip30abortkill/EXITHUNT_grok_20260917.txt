## 1. `ip30abortkill` — HIGH — host death via `abort()`

**File:** `GXEMUL-SEC/src/devices/dev_sgi_ip30.c`

```123:147:GXEMUL-SEC/src/devices/dev_sgi_ip30.c
	case 0x10020:	/*  Set ISR, according to Linux/IP30  */
		d->isr = idata;
		/*  Recalculate CPU interrupt assertions:  */
fatal("IP30 legacy interrupt rewrite: TODO\n");
abort();
	case 0x10028:	/*  Clear ISR, according to Linux/IP30  */
		d->isr &= ~idata;
		fatal(...); abort();
	case 0x10030:	/*  Interrupt Status Register  */
		if (writeflag == MEM_WRITE) {
			d->isr &= ~idata;
			fatal(...); abort();
```

And the tick, after a **legal** mask write:

```74:78:GXEMUL-SEC/src/devices/dev_sgi_ip30.c
	if (d->imask0 & ((int64_t)1<<50)) {
		fatal("IP30 legacy interrupt rewrite: TODO\n");
		abort();
```

**Reachability — CONFIRMED for the ISR pair; BELIEVED for the tick.**

- Constructor `machine_sgi.c` case 30 does **not** `abort()`. It `device_add("sgi_ip30 addr=0x0ff00000")`. Subtype is advertised (`IP30` / `ip30` / `octane`). `ctorabortclass` names ip19/ip20/ip22/ip24/ip27, **not** ip30. `#446` already proved construction reaches `arcbios_init` on ip30.
- Window: `DEV_SGI_IP30_LENGTH = 0x80000` at `0x0ff00000`. Offsets `0x10020` / `0x10028` / `0x10030` / `0x10000` are inside it.
- `case 0x10020` and `0x10028` have **no `writeflag` test**. A guest `ld` **or** `sd` at `0x0ff10020` dies. Instruction: MIPS `ld`/`sd` (or `lw`/`sw`) from kernel mode on `-E sgi -e ip30`.
- Tick: write `imask0` at `+0x10000` with bit 50, then wait. That write is implemented and does not abort; the **next `DEVICE_TICK` does**.

**Not IP22.** `dev_sgi_ip22.c:315` / `:339` are the same `abort()` shape, but `machine_sgi.c` `abort()`s **before** `dev_sgi_ip22_init`. That is construction (`ctorabortclass`), not a guest path.

**Member:** 7 IMPLEMENT (the commented `cpu_interrupt` is the intended model) or 3 DECLINE + LATCHED ANNOUNCE if the interrupt rewrite stays out of scope. Member 5 FAULT **is** available (MIPS), but `abort()` fires before any `return 0`.

**Gate:** none. No ip30 probe under `regress/`. Gate 9 may construct it; nothing feeds `0x10020`. Blind-spot, same class as `armmsrmodekill`.

**Severity HIGH:** `abort()` is worse than `exit(1)` (SIGABRT, core). No in-tree Octane image, so this is probe-HIGH not boot-HIGH — same standing as `mapledmaaddr` / `vmedefaultkill` on an advertised machine.

**Queue check:** named in the 2026-08-17 `exitsweep` correction (`OUTSTANDING_BUGS.md`, “No `abort()` is guest-reachable is FALSE”) and in one closed-row seat note. **No `id`.** `exitunowned76` counts `exit(`, not `abort(`. `cpusexitsweep` is `src/cpus/` only.

## 2. `8259cmdhalt` — MEDIUM — `cpu->running = 0` (halt, not host death)

**File:** `dev_8259.c` command port (`relative_addr == 0`), unimplemented OCW.

```137:140:GXEMUL-SEC/src/devices/dev_8259.c
			} else {
				fatal("[ 8259: unimplemented command 0x%02x ]\n", (int)idata);
				cpu->running = 0;
			}
```

Then it still `return 1`. The access “succeeds”; the strand stops.

**Reachability — CONFIRMED, probe.** `DEV_8259_LENGTH` is 2, so the `default:` arm is dead. The live door is **offset 0, a byte the PIC command port actually takes.** `bus_isa.c` installs this on CATS (`0x7c000020` / `0x7c0000a0`, measured in the `isaorder` row). Guest: ARM `strb` of a command that is not ICW1 (`bit 4`), not `0x0a`/`0x0b`/`0x0c`, not EOI `0x20`/`0x21–0x27`/`0x60–0x67`/`0xe0–0xe7`, not `0x68`/`0xc0–0xc7`. **`strb r0, [pic]` with r0=0 is enough.**

A healthy Linux PIC init mostly writes `0x11` / `0x20`. BELIEVED not on the CATS boot path; CONFIRMED as a one-instruction probe. Gate 14 exercises CATS decode, not PIC OCWs.

**Member:** 2 silent decline or 3 latched. Member 5 FAULT is **not** available (ARM). And the function returns 1 anyway, so FAULT would not fire even on MIPS.

**Why it outranks leftover `exit(` sites:** `armthumbabortkill` shape, on a machine this project actually uses, invisible to `exit(`.

## 3. `lunafbhalt` — MEDIUM — same halt shape, on the luna88k framebuffer

**File:** `dev_lunafb.c`. `lunafb_a` `default:` and `lunafb_b` `default:` plus a ROP-not-all-ones write all do `cpu->running = 0; return 0`.

Installed unconditionally from `DEVINIT(luna88k)` at `0xB1000000`. `lunafb_a` is **512 KB** (`0x80000`) and implements only `BMAP_RFCNT` (`0xB1000000`) and `BMAP_BMSEL` (`0xB1040000` — the comment saying `0xb1000000` for both is wrong; the `#define`s are right). Every other offset in that window, and every `lunafb_b` offset that is not plane-1 detect or `BMAP_FN+4*ROP_THROUGH` with `idata == 0xffffffff`, stops the CPU.

**Reachability — CONFIRMED probe on unmodified `-E luna-88k`.** Guest: m88k `st`/`ld` to e.g. `0xB1000004`. OpenBSD’s `omfb_clear_framebuffer` is cited as using BMSEL, which is implemented (ignored), so BELIEVED the luna boot to `login:` does not hit the `default:`. FAULT **is** available (M88K) and `return 0` would actually deliver it — today the halt runs first.

No dedicated row. Not `lunaabsentcpu` (that was a NULL `INTERRUPT_ASSERT`).

## 4. `mvme187memcoob` — MEDIUM as a rider, not a new kill

`dev_mvme187.c` indexes **before** the switch:

```68:68:GXEMUL-SEC/src/devices/dev_mvme187.c
	odata = ((uint8_t*)&d->memcreg)[relative_addr];
```

Device length **0x200**. After `relative_addr &= ~0x100`, the index is `0..255`. `struct memcreg` is 124 bytes (31 padded registers). **Offsets 124–255 are a host OOB read**, then `default: exit(1)`.

The **kill** is already inside `exitunowned76` (`:80`, `:90`). The **OOB is what `exit(` cannot see**, and it is the `asicindexcase` shape: the `exit(1)` is also the bounds check. A de-fatalisation that does not clamp the index turns a host death into a silent heap read of whatever follows the malloc’d device.

M88K, FAULT available for the kill; the OOB needs a bound, not a member.
