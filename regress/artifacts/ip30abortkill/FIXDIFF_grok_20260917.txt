## Q2 — decline the `isr` write

**Decline it.** Keep clear-on-write only if you have a measured guest that writes `0x10030` expecting clear. There is none.

What the addition licence actually has:

| candidate | warrant? |
|---|---|
| **Decline the write** | **Transferred:** Linux `heart.h` — the document this file cites three times — marks `isr` `(read-only)`. Clearing is `clear_isr` at `0x10028`, which this file already implements. The arm’s own `TODO: is this correct?` is answered **no**. Fable 5.1 already ruled this: member 6 BACKED ACCEPT without a warrant. |
| Keep clear-on-write as “emulator compatibility” | **Neither.** No PROM/Irix/Linux trace in this tree writes `0x10030`. Linux/IP30 would write `0x10028`. “Guests might do it” is “cannot hurt”. |
| Member 4 (keep the computed value) | **Does not apply.** Member 4 is “the model already computes the **right** value and then discards it.” Maple `#528` is that shape. Here the computed value is the **wrong operation**. |

So the write arm becomes: latch, do not `d->isr &= ~idata`, `break`. It owes a **state** row (write declined **and** ISR unchanged), not merely `alive`. That is Fable’s sentence; `kill 30 wr` as survive-only cannot see this repair (Q5).

## Q3 — latch

Two bits, per instance, in `struct sgi_ip30_data`. `DEVINIT` already `memset`s. Crime’s wording: one bit per site, never shared.

| bit | fires on |
|---|---|
| `IP30_W_TICK` | `imask0 & (1<<50)` in `DEVICE_TICK` |
| `IP30_W_ISR` | every ISR-side former abort: set/clear write (recalc stub), set/clear read (direction decline), `isr` write (read-only decline) |

One shared bit lets a Set-ISR write silence the timer diagnostic for the life of the instance. That is the measured reason for two, not three. A third bit for the `0x10030` decline is coverage debt, not this round’s floor — the brief settled two.
